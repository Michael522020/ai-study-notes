# 跨文化改写而非直译

> **核心问题**：中文的「请尽快回复」直译成英文，为什么在当地客户听来不专业？

---

## 0. 直译的六个典型失效

| # | 原文（中文） | 直译（英文） | 当地人的感受 |
|---|---|---|---|
| **1** | 「尽快回复」 | "Reply as soon as possible" | **不专业**——像催款，不像服务 |
| **2** | 「久仰贵司大名」 | "I have long admired your company's reputation" | **奇怪**——中式寒暄，英语商务里没有 |
| **3** | 「附件请查收」 | "Please find attached" | 勉强可用，但各地习惯不同 |
| **4** | 「价格可再商议」 | "The price is negotiable" | 在德国市场**显得轻率** |
| **5** | 「我们是行业领先者」 | "We are a leading company in the industry" | **空洞**，本地客户对自夸敏感 |
| **6** | 「随附样品」 | "Sample is enclosed" | 德国/日本要求**明确的行动指引** |

> **共同点**：**句子在语法上是对的，但在文化上不对。**
> **直译产出的是「语法正确的外语」，不是「本地人会说的话」。**

---

## 1. 跨文化改写的六个维度

### 1.1 语域与正式度（Register）

**同一句话，不同市场的「正式度基准」完全不同。**

| 市场 | 基准正式度 | 特征 |
|---|---|---|
| **德国** | **很高** | 严谨、少形容词、重视技术细节与承诺的精确性 |
| **日本** | **很高** | 敬语层级、间接表达、避免直接否定 |
| **美国** | 中（偏直接） | 友好、benefit-first、**不铺垫** |
| **英国** | 中 | 委婉、含蓄、可能有「轻描淡写」的习惯 |
| **中东（海湾）** | **高** | 正式、问候与礼仪有固定形式、宗教用语敏感 |
| **巴西/拉美** | 中偏低 | **关系优先**、热情、个人化 |

**同一个「改进方案」，在德国要写参数，在美国要先写收益。**

### 1.2 称谓与敬语

| 市场 | 称谓要点 | 常见错误 |
|---|---|---|
| **德国** | **学位与职称是规范的一部分**（`Herr Dr. Meier`）；先姓后名 | 漏掉学位 → 显得不重视 |
| **日本** | **姓 + 敬称 + 职务**（`田中部長`）；层级明确 | 过度亲昵 → 失礼 |
| **法国** | **`M.` / `Mme` + 姓** | 用英语的 `Dear + 全名` |
| **中东** | **头衔 + 家族名**；先问候再谈事 | 直接进入正题 → 失礼 |
| **美国** | `Dear Mr. Smith` | — |

> **称谓错误是最容易被察觉、也最容易被原谅**（对方通常会理解）。
> 但**它决定第一印象**，而第一印象影响后续所有沟通。

### 1.3 表达结构（不是逐句对应）

**英语偏好「结论先行」，很多语言偏好「背景先行」。**

```
英语：结论 → 理由 → 细节
德语：背景/技术细节 → 结论
日语：铺垫 → 委婉提议 → 确认
中文：背景 → 结论（较接近德语）
```

> **同样的信息，语序不同，说服力不同。**
> **直译会保留源语言的语序**——这在英语读者那里读起来「绕」。

### 1.4 说服逻辑

**不同市场被说服的路径不同。**

| 市场 | 什么说服人 | 什么会劝退 |
|---|---|---|
| **德国** | **技术参数、认证、可验证的承诺** | 夸张的形容词、没有数据支撑的形容词 |
| **美国** | **结果与收益、用户案例、简单直接** | 冗长的技术铺垫 |
| **日本** | **可靠性、长期关系、细节完美** | 强推、紧迫感促销 |
| **中东** | **信任、关系、面子、尊称** | 直接谈钱、过于机械 |
| **拉美** | **个人化热情、口头承诺、当面沟通** | 冷冰冰的自动化邮件 |

> **这是最贵的一层差异**——
> **产品文案、邮件序列、谈判话术都要按市场重写，不是翻译。**

### 1.5 禁忌与敏感点

| 类型 | 例子 |
|---|---|
| **符号** | 德国的礼物包装与颜色、日本的包装形式、某些中东市场的左手与特定手势 |
| **数字** | **西方忌讳 13**；部分市场对 4 的忌讳 |
| **宗教** | 中东市场的宗教用语与圣日；欧美市场的宗教敏感度 |
| **身体语言** | 拇指、点指、双手递物 |
| **话题** | 特定国家的历史、宗教、政治话题 |
| **图像** | 手势含义、服装、饮食（清真） |

> **这些通常无法从「语言」推导，只能靠当地知识**——
> **这就是「市场画像卡」存在的理由**（见 §3）。

### 1.6 格式与本地化

**技术层面但极易出错、且直接影响专业观感。**

| 项 | 例子 |
|---|---|
| **日期** | `2026-11-16`（ISO）/ `11/16/2026`（美）/ `16.11.2026`（德）/ `16/11/2026`（欧）——**「11/16」在美式是 11 月 16 日，在欧式是 16 日 11 月** |
| **数字** | `1,234.56`（美/中）vs `1.234,56`（德） |
| **货币** | 符号位置：`$100` / `100 $` / `100 €` / `€100`；**币种要在价格旁明确** |
| **单位** | 公制 vs 英制、温度、重量 |
| **地址** | 收件人姓名、门牌号顺序、邮编位置（**日本邮编在前，德国邮编在城后**） |
| **电话** | 国际区号格式 |
| **名称** | **姓名顺序**（中文「张伟」= 姓张名伟；西方「Wei Zhang」）、**中间名**、**前缀**（Dr./Prof.） |

> **日期歧义是跨境商务里最经典的事故**——
> `03/04` 到底是 3 月 4 日还是 4 月 3 日，取决于对方在哪个国家。
> **解决办法：在跨境文档里一律用 ISO 格式或文字月份名。**

## 2. 本地化（L10n）≠ 翻译

**这是本节最重要的区分。**

| 层次 | 内容 | 谁做 |
|---|---|---|
| **① 语言本地化** | 文本翻译 | 翻译/模型 |
| **② 格式化本地化** | 日期/数字/货币/单位/地址/电话 | **代码**（ICU / CLDR） |
| **③ 文化适配** | 语气、说服逻辑、示例、图像、称谓 | **需要本地专家** |
| **④ 功能本地化** | 本地支付方式、本地物流、本地客服时间、本地法规要求 | **产品 + 工程** |
| **⑤ 法规本地化** | 标签、成分表、警示语、说明书 | **法务 + 本地** |

> **第 ② 层必须用代码做（ICU/CLDR），不能交给模型**——
> **这正是 12 主线说的「确定性的东西不要交给概率模型」。**

```python
# ❌ 让模型处理日期与货币
prompt = f"把价格 {price} 翻译成英文"

# ✅ 代码处理格式化，模型只处理语言
from babel.numbers import format_currency, format_decimal
from babel.dates import format_date
localized = format_currency(price, currency="EUR", locale="de_DE")   # "1.234,56 €"
localized_date = format_date(date(2026, 11, 16), format="long", locale="en_US")
```

> **数字与日期格式错误的代价远大于文案措辞错误**——
> **因为它是「事实错误」，会直接导致商务事故。**

## 3. 怎么让模型做跨文化改写

### 3.1 市场画像卡（Market Profile Card）

**把「当地知识」显式化，作为 prompt 的一部分。**

```markdown
## 目标市场：德国（B2B 工业设备采购）

- **正式度**：高。避免形容词堆砌，用事实与数据说话
- **称谓**： Herr Dr. <姓>（保留学位）；邮件开头写全名与职务
- **语序**：技术细节先行，结论在最后一段
- **说服点**：技术参数、认证（CE/EN 标准）、可验证的交付与售后承诺
- **禁忌**：不用 "as soon as possible"，用具体日期；
  不用夸张的最高级；不承诺无法保证的时效
- **格式**：日期 16.11.2026；货币 1.234,56 €；技术参数用表格
- **语言**：德语（Sie 形式）
```

### 3.2 改写的提示结构

```
【源文本】……
【目标市场画像卡】……
【改写要求】
1. 按目标市场的语域与语序重写，**不要逐句对应**
2. 使用【术语表】中的规范译名
3. 遵循【格式规范】（日期/货币/单位）
4. 保持【事实】完全不变——只改表达，不改信息
5. 如果直译会丢失信息或造成误解，**不要为了「忠实」而保留歧义**
```

**第 4 条与第 5 条是一对**：
**改写可以调整表达，但绝不能改变事实；遇到直译会失真的地方，宁可意译也不保留歧义。**

### 3.3 「事实不变」怎么保证

**用机器校验，而不是靠提示词。**

| 事实类型 | 校验方法 |
|---|---|
| **数字** | 抽取改写前后的数字集合，**必须一致**（除非明确允许换算单位） |
| **型号 / 订单号 / 金额** | 必须在术语表里存在（见 [`02`](./02-多语言Agent的术语一致性.md)） |
| **承诺性表述** | 关键承诺词（交货期、保修、赔付）在改写后仍存在 |
| **日期** | 解析后的日期必须相等（不只是字符串相等） |

> **「数字集合一致」是最简单也最有效的校验**——
> 改写时模型最容易犯的错就是**悄悄改数字**（"30 天" 变成 "一个月"）。

### 3.4 一个实用的校验脚本

```python
import re
NUM_RE = re.compile(r"\d+(?:[.,]\d+)*")

def check_numbers(src: str, dst: str) -> list[str]:
    """改写前后的数字集合必须一致"""
    a = {n.replace(",", "") for n in NUM_RE.findall(src)}
    b = {n.replace(",", "") for n in NUM_RE.findall(dst)}
    if a != b:
        return sorted(a ^ b)      # 对称差 = 出问题的数字
    return []
```

## 4. 本地化检查清单

### 4.1 内容层

- [ ] 语域符合目标市场基准（**不是按英语习惯猜**）
- [ ] 称谓、敬语、头衔正确
- [ ] 语序符合目标语言的表达习惯（**不是逐句对应**）
- [ ] 说服点匹配目标市场（**德国给参数、美国给收益**）
- [ ] 无禁忌符号、话题、图像
- [ ] **所有数字、金额、日期、型号未改变**
- [ ] 术语表规范译名一致

### 4.2 格式层（代码保证）

- [ ] 日期格式（**含歧义检查**）
- [ ] 数字与千分位
- [ ] 货币符号位置与**币种明确**
- [ ] 单位制
- [ ] 地址格式（姓名顺序、邮编位置）
- [ ] 电话与国际区号
- [ ] 时区

### 4.3 功能与法规层

- [ ] 本地支付方式
- [ ] 本地物流与 Incoterms
- [ ] 客服时间与联系方式的本地化
- [ ] 标签/说明书/警示语符合当地法规
- [ ] 隐私政策与数据条款的本地版本

## 5. 工程结论

1. **直译产出的是「语法正确的外语」，不是「本地人会说的话」。**
   六个典型失效（尽快/久仰/请查收/可商议/行业领先/随附样品）都语法正确、文化不对。
2. **跨文化改写有六个维度**：语域、称谓、**表达结构（非逐句对应）**、
   **说服逻辑**、禁忌、格式。
3. **格式层（日期/数字/货币/地址）必须用代码做（ICU/CLDR）**——
   **确定性的东西不要交给概率模型**。
4. **日期歧义是跨境商务最经典的事故**（`03/04`）——
   **跨境文档一律用 ISO 格式或文字月份名**。
5. **数字格式错误是「事实错误」，代价远大于文案措辞错误。**
6. **说服逻辑的差异最贵**——**文案/邮件序列/话术要按市场重写，不是翻译。**
7. **把当地知识显式化成「市场画像卡」**，再交给模型改写。
8. **「事实不变」要靠机器校验**（数字集合一致 + 术语校验），
   不要靠提示词要求——**模型最常悄悄改的是数字**。
9. **本地化有五层**（语言 / 格式 / 文化 / 功能 / 法规），**不要只做第一层**。
