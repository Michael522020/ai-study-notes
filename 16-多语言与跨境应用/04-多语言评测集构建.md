# 多语言评测集构建

> **核心问题**：多语言效果怎么测？「模型说得不地道」这件事，谁来判定？

---

## 0. 三个难点

**多语言评测比单语言难在三点，且都不是技术问题。**

| 难点 | 说明 |
|---|---|
| **① 谁来标注** | 需要**母语者**，且懂业务。找到并组织他们比写代码难得多 |
| **② 什么算「好」** | 「语法对」容易判；**「说得地道」「说得得体」「说服力够」很难** |
| **③ 判官本身** | **LLM 判官在低资源语言上本身就不可靠**——用它判低资源语言 = 用不可靠的东西判不可靠的东西 |

> **推论**：
> **多语言评测的核心投入是「人」与「标注标准」，不是「方法」。**

---

## 1. 五种错误类型（必须分开评）

**把「多语言错误」拆开，才能知道该改什么。**

| # | 错误类型 | 例子 | 归属 |
|---|---|---|---|
| **E1** | **理解错误** | 用户问「多少台起订」，模型答成了「交货期」 | 模型能力 / 检索 |
| **E2** | **术语不一致** | 产品名用错了译名 / 型号被翻译 | **数据层**（术语表） |
| **E3** | **文化不适配** | 语气过硬 / 说服点不对 / 用了禁忌表达 | **提示词与市场画像** |
| **E4** | **格式错误** | 日期 `11/16` 歧义、货币格式错、地址顺序错 | **代码层**（ICU） |
| **E5** | **事实被改** | 「30 天交货」变成「一个月」 | **改写环节**（最危险） |

> **E1~E5 的修复动作完全不同**：
> E1 换模型/加数据，E2 补术语表，E3 改市场画像，E4 改代码，E5 加校验断言。
> **只报一个总分，你不知道该改哪。**

---

## 2. 评测集构建流程

```
① 定义任务与语言矩阵
        ↓
② 采集真实样本（按语言/场景分层）
        ↓
③ 每个语言准备「参考答案」（母语者产出或校订）
        ↓
④ 标注标准与示例（★ 最花时间的部分）
        ↓
⑤ 标注 + 双人仲裁 + 分歧归因
        ↓
⑥ 盲测对照（★ 关键一步，见 §4）
        ↓
⑦ 建基线 + 定期回归
```

### 2.1 关键设计：两个版本的评测集

| 版本 | 构成 | 用途 |
|---|---|---|
| **A 源语言评测集** | 每个语言**独立**的原生样本 + 本地参考答案 | **测真实能力** |
| **B 对比评测集** | 同一批内容的多语言翻译版本 | **测改写/翻译质量**（**不能替代 A**） |

> **只有 B 会产生虚假的安全感**：
> 翻译版测试的是「模型能不能处理翻译后的文本」，
> 而真实用户输入的是**有省略、有口语、有错别字、有本地表达习惯**的原生文本。

**A 集必须包含**：

| 样本类型 | 为什么 |
|---|---|
| **原生口语** | 「多少钱啊」vs「请问贵司的产品报价是多少」 |
| **含错别字** | 当地常见的拼写变体 |
| **含省略** | 真实聊天里的省略主语 |
| **含本地表达习惯** | 地区特有说法 |
| **含代码/型号** | **最容易被模型改错的部分** |
| **含数字与日期** | **格式与事实风险最高** |

## 3. 标注：标准比人力更难

### 3.1 标注维度

| 维度 | 判什么 | 怎么判 |
|---|---|---|
| **事实正确性** | 事实是否与依据一致 | 对照依据/知识库，**可自动化的部分尽量自动** |
| **数字与格式** | 数字是否被改、格式是否对 | **纯自动**（正则 + ICU） |
| **术语正确** | 是否用了规范译名 | **纯自动**（术语表比对） |
| **语法正确** | 语法 | 模型判官可辅助 |
| **地道程度** | 像不像本地人写的 | **母语者主观分** |
| **得体性** | 语气是否合适 | **母语者主观分** |
| **任务完成** | 有没有解决问题 | 规则 + 人工 |

> **前三个维度可以自动化**——
> **把它们从人工标注里剥出来，人工只做后四个，标注成本能降一半以上。**

### 3.2 标注标准怎么写

**不是写「请评价地道程度 1~5 分」，而是给对照示例。**

```markdown
## 地道程度（1~5）

**5 分** —— 母语者会认为这是本地人写的，包含本地惯用表达与自然的语序
   例（德语）："Wir richten uns mit der Anfrage an Sie und melden uns
              gern mit einem Angebot."（自然的商务德语）

**3 分** —— 语法正确、意思清楚，但读得出翻译腔
   例："Wir richten die Anfrage an Sie und antworten gern mit einem Angebot."

**1 分** —— 有语法错误，或使用了不恰当的直译
   例："Wir richten die Anfrage Sie an und freuen uns sehr, ein Angebot zu antworten."

**给分要求**：只看表达质量，不因内容错误扣分（内容另评）。
```

> **「给对照示例」是标注质量的关键**——
> 没有示例的标注标准，不同标注员之间会差一个档。

### 3.3 双人仲裁与分歧归因

| 步骤 | 做法 |
|---|---|
| 两人独立标注 | 不互看 |
| 计算一致率 | 逐维度算（**地道程度的一致率通常最低**） |
| 分歧仲裁 | 第三人裁定，**记录分歧原因** |
| 分歧原因归类 | 标注标准不清 / 样本本身有争议 / 个人偏好 |
| 改标准而不是改人 | **分歧是标准的问题**（多数情况下） |

> **「地道程度」的一致率低是正常的**——
> 它接近于「审美判断」。**降级使用**：把 5 分当 3 分用（合并档位）。

## 4. 盲测对照：多语言版本更关键

**多语言场景下，盲测对照能筛出更多无效题。**

```
去掉图像/去掉上下文后，纯靠语言先验能不能答对？
   → 能答对的题，没测到目标能力 → 剔除或降权
```

**多语言特有的盲测变体**：

| 变体 | 做法 | 筛出什么 |
|---|---|---|
| **无上下文盲测** | 只给问题不给资料 | 测到的是「知识先验」不是「检索能力」 |
| **源语言盲测** | 用源语言问同一个问题 | 差值 = **该语言的真实能力损失** |
| **回译盲测** | 把参考译文回译，与原文比 | 回译偏差大的语言 = **该语言的任务有歧义** |

> **源语言盲测的差值是最有价值的指标**：
> ```
> 语言能力损失 = 源语言正确率 - 目标语言正确率
> ```
> **它把「这个模型在这个语言上弱」量化成了可追踪的数字。**

### 4.1 回译（back-translation）该怎么用

**回译是一个有用的辅助验证，但有两个陷阱。**

| 陷阱 | 说明 |
|---|---|
| **虚假安全感** | 回译很流畅 ≠ 原文对。**流畅的回译可能把错误「美化」了** |
| **掩盖不对称** | 源语言→目标语言 与 目标语言→源语言 的难度不同，**回译只用了一个方向** |

> **用法**：回译**偏差大**的样本 → 人工复核该样本（可能是题有问题）。
> **不要**用回译相似度当质量指标。

## 5. 判官：按语言分别校准

### 5.1 判官选择的决策

```
某个语言的判官一致率够高吗？
  ├─ 够高（≥ 0.75）→ 用 LLM 判官（+ 人工抽检 10%）
  └─ 不够
        ├─ 答案可结构化 → 用规则/精确匹配（数字、术语、格式）
        ├─ 不可结构化 → **用母语者人工标注**（成本高但可靠）
        └─ 折中 → 用**该语言的微调小模型**做判官（需先校准）
```

### 5.2 判官校准怎么做

```python
# 用人工标注的金标准集测判官本身
def calibrate_judge(judge, gold_set, lang):
    agree = sum(judge(item) == item.human_label for item in gold_set)
    return agree / len(gold_set)     # 每种语言分别算
```

**关键**：**每种语言单独算一致率**，然后画一张表：

| 语言 | 判官一致率 | 判官等级 |
|---|---|---|
| en | 0.89 | ✅ 可用 |
| de | 0.82 | ✅ 可用 |
| fr | 0.71 | ⚠️ 谨慎 + 抽检 |
| th | 0.43 | ❌ **改用人工或规则** |
| ar | 0.38 | ❌ **改用人工或规则** |

> **这张表是「判官能不能用」的依据**——
> **不是「模型支持不支持这个语言」**。
> 模型支持的语言里，判官照样可能不可靠。

### 5.3 一个反直觉的点

**「用更强的模型做判官」不一定更好。**
在某些语言上，更强的通用模型反而更容易被「流畅但错误」的回答带偏。
**判官的质量取决于它在该语言上的能力，而不是它总体上的强弱。**

## 6. 规模与抽样

| 目的 | 每语言样本量 | 说明 |
|---|---|---|
| **上线门禁** | **≥ 50 条** | 低于这个数，任何比率的置信区间都宽到不能支撑决策 |
| **方向性判断** | ≥ 20 条 | 只能看趋势，不能做上线决策 |
| **回归测试** | 20~30 条固定集 | **每次改动都跑**，看是否退化 |

**分层采样**（不要随机抽）：

| 层 | 建议占比 | 说明 |
|---|---|---|
| **常见场景** | 40% | 主力路径 |
| **边界场景** | 25% | 长输入、特殊格式、缺信息 |
| **困难场景** | 20% | 需要多步推理或跨文档 |
| **对抗场景** | 15% | 注入、术语陷阱、歧义表达 |

### 6.1 一个必须做的平衡

**每个语言至少要有「该语言特有的困难样本」**：

- 该语言特有的表达习惯（省略、敬语层级）
- 该语言的特有歧义（`03/04` 式日期、`可` 与 `可` 之类）
- 该语言的特有格式（地址、货币、姓名顺序）

> **翻译测试集不会有这些**——
> 这正是「源语言评测集不可替代」的原因。

## 7. 分语言指标看板

**永远分语言看，不要看总分。**

| 指标 | 英文 | 德文 | 阿拉伯文 | 泰文 |
|---|---|---|---|---|
| 任务成功率 | 0.91 | 0.84 | 0.62 | 0.58 |
| 术语一致率 | 1.00 | 0.97 | 0.88 | 0.91 |
| 数字保真率 | 1.00 | 0.99 | 0.95 | 0.93 |
| 格式正确率 | 0.99 | 0.86 | 0.71 | 0.68 |
| **地道程度（母语者）** | 4.6 | 4.2 | 3.4 | 3.6 |
| **源语言盲测差值** | — | 0.07 | **0.29** | **0.33** |

> **这张表能直接读出结论**：
> 阿拉伯文与泰文的**主要问题不是模型能力（格式正确率与地道程度更差），
> 而是格式层**——这指向 ICU/格式化代码，而不是换模型。

## 8. 回归与持续评测

### 8.1 三层回归

| 层 | 内容 | 频率 |
|---|---|---|
| **自动断言** | 数字保真、术语一致、格式正确（**纯代码**） | **每次改动** |
| **金标准回归** | 每语言 20~30 条固定集，跑任务成功率 | **每次改动** |
| **母语者抽检** | 每语言 15~20 条，主观维度 | **每周/每版本** |

### 8.2 自动断言的例子（可直接进 CI）

```python
def multilingual_assertions(src_text, out_text, lang, glossary):
    issues = []
    issues += [f"数字被改: {d}" for d in check_numbers(src_text, out_text)]
    issues += [f"未知型号: {m}" for m in check_identifiers(out_text)]
    issues += [f"术语不一致: {t}" for t in check_term_consistency(out_text, lang, glossary)]
    issues += [f"格式错误: {f}" for f in check_format(out_text, lang)]
    return issues
```

> **这些断言是「确定性的」**——
> **把它们从人工评测里剥出来，是多语言评测降本的第一步。**

## 9. 工程结论

1. **多语言评测的核心投入是「人」与「标注标准」，不是方法。**
2. **五类错误（理解 / 术语 / 文化 / 格式 / 事实被改）必须分开评**——
   修复动作完全不同，**只报总分你不知道该改哪**。
3. **必须有「源语言评测集」**（原生口语、错别字、省略、本地表达习惯、
   型号、日期数字）——**只有翻译版会产生虚假的安全感**。
4. **地道程度与得体性只能靠母语者**，且**标注要给对照示例**——
   没有示例的标准，不同标注员之间会差一个档。
5. **地道程度的一致率天然低**——**合并档位（5 分当 3 分用）**。
6. **盲测对照在多语言下更关键**：
   **「源语言盲测差值」把语言能力损失量化成了可追踪的数字**。
7. **回译是辅助验证，不是质量指标**——它会「美化」错误。
8. **判官按语言分别校准**，一致率低的语言改用规则或人工——
   **「模型支持这个语言」不等于「判官在这个语言上可靠」**。
9. **更强的判官不一定更好**——取决于它在该语言上的能力。
10. **样本量：上线门禁 ≥ 50 条/语言**；回归集 20~30 条固定。
11. **自动断言（数字 / 术语 / 格式）优先自动化**，人工只做主观维度——
   **这是多语言评测降本的第一步**。
