# 两阶段检测器

> **核心问题**：从 R-CNN 到 Sparse R-CNN，这条线的核心思想是什么？为什么它至今仍是高精度任务的默认选择？

---

## 1. 两阶段范式的本质

```
        ┌─────────────────────────────┐
图像 →  │  Backbone + FPN              │ → 特征图
        └─────────────────────────────┘
                          ↓
                ┌──────────────────┐
                │  RPN / Proposal   │ → 候选框（几百个）
                │  Stage 1          │   + 粗分类 + 粗回归
                └──────────────────┘
                          ↓
                ┌──────────────────┐
                │  RoI Head         │ → 精分类 + 精回归
                │  Stage 2          │
                └──────────────────┘
```

**核心思想**：**先「看» 再「判」**。
- Stage 1 负责「图中哪里可能有问题」（高召回，允许大量误检）
- Stage 2 负责「这到底是什么、有多准」（高精度）

**为什么有效**：Stage 2 可以对**每个候选框单独做精细处理**（高分辨率 crop、大感受野、二次分类），这是单阶段做不到的。

## 2. R-CNN（2014）

**论文**：*Rich feature hierarchies for accurate object detection and semantic segmentation*, CVPR 2014
**作者**：Girshick, Donahue, Darrell, Malik

### 2.1 流程

```
1. Selective Search（选择性搜索）生成 ~2000 个候选区域
2. 每个区域 warp 成 224×224，送入 AlexNet（5 层卷积 + FC）
3. 用 4096 维特征 + 线性 SVM 分类
4. 用分类得分做 NMS
5. 用边界框回归精修位置
```

### 2.2 问题

| 问题 | 后果 |
|---|---|
| **区域提议慢** | Selective Search 每张图要 30~60 秒 |
| **特征不共享** | 2000 个区域 → 2000 次前向传播 |
| **需要预训练 + SVM** | 训练流程复杂，无法端到端 |
| **存储爆炸** | 2000 × 4096 维特征要落盘 |

**速度：~60 秒/张**（GPU + 多核 CPU）。

### 2.3 贡献

虽然慢，但确立了「**CNN 特征 + 区域提议**」这个至今未变的范式，并证明了两阶段优于当时的一阶段方法。

## 3. Fast R-CNN（2015）

**论文**：*Fast R-CNN*, ICCV 2015

### 3.1 三点改进

| 改进 | 做法 | 收益 |
|---|---|---|
| **共享卷积** | 全图只算一次卷积，RoI 用特征图裁剪 | 100× 加速 |
| **RoI Pooling** | 把任意尺寸的 RoI 特征池化成固定 7×7 | 统一输入 |
| **多任务损失** | 分类 + 回归联合训练 | 端到端 |

### 3.2 RoI Pooling 的实现

**关键创新**：不在原图上裁剪，而是在**特征图上裁剪**。

```
原图 RoI: (x1,y1,x2,y2)  尺寸 (w, h)
特征图缩放比: s = feature_stride (如 16)
特征图上的 RoI: (x1/s, y1/s, x2/s, y2/s)  尺寸 (w/s, h/s)
                              ↓
                     RoI Pooling: max over 7×7 bin
                              ↓
                       固定 7×7 × C 的特征块
```

**RoI Pooling 的两个技术点**：
1. **量化**：把浮点坐标**向下取整**到整数（这是 Mask R-CNN 要改成 RoIAlign 的原因）
2. **分 bin 池化**：把 RoI 分成 7×7 个 bin，每个 bin 取最大值

### 3.3 量化误差问题

**RoI Pooling 的致命缺陷**：

```
GT box 在原图: (x=100.7, y=200.3, w=50.5, h=30.2)
除以 16 量化:  (6.29, 12.52, ...) → 向下取整 → (6, 12)
误差: 0.29 × 16 = 4.64 像素！
```

**后果**：对小目标（只有 20 像素宽），4.6 像素的量化误差是灾难性的。这直接限制了 Mask R-CNN 的 mask 精度上限。

### 3.4 速度

**~0.5 秒/张**（GPU），比 R-CNN 快 100 倍以上。

## 4. Faster R-CNN（2015）

**论文**：*Faster R-CNN: Towards Real-Time Object Detection with Region Proposal Networks*, NIPS 2015

### 4.1 RPN：把 Selective Search 换掉

**核心思想**：RPN 是一个**共享卷积特征的子网络**。

```
特征图 (C×H×W)
    ↓
3×3 Conv (256 channels)          ← 锚框回归的公共特征
    ↓
  ┌─────┴─────┐
  ↓           ↓
分类分支    回归分支
(2 类:      (4 个参数
 obj/not)    × k 个 anchor)
```

**RPN 的两个输出**：
1. **分类**：每个 anchor 是目标/背景（2 类）
2. **回归**：每个 anchor 的偏移量（$\Delta x, \Delta y, \Delta w, \Delta h$）

### 4.2 Anchor 机制

- 每个特征图位置有 $k$ 个 anchor（论文用 3 种 scale × 3 种 ratio = 9）
- 分类输出 $2k$ 通道，回归输出 $4k$ 通道

### 4.3 多尺度 Anchor

论文用 3 种 scale $\sqrt{2}$ 倍关系（$\{8,16,32\}$ 的面积）× 3 种 aspect ratio（$\{1:1, 2:1, 1:2\}$）。

### 4.4 RPN 的损失

$$
\mathcal{L}_{RPN} = \mathcal{L}_{cls}^{RPN} + \lambda \mathcal{L}_{box}^{RPN}, \quad \lambda = 10
$$

**正样本判定**（IoU > 0.7），负样本（IoU < 0.3），其余忽略。

### 4.5 R-CNN 四模型 → 两模型

| | R-CNN | Faster R-CNN |
|---|---|---|
| 模型数 | 4（region、分类、回归、检测） | **2（RPN + RCNN）** |
| 特征提取 | 重复 2000 次 | **1 次** |
| 端到端 | ❌ | ✅ |
| 速度 | 60s | **0.2s（GPU）** |

### 4.6 交替训练策略

论文提出先训 RPN 再训 R-CNN，交替进行。**现在普遍采用「四模型合一 + 端到端」**（`FasterRCNN` 在 MMDetection 里就是单模型）。

### 4.7 性能

COCO val：39.1 mAP@0.5:0.95（论文），后续改进版普遍到 40+。

## 5. Cascade R-CNN（2017）

**论文**：*Cascade R-CNN: Delving into High Quality Object Detection*, CVPR 2017

### 5.1 问题

**Faster R-CNN 的结构性问题**：
- RPN 输出的候选框质量不高（大部分 IoU 低于 0.6）
- Stage 2 的 RoI 提取是**量化**的，且**只用了一次**
- 训练时 IoU>0.5 就是正样本 → 但推理时目标 IoU 往往只有 0.6~0.8

**作者的洞察**：**训练时的 IoU 分布和推理时的 IoU 分布不匹配**。

### 5.2 解决方案：级联 + 递增 IoU 阈值

```
                    Stage 1     Stage 2     Stage 3
                    ┌────┐      ┌────┐      ┌────┐
RPN proposals ────→ │Box  │ ───→ │Box  │ ───→ │Box  │ ──→ Final
                    │head │      │head │      │head │
                    └────┘      └────┘      └────┘
   IoU 阈值:         0.5         0.6         0.7
   回归精修:          ✓           ✓           ✓
```

**三个关键设计**：

| 设计 | 说明 |
|---|---|
| **递增 IoU 阈值** | 每个 stage 用更高的 IoU 阈值（0.5/0.6/0.7）筛正样本，强制模型处理「更难」的框 |
| **框回归精修 (Box Regression)** | 每个 stage 的输出框**重新输入**给下一个 stage（相当于级联修正） |
| **交替训练** | 训练时各 stage 独立训（用各自阈值的正样本），推理时串联 |

### 5.3 收益

| 模型 | COCO AP |
|---|---|
| Faster R-CNN | 37.4 |
| Cascade R-CNN | 41.9 |

**+4.5 AP**，是所有「结构小改动」里收益最大的之一。

### 5.4 与 IoU-Net 的对比

**IoU-Net**（CVPR 2018）走的是另一条路：不改结构，而是让 Stage 2 预测框的 IoU，并用这个 IoU 作为分类置信度。

两者可以叠加。

## 6. Mask R-CNN（2017）

**论文**：*Mask R-CNN*, ICCV 2017

### 6.1 三点贡献

| # | 贡献 | 说明 |
|---|---|---|
| 1 | **RoI Align** | 消除 RoI Pooling 的量化误差 |
| 2 | **并行分支** | 检测分支 + mask 分支并行，共享 RoI 特征 |
| 3 | **更通用的框架** | 可用于实例分割、全景分割、人物关键点 |

### 6.2 RoI Align

**核心改进**：不做量化，改为**双线性插值**。

```
RoI 特征框: 浮点坐标 (6.29, 12.52, ...) × 16 = (100.64, 200.32, ...)
                           ↓
         采样 4 个点: 精确位置 (6.29, 12.52), (6.29+0.25, 12.52+0.25),
                      (6.29+0.5, 12.52), (6.29+0.25, 12.52+0.25)
                           ↓
         双线性插值得到 4 个值
                           ↓
         4 个值取平均 → 一个 bin 的值
                           ↓
         7×7 个 bin → 固定 7×7 特征
```

**对比**：

| | RoI Pooling | RoI Align |
|---|---|---|
| 量化 | 向下取整 | **无量化** |
| 插值 | 硬分配（bin 内 max） | **双线性插值** |
| 亚像素精度 | ❌ | ✅ |
| 计算量 | 低 | 略高（多 4 次插值） |

**收益**：小物体的 mask 质量提升显著。

### 6.3 Mask 分支

```
RoIAlign 输出 (14×14×256)
    ↓
1×1 Conv (256→256) + ReLU
    ↓
2×3 Conv (256→256) + ReLU
    ↓
1×1 Conv (256→num_classes)   ← 注意是 num_classes，不是 1
    ↓
28×28 的 mask logits
```

**关键设计：每个类别一个 mask channel**。这样分割和分类是「解耦」的 —— 预测「人」的 mask 不会受「车」的 mask 干扰。

### 6.4 Mask 分辨率：28×28 而非全分辨率

**为什么用 28×28？**
- 全分辨率 mask 太大，显存和计算爆炸
- RoIAlign 保留的高分辨率信息已经足够（14×14 的 RoI 特征来自 7×7 的 ROI）
- 训练时用 28×28 的真值 mask 缩放后计算损失，推理时再放大

### 6.5 性能

| 任务 | COCO 指标 | Mask R-CNN |
|---|---|---|
| 框检测 | mAP | 37.9 |
| 实例分割 | mask AP | 34.1 |

**对照**：Mask R-CNN 相比 Faster R-CNN 只多了 4.4% 的计算量，却同时做检测 + 分割。

## 7. Sparse R-CNN（2021）

**论文**：*Sparse R-CNN: End-to-End Object Detection with Learnable Proposals*, arXiv:2103.12797

### 7.1 思想：把两阶段「拉直」成端到端

**传统两阶段的"痛"**：
1. RPN 的 proposal 是「固定结构」（anchor + 回归）产生的，不是「学出来的」
2. Stage 2 是逐 ROI 处理，与图像无关（无法利用 ROI 之间的上下文）
3. 推理时需要 NMS

**Sparse R-CNN 的做法**：
- **取消 RPN**，直接用 N 个「可学习的 proposal（query）」
- 每个 query 是一个 **learned proposal embedding**（通常是 5 维：中心 xy + 尺寸 wh + 类别）
- **不提取 RoI 特征**！用 query 的位置去特征图上采样（deformable attention 风格）
- 迭代 refine：query 逐层更新

```
可学习 query (N × d)
      ↓
[ Transformer Decoder + 迭代 refine ]  × 6
      ↓
输出: (框, 类别)
```

### 7.2 优势

| 优势 | 说明 |
|---|---|
| **完全端到端** | 没有 RPN，没有 NMS |
| **推理更快** | 少了 RPN 和 NMS 的开销 |
| **精度接近** | COCO 45.0 mAP（v1） |
| **可解释** | query 是显式的框，可以追踪它如何演化 |

### 7.3 与 DETR 的区别

| | DETR / Sparse R-CNN |
|---|---|
| Query 初始化 | **从图像特征生成**（DETR）或**可学习的 embedding**（Sparse） |
| 收敛速度 | DETR 极慢（500 epoch），Sparse R-CNN 也要 300 epoch |
| 训练数据量需求 | 大（需要大量数据才能让 query 学到好初始化） |

**后续改进**：**QueryDet**（用粗到细的 query 层级）大幅加速了收敛。

## 8. 两阶段流派的现代变体

| 模型 | 年份 | 关键改进 |
|---|---|---|
| **Mask R-CNN** | 2017 | RoIAlign + mask 分支 |
| **HTC** (Hybrid Task Cascade) | 2019 | 交互式分支 + mask 精修 |
| **Sparse R-CNN** | 2021 | 可学习 proposal |
| **QueryInst** | 2021 | 稀疏 query 的实例分割 |
| **Co-DETR** | 2022 | 协作式 DETR，用两阶段头辅助 DETR 训练 |
| **DINO** | 2022 | 去噪训练 + 对比去噪 |
| **RT-DETR** | 2023 | 高效混合编码器 + 简化 query 选择 |

### 8.1 HTC（Hybrid Task Cascade）

在 Cascade R-CNN 的基础上：
1. 每个 stage 除了框回归，还做 mask 回归（多尺度 mask）
2. stage 间用**交互式 mask** 传递信息（stage i 的 mask 输入给 stage i+1）
3. 加**特征金字塔级联**

### 8.2 Co-DETR（2022）

**思路**：DETR 收敛慢是因为训练信号稀疏。用两阶段的 head 给 DETR 提供辅助监督：

```
       Backbone
          ↓
    ┌─────┼─────────┬──────────┐
    ↓     ↓         ↓          ↓
  DETR  RPN+RCNN   RPN+RCNN  RPN+RCNN   ← 多个不同 stage 的辅助头
    └─────┴─────────┴──────────┘
          ↓
      统一 query 特征 → 最终预测
```

**收益**：DETR 的 mAP 提升明显，收敛加快。

## 9. 两阶段的现代实践（MMDetection）

两阶段模型至今仍是 MMDetection 里的主力。常用配置：

```python
# Cascade R-CNN (MMDetection)
model = dict(
    type='CascadeRCNN',
    backbone=dict(
        type='ResNet', depth=101, num_stages=4,
        out_indices=(0, 1, 2, 3),
        frozen_stages=1,
        norm_cfg=dict(type='BN', requires_grad=True),
        norm_eval=False,          # 小 batch 时 False 更好
        style='pytorch'),
    neck=dict(
        type='FPN', in_channels=[256,512,1024,2048],
        out_channels=256, num_outs=5),
    rpn_head=dict(
        type='RPNHead', in_channels=256,
        anchor_generator=dict(
            type='AnchorGenerator', scales=[8],
            ratios=[0.5,1.0,2.0], strides=[4,8,16,32,64]),
        bbox_coder=dict(type='DeltaXYWHBBoxCoder',
                        target_means=[.0,.0,.0,.0], target_stds=[1.0,1.0,1.0,1.0])),
    roi_head=dict(
        type='CascadeRoIHead', num_stages=3, stage_loss_weights=[1,0.5,0.25],
        bbox_roi_extractor=dict(type='SingleRoIExtractor', roi_layer=dict(type='RoIAlign', output_size=7, sampling_ratio=0))),
)
```

**调参要点**：
- `norm_eval=False`：小 batch（每卡 1~2 张）时，BN 的统计量更新比冻结更有效
- `stage_loss_weights`：[1, 0.5, 0.25]，后面的 stage 权重小
- 推理时 `max_per_img=100`

## 10. 工程结论

1. **两阶段仍然是高精度任务的默认选择**。COCO 上 Cascade R-CNN / HTC / ResNet-101 的精度仍高于绝大多数单阶段模型。
2. **但两阶段的速度劣势在视频场景是致命的**。50ms/帧的检测器只能跑 20 FPS。
3. **如果你的场景是「精度 > 速度」且类别固定，两阶段仍值得优先考虑**（尤其配合知识蒸馏）。
4. **RoIAlign 是必做的**，用 RoI Pooling 会白白损失小目标精度。
5. **Cascade 的 +4.5 AP 是性价比最高的结构改动之一**，如果只能改一处，改成 Cascade。
6. **Sparse R-CNN 代表的「可学习 proposal」是重要方向**，但收敛慢、训练成本高，落地前要评估训练资源。
