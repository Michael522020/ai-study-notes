# 02 · 六大场景与关键能力指标

> **核心问题：6G 到底要多快、多准、多可靠？这些数字能拿来做什么决策？**

---

## 0. 先说结论：三个「新增」才是 6G 的分水岭

ITU-R M.2160 定义了 **6 个使用场景**。前三个是从 5G 场景「增强」来的，后三个是 6G **全新增加**的：

| # | 场景 | 缩写 | 来源 | 一句话 |
|---|---|---|---|---|
| 1 | 沉浸式通信 | **IC** | eMBB 增强 | XR、多感官远程临场、全息通信 |
| 2 | 超可靠低时延通信 | **HRLLC** | URLLC 增强 | 全工业自动化、应急、远程医疗、电网 |
| 3 | 大规模通信 | **MC** | mMTC 增强 | 智慧城市、物流、农业、无电池 IoT |
| 4 | **泛在连接** | **UC** | ★ 新增 | 偏远/农村/海上宽带，卫星等非地面网络 |
| 5 | **AI 与通信融合** | **AIAC** | ★ 新增 | 辅助驾驶、算力卸载、数字孪生、分布式 AI |
| 6 | **通感一体化** | **ISAC** | ★ 新增 | 导航、手势/活动检测、环境监测 |

外加 **4 项跨场景设计原则**（贯穿所有场景，不是独立场景）：

1. **可持续性**（Sustainability）—— 能耗与碳排是硬指标，不是加分项
2. **安全与韧性**（Security and Resilience）
3. **连接未连接的用户**（Connecting the Unconnected）
4. **泛在智能**（Ubiquitous Intelligence）

> **读法**：如果一份 6G 方案只讲「峰值速率」，那它讲的还是 5G 的思路。
> 真正属于 6G 的是 **UC（泛在连接，把海面/荒漠/灾害现场接进来）**、
> **AIAC（网络自己就是 AI 系统的一部分）**、**ISAC（网络同时是传感器）**。

---

## 1. 15 项关键能力：9 项增强 + 6 项新增

| 分组 | 能力 | IMT-2020（5G） | IMT-2030（6G）研究目标 |
|---|---|---|---|
| **增强 9 项** | 峰值数据速率 | 20 Gbit/s | **50 / 100 / 200 Gbit/s** |
| | 用户体验数据速率 | 100 Mbit/s | **300 / 500 Mbit/s** |
| | 频谱效率 | 基准 | **1.5 – 3 ×** IMT-2020 |
| | 区域流量容量 | 10 Mbit/s/m² | **30 / 50 Mbit/s/m²** |
| | 连接数密度 | 10⁶ /km² | **10⁶ / 10⁷ / 10⁸ /km²** |
| | 移动性 | 500 km/h | **500 – 1000 km/h** |
| | 时延（用户面 / 空口） | 1 ms | **0.1 – 1 ms** |
| | 可靠性 | 1−10⁻⁵ | **1−10⁻⁵ ~ 1−10⁻⁷**（99.999% – 99.99999%） |
| | 安全与韧性 | 有 | 增强（后量子等新增要求） |
| **新增 6 项** | 覆盖 | — | 地面 + 空天 + 海洋的综合覆盖能力 |
| | 定位 | 无 | **1 – 10 cm 级**（厘米级） |
| | 感知相关能力 | 无 | **检测概率、虚警概率、分辨率**（ISAC 专属） |
| | AI 相关能力 | 无 | 网络承载/支撑 AI 的能力（模型数量、推理时延等） |
| | 可持续性 | 有（5G 不强调） | 明确的能效/碳指标 |
| | 互操作性 | 有 | 跨域/跨层/跨生态的互操作 |

**6 项新增能力里有 3 项是 6G 独有的业务量纲**：感知相关能力（概率量纲）、定位（厘米量纲）、AI 相关能力（模型量纲）。
这三种量纲在 5G 的指标体系里**根本不存在对应物** —— 这就是「6G 不是 5G 加速」最硬的证据。

## 2. ⚠️ 三条必须记住的口径纪律

这是本章最有价值的部分。6G 的指标被误引用的程度，远高于其他任何一代。

### 纪律一：M.2160 的数字是「研究目标」，不是「准入门槛」

M.2160 原文的措辞是 **"estimated targets for research and investigation"**（供研究与探索的估计目标）。
文件同时明确：

- 表格中的**区间内各数值同等重要**（不是「越高越好，取上限」）；
- **不可能所有场景同时达成**（不同场景的指标是取舍关系，不是叠加关系）。

**所以**：
- ❌ 「ITU 要求 6G 峰值速率 200 Gbps」 —— 错，这是研究目标区间的一个档位。
- ✅ 「M.2160 给出的峰值速率研究目标区间是 50–200 Gbit/s」 —— 对。
- ❌ 「6G 峰值速率 1 Tbps」 —— **这个数字不存在于 M.2160**。它来自学术论文与中国信通院 / IMT-2030 推进组白皮书的研究目标，是**另一套口径**，引用时必须写清楚出处。

### 纪律二：时延必须写清「哪一段」

「6G 时延 0.1 ms」这句话本身是**不完整的**。至少要区分：

| 环节 | 典型量级 | 说明 |
|---|---|---|
| **空口时延**（radio interface latency） | 0.1 – 1 ms | M.2160 的指标对象 |
| 用户面时延（user plane） | 0.1 – 1 ms | 含核心网转发 |
| **端到端业务时延** | 毫秒 ~ 十毫秒级 | 含边缘处理、传感器采集、应用逻辑 |
| **远程操控体感时延** | > 20 ms 即引发操作者不适 | 机器人/无人机场景的工程红线 |

**最容易被忽略的是最后两行。**
一个「空口 0.1 ms」的系统，如果感知数据要回传到中心机房做融合再下发，端到端轻松超过 50 ms。
**对机器人关节控制这类场景，决定成败的是端到端时延与抖动，不是空口时延。**

行业报告里给出的具身智能通信需求就写得很直白：

- 关节实时控制：端到端时延 **≤ 5 ms**，抖动 **≤ 1 ms**
- 远程操控：时延 **> 20 ms** 可能引发操控者眩晕
- 全量上行带宽：**10 Mbps – 1 Gbps**；具身智能训练场单连接日均上传约 30 GB

### 纪律三：可靠性与时延是一对取舍，不能单看

M.2160 的可靠性区间是 **1−10⁻⁵ 到 1−10⁻⁷**（即 99.999% – 99.99999%）。

**注意：1−10⁻⁷ 是在「包大小 10 字节、时延 50 ms」的极限条件下给出的。**
不同业务包长与时延预算下，可靠性数值会显著变化。评估一个方案时，至少要问三件事：

1. 包长是多少？（决定误块率换算）
2. 时延预算是多少？（决定重传窗口）
3. 可靠性是**空口**的、**链路层**的、还是**端到端业务**的？

**工程结论**：招标或选型文件里，**只写「可靠性 99.999%」而不写包长与时延条件的条款是无法验收的**，
因为满足条件的实现方案与成本可以差一个数量级。这在 5G-A 工业专网招标里已经是常见坑。

## 3. 场景 → 能力 → 业务的映射表

这张表是本主线后面所有行业章节的索引：

| 场景 | 关键能力诉求 | 谁买单 | 当期（2026）可用形态 |
|---|---|---|---|
| **IC 沉浸式** | 用户体验速率 300–500 Mbit/s、端到端时延 | 消费娱乐、赛事直播、工业培训 | 5G-A 载波聚合 + XR 专网；Pre-6G 光子太赫兹演示 |
| **HRLLC 超可靠低时延** | 0.1–1 ms 时延、1−10⁻⁷ 可靠性、**确定性** | 工业控制、电网、远程手术 | 5G-A 确定性无线接入 + URLLC 专网；Pre-6G 毫秒级确定性 |
| **MC 大规模通信** | 连接密度 10⁸/km²、无电池 IoT | 智慧城市、农业、抄表 | 5G-A 物联 / RedCap（**这是最成熟的一块**） |
| **UC 泛在连接** | 覆盖（含海面/空中）、卫星协同 | 海洋、偏远地区、应急 | 卫星互联网 + 地面网融合；星地融合工作组 2026 年新设 |
| **AIAC AI 与通信融合** | 网络承载 AI 的能力、算力卸载、意图驱动 | 运营商自身 + 所有 AI 应用 | **AI RAN / RAN Agent / ACN 智能体通信网**（已规模部署） |
| **ISAC 通感一体化** | 检测概率、虚警概率、定位精度 | 低空管理、港口、车联网、公共安全 | **5G-A 通感一体**（已规模商用，见 [`05`](./05-落地案例解剖.md)） |

> **工程结论**：
> **最容易落地的是 ISAC 和 AIAC，最难的是 UC 和 HRLLC。**
> 原因很简单：ISAC / AIAC 是在**现有网络上加功能**（软件 + 少量硬件升级），
> 而 UC 需要新的频谱与卫星体系，HRLLC 需要整个价值链（从设备到行业流程）重新设计。
> 如果要预测「6G 什么时候在你的行业里产生实际价值」，**先看你的场景落在上表的哪一行**。

## 4. 中国口径的 20 项 KPI 与 7 项新增

ITU 的《IMT-2030(6G) 最小技术性能需求》报告把指标细化为 **20 项关键性能指标**，
其中 **7 项为 6G 新增特有指标**，包括：

- 通感融合**检测概率**
- 通感融合**虚警概率**
- **定位精度**
- **通智融合 AI 能力**（通信与智能的融合程度）

对比 ITU 的 15 项「能力」，中国的 20 项 KPI 更偏**可测量**，直接对应招标验收。
这是 2026 年 2 月 ITU 发布《IMT-2030(6G) 空口技术性能指标报告》后的配套动作。

**两者关系**：ITU 定「能力」（What），3GPP 与中国推进组定「KPI 与用例」（How measurable）。
做技术选型时，**看 3GPP 的 TR 22.870（212 个用例）比看白皮书有用** —— 因为用例是场景级的、可对照业务的。

## 5. 常见误引清单

| 错误说法 | 正确说法 |
|---|---|
| 「ITU 规定 6G 峰值 1 Tbps」 | M.2160 的研究目标区间是 50–200 Gbit/s；1 Tbps 来自中国白皮书/论文，**不是 ITU 共识** |
| 「6G 时延 0.1 ms」 | 是**空口/用户面**时延；端到端业务时延是另一个数量级 |
| 「6G 可靠性 99.99999%」 | 条件是 10 字节包 + 50 ms 时延；换条件数值就变 |
| 「6G 已商用」 | 2026 年商用的是 **5G-A 增强能力**；6G 规范 2029-03 才冻结，商用 2030 前后 |
| 「6G 是 5G 的十倍速度」 | 频谱效率目标是 1.5–3×；峰值提升主要来自带宽，不是「十倍」 |
| 「5G-A 的通感一体不算 6G」 | 它是 6G ISAC 能力的技术验证与先行商用形态，**术语上要区分，工程上是同一件事在演进** |
| 「低空经济需要 6G」 | 低空当期主力是 **5G-A 通感一体 + 卫星 + 5G 地面网**；6G 的贡献在 2030 后 |

- 中国侧的 20 项 KPI / 7 项新增指标转述自 **ITU-R《IMT-2030(6G) 最小技术性能需求》** 相关公开材料与 **IMT-2030 推进组**白皮书。
- 机器人与低空通信的时延/带宽需求转述自 **SAC/TC591《具身智能机器人和移动通信技术研究报告》** 及公开行业报告。
