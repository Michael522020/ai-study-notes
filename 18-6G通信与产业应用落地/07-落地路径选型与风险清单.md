# 07 · 落地路径、选型与风险清单

> **核心问题：作为一个具体的项目/企业，我现在该做什么？什么时候该等 6G？有哪些坑？**

---

## 0. 先分清你在产业链上的哪个位置

6G 的落地动作因角色而异，**搞错位置的建议等于没说**。

| 角色 | 你的核心问题 | 本章对应小节 |
|---|---|---|
| **A. 需求方**（有业务痛点的企业/政府/行业客户） | 怎么用现有能力解决？什么时候该升级？ | §2 |
| **B. 集成方 / 交付方**（做方案、做项目） | 怎么把能力打包成可交付、可验收的东西？ | §3 |
| **C. 供应商**（做设备、做算法、做服务） | 产品里哪些能力要提前布局？ | §4 |
| **D. 观察者**（投资、研究、写作） | 该盯哪些指标和时间点？ | §6 |

## 1. 一张自查表：你的项目该不该等 6G

**五个问题，全答「是」才值得把 6G 写进规划；只要有一个答「否」，就用 5G-A + 现有算力做。**

```
□ ① 通信性能是我业务的硬约束吗？
     （不是「体验更好」，是「做不到就做不成」）

□ ② 5G-A / 专网 / 有线 / 卫星 / 本地算力都解决不了吗？
     （请把每个替代方案都写下来逐一排除）

□ ③ 我需要的增量能力，是 6G 新增的 6 项之一吗？
     （覆盖 / 定位 / 感知 / AI 能力 / 可持续性 / 互操作）
     （如果只是「更快更稳」，那是 5G-A 的活）

□ ④ 我能等到 2029–2031 吗？
     （试点可以等，生产线等不了）

□ ⑤ 收益模型里，通信能力是真变量吗？
     （把通信换成最差情况，业务还成立吗？成立就说明通信不是瓶颈）
```

**典型判定**：

| 项目 | ① | ② | ③ | ④ | ⑤ | 结论 |
|---|---|---|---|---|---|---|
| 低空无人机巡检（无地面覆盖区） | 是 | 是 | 泛在连接 + 感知 | 否 | 是 | **不等 6G，用 5G-A + 卫星** |
| 城市低空安防监管 | 是 | 是 | 感知 + 定位 | 否 | 是 | **不等 6G，用 5G-A 通感一体** |
| 柔性产线无线替代 | 是 | 是 | 时延 + 可靠性 | 否 | 是 | **不等 6G，用 5G-A 确定性专网** |
| 机器人云端推理卸载 | 是 | 否 | AI 能力 | 否 | 否 | **通信不是瓶颈，瓶颈是模型与算力** |
| 偏远地区无人值守监控 | 是 | 是 | 泛在连接 | 否 | 是 | 等 6G 没有意义 —— **用卫星** |
| 全息远程手术（移动场景） | 是 | 是 | 时延 + 定位 | **是** | 是 | **等 6G，但先在固定场景用 5G-A 验证** |

> **工程结论**：**绝大多数「6G 项目」应该判为「不等」。**
> 不是因为 6G 不好，而是因为**业务等不起**。
> 真正需要「等 6G」的项目有一个共同特征：**业务本身要运行十年以上，
> 而当前方案的边际成本随规模线性上升**（比如百万级终端的连接成本、全国范围的连续覆盖）。

## 2. 需求方：现在（2026–2027）该做的四件事

### 动作一：把需求翻译成「通信约束 + 感知约束」的量化条款

不要写「需要低时延高可靠」，要写成：

```
□ 时延：P99 ≤ ___ ms（含哪些环节：采集→空口→传输→边缘→应用？）
□ 抖动：P99−P50 ≤ ___ ms
□ 可靠性：___ %（在 ___ 字节包长、___ ms 时延预算下）
□ 上行：保底持续 ___ Mbps（不是峰值）
□ 接入密度：___ 终端/km²
□ 感知：目标类型 ___（给 RCS 范围）、探测概率 ___ %（在虚警 ≤ ___ /min 下）、
        定位精度 ___ cm
□ 定位：___ cm，刷新率 ___ Hz
□ 算力：边缘侧可用 ___ TOPS / ___ GPU
```

> **这一步的价值**：一份写得足够细的约束表，能同时用来 (a) 筛选供应商 (b) 验收 (c) 防止被虚高的宣传数字带偏。
> **这三个用途是同一份文档** —— 这也是为什么它值得先写。

### 动作二：先做「非 6G」的对照基线

**至少准备一条非 6G 方案做对照**，否则你无法证明 6G 能力的增量价值：

| 对照基线 | 适用 |
|---|---|
| 有线（工业以太网 / 光纤） | 工业场景；无线永远打不过有线，要证明的是改造成本优势 |
| 5G 专网 + Wi-Fi 6/7 | 一般场景 |
| 5G-A 专网 + 通感一体 | 低空、港口、水域 |
| 卫星 + 本地边缘 | 偏远、海上、山区 |
| 自建 Wi-Fi + 本地 AI | 室内、固定场所 |

### 动作三：把「感知」当成一个需要独立治理的数据业务

如果项目里有 ISAC，**数据治理的工作量通常大于网络本身**：

```
□ 感知数据的采集范围与边界（拍到谁了？存哪了？）
□ 留存期限与删除机制
□ 使用授权链：谁授权？被感知对象知情吗？
□ 匿名化 / 去标识化方案（不可逆）
□ 跨主体共享的规则（政府 / 运营商 / 行业三方）
□ 审计日志与可追溯性
□ 与现有隐私合规体系的接口（《个人信息保护法》/ GDPR / 行业监管）
```

> **这是 ISAC 项目最常见的失败原因**：技术验收全过，但合规评审卡住，
> 或者上线后因为一次数据争议被迫停摆。**合规工作量必须提前 3–6 个月启动。**

### 动作四：选对试点位置

| 试点位置特征 | 为什么 |
|---|---|
| **有明确监管方**（海事局、交管、应急管理局） | 付费方明确，验收标准天然存在 |
| **有明确事件频次**（每天/每周都会发生） | 3 个月内能拿到足够样本做统计 |
| **有可量化的损失**（事故率、罚款、停机时长、运费） | ROI 说得清 |
| **技术边界干净**（空旷航道 / 独立厂区 / 独立港区） | 避免把「本来就难覆盖的地方」的锅背在通感一体上 |

**反面清单**：不要在**信号本来就复杂的密集城区高楼区**做第一个通感一体试点 ——
那会把遮挡、多径、干扰的所有问题一次性叠加进来，无法归因。

## 3. 集成方：把能力打包成可交付物

### 3.1 交付物的四个层次

```
L1  连接        专网 / 切片 / 确定性 SLA          ← 最容易交付，最难差异化
L2  感知        通感一体 + 目标识别 + 定位        ← 差异化主战场，验收最难
L3  算力        边缘推理卸载 + 算网协同 QoS       ← 与 AI 团队强耦合
L4  闭环        感知→决策→执行的业务闭环          ← 最值钱，最难交付
```

**集成商的战略选择：往 L4 走。**
L1 会被设备商和运营商挤压，L2 是设备商的主战场，L4 才是行业 know-how 的护城河。

### 3.2 交付时的验收要点

- **用探测概率 + 虚警率的组合**，并要求供应商给出**测量方法**（怎么测的、样本多少、什么时间段）
- **要求在你自己场地的实测**，不接受厂商实验室数据作为最终验收依据
- **要求分项口径**：覆盖率是「理论覆盖」还是「实测可用」？
- **要求可回放**：感知结果的原始数据保留多久？能不能用于事后复盘？

### 3.3 一份可以直接用的供应商问询清单

```
【感知能力】
1. 在虚警率 ≤ ___ 的约束下，对 RCS ∈ [__, __] 的目标，探测概率是多少？
2. 定位精度的测试方法和误差分布（P50/P95）？
3. 多径严重场景（___）下的性能衰减曲线？
4. 感知数据的原始格式、留存策略、可导出性？

【网络能力】
5. 时延的测量点在哪一段？P50/P95/P99 分别是多少？
6. 抖动的上界？是否有硬保证还是尽力而为？
7. 上行的保底速率？与峰值的比例？
8. 切片之间是否真隔离？隔离粒度是基站/载波/核心网哪一层？

【工程与运维】
9. 设备成本与部署周期（从下单到可用）？
10. 故障降级方案：感知不可用时业务怎么继续？
11. 是否有第三方认证或标准符合性声明？
```

## 4. 供应商：哪些能力值得提前布局

按「确定会发生 + 现在就能做」两个条件筛：

| 方向 | 判断 | 理由 |
|---|---|---|
| **感知算法（目标识别、虚警抑制、定位）** | ★★★ 值得 | ISAC 已规模商用，需求真实；算法是持续收费的 |
| **边缘推理卸载与算网协同** | ★★★ 值得 | 运营商 capex 35% 已在算力；机器人与无人机的上行爆发是硬需求 |
| **机器人 / 无人机专用连接产品** | ★★★ 值得 | 已有专用 SIM 的先例；标准正在立项（ACN 9 项能力） |
| **AI 原生网管 / 网络智能体** | ★★☆ 值得 | 已有 AN L4.0 认证与规模部署；且运营商自己就是客户 |
| **太赫兹前端模块** | ★☆☆ 谨慎 | 3nm 以下仍在流片验证；成本曲线刚起步；商用远在 2030 后 |
| **RIS 硬件** | ★☆☆ 谨慎 | 部署成本与控制复杂度尚未证明可控；商业场景集中在室内补盲 |
| **全息 / 沉浸式内容平台** | ★☆☆ 谨慎 | 瓶颈在内容与终端生态，不在网络 |
| **6G 概念型咨询与培训** | ★☆☆ 谨慎 | 客户付费意愿存疑；容易做成「卖概念」而非「交付价值」 |

> **工程结论**：**「先做场景里的那一块」比「做 6G 核心」现实。**
> 南京鑫合通感科技做 6G 室内高精度定位设备，首年产值破千万 —— 它不碰基站、不碰协议栈，
> 它做的是**场景里那个别人不愿意做、又确实需要的模块**。这是 6G 产业链上中小企业的现实路径。

## 5. 风险清单（按「发生概率 × 影响」排序）

### 5.1 高概率 · 高影响

| 风险 | 表现 | 缓解 |
|---|---|---|
| **频谱未定导致方案返工** | WRC-27（2027-10/11）结果与预期不符；中频划分不同 → 已建站点需改造 | 不要在 2027 年底前把频谱写死进长期合同；合同里留频谱变更条款 |
| **感知数据合规风险** | 位置数据、生物识别被认定为敏感个人信息；项目上线后被叫停 | 提前 3–6 个月启动合规评审；做不可逆去标识；设计「感知能力交付」而非「数据交易」的商务模式 |
| **虚警率导致一线弃用** | 告警疲劳 → 试点期结束后系统闲置 | 验收时把虚警率作为一等指标；上线后做告警质量复盘 |
| **商业闭环缺失** | 建成之后没人付费，靠补贴维持 | 见 §0 三条筛子；上线前必须锁定付费方合同 |

### 5.2 中概率 · 高影响

| 风险 | 表现 | 缓解 |
|---|---|---|
| **标准碎片化** | 不同区域/联盟的 6G 方案互不兼容（邬贺铨院士观点） | 优先选有国际标准组织背书的技术；避免押注单一厂商私有接口 |
| **太赫兹能耗** | 次太赫兹部署可能使 RAN 能耗增 **4–6 倍** | 能效写进招标要求；用每 bit 能耗而非每站功率评估 |
| **射频器件供应链** | 毫米波/亚太赫兹器件国产化率不足 10%，存在断供与成本风险 | 至少两家供应商；把器件生命周期写进合同 |
| **超长回收周期** | 6G 单站超 200 万元、站数 250–380 万站，运营商 ROI 承压 | 分期建设；优先复用站址（铁塔的数字塔模式） |

### 5.3 低概率 · 高影响（尾部风险）

- **后量子安全**：6G 生命周期长达 15 年，需考虑抗量子密码迁移。**这是现在就该在架构上留口的唯一一项**（因为改架构很贵，改算法便宜）
- **感知信号对抗攻击**：物理层欺骗 / 干扰，可能导致目标误判或漏判；在高价值场景需考虑冗余感知源交叉验证

### 5.4 高概率 · 低影响（容易被忽略的「慢性病」）

| 风险 | 表现 |
|---|---|
| **「6G」话术通胀** | 大量 5G-A 案例被包装成 6G，采购方被误导预算与预期 |
| **指标口径缺失** | 「探测概率 97.9%」「时延 0.1 ms」都不带条件，无法验收也无法比较 |
| **复合型人才短缺** | 同时懂通信、懂 AI、懂行业的工程师极少，交付质量高度依赖个案 |
| **标准化未完成** | 时空同步、AI 融合识别、统一评价体系与标准化尚未完善，跨厂商互通仍是问题 |

## 6. 观察清单：未来五年要盯的八个时间点

| 时间 | 事件 | 该盯什么 | 对你的意义 |
|---|---|---|---|
| **2026-12** | IMT-2030 推进组第二阶段样机定型与组网验证收尾 | 有没有**可运行**的原型系统（不是演示视频） | 判断「6G 能力何时可外采」 |
| **2027-03** | 3GPP R21 **Stage-1 冻结** | 212 个用例最终版；行业用例是否入选 | 用例入选 = 你所在行业被承认 |
| **2027-06** | 第二阶段技术试验收官 | 试验结论是否进入国际标准提案 | 国内结论与国际标准的差距 |
| **2027-10/11** | **WRC-27（上海）** | 议程 1.7 中频划分结果 | **你的频谱方案会不会返工** |
| **2028-06** | R21 **Stage-2 冻结** | 系统架构定稿 | 网络架构是否与你的规划兼容 |
| **2028-12** | R21 **Stage-3 冻结** | 功能冻结 | 设备商开始规模投入 |
| **2029-03** | R21 **ASN.1 / OpenAPI 冻结** | 首版 6G 国际规范完成 | 首版规范 |
| **2029–2030** | ITU IMT-2030 候选技术认定 / 中国 6G 商用启动 | 商用网络是否覆盖你的作业区域 | **这是你真正能用到 6G 的时间点** |

> **工程结论**：**这八个时间点里，只有 WRC-27 会立即影响你现在的合同决策。**
> 其余七个都还是「观察」，不是「行动」。**把有限的精力放在 WRC-27 之前把频谱风险锁进合同条款上，
> 其余时间用来把 5G-A 时代的业务跑出真实数据 —— 那份数据才是你 2030 年做决策的依据。**

## 7. 一页纸总结

```
┌──────────────────────────────────────────────────────────────┐
│  现在（2026–2027）该做的：                                    │
│    · 用 5G-A 通感一体 / 确定性专网 / 卫星 / 边缘算力做业务      │
│    · 把需求写成带口径的量化条款（时延 P99、虚警率、上行保底）    │
│    · 提前启动感知数据的合规治理                               │
│    · 把通信约束与业务 ROI 挂上钩（省了多少停机/多少运费）      │
│                                                              │
│  该等的：                                                     │
│    · 首版 6G 规范（2029-03）                                  │
│    · 商用网络（2030 前后）                                    │
│    · 频谱确定后的长期方案（WRC-27 之后）                       │
│                                                              │
│  不该等的：                                                   │
│    · 任何业务今天就能启动的场景（应急、巡检、监管、工业）      │
│    · 频谱未定时的不可撤销重资产投入                            │
│    · 概念型项目 —— 有交付物才算项目                           │
└──────────────────────────────────────────────────────────────┘
```

## ⚠️ 关于本章数据的性质

- 本章的**风险清单、判定表、问询清单、观察时间点为作者基于公开资料整理的工程判断**，
  **不是任何机构的官方建议，不构成投资、采购或合规意见**。
- 引用的量化数据（国产化率、单站成本、能耗增幅、虚警率等）转述自公开产业报告与媒体报道，
  口径见 [`06-产业生态与商业模式.md`](./06-产业生态与商业模式.md) 的说明与 `05` 的逐条标注。
- 涉及合规的内容（感知数据、位置数据、生物识别）为工程侧的常识性说明，**不构成法律意见**；
  真实项目必须由法务与数据合规团队审核。
