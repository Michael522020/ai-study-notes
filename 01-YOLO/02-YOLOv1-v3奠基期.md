# YOLOv1–v3：奠基期

> **核心问题**：网格回归范式是怎么建立的？它比两阶段快在哪，又在哪些地方先天不足？

---

## 1. YOLOv1（2016）

**论文**：*You Only Look Once: Unified, Real-Time Object Detection*, CVPR 2016
**作者**：Joseph Redmon, Santosh Divvala, Ross Girshick, Ali Farhadi
**arXiv**：1506.02640 ｜ **代码**：原始 darknet（后续有 pytorch 版 Darknet-19 等复现）

### 1.1 网络结构

```
输入 448×448×3
  ↓ conv(32,3×3,s=1) + BN + LeakyReLU        448×448×32
  ↓ conv(64,3×3,s=2) + BN + LeakyReLU        224×224×64
  ↓ conv(128,3×3,s=2)                        112×112×128
  ↓ conv(256,3×3,s=2)                        56×56×256
  ↓ conv(512,3×3,s=2)                        28×28×512
  ↓ conv(1024,3×3,s=2)                       14×14×1024
  ↓ conv(1024,3×3,s=1) + BN                  14×14×1024
  ↓ conv(1024,3×3,s=1) + BN                  14×14×1024
  ↓ conv(1024,3×3,s=1) + BN                  14×14×1024
  ↓ 全局平均池化                             1×1×1024
  ↓ FC(7×7×(2×5+20)) = FC(1470)              输出 1470 维
```

- **24 个卷积层** + 2 个全连接层
- 骨干网络后接 **Global Average Pooling**，让网络对输入尺寸不敏感（这在 v1 是个巧妙设计）
- 输出维度：$S \times S \times (B \times 5 + C) = 7 \times 7 \times (2 \times 5 + 20) = 1470$

### 1.2 预测编码

每个网格 cell 预测 **2 个边界框**，每个框包含：

| 字段 | 维度 | 含义 |
|---|---|---|
| $(t_x, t_y, t_w, t_h)$ | 4 | 框中心相对 cell 的偏移（**归一化到 [0,1]**）、宽高（**相对 cell 宽高归一化**） |
| $t_o$ | 1 | 置信度 = P(物体存在) × P(类别正确) 的联合概率近似 |
| $C$ | 20 | 类别概率（PASCAL VOC 20 类） |

### 1.3 损失函数

$$
\mathcal{L} = \lambda_{\text{coord}} \sum_{i}^{S^2}\sum_{j}^{B}
\mathbb{1}^{\text{obj}}_{ij}
\left[ (t_x - \hat t_x)^2 + (t_y - \hat t_y)^2 + (t_w - \hat t_w)^2 + (t_h - \hat t_h)^2 \right]
+ \lambda_{\text{obj}} \sum_{i}^{S^2}\sum_{j}^{B}
\mathbb{1}^{\text{obj}}_{ij} (t_o - \hat t_o)^2
+ \lambda_{\text{cls}} \sum_{i}^{S^2} \mathbb{1}^{\text{obj}}_{i}
\sum_{c} (p_c - \hat p_c)^2
$$

超参：$\lambda_{\text{coord}} = 100$，$\lambda_{\text{obj}} = 1$，$\lambda_{\text{cls}} = 1$。

**为什么坐标权重是 100？**
因为置信度损失和分类损失是**和**（几十个正样本的量级），而坐标损失是**平方误差**（数值上小 1~2 个数量级）。不放大坐标损失，训练会优先优化分类/置信度，定位精度上不去。这是一个纯粹的经验性调参，没有理论依据 —— 但后续所有版本都保留了这个思路（用不同的损失函数替代裸 MSE）。

### 1.4 推理与 NMS

1. 对每个 cell 的 2 个框，构造完整坐标：中心 = (cell 中心 + 偏移) × cell 尺寸；宽高 = 预测值 × cell 尺寸
2. 计算 $t_o \cdot p_c$ 作为最终类别置信度
3. **按类别分别做 NMS**（threshold 0.5）
4. 输出

### 1.5 性能

| 数据集 | 指标 | 数值 |
|---|---|---|
| PASCAL VOC 2007+2012 | mAP@0.5 | **63.4** |
| — | 速度 | **45 FPS**（Titan GPU，448×448） |
| — | 对比 Faster R-CNN | 63.4 vs 60.5 mAP |

### 1.6 先天不足

| 问题 | 根因 | 后续版本的解法 |
|---|---|---|
| **小目标漏检严重** | 7×7 网格太粗，一个小目标只占格子的 1/50，梯度信号被 49 个背景格淹没 | v2 多尺度 + v3 三尺度输出 |
| **定位精度天花板低** | 网格内位置用 (tx,ty) 表示，量化误差大；且预测的宽高是相对 cell 的绝对比例 | v2 Anchor + v3 直接预测中心偏移 |
| **一个格子只能有一个类别** | 多个物体中心落在同一格 → 只能预测一个 | v3 每格 3 个 anchor（可不同类） |
| **对物体尺寸敏感** | 训练/测试尺寸必须一致 | v2 多尺度训练 |
| **背景误检多** | 没有 anchor 先验，什么都能预测 | v2 Anchor + v5 AutoAnchor |

## 2. YOLOv2（2017）

**论文**：*YOLO9000: Better, Faster, Stronger*, arXiv:1612.08242
**改进点**：7 项，全是针对 v1 的具体缺陷

### 2.1 七项改动

| # | 改动 | 解决 v1 的什么问题 |
|---|---|---|
| 1 | **Batch Normalization** | 收敛慢、梯度不稳定；mAP +~4% |
| 2 | **Anchor Boxes**（k-means 聚类得 5 个） | 定位精度低、尺寸单一 |
| 3 | **多尺度训练**（416 / 416 / 416 三尺度，每 10 epoch 换一次） | 尺寸泛化差 |
| 4 | **Darknet-19 骨干**（改用 3×3 + 1×1 交替） | 特征提取能力弱 |
| 5 | **Passthrough 层** | 13×13 输出分辨率太粗，小目标信息丢失 |
| 6 | **WordTree**（层次化标签树） | 类别数扩展困难 |
| 7 | **联合检测与分类**（9000 类多标签） | 类别覆盖窄 |

### 2.2 Anchor 的表示方式

v2 **不用中心点表示**，而是用**偏移量**：

$$
\underbrace{
\begin{bmatrix}
t_x, t_y, t_w, t_h
\end{bmatrix}
}_{\text{预测值}}
= \underbrace{
\begin{bmatrix}
b_x, b_y, b_w, b_h
\end{bmatrix}
}_{\text{anchor}}
+
\Delta
$$

在 cell 内归一化：
$$
t_x = \frac{w}{w_a}\left(b_x - x_{\text{cell}}\right), \quad
t_y = \frac{h}{h_a}\left(b_y - y_{\text{cell}}\right)
$$
$$
t_w = \log\frac{w}{w_a}, \quad t_h = \log\frac{h}{h_a}
$$

**关键点**：宽高用 **log 空间**编码（$\log(w/w_a)$），因为宽高比是乘性关系，取对数后变成加性，梯度更均衡。这是 YOLO 系列一直沿用的设计。

### 2.3 Passthrough 层（连接）

```
26×26×256  ──┐
              ├── concat → 28×28×(256+512) → conv → 14×14×1024
13×13×512  ──┘
```

把**更细分辨率**的特征直接 concat 到粗特征上，保留小目标信息。做法：先把 26×26×256 拆成 4 个 13×13×64 块，拼成 13×13×256，再和 13×13×512 concat。

> 这个问题在 v3 引入 FPN 后被彻底解决，passthrough 随之淘汰。

### 2.4 性能

| 指标 | v1 | v2 |
|---|---|---|
| VOC mAP@0.5 | 63.4 | **78.6** |
| FPS | 45 | 21（输入 416×416） |
| 类别数 | 20 | 9000 |

## 3. YOLOv3（2018）

**论文**：*YOLOv3: An Incremental Improvement*, arXiv:1804.02767
**作者**：Joseph Redmon, Ali Farhadi

### 3.1 三大改动

#### 改动 1：Darknet-53

```
输入 416×416
  ↓ conv 3×3 s=1                          416×416×32
  ↓ conv 3×3 s=2                          208×208×64
  ↓ [1×1 conv + 3×3 conv] ×2              104×104×128   ← 残差块开始
  ↓ conv 3×3 s=2                           52×52×256
  ↓ [1×1 + 3×3] ×2                        26×26×512
  ↓ conv 3×3 s=2                           13×13×1024
  ↓ [1×1 + 3×3] ×4                        13×13×1024
```

关键：**残差连接**（1×1 降维 + 3×3 升维 + shortcut）使得 53 层可训练。

#### 改动 2：多尺度预测（核心）

v3 引入 **3 个不同尺度的输出**，每个尺度绑定 **3 个 anchor**（共 9 个），anchor 用 k-means 在 COCO 上聚类得到：

| 尺度 | 输出分辨率 | 感受野 | 对应 anchor 尺寸 |
|---|---|---|---|
| **小目标** | 13×13 | 大 | (116,90), (156,198), (363,366) |
| **中目标** | 26×26 | 中 | (30,61), (62,45), (59,119) |
| **大目标** | 52×52 | 小 | (10,14), (23,27), (37,58) |

**为什么这样就能解决小目标？**
- 52×52 的输出图，每个 cell 对应原图 8×8 像素区域 → 小目标占据更多 cell，梯度信号更强
- 反过来，13×13 用于大目标，每个 cell 对应 32×32 像素，能覆盖整个大物体
- **这是 FPN 思想的雏形**（YOLOv3 同时在同一张特征图上做了 3 次预测，论文称之为类 FPN 的多尺度预测）

#### 改动 3：独立 Logistic 分类

v1/v2 用 Softmax，v3 改为**每个类别一个二分类 Logistic**（sigmoid）。

**理由**：Softmax 强制「类别互斥」，但现实中一个物体可以有多个标签（如「人」+「行人」+「男性」），多标签场景下 sigmoid 更合理，且不强制类别间互斥。

> 注：Ultralytics 后续版本仍用 sigmoid + BCE，多分类损失退化形式。

### 3.2 每个 cell 的输出维度

$$
(4 \times 3) + 1 + 80 = 93
$$

- 4 个边界框参数 × 3 个 anchor = 12
- 1 个目标置信度 × 3 个 anchor = 3
- 80 个类别概率 × 3 个 anchor = 240

总计 93 × 3 个尺度。

### 3.3 性能

| 指标 | 数值 |
|---|---|
| COCO test-dev mAP@0.5 | **61.9** |
| COCO test-dev mAP@0.5:0.95 | **33.0**（608×608，多尺度） |
| 对比 YOLOv2 | 44.0 → 33.0 (mAP@.5:.95) |
| Darknet-19 → Darknet-53 | 感受野和梯度流都改善 |

### 3.4 仍然存在的问题

| 问题 | 根因 | 何时解决 |
|---|---|---|
| **NMS 成为瓶颈** | 每张图 3×(13²+26²+52²)×3 ≈ 25200 个候选框 | v10 / v26 |
| **正负样本极不平衡** | 25200 个框里正样本可能只有 10 个 | RetinaNet 的 Focal Loss → v6 的 TAL |
| **Anchor 依赖** | 换数据集要重算 anchor | v5 AutoAnchor → v8 Anchor-free |
| **骨干网络过时** | Darknet-53 已非最优 | v5 的 Focus+CSP，v7 的 RepConv |

## 4. 奠基期的技术遗产

到 v3 为止，YOLO 确立的以下设计**至今仍在每一个版本中**：

| 遗产 | 现状 |
|---|---|
| **网格/位置上的直接回归** | v8+ 变成「每个位置一个预测」，本质相同 |
| **多尺度输出** | v8+ 变成 P3/P4/P5 三个尺度的 Head |
| **Anchor 先验（宽高 log 编码）** | v8 改成 Anchor-free 直接预测边距，但**log 编码思想**在 DFL 里保留 |
| **每尺度多个预测头** | v5+ 每尺度 3 个 anchor，v8+ 每尺度 1 个 |
| **sigmoid 多标签分类 + BCE** | 一直沿用 |
| **按类别做 NMS** | v10+ 改为一对一分配免除 NMS |

## 5. 工程结论

1. **v1/v2 是理解 YOLO 的最佳教具**，但不要在生产中用：没有 BN、没有现代增强、解码逻辑与现代版本完全不同。
2. **v3 的多尺度思想是整个检测领域的通用武器**，不只是 YOLO。FPN、BiFPN、NAS-FPN 全是它的延续。
3. **log 编码宽高**的直觉：位置是加性的（平移不变），尺寸是乘性的（尺度相关），取对数统一。理解这一点，能解释为什么 DFL 要在离散分布上建模而不是直接回归。
4. **读 v1/v2/v3 论文的顺序**：v1 → v3 → v2（v3 论文极短但信息密度高，v2 论文更详细）。v3 论文只有 9 页但被引用 2 万次。
