# YOLOv6–v10：分化期

> **核心问题**：v5 之后 YOLO 进入「多团队并行探索」阶段。这段时间里最重要的三个思想是什么？

---

## 0. 分化期的地图

```
2020 ─ 2021 ─ 2022 ─ 2023 ─ 2024
 │       │       │       │       │
 v5     v6     v7     v9     v10
YOLOX  (美团) (ChinChony) (WongKinYiu) (清华MIG)
        │       │       │       │
     解耦头   重参数化  PGI/GELAN  NMS-free
     TAL分配  辅助头    梯度流    一致双分支
```

同期还有大量平行分支：DAMO-YOLO（阿里）、YOLOv4-Transformer（阿里的 ViT 化尝试）、EfficientYOLO、YOLOv8-World 等。

## 1. YOLOv6（2021–2022）

**论文**：*YOLOv6: A Single-Stage Object Detection Framework for Industrial Applications*, arXiv:2209.02976
**仓库**：`meituan/YOLOv6` ｜ **定位**：**部署效率优先**（美团要在美团 App 里跑）

### 1.1 四大改动

| 改动 | 内容 | 解决什么 |
|---|---|---|
| **EfficientRep** | 训练多分支 / 推理重参数化 | 部署时分支全折叠，纯卷积，零额外延迟 |
| **解耦头**（Decoupled Head） | 分类回归分支完全独立 | 梯度互相干扰 |
| **TAL 标签分配** | Task-Aligned Assigner | 固定 IoU 阈值不适应困难样本 |
| **自蒸馏策略** | 用自身大模型微调小模型 | 小模型精度天花板 |

### 1.2 EfficientRep（重参数化）

**核心思想**：训练时用多分支（增强表达力），推理时把分支数学等价地折叠成单个 3×3 卷积（零推理开销）。

```
训练态：                推理态（等价）：
    y ──┬─→ 3×3 Conv ──┐         ┌─────────────┐
        │              ├─→ + ──→ │ Conv 3×3     │
        ├─→ 1×1 Conv ──┘         │ (等价合并)   │
        │                        └─────────────┘
        └─→ Identity ──┘
```

数学等价性（以 3×3 + 1×1 + Identity 为例）：

$$
y = W_3 \star x + W_1 \star x + x
$$

其中 Identity 分支等价于一个**中心权重为 1 的 1×1 卷积**（即一个 3×3 卷积只在中心位置非零）。因此三者可合并为：

$$
W_{\text{fused}} = W_3 + \text{pad}(W_1) + I_{\text{center}}, \quad
b_{\text{fused}} = b_3 + b_1
$$

BN 也可以折叠：推理时把 BN 的 $\gamma, \beta$ 和均值方差吸收进卷积权重。

> **注意**：RepVGG 的核心结论是「**推理期结构简单 → 对硬件更友好**」。这在 NPU/FPGA 上尤其重要，因为多分支会触发 NPU 的分支融合失败或走更慢的路径。

### 1.3 TAL（Task-Aligned Assigner）

这是 YOLOv6 最具影响力的贡献，v8 直接继承了它。

**问题**：v5 用固定 IoU 阈值（0.2 / 0.7）划分正负样本，但：
- **IoU 高的样本不一定是分类得分高的**
- 两者不一致时，训练信号是矛盾的

**TAL 的思想**：让**分类得分**和**IoU**共同决定正样本选择 —— "task-aligned"（任务对齐）。

**流程**：

```
Step 1: 对每个 GT，计算每个 anchor 的分类预测得分 c 和回归 IoU 值 q
Step 2: 计算对齐分数
        s = c^α · q^β     （α=0.5, β=6.0 为超参）
        s = s · q_mask    （q < 阈值(0.7?) 的置 0）
Step 3: 对每个 GT，取分值 top-k 的 anchor 作为正样本
        k = max(10, int(0.9 × 归一化后的候选数))
Step 4: 对一个 anchor 被多个 GT 争抢的情况，
        保留「对齐分值最高的那个 GT」（one-to-one 仲裁）
Step 5: 剩余 anchor 中 IoU > 阈值(0.7) 的忽略，其余为负样本
```

**为什么 α=0.5, β=6？**
- β 远大于 α → **IoU 主导**（IoU 差 0.1，对齐分就差 6 倍以上）
- 意思：「**首先这个框要准**，其次分类要自信」

### 1.4 YOLOv6 的性能（COCO val）

| 模型 | mAP@0.5:0.95 | 参数量 | GFLOPs | 速度（TensorRT FP16） |
|---|---|---|---|---|
| YOLOv6-N (v3.0) | ~35.0 | 1.7M | 8.9G | ~3.0 ms |
| YOLOv6-S | ~44.0 | 9.5M | 36.0G | ~5.2 ms |
| YOLOv6-M | ~50.0 | 21.4M | 79.0G | ~8.1 ms |
| YOLOv6-L | ~53.1 | 36.5M | 123.7G | ~10.5 ms |
| YOLOv6-B | ~47.9 | 37.3M | 124.8G | — |

> **口径**：美团仓库 v3.0，COCO val，640 输入。v2.0 与 v3.0 数字不同，引用时务必带版本。

### 1.5 意义

YOLOv6 的历史地位不在于它自己的精度，而在于它**证明了「解耦头 + TAL」是更好的组合**，直接影响了 YOLOv8。

## 2. YOLOv7（2022）

**论文**：*YOLOv7: Trainable bag-of-freebies sets new state-of-the-art*, arXiv:2207.02696
**仓库**：`WongKinYiu/yolov7`
**核心主张**：**「可训练 Bag-of-Freebies」** —— 只改训练结构，推理时零开销

### 2.1 与 v4 的 BoF 的区别

| | v4 的 BoF | v7 的可训练 BoF |
|---|---|---|
| 是否改网络结构 | 否 | **是**（但推理时结构不变） |
| 例子 | 增强、损失、cmBN | 辅助头、重参数化、缩放策略 |
| 推理开销 | 无 | **无** |

### 2.2 三个关键技巧

#### 技巧 1：模型缩放方法（Scaling）

v7 提出的缩放策略与 v5 的缩放不同：

- v5/Lee 的缩放：**按比例加深加深**（depth & width 线性缩放）
- v7 缩放：**concat 所有层**（而不是宽度），普通 Conv 和 RepConv 分配不同通道数
  - 公式：$d_{total} = \max(d_{model}, d_{max} \times n_{concat}/n_{max})$，再和 $d_{model}$ 取 max

#### 技巧 2：重参数化卷积（RepConv）

部署友好的多分支卷积：

```
训练态：3×3 Conv (identity 分支) + 3×3 Conv + 1×1 Conv
推理态：折叠为单个 3×3 Conv
```

（数学同 EfficientRep，见 §1.2。）

#### 技巧 3：辅助头（Auxiliary Head）

**问题**：YOLO 的标签分配是「正样本稀疏 + 负样本极多」，浅层特征缺乏监督信号。

**v7 的方案**：在 Backbone 的 P3/P4/P5 位置挂**辅助头**（lead head），训练时用 GT 直接监督（标签分配规则与主头不同：把 GT 分配到最近的 anchor 位置），**推理时丢弃**。

```
        Backbone
      P3 ─────┬──→ [辅助头]  ← 训练时监督，推理丢弃
              │
      P4 ─────┼──→ [辅助头]
              │
      P5 ─────┴──→ [主头 lead head] ← 推理只用这个
                        ↑
                    Neck 输出
```

**收益**：训练时给浅层更多监督 → 特征更鲁棒 → 推理零开销。这是「训练技巧」而非「结构升级」的典型。

### 2.3 性能

| 模型 | COCO val mAP@0.5:0.95 |
|---|---|
| YOLOv7 | 51.7 |
| YOLOv7-L | 51.3 |
| YOLOv7-X | 53.1 |
| YOLOv7-tiny | 37.3 |

> **口径**：v7 论文 Table 1，640 输入，val 集。注意 v7 论文里的 YOLOv7 是带 "chained model" 的配置，数字与 ultralytics 复现版有差异。

### 2.4 评价

**优点**：思路清晰，「零推理代价」的自我约束让方法易于落地。
**局限**：
- 辅助头增加了训练成本（多一次前向）
- 缩放策略复杂，难以手工构造
- 生态远不如 v5/v8，导出/部署需要自己适配

## 3. YOLOv9（2024）

**论文**：*YOLOv9: Learning What You Want to Learn Using Programmable Gradient Information*, arXiv:2402.13616
**仓库**：`WongKinYiu/yolov9`
**核心主张**：**别堆模块，要修复梯度信息流**

### 3.1 问题诊断：梯度信息流

v9 论文的核心论证是：**深度网络的梯度信息在反向传播中会「衰减」**，导致：
1. 浅层特征更新不足
2. 训练收敛慢
3. 参数效率低

传统解法（加模块）治标不治本。

### 3.2 PGI（Programmable Gradient Information）

**多层特征聚合** + **梯度流控制**：

```
   Backbone 各级特征
       ↓
   [ 多个 Conv 分支 ]  ← 提供不同感受野的路径
       ↓
   [ 多级特征聚合 ]    ← 融合各分支
       ↓
   [ 一致性处理 ]      ← 用 1×1 conv 统一通道 + 拼接
       ↓
   送入 Neck
```

**三个组件**：
1. **多分支特征聚合（MFA）**：多条路径提取不同尺度特征
2. **局部梯度信息（LGI）**：控制梯度在各分支的传播
3. **梯度层聚合（GLA）**：把不同层的信息聚合

### 3.3 GELAN

把 CSPNet 的梯度路径思想推广到任意模块：

```
      x ─────────────┐
      ↓              │
   [ 模块 A ]        │
      ↓              │
   [ concat ] ←──────┘
      ↓
   [ 模块 B ]  → 输出
```

**关键**：GELAN 让 YOLO 的骨干、颈部都能用统一方式「替换任意模块」，结构设计自由度大幅提升。

### 3.4 性能

| 模型 | COCO val mAP@0.5:0.95 | 参数 |
|---|---|---|
| YOLOv9-T | 38.9 | 2.0M |
| YOLOv9-S | 46.7 | 7.1M |
| YOLOv9-M | 48.4 | 20.1M |
| YOLOv9-C | 49.1 | 25.3M |
| YOLOv9-E | 50.6 | 58.1M |

### 3.5 评价

**优点**：理论叙事完整，「梯度信息流」的概念有普适价值。
**局限**：
- 工程实现复杂，训练比 v8 慢
- 生态薄弱，TensorRT / NPU 导出需要自己适配
- 相比 v8 的精度提升（+1~2 mAP）不足以抵消迁移成本

> **工程结论**：v9 更适合**研究**（理解梯度流设计）而非**生产**（除非你已有成熟的 v9 适配）。

## 4. YOLOv10（2024）

**论文**：*YOLOv10: Real-Time End-to-End Object Detection*, arXiv:2405.14458
**仓库**：`THU-MIG/yolov10`
**核心突破**：**NMS-free 端到端检测**

### 4.1 问题：NMS 为什么慢

```
网络输出 8400 个候选框（YOLOv8n 640 输入）
      ↓
  置信度过滤 → 剩 ~100 个
      ↓
  按类别分组
      ↓
  NMS（GPU 上串行/低并行）→ 剩 ~10 个
```

NMS 的三个问题：
1. **延迟高**：是纯后处理，与 GPU 并行能力不匹配
2. **不可微**：无法端到端训练
3. **阈值敏感**：NMS 阈值是超参，换数据集要重调

### 4.2 一致双分支标签分配（Consistent Dual Assignments）

v10 的核心：**让训练时的正样本分配与推理时的输出结构一致**。

```
         特征
          ↓
    ┌─────┴─────┐
    ↓           ↓
[一对多分支]  [一对一分支]
One-to-Many   One-to-One
    ↓           ↓
 密集正样本   唯一匹配
(提供梯度)   (与推理一致)
    ↓           ↓
   仅训练     训练+推理
```

**一对多分支**（仅训练时）：
- 多个 anchor 都可以匹配同一个 GT
- 提供**密集的梯度信号**，训练更充分
- 类似 ATSS / TAL 的思路

**一对一分支**（训练 + 推理）：
- 每个 GT 只匹配**一个**预测位置（匈牙利匹配）
- 输出天然无重复 → **不需要 NMS**

**「一致」的含义**：推理时用的一对一分支，其训练时的匹配方式与输出结构完全一致 → 训练-推理无 gap。

### 4.3 一致性对齐损失（Consistency Alignment）

v10 发现：一对多分支和一分支的预测会漂移。加入两个对齐损失：

$$
\mathcal{L} = \mathcal{L}_{\text{one-to-many}} + \mathcal{L}_{\text{one-to-one}} + \alpha \mathcal{L}_{\text{cls-align}} + \beta \mathcal{L}_{\text{box-align}}
$$

- $\mathcal{L}_{\text{cls-align}}$：让两个分支的分类输出分布一致
- $\mathcal{L}_{\text{box-align}}$：让两个分支的框回归一致

### 4.4 性能

| 模型 | COCO val mAP@0.5:0.95 | 延迟 (TensorRT FP16, T4) |
|---|---|---|
| YOLOv10-N | 38.5 | 1.79 ms |
| YOLOv10-S | 39.6 | 2.29 ms |
| YOLOv10-B | 40.5 | 3.34 ms |
| YOLOv10-L | 41.4 | 4.89 ms |
| YOLOv10-X | 42.4 | 6.66 ms |

**对比 YOLOv8**：
- YOLOv10-S vs YOLOv8-S：延迟降低约 **1.8×**，mAP 略高
- YOLOv10-B vs YOLOv8-B：延迟降低约 **1.25×**

> **口径**：v10 论文 Table 3/4，T4 GPU，batch=1，FP16，640 输入，含 NMS（v8）与不含 NMS（v10）的对比。

### 4.5 意义

v10 是 YOLO 历史上第一次**从输出表示层面消除 NMS**。这带来三个工程好处：
1. **延迟可预测**：没有后处理抖动
2. **可完整导出为单个 ONNX 图** → NPU / TensorRT 部署更简单（**尤其对不支持复杂算子的 NPU 至关重要**）
3. **端到端可微** → 理论上能做更好的蒸馏/量化

| 维度 | YOLOv6 | YOLOv7 | YOLOv9 | YOLOv10 |

| 年份 | 2021–22 | 2022 | 2024 | 2024 |

## 6. 工程结论

1. **v6 的 TAL 是这一时期最有价值的遗产**，v8 继承并成为默认。理解 TAL 是理解现代 YOLO 的必修课。
2. **重参数化（v6/v7）现在重新变得重要**，因为 NPU 部署对分支结构敏感。如果你在 RK3588S / 其他 NPU 上部署，遇到「模型能跑但特别慢」，先检查有没有多分支没折叠。
3. **v9 适合学习不适合生产**。它的梯度流思想可以借鉴，但除非你愿意自己适配整条部署链路。
4. **v10 的 NMS-free 是分水岭**。从 v10 开始，「导出到 NPU 要不要保留 NMS 节点」这个坑基本消失。
5. **如果你在 v6 和 v8 之间选**：选 v8（生态好、精度接近、TAL 已被验证）。v6 的独特价值只剩 EfficientRep 的重参数化思路。
