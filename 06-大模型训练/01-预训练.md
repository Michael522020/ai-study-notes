# 预训练：范式、数据与 Scaling Law

> **核心问题**：预训练到底在算什么？为什么数据比架构更重要？什么时候你才真的需要自己预训练？

---

## 1. 预训练在整条链路里的位置

### 1.1 三阶段范式

```
阶段一  预训练 (Pre-training)     ← 本章
        自监督 · 海量通用语料 · 学「语言规律 + 世界知识 + 推理的原材料」
                    ↓
阶段二  中期训练 (Mid-training)
        领域继续训练 · 长上下文扩展 · 高质量退火 (annealing)
                    ↓
阶段三  后训练 (Post-training)     ← 见 02-微调.md
        SFT → 偏好对齐 (RLHF/DPO) → 推理能力激发 (RLVR/GRPO)
```

| 阶段 | 目标 | 数据量级 | 成本量级 | 谁在做 |
|---|---|---|---|---|
| **预训练** | 通用能力底座 | 10¹¹ ~ 10¹³ tokens | 10⁵ ~ 10⁷ GPU 小时 | 只有少数实验室 |
| **中期训练** | 领域 / 长上下文 / 高质量 | 10¹⁰ ~ 10¹¹ tokens | 10³ ~ 10⁵ GPU 小时 | 大厂、部分开源社区 |
| **后训练** | 行为对齐 | 10⁴ ~ 10⁷ 条样本 | 10¹ ~ 10³ GPU 小时 | **几乎所有人** |

> **工程结论**：**99% 的团队应该停在第三阶段。** 预训练是资本密集型游戏，不是工程问题。

### 1.2 自监督目标函数谱系

| 范式 | 代表模型 | 目标 | 强在哪 | 弱在哪 |
|---|---|---|---|---|
| **Causal LM**（自回归） | GPT / LLaMA / Claude | 预测下一个 token | 天然适配生成；与推理、RL 天然对齐 | 一次前向只从每个位置学到 1 个 token 的监督信号 |
| **Masked LM** | BERT | 还原被掩码的 token | 双向编码，适合理解类任务 | 不能直接生成 |
| **Span Corruption** | T5 / UL2 | 还原连续片段 | 兼顾理解与生成 | 预处理链路复杂 |
| **Prefix LM** | GLM | 前缀双向 + 后缀自回归 | 兼顾两者 | 实现与超参更复杂 |

**自回归语言模型的完整目标函数**：

$$
\mathcal{L}_{\text{CE}}(\theta) = -\frac{1}{T}\sum_{t=1}^{T}\log p_\theta(x_t \mid x_{<t}),
\qquad
p_\theta(x_t \mid x_{<t}) = \frac{\exp(e_{x_t}^{\top} h_t)}{\sum_{v \in \mathcal{V}} \exp(e_v^{\top} h_t)}
$$

其中 $h_t$ 是第 $t$ 步 Transformer 输出的隐状态，$e_v$ 是词表里第 $v$ 个 token 的输出嵌入。

**困惑度（PPL）** 是这份损失的指数形式：

$$
\mathrm{PPL} = \exp(\mathcal{L}_{\text{CE}})
$$

**跨 tokenizer 比较要用 bits-per-byte（BPB）**，因为不同 tokenizer 把同样文本切成不同数量的 token，直接比 PPL 是错的：

$$
\mathrm{BPB} = \frac{\mathrm{NLL\ per\ token}}{\ln 2 \times (\mathrm{bytes\ per\ token})}
$$

> **避坑**：看到「模型 A 的 PPL 是 8.2，模型 B 是 8.5」就下结论是错的，除非两者的 tokenizer 和评测文本完全一致。

### 1.3 预训练到底在学什么

三层，从浅到深：

1. **统计规律** —— 词频、语法结构、篇章连贯性。这一层最容易获得，也最先饱和。
2. **世界知识** —— 实体、事实、关系。这层主要靠**权重容量**存储，是「模型记住了什么」的来源。
3. **推理的原材料** —— 问题的模式、步骤模板、链条结构。**注意：这不等于推理能力。**

> **关键澄清**：**预训练本身不产生「会推理」的模型，它只提供「可以被 RL 激发」的原材料。**
> DeepSeek-R1（2025）的结论是：base model 必须先具备足够强的长链思考先验，RL 才能把它激发出来；一个弱 base 用大规模 RL 是训不出推理能力的。
> 这条结论直接决定了：**不要用「我要训推理模型」当作从零预训练的理由。**

## 2. 数据：决定上限的那一半

### 2.1 质量 > 数量

| 工作 | 年份 | 核心结论（论文报告值） |
|---|---|---|
| **RefinedWeb** | 2023 | 清洗后的 CommonCrawl 在同等 token 量下优于原始语料 |
| **FineWeb** | 2024 | 公开 15T tokens 的高质量英文语料 |
| **DataComp-LM (DCLM)** | 2024 | 把「清洗 + 过滤」标准化，暴露出过滤器的价值 |
| **FineWeb-Edu** | 2024 | 用分类器筛「教育性」文本，**同样 1T token 下基准分显著高于通用高质量语料** |

FineWeb-Edu 的结论值得反复强调：**在同样的 token 预算下，把「垃圾内容」换成「有价值内容」，收益大于把 token 数翻倍。**

### 2.2 清洗流水线（最容易被跳过、也最值钱的一环）

```
原始网页 / PDF / 代码 / 书籍
   ↓ ① 正文抽取（boilerplate removal：导航、页脚、广告、模板文本）
   ↓ ② 语言识别与过滤（fastText / CLD3，按语种阈值过滤）
   ↓ ③ 去重
   │    ├─ 精确去重（hash / 段落级）
   │    ├─ 模糊去重（MinHash + LSH，Jaccard 阈值 ≈ 0.8）
   │    └─ 语义去重（SemDeDup：embedding + 聚类 + 阈值过滤）
   ↓ ④ 质量过滤
   │    ├─ 规则过滤（长度、符号比例、标点比例、模板文本）
   │    ├─ 困惑度过滤（fastText / KenLM 质量分类器）
   │    └─ 模型打分（小型质量分类器蒸馏出硬标签）
   ↓ ⑤ 毒性与 PII 过滤
   ↓ ⑥ 数据混合（各 domain 权重）
   ↓ ⑦ 分片与打包（packing 成固定长度序列，消除 padding 浪费）
```

**去重的收益（论文报告值）**：

- Lee et al. 2021《Deduplicating Training Data Makes Language Models Better》：去重能减少「复读」和记忆化，对同样算力下的效果有可测提升。
- FineWeb 的消融：精确去重 + 模糊去重带来的收益，在不同规模的模型上**单调为正**——小模型受益更明显。

**经验法则**：

- 去重优先级 **高于** 质量过滤；两者都做，成本远低于换架构。
- 模糊去重的 Jaccard 阈值从 0.8 起调；中文语料因为分词粒度差异，阈值可能要往下调。
- 语义去重（SemDeDup 类）成本高一个数量级，但它是唯一能干掉「换皮重复」的手段——**网页语料里同一篇文章的十几个镜像站，只能靠它清掉。**

### 2.3 数据混合与课程学习

| 做法 | 代表 | 说明 |
|---|---|---|
| **固定人工比例** | 早期通例 | 简单，但常常拍脑袋 |
| **代理模型学混合权重** | **DoReMi**（NeurIPS 2023） | 用小模型在 proxy 数据上学出最优 domain 权重，再外推到大模型 |
| **在线课程学习** | 各类工作 | 让模型先学易的再学难的 |

**实践上**，多数团队最终还是用手工比例 + 消融来确定混合，DoReMi 类方法主要在超大模型上才显出优势（因为代理模型与目标模型的失配在小规模下不划算）。

### 2.4 中文与多语言

| 现象 | 解释 |
|---|---|
| 中文文本的 token 数比英文少 | UTF-8 下汉字 3 字节，主流 BPE 对中文的切分粒度比英文子词更粗 |
| 但「信息密度」不等于「token 数」 | 不能据此认为中文 token 更「值钱」——要按 BPB 口径比 |
| **真正的坑** | 领域中文语料（书籍、百科、专业文档）的价值 **远高于** 英文机翻版 |
| 语言崩塌 | 参数量增大时，小语种能力被牺牲（这是多语言模型最常见的取舍） |

> **工程结论**：如果你的业务在中文，**不要用英文语料微调模型来「教它中文」**。正确顺序是：中文强 base → 领域中文继续训练 → SFT。

### 2.5 版权与合规（2024 起的一号问题）

**已发生的诉讼与监管**：纽约时报诉 OpenAI、Getty 诉 Stability、作家集体诉讼、欧盟 AI Act 的训练数据披露义务、GDPR 的「被遗忘权」与模型的关系。

**技术事实**：模型可以靠提示输出已知内容的复现（"输出《哈姆雷特》第三章"），这使得「训练数据是否侵权」比传统版权法更复杂。

**工程实践清单**：

| 动作 | 说明 |
|---|---|
| 优先用明确授权的语料 | CC BY / 开放许可 / 自有数据 / 公开领域作品 |
| 维护数据来源台账 | 每个数据集记录 URL、许可证、抓取时间、过滤规则 |
| 处理 opt-out 与 robots.txt | 尊重站点声明与爬取协议 |
| 看权重许可 | 开源权重的**权重**和**代码**可能不是同一套许可（如 Llama 社区许可） |
| 输出侧兜底 | 版权过滤、引用溯源、水印（对产品化更重要） |

> 数据许可的风险不是「训练时」的问题，而是「**产品上线时**」的问题——很多团队是在发布前才发现语料来源说不清。

### 2.6 合成数据

**优势**：可按需生成高质量指令、推理链、代码、可验证样本；覆盖长尾场景成本极低。

**风险 —— 模型坍塌（model collapse）**：
Shumailov et al.（*Nature*, 2024）系统研究了「用模型生成数据训练模型」的递归效应，结论是：**小语料、大量重复的合成数据会导致模型逐步丢失原始分布的长尾部分**，误差逐代放大。

**实践建议**：合成数据必须挂在**外部锚点**上，而不是纯模型自生成：

| 锚点类型 | 例子 |
|---|---|
| 代码执行结果 | 生成题目 → 实际运行 → 用真实输出过滤 |
| 形式化/符号引擎 | 数学题 → SymPy/Lean 验证 → 只留通过的 |
| 结构化知识源 | 数据库、维基表格、规则引擎 |
| 人工抽检 | 抽样人工验证，作为数据质量的守门 |

## 3. 架构

### 3.1 主流仍是 Transformer Decoder，但四条明确的技术路线

1. **MoE（稀疏混合专家）** —— 总参数涨、激活参数不涨
2. **状态空间模型 / 线性注意力** —— 长上下文的复杂度从 $O(L^2)$ 降到近线性
3. **混合架构** —— attention 与 SSM 交替堆叠
4. **多 token 预测（MTP）** —— 训练时一次预测多个后续 token 作为辅助任务，加速收敛

### 3.2 MoE：参数与激活解耦

$$
y = \sum_{i \in \mathcal{T}(x)} g_i(x) \cdot E_i(x)
$$

其中 $\mathcal{T}(x)$ 是被路由到的专家集合（top-k），$g_i(x)$ 是路由权重（通常经 softmax 后归一化）。

| 模型 | 总参数 | 激活参数 | 关键设计 |
|---|---|---|---|
| **Switch Transformer**（2021） | — | 1 个专家 | 负载均衡辅助损失 |
| **Mixtral 8×7B**（2024） | 46.7B | 12.9B | 8 专家 top-2，标准 dense FFN |
| **DeepSeek-V3**（2024） | 671B | 37B | fine-grained 专家、**aux-loss-free 负载均衡**（用可调 bias 修正路由）、共享专家、MLA |

**MoE 的真实代价（常被忽略）**：

| 代价 | 说明 |
|---|---|
| 显存 | **所有**专家参数都必须在显存里，「激活参数少」不等于「显存少」 |
| 通信 | 专家并行的 all-to-all 通信量大，跨节点带宽要求高 |
| 部署 | 推理需要专家并行框架，小显存设备上不友好 |
| 负载不均 | 热门专家过载、需要容量因子（capacity factor）丢 token |

> **工程结论**：MoE 优化的是 **训练/推理的单位算力成本**，不是显存占用，也不是部署复杂度。如果你只有单卡或要跑在边缘设备上，MoE 通常是负收益。

### 3.3 位置编码与长上下文

| 方案 | 机制 | 优点 | 缺点 |
|---|---|---|---|
| **正弦 / 可学习绝对位置** | 直接加到输入嵌入 | 简单 | 长度外推差 |
| **RoPE**（2021） | 按位置旋转 query/key | 相对位置性质好、随距离自然衰减 | 直接外推会掉点 |
| **ALiBi**（2021） | 给注意力分数加线性距离偏置 | 外推好、极简 | 绝对位置不感知 |
| **NoPE** | 不用位置编码 | 最简洁 | 严格依赖因果掩码保证因果性 |
| **插值 / 缩放** | NTK-aware、**YaRN**（2023）、PI、**LongRoPE**（2024） | 把窗口扩到长上下文 | **必须配合长上下文档位继续训练** |

**为什么 RoPE 直接外推会掉点**：RoPE 的旋转频率是位置相关的高频信号，训练时没见过的更远位置，其旋转相位落在训练分布之外，注意力 logits 分布失真。

**长度外推的三步完整做法**（缺一不可）：

```
① 换位置编码的缩放方式（YaRN / NTK-aware / LongRoPE）
      ↓
② 用长上下文档位做继续训练（哪怕只有 1k~10k 条长样本）
      ↓
③ 评测长上下文专用指标（RULER / NIAH / LongBench）
```

> **工程结论**：**长上下文不是「改个参数」就有的。** 跳过第 ② 步，最常见的症状是「大海捞针（NIAH）在中间位置正确率断崖式下跌」。

### 3.4 注意力与 KV cache 的工程优化

| 技术 | 解决什么 | 说明 |
|---|---|---|
| **FlashAttention / -2 / -3** | 显存与速度 | IO 感知的分块计算，**不改数学结果**，只是改变计算顺序避免 HBM 反复读写 |
| **PagedAttention**（vLLM） | KV cache 显存 | 借鉴 OS 虚拟内存的分页管理，减少碎片 |
| **GQA / MQA** | KV cache 大小 | 多头共享 K/V，头数从 MHA 降到 GQA 再到 MQA |
| **MLA**（DeepSeek-V2/V3） | KV cache 大小 | 把 KV 压缩到低维 latent 再缓存 |

**这里的核心 trade-off**：KV cache 大小 ≈ 2 × layers × heads × head_dim × seq_len × batch × bytes，是长上下文推理的**第一显存杀手**。

## 4. Scaling Law

### 4.1 Kaplan et al. 2020：三条幂律

$$
L(N) \approx \left(\frac{N_c}{N}\right)^{\alpha_N},
\qquad
L(D) \approx \left(\frac{D_c}{D}\right)^{\alpha_D},
\qquad
L(C) \approx \left(\frac{C_c}{C}\right)^{\alpha_C}
$$

论文报告的指数（后续拟合版本略有差异）：$\alpha_N \approx 0.067$，$\alpha_D \approx 0.095$，$\alpha_C \approx 0.050$。

**核心结论**：模型、数据、算力三者 **都不能停**。任何一个不增长，另两个的增长都会被浪费——因为总损失里三者是乘法关系（$C = 6ND$，其中 $N$ 和 $D$ 同时涨才让 $C$ 涨得最快）。

### 4.2 Chinchilla（Hoffmann et al. 2022）：修正了「参数优先」的错误

**当时的普遍做法**：给定算力，把参数堆到极大、数据给够 —— LLaMA 1 之前的主流。

**Chinchilla 的修正**：同等算力下，**模型和数据应该大致同比放大**。

$$
D^* \propto C^{0.73}, \qquad N^* \propto C^{0.27}
$$

**经验法则**：**约 20 tokens / param**。

**Chinchilla 的实证**：70B 参数 + 1.4T tokens 的模型，用 Gopher（约 4× 的算力）更少的训练算力达到更低的 loss。

> 注意 $D^* \propto C^{0.73}$、$N^* \propto C^{0.27}$ 中指数之和为 1，这是「算力最优」的定义——在总 FLOPs 固定时，两边按这个比例分配最优。

### 4.3 后续修正与质疑（必须知道，否则会抄错常数）

| 工作 | 年份 | 结论 |
|---|---|---|
| **Bashir et al.《Compute-Optimal Scaling Laws for Neural Language Models》** | 2024 | 用更严谨的拟合**修正了 Chinchilla 的常数**，建议更低的 tokens/param（具体数值依赖设置，引用前请核对原文） |
| **Besiroglu et al.《Chinchilla scaling: A replication attempt》** | 2023 | 独立复现**未能达到** Chinchilla 报告的 loss —— 说明 scaling law 的经验常数**不可跨实现直接套用** |
| **2024+ 的实践漂移** | — | 业界实际训了大量「**过度训练**」模型（LLaMA 系列约 20~21 tokens/param，后续版本远超），因为优化目标是**推理成本**而非训练成本 |

**为什么会出现漂移**：训练一次成本高，但推理次数是训练的成千上万倍；在推理总量足够大的场景下，把训练算力多分给「数据」在**摊销后的总成本**上更划算。这就是 scaling law 从「训练最优」走向「推理最优」的过程。

> **工程结论**：**Scaling law 的真正用法不是照抄「20 tokens/param」，而是理解 $N$、$D$、$C$ 三者的交换率。** 你要回答的问题是：「我的瓶颈是**知识不够**（该加数据 / 加参数）还是**推理能力不够**（该加 RL / 后训练）？」

### 4.4 涌现能力的争论

**Schaeffer et al.《Are Emergent Abilities of Large Language Models a Mirage?》（NeurIPS 2023）**：很多被描述为「涌现」的能力，其实是**评测指标不连续**造成的错觉——把「准确率」换成「token 级概率」、把 pass@1 换成 pass@k，曲线就平滑了。

**对实践的影响**：

- ❌ 不要用「某个能力到某个 scale 突然出现」来规划训练进度或采购预算。
- ✅ 用连续指标（如 log-likelihood、平均 pass rate 曲线）跟踪训练。
- ✅ 对「涌现」的宣传保持警惕，尤其是那些刚好在某个参数量上跳变的营销叙事。

## 5. 训练工程

### 5.1 显存构成（以 AdamW + 混合精度为例）

| 项 | 每参数字节 | 7B 模型 |
|---|---|---|
| 参数（bf16） | 2 | 14 GB |
| 梯度（bf16） | 2 | 14 GB |
| AdamW 一阶矩 $m$（fp32） | 4 | 28 GB |
| AdamW 二阶矩 $v$（fp32） | 4 | 28 GB |
| fp32 master weights | 4 | 28 GB |
| **小计（无分片）** | **16** | **112 GB** |
| 激活值 | 随 batch × seq 变化 | 与序列长度、重计算策略强相关 |

→ **单卡放不下 7B 的全参训练**（即使 80GB 卡也因为激活值而不够），必须多卡 + 分片。

**省显存的常见手段**（按性价比排序）：

| 手段 | 效果 | 代价 |
|---|---|---|
| bf16 混合精度 | 相对 fp32 省一半 | 几乎无 |
| 激活重计算 (gradient checkpointing) | 激活显存大降 | 慢 20~40% |
| ZeRO-3 / FSDP | 显存 ≈ 16/N + 激活 | 通信变多 |
| 优化器换 Adafactor / 8-bit Adam | 省 4~6 bytes/param | 收敛可能变慢 |
| SGD / Lion | 省更多 | 需重调超参 |

### 5.2 并行策略

| 技术 | 切什么 | 解决什么 | 通信量 |
|---|---|---|---|
| **DP**（数据并行） | 切 batch | 梯度 all-reduce | 中 |
| **ZeRO-1** | 切优化器状态 | 省 8 bytes/param | 低 |
| **ZeRO-2** | + 切梯度 | 再省 2 bytes/param | 低 |
| **ZeRO-3 / FSDP** | + 切参数 | 显存 ≈ 16/N + 激活 | 高（需要 all-gather 参数） |
| **TP**（张量并行） | 切单层矩阵 | 单层放不下时用 | **极高**，需 NVLink |
| **PP**（流水并行） | 切层 | 跨节点带宽差时用 | 低（点对点） |
| **EP**（专家并行） | 切专家 | MoE 专用 | 高（all-to-all） |

**主流组合**：单机内用 NVLink 做 TP，跨机用 PP + DP；MoE 额外加 EP。

> **工程结论**：**并行策略的选择不是性能优化，是可行性问题。** TP 跨机走 IB 网会崩掉，所以「TP 放在节点内」是硬约束，不是调优项。

### 5.3 数值与训练稳定性

| 问题 | 现象 | 处理 |
|---|---|---|
| **fp16 溢出** | loss 变 NaN | 换 bf16（动态范围大，无需 loss scaling） |
| **loss spike** | loss 突然从 2.0 飙到 10+ | **跳过该 batch**（设阈值丢弃，不要硬跑）；事后分析数据 |
| **logits 爆炸** | 少数 token 概率异常大 | **z-loss**：$10^{-4} \cdot \log\text{sumexp}^2$ |
| **梯度爆炸** | grad norm 尖峰 | `clip_grad_norm = 1.0` |
| **小 batch 下 Adam 偏差** | 早期 loss 抖动大 | warmup 拉长、batch 加大 |
| **权重衰减的实现差异** | L2 vs decoupled | AdamW 的 **decoupled** weight decay 与 L2 正则不等价 |

### 5.4 优化器与调度

- **AdamW**（Loshchilov & Hutter, 2019）：解耦权重衰减，是当前事实标准。
- **调度**：warmup（通常 2,000~5,000 步，或总步数的 1~3%）+ cosine decay 到 ~10% 峰值。
- **μP（maximal update parametrization，Yang & Hu 2022）**：让超参在改变宽度/深度时保持可迁移。**2024 年后被广泛推荐**——它解决的是「我改了模型宽度却要重调一遍 lr」的痛点。
- **学习率是最重要的超参**，也是最该先扫的。粗扫 3 个数量级（1e-5 / 1e-4 / 1e-3）比精调其它参数收益大。

### 5.5 Checkpoint 与容错（工程必需品）

大规模训练 **一定会挂**。必须假设硬件会故障、节点会被抢占、磁盘会写坏。

| 要求 | 说明 |
|---|---|
| 分片 checkpoint | 按 rank 分片存，避免单个大文件写失败即全丢 |
| 异步保存 | 保存不阻塞训练（用独立进程 + 内存拷贝） |
| 完整状态 | optimizer state + RNG state + dataloader position + global step，缺一不可续训 |
| 弹性伸缩 | 节点故障后自动重启并跳过已完成步 |
| 定期自检 | 能从任意 checkpoint 续训，且 loss 曲线连续 |

> **工程结论**：**「能续训」和「能训练」是两个工程量级。** 没有做过「从第 4000 步的 checkpoint 精确续训」的团队，第一次真故障时会损失整轮算力。

## 6. 成本量级（自己估算用）

**训练 FLOPs 的标准近似**：

$$
C \approx 6 N D
$$

（$N$ = 参数量，$D$ = token 数；前向 2 FLOPs/param/token，反向是其 2 倍。MoE 用**激活参数量**代替 $N$。）

**例：7B 模型 × 1T tokens**：

$$
C = 6 \times 7\times 10^{9} \times 10^{12} = 4.2 \times 10^{22}\ \text{FLOPs}
$$

A100-80GB 的 bf16 峰值约 312 TFLOPS，取 40% MFU → 有效约 125 TFLOPS/GPU：

| 配置 | 估算耗时 | 备注 |
|---|---|---|
| 8 × A100-80G | ≈ 560 小时（23 天） | 单机 |
| 64 × A100-80G | ≈ 70 小时（3 天） | 一个 8 卡节点 |
| 512 × A100-80G | ≈ 9 小时 | LLaMA-1 论文报告 7B 用 **184,320 A100 GPU 小时**（≈360 h/GPU，对应 MFU 约 25~30%） |

**参考量级**（论文报告值，用于交叉验证）：LLaMA-1 65B 使用 1.4T tokens、约 **700 万 A100 GPU 小时**。

> ⚠️ 上述数字随 MFU、序列长度、并行效率、是否重计算、是否 MoE 变化极大，**是量级估算，不是报价**。

**一个能自检的 sanity check**：

$$
\text{单卡小时} \approx \frac{6ND}{\text{单卡有效 FLOPS} \times 3600}
$$

如果你的估算和论文报告差 3 倍以上，先查 MFU 假设和是否算漏了 embedding / 重计算。

## 7. 评测预训练模型

| 类别 | 指标 | 说明 |
|---|---|---|
| **内在** | PPL / BPB | 只在同 tokenizer、同数据、同上下文长度下可比 |
| **通用能力** | MMLU / GSM8K / HumanEval / MBPP / C-Eval | 知识 + 推理 + 代码 |
| **长上下文** | RULER / NIAH / LongBench / ∞Bench | 位置效应、检索、多跳聚合 |
| **效率** | 吞吐 / 显存 / MFU | 训练侧健康度 |
| **鲁棒性** | 多语言、长上下文、指令跟随 | 后训练阶段补 |

**工具**：`lm-evaluation-harness`（EleutherAI）、**HELM**（Stanford CRFM）、**OpenCompass**（中文）、SuperCLUE。

**数据污染（contamination）必须主动排查**：

| 手段 | 说明 |
|---|---|
| 时间切分评测 | 用评测发布之后新出的题（如 LiveBench 每月更新） |
| n-gram 重叠分析 | 训练集与测试集的长子串匹配（13-gram 是常用阈值） |
| 改写基准 | 换表述、换数字、换顺序 |
| 扰动一致性 | 同题换皮后分数大幅波动 → 说明背的是原题 |

> **避坑**：预训练分数高不一定是「能力强」，也可能是「见过题」。**在业务数据上的表现才是唯一有效的验收标准。**

## 8. 我到底要不要自己预训练？

| 你的情况 | 建议 | 理由 |
|---|---|---|
| 做垂直领域应用 | **不要预训练** | 先做继续预训练（中期训练，10¹⁰ token 量级）或直接 SFT + RAG，ROI 高得多 |
| 要研究架构 / 训练算法 | 需要，但**先从 100M~1B 复现** | 7B 级别的研究成本足以劝退大部分想法 |
| 做中文 / 小语种垂直模型 | **继续预训练 + 全参 SFT** | 性价比最高的组合 |
| 要训推理模型 | **不要从零训** | 先拿强 base，再做 RLVR / 蒸馏 |
| 商业项目 | **不要** | 预训练 ROI 极低，能力差距可用后训练 + 检索补 |

**从零预训练的「最小可行规模」**：

| 规模 | 算力量级 | 用途 |
|---|---|---|
| 100M 参数 + 1B tokens | 单卡可跑 | 教学、跑通全流程 |
| 1B 参数 + 10B tokens | 数卡 | 能复现有意义的性能差异 |
| 7B 级别 | 8 卡以上 + 工程化 | 只有在做严肃对比实验时才值得 |

## 9. 工程结论

1. **预训练是资本密集型游戏，绝大多数团队应该只做后训练。** 你的产出应该在第 2、3 阶段。
2. **数据质量 > 数据数量 > 架构花活。** 清洗流水线是全流程 ROI 最高的投入。
3. **Scaling law 用来理解交换率，不是用来抄常数。** 常数在不同实现、不同年份之间已经变过好几轮。
4. **长上下文必须靠训练获得**，改参数只是必要条件之一。
5. **训练一定会挂**，容错与续训是必需品。
6. **别用「涌现」规划进度**，用连续指标。
7. **合规从第一天算进成本**，不是上线前才发现说不清。
8. **合成数据必须挂外部锚点**，否则递归训练会坍塌。
