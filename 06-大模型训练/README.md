# 06 · 大模型训练研究笔记

> **从预训练底座到 LoRA 适配的完整训练链路地图。**

这一章要回答的问题很朴素：**一个大模型是怎么被「造」出来的？我该从哪一步开始？**

先把话说清楚——训练不是一件事，而是三件事：

```
预训练 (Pre-training)  →  中期训练 (Mid-training)  →  后训练 (Post-training)
   海量通用语料              领域/长上下文             SFT → 偏好对齐 → 推理激发
   10¹¹~10¹³ tokens          10¹⁰~10¹¹ tokens         10⁴~10⁷ 条样本
   10⁵~10⁷ GPU 小时          10³~10⁵ GPU 小时         10¹~10³ GPU 小时
```

**成本跨越了四个数量级。** 这个落差决定了绝大多数团队应该做的是最后一格，而不是第一格。

## ⚡ 一张表看懂三种训练

| | **预训练** | **SFT（微调）** | **LoRA** |
|---|---|---|---|
| **在学什么** | 语言规律 + 世界知识 + 推理原材料 | 任务格式、指令跟随、输出风格 | 同 SFT，但只改一小部分参数 |
| **数据** | 10¹¹+ tokens | 10³~10⁵ 条样本 | 同 SFT |
| **可训练参数** | 100% | 100%（全参）或 <5%（PEFT） | 0.01% ~ 5% |
| **7B 的显存** | TB 级集群 | 112 GB + 激活 | 12 ~ 25 GB（QLoRA 可到 8 GB） |
| **产出** | 一个基座模型 | 一个任务专用模型 | 几十 MB 的 adapter 文件 |
| **推理开销** | — | 零 | 合并后零 |
| **能做的人** | 少数实验室 | 几乎所有人 | 几乎所有人（单卡即可） |

## 🧭 三个贯穿全篇的核心矛盾

### 矛盾 1：知识 vs 行为

- 微调擅长改**行为**（格式、风格、流程），不擅长改**知识**（事实、数值、需溯源的内容）
- 硬把知识塞进权重，会得到「模型自信地编造」

**解法**：**RAG 管知识，SFT 管行为**（详见 §02 §1.3）

### 矛盾 2：容量 vs 遗忘

- 全参微调上限最高，但改动幅度大 → 通用能力退化（灾难性遗忘）
- 低秩适配改动受限 → 遗忘少，但容量有上限

**解法**：先用 LoRA 试；涨不动再加容量；通用能力是硬约束（详见 §02 §2.3）

### 矛盾 3：效果 vs 成本

- 预训练/全参微调能换来更强能力，但算力门槛是数量级的差距
- 大多数业务场景里，**能力差距可以用检索、工具调用、prompt 工程补回来**

**解法**：**从最便宜的那一格开始，只在实测数据证明不够时才往上爬**（详见 §01 §8）

## 📌 一句话决策指南

| 你的情况 | 起点 |
|---|---|
| **模型不知道最新事实 / 私有文档** | RAG（不要微调）→ [`../03-RAG/`](../03-RAG) |
| **模型不会按你要的格式输出** | 先 Prompt + few-shot → 不够再 SFT |
| **模型「领域感」不够（术语、行话、文体）** | 继续预训练（中期训练）→ [`01-预训练.md`](./01-预训练.md) §8 |
| **模型输出「能跑但不是我要的那种好」** | DPO 偏好对齐 → [`02-微调.md`](./02-微调.md) §5.2 |
| **显存只有一张 24GB 卡** | LoRA + gradient checkpointing → [`03-LoRA.md`](./03-LoRA.md) §5.3 |
| **显存只有一张 12GB 卡** | QLoRA (NF4) → [`03-LoRA.md`](./03-LoRA.md) §4.1 |
| **一个基座要挂多个任务** | LoRA adapter 不合并，或 AdaLoRA / VeRA |
| **推理延迟敏感、不能有额外开销** | 训练后 **merge** adapter |
| **要训推理模型（长思维链）** | **不要从零预训练**，拿强 base 做 RLVR / 蒸馏 |
| **预算有限、要快速见效** | 开源权重 + LoRA + 少量高质量数据（1000 条量级即可） |

## 🧪 必须动手做的三个练习

| # | 练习 | 产出 | 检验的能力 |
|---|---|---|---|
| **A** | 拿一个开源模型，用 1,000 条**人工精修**数据做 LoRA SFT | 一个 adapter + 效果对比报告 | 是否理解「质量 > 数量」 |
| **B** | 同一份数据，分别跑 r=4/8/16/32 和不同 target_modules | 一张消融表 | 是否理解「加模块 > 提 rank」 |
| **C** | 自己实现一遍 LoRALinear（不 import peft），并验证初始化输出 == 基座输出 | 40 行代码 | 是否真正理解而不是背下来 |

> 练习 C 是最值得做的：**它能一次暴露你对 LoRA 初始化、缩放系数、合并逻辑的三个常见误解。**
