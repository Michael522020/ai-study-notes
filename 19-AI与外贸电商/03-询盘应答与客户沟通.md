# 03 · 询盘应答与客户沟通

> **这一章的任务：把「一封询盘怎么回」拆成一条可复核的流水线，并明确——AI 写的是草稿，按钮按的是人。**

---

## 1. 为什么询盘应答是外贸 AI 的第一站

因为它同时满足四个条件，这四个条件凑齐的场景不多：

| 条件 | 外贸询盘是否满足 |
|---|---|
| 量大 | 每天几十到几百封 |
| 输入结构化程度中等 | 文本 + 附件 + 历史往来 |
| 有明确正确答案 | 「他问的是 304 不锈钢板 2mm 的价格」 |
| **错了看得见** | 客户会回「不是这个规格」 |

**最后一条最关键。** 有一些场景错了会被自动发现（这让它们适合早期试点），询盘属于这类。

---

## 2. 询盘的四种类型，处理方式完全不同

**把所有询盘丢给同一个提示词，是外贸 AI 最常见的失败原因。**

| 类型 | 特征 | 该做什么 |
|---|---|---|
| **A 型：规格明确** | 给了尺寸、材质、数量、用途 | **几乎可全自动**：调价表 → 报价单 → 邮件 |
| **B 型：规格模糊** | 「要不锈钢的」「量很大」 | **AI 做澄清提问**，人确认后回 |
| **C 型：钓鱼/同行** | 问题泛、没有具体信息、要样品 | **规则筛掉**，AI 只做初筛 |
| **D 型：需求不匹配** | 要的产品你没有 | **直接回「不供」或转介**，别硬聊 |

**A 型和 B 型的分界，是「参数能不能填进报价表」。** 能填进去的走自动化，填不进去的先问。

> **一个很实用的判据：如果一封询盘的回复里，AI 需要「猜」一个数字，那这封询盘就不该全自动回。**
> 猜出来的报价比不报价更糟——它会带着一个错误数字进入客户的比价表。

---

## 3. 首响时间到底值多少钱

这是询盘场景里唯一值得认真算的账。

### 3.1 算式

```
询盘响应率 = 已回复询盘数 / 询盘总数

月度损失询盘数 = 月询盘总量 × (基准响应率 - 实际响应率)

单条询盘期望毛利 = 客单价 × 毛利率 × 成交转化率（按询盘计）

月度挽回毛利 = 月度损失询盘数 × 单条询盘期望毛利
```

### 3.2 怎么用这个算式

**关键是不要直接相信行业里流传的「响应速度翻倍转化率」这类说法。** 自己测：

```
做法：
1. 把过去 6 个月的询盘按首响时间分档（<1h / 1-6h / 6-24h / >24h）
2. 每档统计「回复率」和「成交率」
3. 特别看：同一天、同一品类、同一国家的询盘（控制变量）
```

**你会发现两件事：**
1. 首响时间的边际收益在几小时后就急剧衰减——**从 24 小时变成 2 小时有用，从 2 小时变成 2 分钟几乎没用**。
2. **回复率提升不等于成交率提升。** 快速回复会吸引更多低质量询盘，冲淡了成交率。

> **因此「7×24 秒回」的卖点，在大多数 B2B 外贸场景里是虚的。**
> 真正有价值的是「**8 小时内、且带着准确规格与报价区间**」。AI 的作用是把「8 小时」压到「20 分钟人工复核 + 自动发出」，而不是压到 0。

### 3.3 什么时候秒回确实有价值

| 场景 | 为什么秒回重要 |
|---|---|
| 电商平台的站内信 | 平台算法与买家预期都指向即时响应 |
| 询盘量极大、单条价值极低 | 此时是「筛选竞争」，快本身就是筛子 |
| 高峰期（如展会后一周） | 队列积压本身在劝退客户 |

## 4. 客户画像卡：回信之前必须有的东西

**没有画像卡的自动回复，回复得越快越危险。** 因为它会用错误的语气、错误的重点，回一个本来会成单的客户。

画像卡的最小可用字段：

```
# 客户画像卡
公司:           XXX GmbH（德国，汽车零部件二级供应商）
国家/地区:      德国
规模线索:       官网 careers 显示 120 人（来源 URL）
主营:           金属冲压件，配套汽车 Tier-2
可能的用途:     我们产品可用于其冲压模具的耐磨件（推断，依据：产品页「工具与模具」栏目）
采购角色:       姓名 / 职位 / 语言
历史往来:       3 月询过同类产品报价，当时说「等预算」；6 月来过展会
采购量级线索:   上次询价量级为 500 件级（按上次询盘记录）
关键约束:       需要德语资料 + 需符合 RoHS（客户上封邮件提到）
已识别风险:     之前提到过「供应商需在德国本地有库存」
```

**这个卡片的价值有两条：**
1. **让回复有针对性**（用他的行业词，不是我方的黑话）。
2. **让业务员 30 秒接手**——这是 AI 回复能不能被业务接受的关键。

> **画像卡的真正作用不是「让 AI 更聪明」，而是「让 AI 的输出可以被一个忙碌的人快速判断对错」。**
> 如果卡片填不满，说明这个客户值得你花 20 分钟人工读一封询盘，而不是让 AI 自动回。

## 5. 回复的结构：固定骨架 + 变量槽位

**不要让 AI「自由发挥地写一封回复」。** 用固定骨架，AI 只填槽位：

```
模板骨架（示意）：
────────────────────────────────
主题: [产品名] - [规格/型号] 报价与交期 [公司简称]

X 您好：

感谢您关于 [询盘产品] 的询问。

根据您提供的信息（[逐条复述规格：材质/尺寸/数量/用途/目的地]），
我们的对应型号是 [型号]，[关键参数 1] / [关键参数 2]。

单价: [价格]（依据: [成本基准 + 汇率 + 数量档]，有效期 [天数]）
交期: [交期]，起订量 [MOQ]
付款方式: [方式]

[1 段针对性说明：为什么推荐这个型号 —— 要接住他刚才提的用途]
[1 段需要确认的信息：明确列出你还需要他回答的 1~2 个问题]

如需样品，我们可在 [天数] 内寄出。
[低承诺 CTA]
────────────────────────────────
```

**这个骨架的价值：**

| 好处 | 说明 |
|---|---|
| **可审计** | 每个空位都能追溯到数据源或人工输入 |
| **风格统一** | 不会这次写「您好」下次写「Hi」 |
| **漏项可检测** | 价格、有效期、交期、付款方式少一个 → 校验规则报错 |
| **可分市场微调** | 只换槽位取值逻辑，不重写模板 |

> **「AI 写自由文本」到「AI 填固定模板」的这一步，是外贸 AI 从「演示」变成「生产」的分水岭。**
> 前者的输出每次都不一样（没法审、没法测、没法复盘）；后者每次都长得一样（可以逐条 diff、可以回归测试）。

## 6. 报价：**必须是程序算的**

这是本章最硬的一条规则。

```
❌ 禁止：把规格 + 客户信息喂给模型，让它输出报价邮件

✅ 正确：
   规格 → 结构化 → 查价表（程序）→ 加规则（数量档/交期/运费/汇率/税费）
        → 生成报价单（程序）→ 模型只负责「把报价单翻译成人话 + 写上下文」
```

**「翻译成人话」这一步才是模型该干的。** 它不碰数字。

### 6.1 报价必须落库的东西

| 项 | 为什么必须由程序处理 |
|---|---|
| **成本基准** | 基础价来自 ERP/BOM，人工录入也该是**录入后锁版本** |
| **汇率** | 必须来自**外部实时源**，且**在报价单上写明取数时间**——这是最容易被忽略的一条 |
| **数量档价** | 规则表，不允许模型自由发挥 |
| **运费与保险** | 走物流商接口或固定价表 |
| **税费** | 目标市场的进口税、VAT reverse charge 等，**按目的国 + HS 编码查表** |
| **有效期** | 固定规则（如 7 天），且到期自动失效 |
| **付款与汇率风险条款** | 固定条款文本 |

> **一个真实的坑：报价单上的汇率没有取数时间。**
> 三个月后客户拿这份报价来下单，你既说不清用的哪天的汇率，也无法解释价格为什么变了。
> **所有含汇率的报价单，汇率必须带时间戳。**

### 6.2 报价的三个校验（都该是自动的）

1. **一致性校验**：报价单上的型号、单价、数量、总额是否互相自洽（总额 = 单价 × 数量 × (1 ± 税率)）。
2. **基准校验**：单价是否落在价表允许区间内（防止有人手工改价后被 AI 引用）。
3. **时效校验**：汇率取数是否在 N 小时内、价表版本是否最新。

**任一校验不过 → 不出报价单，返回给人。**

## 7. 语气：怎么不像机器

### 7.1 三个具体动作

1. **用对方的词。** 客户写 `Blech`（德语板材），你别写 `steel sheet`。这需要词表，见 16 主线的术语一致性。
2. **把「我们」改成「你/您」。** 模板通病是一堆排比句的「我们拥有…我们提供…我们承诺…」，改成直接说事。
3. **删掉所有没有信息量的形容词。** 「优质」「专业」「领先」「一站式」——这些词客户一天看五十封，会直接归类为垃圾。

### 7.2 不要做的三件事

| 不要做 | 为什么 |
|---|---|
| 每次都问「请问您贵姓？」 | 客户名里就有 |
| 每次都附公司介绍 | 客户找的是你，不是你公司 |
| 每次都以「期待与您合作」结尾 | 客套话占掉了客户最后一眼的位置 |

### 7.3 一封「像人」和「像机器」的信对照

```
像机器：
  尊敬的张先生，
  您好！感谢您对我们公司的关注与信任。我们是一家专业从事 XXX 的高新技术企业，
  拥有多条先进的生产线和丰富的出口经验。我们相信我们的产品能够完美满足您的需求。
  如有任何疑问，请随时与我们联系。期待与您的合作！

像人：
  张先生，
  您问的 2mm 304 板，我们有对应型号 S201，常规厚度公差 ±0.03mm。
  1000 件的价格区间我放在附件里（含 20% 量折扣）。
  两点想确认：① 您要的表面是 2B 还是 No.4？② 目的地是汉堡还是鹿特丹（运费差别不小）。
  样品这周可以寄出。
```

**差别不在语言水平，在「有没有具体信息」和「有没有把球踢回去」。**
后者（提出澄清问题）是**专业感的最强来源**——它说明你在认真读这封信。

## 8. 跟进与逼单：AI 的边界

### 8.1 能做的

- 判断「客户是否已回复」「上次触达距今多久」「当前处于漏斗哪一步」
- 起草跟进邮件（**但语气模板化反而暴露自动化**，要留人写的空间）
- **提醒**：某客户 30 天无回应，是否要换角度再触达

### 8.2 不能做的

- **自动判断「客户还在考虑 vs 已经放弃」**——这两者在邮件里的表现几乎一样
- **自动给折扣**（折扣影响毛利，且容易被滥用）
- **自动承诺交期**（交期是产能与排产的函数，不在 CRM 里）
- **自动判断「这单该不该放弃」**

### 8.3 一个可用的判断框架：看「信息泄露度」

客户在邮件里透露的信息越多，说明他越认真：

```
越来越具体（材质、尺寸、数量、图纸）→ 认真
给了具体时间（"下周之前要答复"）→ 认真
问的是细节（打样费、最小起订、交期能否压缩）→ 认真
反复确认同样的话（说明第一封没被理解）→ 不是不认真，是你的信有问题
只回 "Thanks" / "收到" → 礼貌结束
不回 → 可能只是忙
```

**AI 可以把这些信号提取出来给人看，但「这单还追不追」必须人来定。**

## 9. 本章工程结论

1. **询盘要分型（A 规格明确 / B 模糊 / C 钓鱼 / D 不匹配），分型后的处理方式完全不同。**
2. **「AI 需要猜一个数字的询盘，就不该全自动回」**——这是最实用的一条判据。
3. **首响时间的边际收益在几小时后急剧衰减**；真正有价值的是「8 小时内 + 带准确规格与报价区间」，不是「秒回」。
4. **回复率提升 ≠ 成交率提升**，别只追前者。
5. **客户画像卡是 AI 回复能被业务接受的前提**，且它的作用是「让人快速判断对错」，不是「让模型更聪明」。
6. **回复用固定骨架 + 变量槽位**，不要自由发挥；固定结构才能逐条 diff 与回归测试。
7. **报价必须由程序算**：成本、汇率、数量档、运费、税费、有效期全部落程序；模型只负责把它翻译成人话。
8. **含汇率的报价单必须带汇率取数时间戳。**
9. **三条硬校验（一致性 / 基准 / 时效）任一不过就不出单。**
10. **语气靠三件事变自然**：用对方的词、少用「我们」、删掉空洞形容词；**结尾提一个具体的澄清问题**比任何客套都有效。
11. **折扣、交期、放弃决策都不交给 AI。**
