# 08 · 跨境合规与风控

> **这一章的任务：把跨境合规拆成六道闸，每道闸说清「挡什么、由谁执行、失效时会怎样」。**
>
> **免责：本章是工程侧的常识性说明，不是法律或税务意见。各市场规则变动频繁且按 HS 编码与原产地细分，真实决策前必须由报关行、税务顾问或目标市场律师复核。**

---

## 0. 一句话原则

> **合规不是「AI 的一个功能」，是「系统的默认拒绝态」。**
>
> 合规逻辑的正确写法是：**默认阻断，命中放行**；不是「默认放行，命中提示」。
> 这两种写法的差别，在名单服务超时或规则写错的那一天，会变成真实的法律后果。

---

## 1. 六道闸

| # | 闸 | 挡什么 | 谁执行 | 失效后果 |
|---|---|---|---|---|
| 1 | **交易对象筛查** | 制裁名单命中 | 规则引擎 + 名单服务 | 极高（法律 + 银行冻结 + 声誉） |
| 2 | **数据跨境** | 客户数据出境、个人数据合规 | 规则引擎 + 架构约束 | 极高（GDPR 等高额罚则） |
| 3 | **产品准入** | 产品认证、标签、说明书语言 | 查表 + 人审 | 高（清关扣留、下架、召回） |
| 4 | **知识产权** | 商标、专利、外观、图片版权 | 检索 + 人审 | 高（下架、索赔、账号封停） |
| 5 | **平台规则** | 平台政策、账号健康、评价操纵 | 规则 + 监控 | 中高（封店，失去流量） |
| 6 | **支付与资金** | 拒付、欺诈、异常资金流 | 风控规则 + 人工复核 | 中高（坏账、账号冻结） |

**六道闸的共同点：都是「规则明确 + 出错代价高」。**
**所以它们的正确实现都是确定性代码 + 人工闸，而不是模型判断。**

---

## 2. 第 1 道闸：交易对象筛查

### 2.1 为什么它必须是硬闸

**一次制裁名单命中，后果是复合的：**
法律处罚 + 银行冻结与拒付 + 合作方终止 + 平台账号风险 + 公开声誉。
**而且往往是不可逆的。**

```
正确形态:
  交易对象 → 标准化（去后缀、去公司形态词、地址归一）→ 多名单并行筛查
          → 任一命中 / 名单不可用 → 阻断 + 人工复核
          → 全未命中 → 放行，记录筛查证据

错误形态:
  交易对象 → 模型判断「这个人像不像被制裁的」→ 放行
```

### 2.2 四份名单，不是四类人

常见误解是「查制裁名单 = 查一个人」。实际上至少要并行查：

| 名单 | 查什么 |
|---|---|
| **主体名单** | 被制裁的实体、个人 |
| **别名名单** | 同一主体的别名、旧名、拼写变体 |
| **物项/行业名单** | 受出口管制的物项与技术（**与主体无关**） |
| **关联与所有权名单** | 被持股 ≥50% 的子公司、代理行 |

> **「只查主体名单」是最常见的漏。** 一个被制裁实体 100% 持股的子公司，通常也受限；
> 一个「看起来无关」但持有受管制技术的公司，可能因物项项被限制。

### 2.3 三条必须写进代码的规则

```
① 名单不可用时阻断业务（fail-closed，不是 fail-open）
   —— 名单服务超时/网络故障时，绝不能「查不到就当没问题」

② 命中不得人工直接放行
   —— 人工只能「升级给合规负责人」，最终放行要留书面依据

③ 筛查结果必须留证
   —— 谁在什么时候、用哪个名单版本、查的哪个标准化后的名字、结果是什么
```

**第 ① 条是本节最重要的一条。**
系统设计时把「名单服务失败」当成「无命中」，是那种在一次服务抖动里就可能造成实质违规的错误。

### 2.4 AI 在这里的唯一合理位置

| 能做 | 不能做 |
|---|---|
| **实体名称标准化与消歧**（去公司形态词、多语种变体、拼写近似、识别同一主体的多种写法） | **判定是否命中** |
| 归并同一主体的多个记录 | **判断某条记录是否应被忽略**（例如已被撤销的记录） |
| 生成审计报告与证据摘要 | **放行决定** |

> **模型处理「名字怎么对齐」，规则处理「命中了怎么办」。**
> 这个分工是本章所有合规闸的通用模式。

## 3. 第 2 道闸：数据跨境

数据合规的框架在 16 主线（[`跨境合规与数据主权`](../16-多语言与跨境应用/05-跨境合规与数据主权.md)），这里只补工程落地。

### 3.1 数据分类先行

```
L0 公开：产品目录、公开营销素材 → 随便发
L1 内部：内部流程、非敏感文档 → 默认不出境
L2 商业敏感：报价策略、客户名录、成本结构 → 需评估 + 脱敏 + 合同约束
L3 个人数据：任何可识别到自然人的信息（**含 B2B 询盘里的联系人姓名与邮箱**）
L4 特殊类别：健康、生物识别、政治、宗教、种族、工会、刑事记录
```

**一个常被忽略的点：B2B 外贸的询盘里也有个人数据。**
业务员姓名、公司邮箱、企业地址，如果这些被发到境外的 AI 服务上，**它就是个人数据出境**，跟 B2C 订单里的电话号码没有本质区别。

### 3.2 数据本地化的三种强度

| 强度 | 含义 | 对架构的要求 |
|---|---|---|
| **L1 存储本地** | 数据存在本地 | 部署一套本地推理，或用区域化部署 |
| **L2 处理本地** | 存储与推理都在本地 | **必须本地推理**；云 API 不合规 |
| **L3 控制权本地** | 数据可以出境，但控制权（谁能访问、谁能留存）留在本地 | 合同约束 + 技术隔离（自有密钥、留存期、可审计） |

**L1 与 L2 的差别经常被忽略：**
「数据存在我自己的服务器，但每次调用都发给境外的模型 API」——**数据出境了，只是出境后又回来了。**
这在严格的合规口径下不满足 L2。

### 3.3 AI 工具引入前必须回答的五个问题

```
□ 这个工具会把我的数据发到哪里？（哪个国家、哪个服务商、哪个子公司）
□ 对方是否用我的数据训练其模型？（合同条款，不是「相信他们不会」）
□ 数据留存多久？能否要求零留存？
□ 我能不能审计？有没有日志与删除接口？
□ 如果这个工具明天不可用了（比如被禁用），我的业务能不能继续？
```

**第 ⑤ 个问题最容易被跳过，也最能暴露「把业务押在单一外部服务上」的风险。**

> 结合仓库里的 `09-本地大模型推理与部署` 主线：当合规要求 L2 时，
> **「云端大模型 + 本地小模型兜底」不是降级方案，是必须提前准备的双通道架构。**
> `07-Agent与智能体` 里的成本闸门设计同样适用——本地通道的闸门要用「token + 延迟」而不是「美元」。

## 4. 第 3 道闸：产品准入

### 4.1 三类要求

| 类型 | 例子 | 谁来定 |
|---|---|---|
| **强制认证** | 欧盟 CE（对应指令）、美国 FCC、电池法规、RoHS | 目标市场的法规与主管机构 |
| **强制标签与说明书** | 原产国、责任人、警示语、说明书语言、批次号 | 目标市场法规 + 平台要求 |
| **进口方责任** | 进口商需注册、需持证、需备案 | 目标市场海关与主管机构 |

### 4.2 这道闸的 AI 适配度：低

**「我的产品需要什么认证」这个问题，答案在目标市场的法规文本里，不在模型里。**

```
模型能做的:
  - 把产品描述翻译成法规语言，帮你检索相关法规条目
  - 把法规原文整理成检查表
  - 检查你的 Listing / 说明书 / 标签是否符合你提供的检查表
模型不能做的:
  - 判断你的产品属于哪个法规类别（这是分类判定）
  - 判断某个具体认证是否适用
  - 判断你的产品是否满足技术要求（需测试报告）
```

**正确做法：把「产品 → 需要的认证」做成一张受控的表**，由合规顾问或第三方实验室出具，
之后每次上新 SKU 走一次这张表。**AI 负责的是「提醒你有哪些表要过」和「检查交付物是否齐全」。**

### 4.3 最容易踩的一条：认证宣称的白名单

见 [`04-商品内容与多语种商品页.md`](./04-商品内容与多语种商品页.md) 的认证词表。
**「FDA Registered」与「FDA Approved」混用是欧美市场最常被平台与监管关注的宣称问题之一。**

## 5. 第 4 道闸：知识产权

### 5.1 三类风险

| 类型 | 风险来源 | 后果 |
|---|---|---|
| **商标** | 用了别人的品牌词做关键词或标题 | 平台下架、律师函 |
| **版权** | 图片、字体、音乐、说明书、视频 | 下架、索赔 |
| **专利** | 产品结构落入他人专利范围 | 禁令、赔偿、召回 |

### 5.2 AI 的作用与红线

```
能做:
  - 批量检索公开商标数据库，做初筛
  - 检查你的文案/图片是否用了与他人高度近似的表述
  - 建立「已用素材台账」：每张图、每段文案、每个字体，记录来源与许可
红线（不能做）:
  - 不能靠「检索没查到」就认为可以用（数据库有滞后，且有未注册商标）
  - 不能用 AI 生成的图/文案就认为无版权风险（生成物仍可能与在先作品近似，
    且字体、模板、训练素材都可能带第三方权利）
```

**「已用素材台账」是最值得做的一件事。** 它把「我有没有侵权」从主观判断变成可查记录，
而且成本极低——每条素材记一行：来源、许可类型、下载日期、授权凭证位置。

## 6. 第 5 道闸：平台规则

### 6.1 为什么它单列一道闸

**平台规则不是法律，但它有法律效果**（封店 = 失去这个渠道的全部资产）。
而且它**变动的频率远高于法律**——所以「把规则写进代码」是不可能的。

### 6.2 三层做法

```
层 1: 硬规则（会立即封号/下架的）
  - 禁止的认证宣称
  - 禁止的评价操纵（自购、返现卡、批量同质化好评）
  - 禁止的联系方式与站外引流
  - 禁止的品牌滥用
  → 这些写成发布前的硬校验

层 2: 软规则（影响权重与曝光的）
  - 标题长度与格式
  - 图片数量与尺寸
  - 类目选择与属性完整度
  - 描述的关键词布局
  → 写成评分项，给出「合规度」而不是「合规/不合规」

层 3: 行为模式（算法识别但规则不写明的）
  - 上新节奏异常
  - 订单-评价时间分布异常
  - 账号操作行为异常
  → 只能靠监控与人工判断
```

### 6.3 规则版本管理

**「我当时是按哪一版规则做的」必须能查出来。**

```
每次内容发布记录:
  - 使用的规则集版本号
  - 规则集生效日期
  - 校验结果（哪条硬规则、哪几条软规则、得分）
  - 人工复核人（如果做了）
```

**平台规则改了之后，要能跑一次「存量内容重扫」**，找出因规则变更而失效的历史内容。
这件事没人会主动做，但它是下架潮的常见原因。

## 7. 第 6 道闸：支付与资金

### 7.1 三类风险

| 风险 | 表现 | 应对 |
|---|---|---|
| **拒付（Chargeback）** | 买家投诉后银行强制扣回 | 证据链完整（物流签收、沟通记录、页面快照） |
| **欺诈** | 盗卡下单、货不对板 | 设备指纹、地址校验、速度规则、3DS |
| **异常资金流** | 账户被用于洗钱、跑分 | 交易图谱分析、账户行为基线 |

### 7.2 AI 的位置

| 能做 | 不能做 |
|---|---|
| 从沟通记录与物流证据中**自动整理拒付抗辩材料** | 做拒付决策（涉及金额与政策） |
| 识别异常订单模式并告警 | 冻结账户（影响客户，必须人做） |
| 对新客户做风险评分 | **对新客户直接拒绝**（会误杀大量真实买家） |

### 7.3 拒付抗辩的准备要前置

**拒付抗辩是「平时留痕，出事时拼装」。**
如果平时没有保存「客户下单时的页面快照」「客服与买家的沟通记录」「物流签收凭证」，
事后基本无法抗辩。

**这与 AI 无关，与流程有关。** 但 AI 可以把「留痕」变便宜：把散落在各处的证据自动归档成一份可提交的档案。

## 8. 合规闸的通用工程模式

六道闸虽然内容不同，实现模式高度一致：

```
┌─ 规则层（确定性，必须）
│   名单与规则命中判断
│   金额阈值判断
│   必填字段完整性
│   数据分类与出境路径检查
│
├─ 数据层（模型可用，但输出要可核）
│   实体名称标准化与消歧
│   产品描述 → 法规关键词检索
│   文案/素材的近似与台账整理
│
├─ 闸门层（默认阻断 + 升级路径）
│   任一硬规则不通过 → 阻断
│   名单服务不可用 → 阻断（fail-closed）
│   模型置信度低于阈值 → 升级人工
│
└─ 证据层（留痕，可审计）
    规则版本、命中依据、决策人、决策时间
```

### 8.1 三条不能省的

1. **默认阻断。** 所有合规闸的默认态是「不放行」。
2. **降级即阻断。** 外部服务不可用时，行为等同于命中。
3. **留证。** 每一次放行都要能回答「依据哪一版规则、谁批准的」。

### 8.2 和 12 主线的关系

**合规闸是 12 主线「五道闸」里「边界闸」的具体化。**
12 主线说的是「要不要做」，这里说的是「做了以后，哪些动作不能自动做」——
两者都指向同一个结论：**把判断留给模型，把执行留给规则。**

## 9. 本章工程结论

1. **合规是系统的默认拒绝态，不是模型的一个功能。**
2. **六道闸**：交易对象筛查、数据跨境、产品准入、知识产权、平台规则、支付与资金。
3. **筛查必须 fail-closed**：名单服务不可用时阻断业务；命中不得人工直接放行；筛查结果必须留证。
4. **四份名单并行**（主体、别名、物项、关联与所有权），只查主体是最常见的漏。
5. **模型处理「名字怎么对齐」，规则处理「命中了怎么办」**——这个分工适用于所有六道闸。
6. **B2B 询盘里的联系人姓名与邮箱也是个人数据**，也会出境。
7. **L1 与 L2 的差别**：「存本地但每次调用境外 API」不等于数据本地化；合规要求 L2 时必须本地推理。
8. **引入 AI 工具前问五个问题**，尤其最后一个：「它明天不可用了，业务能不能继续」。
9. **产品认证走受控表，不走模型判断**；认证宣称用白名单 + 证据编号。
10. **素材台账把「有没有侵权」变成可查记录**，成本极低、价值极高。
11. **平台规则分三层**（硬/软/行为），且要记录规则集版本号，并支持规则变更后的存量重扫。
12. **拒付抗辩靠平时留痕**，AI 能让留痕变便宜，但留痕本身是流程问题。
