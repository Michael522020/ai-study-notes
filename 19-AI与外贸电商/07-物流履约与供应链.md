# 07 · 物流履约与供应链

> **这一章的任务：把履约链条拆开，指出 AI 在这一段的真实位置——它能做的是「预测与提醒」，不能做的是「承诺时效」和「异常决策」。**

---

## 1. 履约链条：六个环节与两种模式

### 1.1 B2B 与 B2C 的履约完全不同

| | B2B（工厂外贸） | B2C（跨境电商） |
|---|---|---|
| **批量** | 大批量、少批次 | 小批量、多批次 |
| **履约主体** | 客户指定货代 / 我方安排 | 平台物流 / 第三方海外仓 |
| **最难的环节** | **报关与单证**（不是运输） | **末端派送与退件** |
| **成本结构** | 头程成本占比高 | 尾程成本占比高 |
| **时效承诺** | 合同约定交期，**可协商** | 平台时效，**不可协商** |

> **B2B 外贸的物流痛点是「单证」，B2C 的痛点是「末端」。**
> 这决定了 AI 在两边的价值点完全不同：B2B 在**单证自动化与异常预警**，B2C 在**轨迹聚合与退件处理**。

### 1.2 六个环节

| # | 环节 | 主要动作 | 主要失败模式 |
|---|---|---|---|
| 1 | **备货与配货** | 拣货、核对、包装 | 错发、漏发 |
| 2 | **出口报关** | 申报、 HS 编码、 退税单证 | 归类错误、查验滞留 |
| 3 | **头程** | 订舱、装柜、起飞、到港 | 甩柜、爆舱、港口拥堵 |
| 4 | **清关与关税** | 申报、目的国放行 | 查验、关税调整、滞港费 |
| 5 | **尾程派送** | 转运、派送、签收 | 妥投失败、地址问题 |
| 6 | **退件与逆向** | 退运、换货、弃件 | 弃件率高、退款周期长 |

## 2. 单证：AI 在外贸履约里最实在的价值点

### 2.1 为什么单证值得优先做

| 特征 | 单证工作 |
|---|---|
| 重复度高 | 每次订单的箱单、发票、报关单要素结构相同 |
| **有明确的正确答案** | 发票金额 = 订单金额 × 汇率；箱单数量 = 订单数量 |
| 错了有代价且**看得见** | 海关查验、退税失败、货款被扣 |
| 文档格式多样 | PDF、Excel、扫描件、邮件正文 |

**「有明确正确答案 + 看得见」这两个条件同时满足的场景，就是 AI 试点最好的起点。**

### 2.2 能自动化的与不能自动化的

| 环节 | AI 能做 | 必须人做 |
|---|---|---|
| **箱单/发票生成** | 从订单数据生成并填模板 | **核对金额、收货人、原产国** |
| **发票合规性预检** | 对照目标国/进口商的发票要求逐条检查 | 判断检查结果是否可接受 |
| **报关要素抽取** | 从订单与产品资料提取品名、材质、用途、HS 候选 | **HS 编码归类与申报** |
| **产地证/认证文件核对** | 比对证书有效期、覆盖型号、签名印章 | 缺失或不符时的处理决策 |
| **单证一致性交叉核对** | 三份文件（箱单/发票/合同）的品名、数量、金额是否一致 | 不一致时的取舍 |

### 2.3 HS 编码：模型能给候选，不能给结论

**HS 编码归类是一个有强烈先例依赖、且错误代价直接落在税上的专业判断。**

```
AI 可以做的:
  - 根据产品描述（材质、用途、工作原理）给出候选编码 + 各自的理由
  - 检索你过去的归类档案（同品类历史归类 + 海关反馈）
  - 标记「描述信息不足以归类」的品，提示补什么信息
必须人做的:
  - 最终申报编码
  - 归类依据的留存（供后续海关问询时举证）
```

> **一个实用的做法：建一份「本司历史归类档案」，把每个 SKU 的归类、依据、归类日期、依据的描述版本都存下来。**
> AI 每次归类先查这份档案——**这比让模型「重新思考」可靠得多**，因为历史归类有海关的实际反馈背书。

### 2.4 单证的一致性交叉核对

这是最值得自动化的一项，因为它是**纯规则、可穷尽**的：

```
核对项:
  □ 合同 / PO ↔ 发票: 品名、规格、数量、单价、总额、币种、贸易术语
  □ 发票 ↔ 箱单: 件数、每箱数量、净重/毛重、总体积
  □ 发票 ↔ 报关单: 品名（中文/外文）、数量、金额、币种、原产国
  □ 订单 ↔ 实际发货: 数量、SKU、批次
  □ 证书 ↔ 货物: 覆盖型号、有效期、签发主体
  □ 全套单证内部: 总重量 = Σ箱单净重 + 包装重; 总金额 = Σ发票行金额
```

**任一项不一致 → 不出单，转人工。**
这套规则用代码写只有几百行，用模型写反而更不可靠。

## 3. 库存与补货

### 3.1 补货点的公式

```
补货点 ROP = 日均销量 × 采购+生产提前期 + 安全库存

安全库存 SS = Z × √(LT × σ_d² + d² × σ_L²)
   Z  = 服务水平对应的标准正态分位数（如 95% → 1.65）
   LT = 提前期均值（天）
   d  = 日均销量
   σ_d = 日销量的标准差
   σ_L = 提前期的标准差（**海运/空运的头程波动很大，这个项常被忽略**）

再订货量 EOQ = √(2 × 年需求量 × 单次订货成本 / 每件年持有成本)
```

**提前期的波动（σ_L）在跨境场景里往往比销量波动更大**，因为它受拥堵、甩柜、旺季附加费影响。**只算销量波动会显著低估安全库存。**

### 3.2 AI 的位置：预测与解释，不替代公式

| 能做 | 不能做 |
|---|---|
| 用你的历史销量做时间序列预测（含季节性、促销标记） | 直接决定备货量（**这是资金决策**） |
| 预测头程时效分布（不是均值，是分位数） | 承诺交期 |
| 识别异常销量（可能是刷单、也可能是一次性大单） | 判断「该不该多备一点货」 |
| 把预测转成人能懂的理由（「因为欧洲仓爆仓 + 海运延误 7 天」） | — |

> **预测输出必须是分位数，不是均值。**
> 备货看的是「最坏情况有多坏」，均值会让你在 95% 的时间里备少了货，而在剩下的 5% 里损失巨大。
> **对外承诺时效用 P90，备货用 P95 或 P99。**

### 3.3 一个常见误判：把促销当趋势

**促销期的销量不能进趋势模型。** 促销会提前透支后续需求，也会让模型学到「这个品需求在涨」的错误结论。

```
正确做法:
  训练数据里给每个点打标记：日常 / 促销 / 大促 / 断货
  - 断货期的「低销量」要剔除（那是缺货不是没需求）
  - 促销期单独建模
  - 模型训练时只用「日常」点
```

**断货期数据不剔除，是选品预测最经典的自欺。**

## 4. 时效与异常：AI 的高价值区

### 4.1 异常的三类与处理

| 类型 | 例子 | 能不能自动决策 |
|---|---|---|
| **数据异常** | 轨迹 3 天没更新（可能只是没扫描） | **可自动**：查承运商接口、确认是丢件还是漏扫 |
| **业务异常** | 妥投失败、地址不全、买家拒收 | **可部分自动**：按规则发起处理（改派、退件、联系买家） |
| **判断异常** | 该换哪个物流商、要不要加急、要不要弃件 | **不可自动**：涉及成本与客户关系 |

### 4.2 一个能自动化的完整链路

```
物流轨迹聚合（多承运商 API + 邮件通知 + 平台消息）
   ↓
标准化事件（统一成「已揽收/在途/清关中/派送中/妥投/异常」+ 时间戳 + 位置）
   ↓
异常检测（规则 + 统计）
   - 轨迹停滞 N 天（且非周末/非假期）
   - 妥投失败
   - 清关停留超阈值
   - 重量/尺寸异常（可能申报不符）
   ↓
自动处置（白名单内的动作）
   - 发通知给买家（含新的预计时间）
   - 触发物流商查件
   - 生成内部工单
   ↓
升级（不在白名单内）
```

> **「自动处置」必须有白名单，且白名单里只放「可逆、低金额、不影响客户权益」的动作。**
> 弃件、退款、换渠道——这些都不在白名单里，必须升级。

### 4.3 对买家的主动沟通

**主动告知延误比被动等投诉好**，这条在跨境电商里是硬经验。

```
好的延误通知:
  "您的订单 XX 预计比原计划晚 3~5 天到达。
   原因是[目的地港口/清关/天气]。
   我们已[已做的动作]，新的预计送达时间为 [日期]。
   如有不便，可选择 [退款/改地址/等待] 中的任一。"
```

**这条通知里最值钱的是最后那句**——给客户选择权，比单纯的道歉更能降低差评率。
AI 可以生成这段文字，但**承诺的日期必须来自物流商的实时数据，不是模型估的**。

## 5. 退货与逆向物流

### 5.1 退货的三种去向

| 去向 | 适用 | 成本 | 说明 |
|---|---|---|---|
| **本地退回再处理** | 高价值、可二次销售 | 高（仓租 + 质检 + 重新上架） | 退货率高的品要算清这笔账 |
| **本地销毁/弃件** | 低价值、破损、不可再售 | 中 | 有环保与合规要求 |
| **退回中国处理** | 高价值、批量 | 极高（国际运费可能超过货值） | **必须设门槛，否则是亏钱买评价** |

### 5.2 AI 的位置

| 能做 | 不能做 |
|---|---|
| 根据历史数据预测「这个品在这个市场的退货率会偏高」 | 决定某个订单退不退 |
| 从退货原因中聚类，识别**是产品问题还是描述问题** | 决定弃件还是入库 |
| 建议「哪些品该在 Listing 里加尺寸对照图」 | 决定要不要给某个客户退款 |

**「退货原因聚类 → 反推 Listing 改进」是本节最实在的闭环。**
如果某品的退货里 40% 写着「比想象中小」，那问题不在客服，在详情页缺尺寸对照——**而这个改动的收益远大于多派两个客服。**

---

## 6. 逆向的三个可提前做的动作

1. **在 Listing 里预先降低退货**：加尺寸对照图、标注「包装内含 X 件」、明确「不含 Y」。**这三件事的投入极小，回报直接体现在退货率上。**
2. **在客服话术里前置**：先问「您收到的尺寸与预期差多少」，把退货变成换货。
3. **在选品阶段就标出高退货品类**：见 [`06`](./06-选品与定价决策.md) 的有效毛利公式。

## 7. 本章工程结论

1. **B2B 的物流痛点是单证，B2C 的痛点是末端**，AI 的价值点因此完全不同。
2. **单证是最适合 AI 试点的环节**：重复度高、有明确正确答案、错了看得见。
3. **单证生成能自动化，但 HS 编码归类只能给候选。** 建**本司历史归类档案**（含依据与日期），AI 每次先查档案再推理。
4. **单证一致性交叉核对是纯规则任务，用代码写，不用模型写。**
5. **安全库存要算提前期的波动（σ_L）**——跨境场景里它常大于销量波动。
6. **预测输出分位数而非均值**：对外承诺用 P90，备货用 P95/P99。
7. **训练数据要打标：日常/促销/大促/断货。断货期数据不剔除 = 自欺。**
8. **异常自动处置要有白名单**，只放可逆、低金额、不影响客户权益的动作；弃件与退款必须升级。
9. **延误通知要给客户选择权**，但承诺日期必须来自物流商实时数据。
10. **退货原因聚类要反推 Listing 改进**——这是履约环节最高杠杆的闭环。
