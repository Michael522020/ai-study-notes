# 04 · 商品内容与多语种商品页

> **这一章的任务：把「写商品页」拆成可评测的流水线，并明确——生成不等于可发布，最后一道是平台规则和事实核对。**

---

## 1. 先分清：商品内容有四种活

「AI 写详情页」这种说法把四件不同的事混在了一起，它们的失败模式完全不同。

| 类型 | 输入 | 例子 | 产出风险 |
|---|---|---|---|
| **翻译型** | 一段已有文案 | 把中文详情页译成德语 | 语法正确、文化错误 |
| **改写型** | 一段已有文案 | 把中文详情页改写成面向德国买家的版本 | 改变事实（说大话） |
| **生成型** | 一堆参数与卖点 | 从规格表生成五点描述 | **幻觉：编出不存在的参数** |
| **优化型** | 已有内容 + 竞品数据 | 改标题以提高点击 | 违反平台规则 |

**这四类的可用性依次下降，工程要求依次上升。**

> **最容易做的是翻译型，最有价值的是优化型，而风险最高的是生成型。**
> 大多数团队直接从「生成型」开始，然后被平台判定虚假宣传。

---

## 2. 生成型内容的最大风险：编参数

**一条规则要记住：**

> **模型可以写「怎么描述」，不能写「是什么」。**
> 参数、尺寸、材质、认证、功率、保修期——这些只能来自**结构化数据源**（ERP、规格书、检测报告），不能来自模型的记忆。

### 2.1 输入必须是结构化的，不是「一段产品介绍」

```
❌ 输入："我们有一款高品质的不锈钢水杯，容量 500ml，食品级材质..."
   → 输出会包含 "500ml"、"食品级"，因为模型从文本里"读到"了这些
   → 但它也可能编出 "750ml"、"304 不锈钢"、"可微波"

✅ 输入（结构化）：
   {
     "容量_ml": 500,
     "材质": "304 不锈钢（内胆）",
     "盖体": "PP + 硅胶密封圈",
     "认证": ["FDA", "LFGB"],
     "保温_小时": {"热": 12, "冷": 24},          // 取自检测报告编号
     "适用": ["咖啡", "茶", "果汁"],
     "禁用": ["微波炉", "洗碗机（上层）"],
     "重量_g": 285,
     "包装": {"单只": "...", "套装": "..."}
   }
```

**然后在生成后做一次「事实回指校验」：**

```
规则：输出中出现的每一个数字、每一个材质词、每一个认证名，
     必须在结构化输入里能找到同源项。
找不到 → 标记为「无源声明」→ 人工处理或删除。
```

**这个校验可以做得很轻**：把输入里的所有 token（数字 + 专有名词 + 认证名）建成一个白名单，输出里出现不在白名单里的就标记。召回率不重要，**漏检才致命**。

### 2.2 认证词是最危险的

`FDA`、`LFGB`、`BPA Free`、`CE`、`RoHS`、`FDA Registered`、`FDA Approved` —— 这些词在法律上不是一回事：

| 词 | 实际含义 |
|---|---|
| **FDA Registered** | 制造商已向 FDA 登记（**不代表通过审核**） |
| **FDA Approved** | 需要 510(k) 等审批流程（**绝大多数食品接触材料拿不到**） |
| **LFGB** | 德国食品法合规测试（**是"符合"不是"批准"**） |
| **CE** | 符合欧盟相关指令的合格评定（**不是质量认证**） |
| **RoHS** | 有害物质限值符合（**电子电气产品**） |

**用错一个词，在欧盟市场就是虚假宣传。** 处理办法：

1. **建一份「认证词白名单 + 准确定义 + 适用市场」表**，每个词写清「我们能说 / 不能说 / 要附什么证据」。
2. **生成时只允许从白名单里取词**，且每个词自动带上它的证据编号。
3. **人工签字一次**，确认白名单本身正确——**这比审核每条 Listing 更省事**。

## 3. 标题、卖点与描述：三种结构的写法

### 3.1 标题（Title）

平台标题不是文案，是**检索入口**。核心规则：

```
[品牌/无品牌] + [核心品类词] + [关键规格] + [关键用途/场景] + [差异化词]
```

**AI 该做的**：根据已有关键词和竞品标题，生成 N 个候选，人选。
**AI 不该做的**：为了可读性改动品类词（把 "Water Bottle" 写成 "Hydration Solution" 就是自断流量）。

> **标题里最值钱的不是形容词，是买家真正会搜的那个词。**
> 形容词几乎不产生搜索量。

### 3.2 五点描述（Bullet Points）

五点是有**角色分工**的，不能五条都是卖点：

| 点 | 角色 | 内容 |
|---|---|---|
| 1 | **核心是什么** | 品类 + 关键规格（买家扫一眼就要知道合不合适） |
| 2 | **解决什么问题** | 使用场景与痛点 |
| 3 | **差异在哪** | 与同类的具体差异（**必须有依据**） |
| 4 | **怎么用 / 怎么装** | 使用与安装信息，降低退货 |
| 5 | **买前要知道什么** | 限制条件、包装内容、注意事项 |

**第 5 点最容易被跳过，也最影响退货率。** 把「不能微波」「不含充电器」「仅含本体不含配件」写清楚，比多夸一句能少退很多单。

### 3.3 描述（Description）

描述的作用是**把规格翻译成收益**，不是重复五点。

**结构：**
```
1. 一句话场景（谁、在什么情况下、解决什么）
2. 展开讲产品怎么工作（讲原理，不要营销腔）
3. 具体规格（表格化，数字来自结构化数据）
4. 包装清单（写了能少退单）
5. 售后与质保（写清楚，反而不增加咨询）
```

### 3.4 一个能用的提示词骨架

```
你的任务：根据给定的产品结构化数据与目标市场画像，写出该平台该品类的五点描述。

硬性规则：
1. 只使用输入数据中出现的信息。任何输入中没有的数字、材质、认证、参数一律不得出现。
2. 认证词只能从【允许词表】中选取，且必须附带对应的证据编号。
3. 每点不超过 200 字符（平台上限 - 10，留余量）。
4. 第 5 点必须是「限制与注意事项」，若输入中无限制信息则写「包装清单」。
5. 禁止使用这些词：[禁用词表]
6. 目标市场画像：{市场}；买家最关心的前三件事：{列表}

输出格式：5 行，每行「要点标题 | 内容」

产品数据：
{结构化输入}
```

**注意第 3 条和第 5 条：长度限制和禁用词表必须硬编码在提示词里，而不是「请简洁一点」。**
「请简洁」对模型的约束力远不如「不超过 200 字符」。

## 4. 多语种：翻译、改写与本地化的三层

这一节的技术细节在 16 主线，这里只给**在商品页场景下的操作结论**。

### 4.1 三层，别混

| 层 | 做什么 | 能不能用 AI 自动 |
|---|---|---|
| **L1 翻译** | 把中文变成德语 | **能，但要人抽检** |
| **L2 跨文化改写** | 针对德国买家重写卖点、调整场景、换掉不合文化的表达 | **AI 出草稿，人定** |
| **L3 本地化合规** | 单位制、认证、电气标准、节日、禁忌、法定标签语言 | **不能，要查表** |

### 4.2 L2 的六个改写维度

写多语种商品页时，**只翻译不改写是转化率损失最大的一种偷懒**。六个维度：

| 维度 | 例子（示意） |
|---|---|
| **场景** | 中国的「送长辈」→ 德国的「办公室/会议场景」 |
| **单位与度量** | 中国的「保温 12 小时（室温）」→ 明确写「预热到 95°C 后保温 6 小时」 |
| **认证与标准** | 目标市场不认的认证要删，认的要加 |
| **表达强度** | 中文「极致」「顶级」直译成德语会显得廉价，要换成具体参数 |
| **利益点排序** | 德国买家更关心材质与可维修性，美国买家更关心即用性 |
| **合规声明** | 法定标签语言、责任人、警示语 |

### 4.3 L3 是查表，不是生成

```
本地化检查表（每市场 × 每品类一份）：
- 法定标签语言：{市场} 要求什么语言的标签
- 强制内容：警告语、责任人、批次号、原产国
- 单位制：公制 / 英制，哪些必须双标
- 电气与机械标准：插头电压、频率、认证标识
- 包装与说明书：语言、必备图示
- 禁用表述：{市场} 禁止的绝对化用语
```

**这张表是人写的、审过的、版本受控的。** 模型只能「对照表检查」，不能「生成合规内容」。

## 5. 关键词：这是数据问题，不是文案问题

**Listing 优化里最容易做错的一件事，是让模型「想几个关键词」。** 模型会给出看起来合理的、但没人搜的词。

### 5.1 关键词的三个来源

| 来源 | 怎么拿 | 用途 |
|---|---|---|
| **平台搜索建议** | 平台搜索框的下拉联想 | 最高优先级（这是真实用户的查询前缀） |
| **竞品标题/五点反查** | 抓取 top N 竞品的标题，抽取高频词组 | 次高 |
| **平台官方工具** | 各平台的关键词/广告词工具 | 官方口径，优先级最高 |

### 5.2 词的使用位置有讲究

| 位置 | 规则（以主流平台为例，具体以当期政策为准） |
|---|---|
| 标题 | 核心词 1~2 个，**顺序有讲究**（前段权重高） |
| 五点 / 描述 | 长尾词与同义词自然分布，**不要堆砌** |
| 后台搜索词 | 放标题里没写但确实相关的词，**不重复标题已有的词** |
| 主题字段（部分平台） | 单个主题词，作用是分类归集，**不要浪费在泛词上** |

> **关键词堆砌是平台判定违规的高发区**，也是「AI 写的 Listing 味道」的主要来源。
> AI 负责**把已经确定的关键词自然地铺进文案**，不负责决定用哪些词。

### 5.3 一个能自动化的东西：标题变体批量生成

```
输入：核心词表 + 规格 + 卖点 + 目标市场
输出：N 个标题候选（长度符合上限、无禁用词、每个核心词位置不同）
人工：选 1 个 + 记录为什么选它（用于回测）
```

**「记录为什么选」这一步是回测的基础**——三个月后你才知道哪一类标题有效。

## 6. 图片与视频

### 6.1 AI 能做的与不能做的

| 能做 | 不能做 |
|---|---|
| 生成背景图、场景图、装饰元素 | 生成**产品本体**（会与实物不符 → 退货 + 平台判定虚假宣传） |
| 抠图、修图、统一色调与尺寸 | **改变产品的颜色、比例、结构**（这是虚假宣传的红线） |
| 文案图上的多语种排版 | 用 AI 生成的图冒充实拍图（各平台规则不同，须查当期政策） |
| 从长视频抽帧做商品短片 | 用 AI 生成「产品在使用中」的演示视频（误导性） |

> **原则：AI 可以做「场景与装饰」，不能做「产品本身」。**
> 客户收到的货必须和图上一样——这条没有商量余地。

### 6.2 多语种图上的文字

图上带文字是最容易出事的部分：

- **字体要能覆盖目标语言的字符集**（阿拉伯语、泰语、越南语的字重与排版完全不同）
- **RTL 语言（阿拉伯语、希伯来语）要镜像排版**
- **文字不能压住产品细节**
- **翻译要与文案里的措辞一致**（同一术语在图和文案里不能两种译法，见 16 主线）

**图上文字建议走「设计模板 + 程序填字」的路线，而不是让 AI 直接出图带字。**
程序填字能保证字体、字号、位置、RTL 处理都一致；AI 出图带字则每次都不一样。

## 7. 发布前的检查：一张可执行的清单

```
□ 事实回指：所有数字/材质/认证词都能在结构化数据中找到同源项
□ 认证白名单：所有认证词都在白名单内，且带证据编号
□ 禁用词：产品特定禁用词表 + 目标市场禁用表述，两张表都过
□ 长度：标题/五点/描述各字段均在平台上限内
□ 关键词：核心词在标题中，长尾词在五点/描述中，无堆砌
□ 多语种：术语与源语言版本一致（对照术语表，不是重新翻译）
□ 本地化：对照该市场该品类的本地化检查表逐条过
□ 包装清单：写明「包含什么 / 不包含什么」
□ 限制条件：写明不可用场景
□ 图片：产品本体与实物一致，无 AI 生成的假演示
□ 多语种图片：字体覆盖、RTL、位置不压产品
□ 平台专项：品类特有的资质/认证/警示要求
```

**前六条可以自动化（程序 + 规则），后六条必须人看。**
这张表是「生成 → 发布」之间的**闸门**，不是「建议」。

## 8. 本章工程结论

1. **商品内容分四类（翻译 / 改写 / 生成 / 优化），失败模式不同，可用性依次下降。**
2. **模型可以写「怎么描述」，不能写「是什么」。** 参数、材质、认证一律来自结构化数据源，并做**事实回指校验**（输出 token 白名单法）。
3. **认证词是法律风险最高的一类词**（「FDA Registered」≠「FDA Approved」）。用**白名单 + 证据编号 + 人工签一次**，不要逐条审。
4. **五点描述有角色分工**，第 5 点必须是「限制与注意事项」——写清楚能降退货。
5. **长度限制与禁用词要硬编码在提示词里**，不要写「请简洁一点」。
6. **多语种分三层**：翻译可自动、跨文化改写要人定、**本地化合规必须查表**。
7. **关键词是数据问题**：来自平台联想、竞品反查与官方工具；AI 只负责把已确定的词自然铺进文案。
8. **AI 可以做场景与装饰，不能做产品本体**——图必须和货一样。
9. **图上文字走「模板 + 程序填字」**，不走 AI 出图带字。
10. **发布前 12 条检查：前 6 条自动化，后 6 条人工。** 这是一道闸，不是建议。
