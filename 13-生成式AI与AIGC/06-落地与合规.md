# 落地与合规

> **核心问题**：生成的图能不能商用？要不要加水印？一次「可用图」实际成本是多少？

---

## 0. 三个必须先问的问题

**在写第一行生成代码之前，先把这三个问题问清楚：**

```
① 底模的许可证允许商用吗？
② 训练素材（你的图、LoRA 的训练图）有商用授权吗？
③ 生成的内容会被用于什么场景（广告？商品？内容平台？教育？）
```

> **这三个问题的答案组合起来才决定「能不能商用」。**
> **只看底模许可是不够的**——这是最常见的误判。

---

## 1. 底模许可速查

> **⚠️ 许可条款会随版本更新**，下表是**常见开源模型的许可类型**，
> **具体条款必须回模型仓库的 LICENSE 文件确认**。

| 类型 | 代表 | 商用 | 关键限制 |
|---|---|---|---|
| **Open RAIL-M** | SD 1.x | ✅ | 有「使用限制」条款（不得用于违法、侵权等） |
| **Open RAIL++-M** | SD 2.x / 2.1 / SDXL | ✅ | 比 RAIL-M 更严格（增加了不得用于生成非法内容等） |
| **社区许可（有营收门槛）** | **SD 3.x** | ⚠️ 有条件 | **年收入超过门槛需另购商业许可** |
| **非商业许可** | **FLUX.1-dev** 等 | ❌ | 明确不可商用；另有 Apache-2.0 的 schnell 版本 |
| **Apache-2.0 / MIT** | 部分少步模型 | ✅ | 宽松 |
| **订阅 ≠ 商用权** | Midjourney 等 | ⚠️ | **订阅给的是使用权，不是商用授权**；营收规模不同档位不同 |

### 1.1 「可商用」不等于「无限制」

**Open RAIL 类的许可通常附带「使用限制」**，大意是：

- 不得用于生成违法、侵权、仇恨、暴力等内容
- 不得用于侵犯他人权利（商标、肖像、版权）
- 不得用于某些高风险场景（如某些医疗、法律用途）

> **这些限制在商业场景里是实质性的**——
> 「不得用于生成侵犯他人权利的内容」意味着**你要为输出负责**，
> 不能说「是模型生成的」。

### 1.2 LoRA 的许可是**叠加**的

```
LoRA 可否商用 = 底模许可 ∩ 训练素材版权 ∩ 你的使用场景
```

| 环节 | 风险 |
|---|---|
| **底模** | 看底模 LICENSE |
| **训练素材** | **用别人的图训练商用 LoRA = 侵权的常见来源** |
| **分发** | LoRA 权重本身的分发是否受限（有些底模的衍生品有额外条款） |

> **实务建议**：
> 商用 LoRA 的训练素材必须**自拍、已授权、或明确可商用**。
> **从网上扒图训练再商用**是最典型的法律风险来源。

## 2. 训练数据与版权

### 2.1 生成模型训练数据的现状

**主流开源生成模型的训练数据（LAION、CC、互联网图片）大面积未经逐张授权。**

| 立场 | 内容 |
|---|---|
| **权利人** | 未经授权的抓取与训练构成侵权 |
| **模型发布方** | 依据 RAIL 类的「使用限制」承担责任（**模型提供者的责任是「你不能用来侵权」**） |
| **使用者** | **通常被认为风险较低**（你不知情、且模型不复制原图），但**不是零风险** |

### 2.2 生成物的版权性

| 情形 | 大多数司法辖区的立场 |
|---|---|
| **纯 AI 生成，无人类创作成分** | **不受版权保护**（不能独占使用，别人可以用同样描述生成类似结果） |
| **人类有实质性创作贡献** | 可能受保护（但「实质性贡献」需要举证） |
| **AI 生成 + 人工精修** | 视修改幅度，可能构成演绎作品 |

> **对业务的直接影响**：
> - **你的「独家」产品图可能不独占**——竞品可以用同样的 prompt 生成类似图
> - **不要把 AI 生成图当作「版权资产」来经营**
> - **商标、肖像、著作权等第三方权利依然适用**——模型不生成 ≠ 不侵权
>   （尤其：**生成「像某个品牌/某个人」的图仍然可能侵权**）

> **⚠️ 本节是工程视角的梳理，不构成法律意见。具体场景请咨询法务。**

## 3. 内容安全

### 3.1 三道过滤

| 层 | 拦什么 | 手段 |
|---|---|---|
| **输入侧** | 违规的提示词、违规的参考图 | 关键词/分类器；对**上传的参考图**也要审（它可能含违规内容） |
| **生成侧** | 模型本身的 NSFW 能力 | 选**已做安全微调**的底模；社区有 NSFW 版与安全版 |
| **输出侧** | 生成结果里的违规内容 | **图像分类器逐张审**（NSFW / 暴力 / 敏感） |

> **输出侧审查是必须的**——
> 输入提示词是干净的，**不代表输出是干净的**
> （例如「解剖学教学图」这样的提示词可能生成违规内容）。

### 3.2 商用场景的额外要求

| 要求 | 说明 |
|---|---|
| **审核留痕** | 记录「谁在何时请求生成什么、结果是什么、是否通过」 |
| **人工复审** | 高风险场景（医疗、金融、未成年人相关）必须有 |
| **黑名单/白名单** | 拦截特定主体、允许特定用途 |
| **用户协议** | 明确用户不得生成什么；违反怎么处理 |

## 4. AI 生成内容标识

> **⚠️ 以下为工程视角梳理，条文与适用范围以官方最新发布为准，上线前必须由法务确认。**

**核心要求分两类**：

| 类型 | 形式 | 谁负责 |
|---|---|---|
| **显式标识** | **用户可见**（图片角标、界面提示、发布时声明） | 服务提供者 + 用户 |
| **隐式标识** | **文件元数据**里嵌入（不改变视觉） | 服务提供者 |

### 4.1 对工程的影响

| 影响 | 具体做什么 |
|---|---|
| **输出环节加标识** | 生成后写入元数据；必要时叠可见水印 |
| **元数据不能被抹掉** | **注意**：很多平台的图片处理会**剥掉 EXIF/元数据** → 隐式标识会丢失 |
| **发布流程加声明** | 产品侧提供「此内容由 AI 生成」的勾选项与提示 |
| **保留记录** | 标识信息要与生成记录关联留存 |

> **「元数据会被平台剥掉」是隐式标识最大的工程风险**——
> 这正是**不可见水印**（下一节）存在的原因。

---

## 5. 水印与溯源

### 5.1 两种水印

| 类型 | 做法 | 优点 | 局限 |
|---|---|---|---|
| **不可见水印** | 在频域/潜空间嵌入**人眼看不见但能检测**的信号 | **抗裁剪、抗压缩、抗截图** | 可能被强攻击去除；对小尺寸图效果下降 |
| **可见水印** | 角标、文字 | 直观、可感知 | **会被裁掉**；影响观感 |
| **元数据标识** | 文件元数据 | 标准、无视觉影响 | **平台会剥掉** |
| **内容凭证（C2PA）** | 签名式的来源链（谁、用什么工具、何时编辑） | **可验证、可追溯** | 需要生态支持 |

### 5.2 实际建议：组合使用

```
① 隐式标识写进元数据（标准做法，被平台剥掉也不影响其他层）
② 叠加不可见水印（抗平台处理）
③ 产品界面可见提示（面向终端用户）
④ 生成记录留档（谁、何时、什么 prompt、什么模型）
⑤ 对外发布时提供 C2PA 凭证（面向有合规要求的场景）
```

> **不可见水印的工程要点**：
> - **嵌入强度要匹配输出分辨率**——图越大水印越明显，也越容易被攻击
> - **检测阈值要按「假阳率」定**，不是按「准确率」
> - **要测过「抗攻击」**：JPEG 压缩、缩放、裁剪、截图重拍、滤镜

## 6. 成本模型

### 6.1 真正的成本单位是「一次可用图」

```
一次可用图成本 = 单次生成耗时 × GPU 单价 ÷ 可用率
```

**「可用率」是整个模型的核心变量**：

| 场景 | 可用率（量级） | 说明 |
|---|---|---|
| **精确控制（ControlNet + LoRA + 人工修）** | **5%~20%** | 废图多，但可用图质量高 |
| **提示词生成 + 人工挑选** | **1%~5%** | 抽卡式 |
| **批量模板化（同一模板换内容）** | **30%~70%** | **最省** |
| **端到端自动化（无人干预）** | **< 1%** | **几乎不可行** |

**实例**：

```
单张生成：2 秒 × $0.5/小时 ÷ 3600 = $0.00028
可用率 5% → 一次可用图 = $0.0056
可用率 1% → 一次可用图 = $0.028
```

> **可用率从 5% 降到 1%，成本涨 5 倍。**
> **这比任何模型优化都重要**——
> **提高可用率（更好的控制、更好的 prompt、更好的工作流）是最划算的优化。**

### 6.2 成本优化顺序

| 顺序 | 手段 | 效果 |
|---|---|---|
| 1 | **提高可用率**（控制 + 工作流 + prompt 模板） | **5~10×** ⭐ |
| 2 | **少步模型**（Turbo / LCM） | 2~4× |
| 3 | **批量推理**（提高 GPU 利用率） | 2~5× |
| 4 | **fp16 / 推理引擎优化** | 1.5~2.5× |
| 5 | **降分辨率 + 超分** | 按需 |
| 6 | **量化** | 1.3~2× |

> **第 1 条是最反直觉但最正确的**：
> **与其花力气把图生成快 2 倍，不如把废图率从 5% 降到 2%。**

### 6.3 一个务实的流程设计

```
① prompt 模板化 + 参数固定        → 保证基线可复现
② 一次生成 N 张（批量）          → 提高 GPU 利用率
③ 自动过滤（质量/合规分类器）     → 淘汰明显废图
④ 人工挑选                       → 剩余的小量
⑤ 局部修复（inpaint）             → 救回大部分小瑕疵
```

> **第 ⑤ 步的价值**：**inpaint 修一张图比重新生成一张便宜得多**，
> 且能保住已经正确的部分。**这让可用率从 5% 提到 15% 成为可能。**

## 7. 部署形态

| 形态 | 适合 | 成本 | 注意事项 |
|---|---|---|---|
| **云 API** | 快速验证、量小 | 低（按量） | **数据出境**；条款变更；不可控 |
| **自托管 GPU** | **量大、要定制、要保密** | 高（一次性 + 运维） | 显存/驱动/模型许可 |
| **端侧/工作站** | 内部使用、涉密 | 中 | 8 GB 显存跑 SD1.5；SDXL 需 12~16 GB |

### 7.1 显存参考

| 模型 | 分辨率 | 显存 |
|---|---|---|
| SD 1.5 | 512×512 | **4~6 GB** |
| SD 1.5 + ControlNet | 512×512 | 6~8 GB |
| SDXL | 1024×1024 | **10~12 GB** |
| SDXL + ControlNet | 1024×1024 | 12~16 GB |
| Flux.1-dev | 1024×1024 | **16~24 GB** |

> **⚠️ 量级参考**，与 batch、精度、VAE、注意力实现强相关。**引用前请在自己机器上实测。**

### 7.2 自托管的隐性成本

**别只算显卡**：

| 项 | 常被忽略 |
|---|---|
| **模型许可成本** | 有些模型的商业授权要单独付费 |
| **审核的人力** | 内容审核是持续成本 |
| **存储与带宽** | 出图要存、要用、要传 |
| **版本管理** | 模型/LoRA/ControlNet 的组合管理 |
| **GPU 折旧** | 一般 3 年 |

> **一个经验判断**：
> **如果 GPU 的有效利用率低于 30%（大部分时间在等审核/等人工），
> 那「用云 API」通常更划算。**

## 8. 工程化的必备能力

| 能力 | 说明 |
|---|---|
| **生成记录（Provenance）** | **每次生成记录：prompt / 负向 prompt / seed / 模型 / LoRA / ControlNet / 强度 / 步数 / 时间 / 用户** |
| **可复现** | 同 seed + 同参数 → 同结果 |
| **批处理与队列** | 提高 GPU 利用率；支持失败重试 |
| **参数模板** | 固化「好用的配置」，避免每次重调 |
| **自动质检** | 质量分类器 + 合规分类器 + 重复度检测 |
| **人工审核工作台** | 批量看、批量通过/拒绝、批量重生成 |
| **版本管理** | 模型/LoRA/ControlNet 的版本与组合可追溯 |

> **「生成记录」是最容易被省、也最不该省的一项**——
> 没有它，出现「这张图有问题」时**无法定位是哪次生成、什么参数**，
> 也就无法复现和回溯。

### 8.1 生成记录的最小字段

```json
{
  "gen_id": "<唯一 ID>",
  "ts": "<时间戳>",
  "user_id": "<用户>",
  "task_id": "<业务任务>",
  "model": {"base": "sd_xl_base", "lora": ["style_v3"], "controlnet": ["canny@0.7"]},
  "params": {"prompt": "...", "negative": "...", "seed": 12345,
             "steps": 30, "cfg": 6.0, "size": [1024, 1024], "sampler": "dpm++"},
  "output": {"file": "<路径>", "sha256": "..."},
  "review": {"auto_score": 0.82, "human": "approved", "reviewer": "<用户>"},
  "provenance": {"watermark": "invisible", "c2pa": "<凭证>"}
}
```

## 9. 常见错误

| 错误 | 表现 | 纠正 |
|---|---|---|
| **只看底模许可** | 忽略素材版权 | 三个问题一起答 |
| **用「订阅」当商用授权** | 营收规模超门槛 | 看清条款的营收门槛 |
| **从网上扒图训 LoRA 再商用** | 侵权风险 | 素材必须自拍/授权/可商用 |
| **没有输出侧审查** | 生成违规内容流出 | 逐张审 |
| **只有元数据标识** | 平台剥掉后无法溯源 | 叠不可见水印 |
| **只算单张生成成本** | 忽略废图率 | 按「一次可用图」算 |
| **没有生成记录** | 无法复现、无法回溯 | 记录 seed + 全部参数 + 哈希 |
| **自动化程度过高** | 无人复核直接对外 | 高风险场景必须有人工闸 |
| **在 CPU 上推理** | 慢到不可用 | 显存够就用 GPU |

## 10. 工程结论

1. **「能不能商用」= 底模许可 ∩ 素材版权 ∩ 使用场景**，只看一项必错。
2. **订阅 ≠ 商用授权**；很多模型的商业授权有**营收门槛**。
3. **「可商用」不等于「无限制」**——RAIL 类许可附带了「你不能用来侵权」的使用限制，
   **输出责任在使用者**。
4. **纯 AI 生成物通常不受版权保护** → 你的「独家」图可能不独占；
   但**第三方权利（商标/肖像/著作权）依然适用**。
5. **输出侧审查是必须的**——干净提示词不等于干净输出。
6. **隐式标识会被平台剥掉** → 要叠**不可见水印**；并测过抗压缩/裁剪/截图。
7. **成本的正确单位是「一次可用图」**——
   **可用率从 5% 降到 1% 成本涨 5 倍**，这比任何模型优化都重要。
8. **最划算的优化是提高可用率**（控制 + 工作流 + 模板），不是把生成加快。
9. **inpaint 修一张图比重新生成便宜得多**，能显著提高可用率。
10. **生成记录（prompt/seed/全部参数/输出哈希/审核结果）是不能省的**——
   它是复现、回溯与合规的共同基础。
