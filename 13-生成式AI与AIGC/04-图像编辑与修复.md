# 图像编辑与修复

> **核心问题**：怎么改一张已有的图？「把狗换成猫」和「把画质提高一倍」是同一类问题吗？

---

## 0. 编辑的四个基本操作

| 操作 | 输入 | 控制粒度 | 难点 |
|---|---|---|---|
| **局部重绘（Inpainting）** | 原图 + 遮罩 | **像素级**（哪里改哪里） | 边界融合、与原图风格一致 |
| **扩图（Outpainting）** | 原图 | 区域级 | 延展的合理性 |
| **整体变换（img2img）** | 原图 + 提示词 | 全图 | 变化幅度控制 |
| **指令式编辑** | 原图 + **自然语言指令** | 语义级 | **指令理解 + 定位** |

> **前三个是「结构化的编辑」，第四个是「意图驱动的编辑」**——
> 前三个稳定可控，第四个强大但不可靠。**产品里通常以结构化为主。**

---

## 1. Inpainting：局部重绘

### 1.1 两个关键参数

```python
out = pipe(
    prompt="a cat sitting on a wooden chair",
    image=original,
    mask_image=mask,               # 白色 = 要重绘
    strength=0.75,                 # ★ 重绘强度
    mask_blur=8,                   # ★ 遮罩羽化
    num_inference_steps=30,
)
```

| 参数 | 作用 | 建议 |
|---|---|---|
| **`strength`** | 重绘强度 | 0.6~0.85 |
| **`mask_blur`** | 遮罩边缘羽化 | **6~12**（太小边缘会「拼贴感」） |
| `mask_padding` | 遮罩外扩 | 20~32（给模型留上下文） |
| `inpaint_full_res` | 全分辨率处理 | 分辨率高时开（否则接缝明显） |
| `inpaint_area` | `mask` / `crop` | 大面积改动用 `crop`（更快、边缘更好） |

### 1.2 强度的语义

| strength | 效果 | 适用 |
|---|---|---|
| **0.2~0.4** | 几乎原图，只微调 | 修瑕疵、换表情细节 |
| **0.5~0.7** | 局部重绘，与原图协调 | **换物体、调细节** |
| **0.8~0.95** | 大幅重绘 | 完全换掉 |
| **1.0** | 只用 prompt，**忽略原图内容** | 在遮罩区域从零生成 |

### 1.3 两个关键的工程技巧

**① 两阶段编辑**

```
阶段 1（大遮罩 + strength 0.9）→ 主体位置大致对
阶段 2（小遮罩 + strength 0.4）→ 细化边缘、光影、材质
```

**② Inpaint 优先于「生成 + 合成」**

```
❌ 生成一张新图 → 抠出来贴上去   → 接缝、透视、光影全不一致
✅ 直接 inpaint                    → 模型自己处理融合
```

> **融合是 inpaint 相对「合成」的核心优势**，也是它不可替代的地方。

### 1.4 局部编辑的常见失败

| 失败 | 表现 | 处理 |
|---|---|---|
| **接缝明显** | 新旧区域边界生硬 | 提高 `mask_blur`、降低 strength、两阶段 |
| **风格不统一** | 新区域像「贴上去的」 | prompt 里描述**原图的风格与光线**；用参考图（IP-Adapter） |
| **比例错误** | 物体大小不合理 | 在 prompt 里明确尺寸与位置；用 ControlNet 约束 |
| **手/文字崩** | 细节结构错乱 | 局部重绘 + 人工修；或用更小的 mask 只修手部 |

## 2. Outpainting：扩图

### 2.1 两条路线

| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 原生外扩** | 用原图作 inpaint，遮罩在外侧 | **无缝**（模型知道原图内容） | 受原图分辨率限制；边缘可能重复 |
| **B 生成大图再裁** | 直接生成大尺寸，裁出需要的部分 | 构图完整、灵活 | **接缝可能不匹配** |

### 2.2 原生外扩的做法

```
① 把画布扩大到目标尺寸，原图居中放置
② 新增区域设为遮罩（待重绘）
③ 原图区域设为「已知条件」（mask=0）
④ 用原图 + prompt 做 inpaint，prompt 描述整体场景
```

**要点**：
- **prompt 要描述「整个画面」，不只是新增部分**——否则新增区域与原图内容无关
- 分多次外扩（每次扩一圈）比一次扩很多更稳
- **SD 原生分辨率之外的区域质量会下降**（SD1.5 在 512 外）

## 3. img2img：整体变换

```python
out = pipe(prompt="oil painting style", image=original, strength=0.6)
```

| strength | 效果 |
|---|---|
| **0.15~0.3** | 轻微调整（加一点光照、改配色） |
| **0.4~0.6** | **风格迁移**（保留构图，重绘风格） |
| **0.65~0.85** | 大改（保留大致构图，内容大变） |
| **0.9~1.0** | 几乎重新生成 |

> **关键**：**strength 是「保留多少原图结构」的旋钮，不是「效果强度」的旋钮。**

### 3.1 SDEdit：更精细的控制

**SDEdit 是 img2img 的一个变体**，做法不同：
1. 给原图加噪到某个中间步（t = τ·T）
2. 然后**完全按标准扩散流程**去噪

**与 img2img 的差别**：

| | img2img | SDEdit |
|---|---|---|
| 起点 | 直接从带噪潜变量开始 | **先加噪再走标准流程** |
| 结果 | 更「贴原图」 | 更「像原图生成的」 |
| 采样器要求 | 任意 | **需要支持 SDEdit 的调度器**（UniPC 等） |

> **实践上两者差别不大**，但 SDEdit 在「保持原图统计特性」上更干净。

## 4. 指令式编辑

**InstructPix2Pix（2023）**：直接用自然语言指令编辑。

```
"make the dog wear a hat"
"add snow to the scene"
"turn the leaves green"
```

### 4.1 它是怎么做到的

**训练时构造「原图 → 指令 → 编辑后图」的三元组**，
让模型学会「指令 + 原图 → 改哪」。

### 4.2 能力与边界

| 能做 | 做不好 |
|---|---|
| 改颜色、加物体（简单）、改风格 | **空间定位**（「把左边的换掉」经常搞错） |
| 改属性（表情、季节、材质） | 大幅结构改动 |
| 简单的增减 | 精确的数量控制 |
| | **文字与手部**（仍然崩） |

### 4.3 三种编辑方式怎么选

| 方式 | 精确度 | 灵活度 | 稳定性 | 推荐场景 |
|---|---|---|---|---|
| **Inpainting + 遮罩** | **最高** | 低 | **最高** | 已知要改哪，改动明确 |
| **img2img + ControlNet** | 高 | 中 | 高 | 有结构图约束 |
| **指令式编辑** | **低** | **最高** | 低 | 探索性修改、批量尝试 |

> **产品建议**：
> **能用遮罩就不要用指令**。
> 指令式编辑作为「快速试多个方案」的辅助工具，而不是主流程。

## 5. 超分与细节增强

### 5.1 三条路线

| 路线 | 做法 | 适用 |
|---|---|---|
| **A 通用超分模型** | Real-ESRGAN / SwinIR / SUPIR | **已有高质量原图**要放大 |
| **B Latent Upscaler** | SD 生态的专用潜空间超分 | **SD 生成图**要放大（能补细节） |
| **C hires fix 工作流** | 低分辨率生成 → 二次 img2img 精修 | **从零生成高质量图** |

### 5.2 hires fix 工作流（SD 生态的标准做法）

```
第 1 步：512×512 生成（SD1.5 原生分辨率）
第 2 步：放大到 1024×1024（普通插值）
第 3 步：以放大图做 img2img，strength=0.3~0.5 再跑一遍
         → 模型在放大图的基础上「补细节」
```

| 参数 | 建议 |
|---|---|
| 第 1 步分辨率 | **等于模型的原生分辨率**（SD1.5=512, SDXL=1024） |
| 第 3 步 strength | 0.3~0.5（太低没细节，太高会跑偏） |
| 第 3 步 CFG | 降一点（5~6） |
| 放大倍数 | 1.5~2×（**一次放大 4× 容易出伪影**） |

> **「SD1.5 出 1024 很糊」的正解就是这个工作流**，
> 而不是把 SD1.5 直接拉到 1024 出图。

### 5.3 SUPIR：新一代的高质量修复

**SUPIR = 扩散超分 + 大型语言模型引导**（用文本 prompt 指导细节重建）。

| 特性 | 说明 |
|---|---|
| **prompt 引导** | 可以用「清晰的毛发细节、自然皮肤纹理」来指导 |
| **面部修复** | 集成人脸修复模型 |
| **成本** | **比普通超分慢很多**（多次扩散采样） |

## 6. 修复类任务

| 任务 | 常用方法 | 注意事项 |
|---|---|---|
| **去噪 / 去划痕** | 专用修复模型 / inpaint | 用原图做 img2img + 低 strength（0.2~0.4） |
| **去摩尔纹 / 去压缩噪点** | 专用去噪模型 | 先试传统算法（**更快、零成本**） |
| **人脸修复** | GFPGAN / CodeFormer | CodeFormer 保身份更好 |
| **老照片修复** | 上色模型 + 人脸修复 + 超分 | **上色是主观的**，需人工确认 |
| **去水印** | inpaint + 内容填充 | **有法律风险**，见 §6 |
| **暗光 / 运动模糊** | 专用增强模型 | 先确认不是采集问题 |

> **一个务实的原则**：
> **能用传统算法（OpenCV、频域滤波）解决的，不要用扩散模型**——
> 传统算法是毫秒级、零成本、结果可预测；
> 扩散模型是秒级、有随机性、可能引入新伪影。

### 6.1 关于去水印的边界

| 情形 | 态度 |
|---|---|
| **去除自己图片上的水印** | 一般可以 |
| **去除他人作品的版权水印** | **不应当做**（可能违法且违反平台规则） |
| **去除平台自动添加的角标** | 取决于平台条款 |

> **本章只讲技术原理，不提供去除他人版权标识的操作指引。**
> 相关边界见 [`06`](./06-落地与合规.md) §4。

## 7. 视频编辑与插帧

| 任务 | 方法 | 难度 |
|---|---|---|
| **视频超分** | 逐帧超分 + 时序一致性处理 | 中（会有闪烁） |
| **视频插帧** | RIFE / FILM 等专用模型 | 低（专用模型，非扩散） |
| **视频 inpainting** | 视频扩散模型 + 时序注意力 | **高** |
| **文本驱动的视频编辑** | Video-P2P / TokenFlow 等 | 高 |
| **视频风格化** | 视频扩散 + ControlNet（逐帧 + 时序一致） | 中高 |

> **视频的核心难点是「时序一致性」**：
> 逐帧独立处理会产生闪烁（flicker）。
> 解法要么用**时序感知的模型**，要么在后期做**时序平滑**。

> **工程结论**：**视频编辑优先用专用模型（插帧、超分），少用扩散**——
> 扩散视频模型对显存要求高（通常 ≥ 24 GB），且调参空间大。

## 8. 工作流设计原则

**一个可靠的编辑工作流应该分阶段，每阶段可回退：**

```
① 原图分析      → 判断质量、识别问题区域
② 结构调整      → Inpainting / 扩图（几何层面）
③ 细节增强      → 超分 / 修复（像素层面）
④ 风格统一      → img2img / 风格 LoRA
⑤ 人工确认      → ★ 每一步之间
```

**三条原则**：

| # | 原则 | 原因 |
|---|---|---|
| **1** | **结构调整在前，细节增强在后** | 结构调整会改变像素，先超分再改结构等于白做 |
| **2** | **每一步都保存中间结果** | 扩散是随机的，同一参数重跑结果不同；**要能回到上一步换种子重试** |
| **3** | **最后一步留人工确认** | 生成内容必须有人负责 |

> **第 2 条是工程上最容易被忽略的**：
> 批量生成流程里，**必须记录每一步的 seed + 参数**，
> 否则发现某张不好时无法复现也回不去。

## 9. 工程结论

1. **编辑分四类**：局部重绘（Inpainting）/ 扩图 / 整体变换（img2img）/ 指令式编辑。
   **前三个稳定可控，第四个强大但不可靠。**
2. **`mask_blur` 是 inpaint 质量的关键**（6~12），太小会有拼贴感。
3. **`strength` 是「保留多少原图结构」的旋钮**，不是效果强度。
4. **inpaint 优于「生成 + 合成」**——融合是它的不可替代之处。
5. **两阶段编辑**（粗修 + 细化）比一步到位质量好。
6. **原生外扩优于「生成大图再裁」**——前者无缝。
7. **指令式编辑适合探索、不适合主流程**；能用遮罩就不要用指令。
8. **SD1.5 出高分辨率要走 hires fix 工作流**（512 生成 → 放大 → 低 strength 二次 img2img）。
9. **能用传统算法解决的不要用扩散模型**——毫秒级、零成本、结果可预测。
10. **批处理必须记录每一步的 seed + 参数**，否则无法复现与回退。
11. **结构调整在前、细节增强在后**；每阶段之间留人工确认点。
