# 可控生成

> **核心问题**：怎么让出图「按我说的来」？边缘、深度、姿态、风格、角色——各用什么手段？

---

## 0. 控制手段总览

**生成模型的天性是「随机」**。要可控，就得**外部注入条件**。

| 手段 | 控制什么 | 需要的额外资产 | 训练成本 | 保真度 |
|---|---|---|---|---|
| **Prompt** | 语义（有什么、什么风格） | 无 | 无 | **最低** |
| **ControlNet** | **几何结构**（边缘/深度/姿态/分割） | 结构图 | **零**（用现成权重） | **高** |
| **T2I-Adapter** | 结构（比 ControlNet 轻） | 结构图 | 零 | 中 |
| **IP-Adapter** | **视觉风格 / 角色特征** | 参考图 | 零（现成权重） | 中 |
| **LoRA** | **特定概念**（角色/风格/产品） | 训练图 | **有** | **最高** |
| **Inpainting** | 局部区域 | 遮罩 | 零 | 高 |
| **区域提示** | prompt 的作用范围 | 遮罩 | 零 | 中 |
| **重绘 / img2img** | 整体风格迁移 | 原图 | 零 | 中高 |

> **决策的第一原则**：
> **控制「结构」用 ControlNet，控制「风格与概念」用 LoRA/IP-Adapter，控制「局部」用遮罩。**
> **三者常常要叠加。**

---

## 1. ControlNet：结构控制的事实标准

### 1.1 原理

**ControlNet 的核心设计是「冻结原模型 + 训练一个平行的条件分支」：**

```
        ┌─────────────┐
条件图 ──▶ 条件 Encoder │──┐
        └─────────────┘   │
                          ▼
   ┌─────────┐      ┌───────────────┐
   │ 原 UNet │─────▶│ Zero Conv 注入 │
   │ (冻结)  │      │  (可训练)      │
   └─────────┘      └───────────────┘
                          │
                          ▼
                       噪声预测
```

**两个关键设计**：

| 设计 | 说明 |
|---|---|
| **Zero Convolutions** | 注入层的卷积权重**初始化为 0** → 训练开始时**完全不影响原模型**，训练越久影响越大 |
| **只训副本** | 原 UNet 冻结 → **不破坏原模型能力**，且**显存友好**（只需存一份冻结权重的激活） |

> **Zero Conv 的意义**：它让 ControlNet 成为「**可插拔**」的——
> 拔掉它，模型行为完全不变。这对「一个底模 + 多个 ControlNet」的产品形态至关重要。

### 1.2 常见的 ControlNet 类型

| 类型 | 输入 | 用途 | 质量 |
|---|---|---|---|
| **Canny** | 边缘图 | 保持构图轮廓 | **最高**（信息最明确） |
| **Depth** | 深度图 | 保持空间结构 | 高 |
| **Pose / OpenPose** | 骨架图 | **人物姿态** | 高 |
| **Normal** | 法线图 | 3D 形状 | 高 |
| **Lineart** | 线稿 | 动漫线稿上色 | 高 |
| **Scribble** | 涂鸦 | 粗略构图 | 中高 |
| **Segmentation** | 语义分割图 | **精确控制区域内容** | **最高** |
| **Midas** | 软深度 | 深度估计不准时的替代 | 中 |
| **Reference** | 参考图 | 保持主体一致 | 中 |

> **选型经验**：
> - **要构图** → Canny 或 Lineart（信息密度高）
> - **要姿态** → OpenPose
> - **要「区域里放什么」** → **Segmentation**（最精确）
> - **只有一张原图，没有结构图** → 先跑 depth/pose 预处理器生成

### 1.3 ControlNet 强度

```python
# 伪代码
out = pipe(
    prompt="a chinese restaurant interior, warm lighting",
    image=control_image,
    controlnet=controlnet,
    controlnet_conditioning_scale=0.8,   # 强度
    num_inference_steps=30,
    guidance_scale=7.0,
)
```

| 强度 | 效果 |
|---|---|
| **0.0~0.3** | 约束太弱，结构被忽略 |
| **0.5~0.8** | **常用区间**，结构与语义平衡 |
| **1.0** | 结构很强，但细节僵化、像「填色」 |
| **>1.2** | **崩坏**（结构过约束，语义被扭曲） |

> **配合技巧**：**强度高时把 CFG 降下来**（7.5 → 5~6），
> 否则「结构约束 + 语义放大」双重施压，容易产生诡异结果。

### 1.4 多 ControlNet 叠加

**可以同时挂多个 ControlNet**（不同类型），但要注意：

| 问题 | 表现 | 处理 |
|---|---|---|
| **权重竞争** | 两个控制互相抵消 | 各降低强度（如 0.6 + 0.4） |
| **语义冲突** | 深度图和姿态图矛盾 | 检查两个条件图本身是否自洽 |
| **速度** | 每个 ControlNet 一次额外 UNet 前向 | **N 个 ControlNet ≈ 慢 (N+1) 倍** |

> **实用建议**：**先用一个 ControlNet 跑通**，再叠加第二个。
> 同时挂三个以上通常收益递减、调试困难。

## 2. T2I-Adapter：更轻的替代

**区别**：

| | ControlNet | T2I-Adapter |
|---|---|---|
| 结构 | 复制 UNet encoder 分支 | **小 adapter**，注入到 UNet 特征 |
| 参数量 | 大（约 1/3 底模） | **小（几千万）** |
| 训练成本 | 高 | 低 |
| 效果 | **更强** | 稍弱 |
| 组合能力 | 强 | 弱 |

> **T2I-Adapter 的价值在「多条件组合」**——
> 它轻，可以同时挂多个而不至于太慢。

---

## 3. IP-Adapter：用参考图控制风格

**原理**：把参考图用 CLIP 图像编码器编码，**通过 cross-attention 注入**到 UNet。

| 变体 | 作用 |
|---|---|
| **IP-Adapter** | 通用参考图（风格 + 内容） |
| **IP-Adapter Plus** | **用更细的特征**（不是只取一个池化向量），细节保留更好 |
| **IP-Adapter Face** | 人脸身份 |
| **IP-Adapter Depth / Tile** | 深度/拼贴图做结构参考 |

**特点**：

| 优点 | 局限 |
|---|---|
| **零训练**（现成权重） | 对**具体物体**的还原度不如专门训练的 LoRA |
| 可以换模型用 | 参考图的「主体特征」会与 prompt 打架 |
| 支持多张参考图 | 相似度控制粒度较粗 |

> **IP-Adapter 与 LoRA 的选择**：

| 需求 | 选择 |
|---|---|
| 风格参考（画风、氛围） | **IP-Adapter** |
| 特定角色/产品，要**高还原度** | **LoRA**（要训练） |
| 快速试风格 | IP-Adapter |

## 4. LoRA：把一个具体概念训进模型

### 4.1 三种典型用途

| 类型 | 训练素材 | 目标 |
|---|---|---|
| **角色 LoRA** | 10~30 张同一个人的多角度照片 | 还原这个人的长相 |
| **风格 LoRA** | 10~50 张同一风格作品 | 迁移画风（线稿、水彩、某插画师） |
| **产品/物体 LoRA** | 20~50 张同一产品 | 让模型认识自家产品 |

### 4.2 角色 LoRA 的关键：素材要覆盖变化

**只给同一角度的 20 张图 → 模型会学到「这个角度」而不是「这个人」。**

**好的素材集**（20~30 张）：

| 维度 | 要求 |
|---|---|
| **角度** | 正面 / 侧面 / 3/4 侧 / 背面 |
| **表情** | 平静 / 微笑 / 大笑 / 严肃 |
| **光线** | 室内 / 室外 / 逆光（至少两类） |
| **景别** | 半身 / 全身 |
| **光线** | 正面 / 侧面 / 逆光（至少两类） |
| **背景** | 简单背景为主（模型学的是人，不是背景） |

**反面教材**：全部是同一张脸的相似照片 → LoRA 出来「像照片不像人」。

### 4.3 训练参数

```yaml
# 典型配置（diffusers / kohya 风格）
network_dim: 32~64        # 角色用 32~64，风格可用 16~32
network_alpha: 16~32
train_batch_size: 1
gradient_accumulation_steps: 4
learning_rate: 1e-4
lr_scheduler: cosine
max_train_steps: 1500~3000
resolution: 512
mixed_precision: bf16
```

| 参数 | 角色 LoRA | 风格 LoRA | 说明 |
|---|---|---|---|
| `network_dim` | **32~64** | 16~32 | 角色要记细节，rank 高一些 |
| 训练步数 | 1500~3000 | 800~1500 | **看 loss 曲线，不要死磕步数** |
| `caption` | **只写触发词 + 通用描述** | 写风格描述 | 角色 LoRA 用**短 caption**，避免模型学到描述词 |

> **caption 策略很关键**：
> 角色 LoRA 用「`triggersketch, a man`」这种**极短 caption**，
> 模型就会把「触发词 → 这个人」强绑定。
> caption 太丰富，模型会学到「描述词 → 图像」而不是「触发词 → 人」。

### 4.4 触发词与权重

```text
"triggersketch man, wearing a red jacket, standing in a park"
                   ↑ 触发词
```

| 技巧 | 说明 |
|---|---|
| **触发词唯一** | 用罕见的组合（如 `triggersketch`），避免与已有概念冲突 |
| **权重** | `(triggersketch:1.2)` 可加强；`<lora:...:0.8>` 调 LoRA 强度 |
| **多个 LoRA** | 可以叠加，但**互相干扰**（一个角色的 LoRA 会影响另一个） |

> **多 LoRA 叠加的现实**：技术上可行，但**结果依赖具体组合**，
> 必须每个组合都实测。**产品里不要依赖叠加**——要稳定就用单个 LoRA。

## 5. 区域提示：让不同 prompt 作用不同区域

**问题**：一张图里既要「左边的山」又要「右边的人物」，prompt 怎么写都容易串。

**解法（Regional Prompting）**：给每个 prompt 配一个**注意力遮罩**。

```
prompt = "mountain, forest, man, dog"
masks = [mountain_mask, forest_mask, man_mask, dog_mask]
```

**原理**：在 cross-attention 里**按区域限制每个 token 的注意力范围**。

| 优点 | 局限 |
|---|---|
| **精确控制布局** | 需要手绘/生成遮罩 |
| 零训练 | 遮罩边缘会有串色 |
| 可与 ControlNet 叠加 | 遮罩数量多时调试复杂 |

> **另一个更简单的替代**：**用分割图 ControlNet + 区域化描述**，
> 或者**分区域多次生成 + 合成**（Inpainting 流水线）。

---

## 6. 组合拳：常见的三种组合

### 6.1 结构 + 风格

```
ControlNet（结构） + IP-Adapter（风格） + Prompt（语义）
```

**典型场景**：照着某张构图，但要某家店的画风。

### 6.2 结构 + 概念

```
ControlNet（结构） + 角色/产品 LoRA（概念） + Prompt（场景）
```

**典型场景**：这张构图，但主角是某个具体的人/产品。

### 6.3 局部 + 全局

```
Inpainting（局部重绘） + 全局 prompt（保持一致）
```

**典型场景**：换掉图里的某个物体，其他部分不动。

> **组合的原则**：
> **每加一个条件，就降一点其他条件的强度**——
> 三个条件都开满，结果就是「谁都不满足」。

## 7. 常见问题速查

| 症状 | 原因 | 处理 |
|---|---|---|
| **ControlNet 结构被忽略** | 强度太低 | 提到 0.7~0.8 |
| **出图像「给线稿填色」** | 强度太高 / CFG 太高 | 降强度到 0.6，CFG 降到 5~6 |
| **LoRA 出的人物不像** | 素材角度单一 / rank 太低 / 训练步数不够 | 补素材、rank 提到 64、加步数 |
| **LoRA 影响其他内容** | 学到了背景/风格 | caption 更短、素材背景更干净 |
| **IP-Adapter 与 prompt 打架** | 参考图内容与 prompt 冲突 | 换参考图，或降低 IP 权重 |
| **多个 ControlNet 互相抵消** | 权重竞争 | 各降强度 |
| **角色 LoRA 换场景就崩** | 学得太深 | 降 LoRA 权重 / 减少步数 / 增大 rank 容量 |
| **区域提示边缘串色** | 遮罩边缘处理 | 遮罩羽化 |

## 8. 工程结论

1. **控制手段分工明确**：**结构用 ControlNet、风格与概念用 LoRA/IP-Adapter、局部用遮罩。**
2. **ControlNet 的 Zero Conv 让它「可插拔」**——拔掉不影响原模型，这是「一底模 + 多 ControlNet」产品形态的基础。
3. **Canny / Segmentation 是保真度最高的控制类型**，因为信息最明确。
4. **ControlNet 强度 0.5~0.8 是常用区间**；> 1.2 会崩坏。
5. **每加一个条件就降一点其他条件的强度**——三个条件都开满就是「谁都不满足」。
6. **N 个 ControlNet ≈ 慢 (N+1) 倍**，先用一个跑通再叠加。
7. **IP-Adapter 零训练、适合风格；LoRA 要训练、适合具体角色/产品的高还原度。**
8. **角色 LoRA 的素材必须覆盖角度/表情/光线变化**——
   只给同角度照片，模型学到的是「这个角度」不是「这个人」。
9. **角色 LoRA 用极短 caption**（触发词 + 通用词），让触发词与人强绑定。
10. **不要依赖多个 LoRA 叠加**——结果依赖具体组合，必须逐组合实测。
