# 采样器与加速

> **核心问题**：同样的模型，为什么有的 4 步出图、有的要 50 步？加速到底加速了什么？

---

## 0. 四条加速路线

```
① 更好的求解器      → 同样的步数，画质更好（少步不行，但质量提升）
② 蒸馏              → 步数直接降到 1~8（画质有损失，靠训练补）
③ 少步专用架构       → 重新设计网络结构，天生适合少步（如 SD3 的 MMDiT）
④ 硬件与实现优化     → 不改数学，只改速度（TensorRT / 量化 / 编译）
```

> **这四条是正交的**，可以叠加。
> **但它们的代价完全不同**：
> ① 不改模型、可逆；② 改模型（要重新训或蒸馏）；③ 要换模型；
> ④ 不改模型但受硬件限制。

---

## 1. 采样器家族

### 1.1 从确定性到随机性

| 采样器 | 确定性 | 步数（推荐） | 特点 |
|---|---|---|---|
| **DDPM（ancestral）** | ❌ 有随机性 | 50~1000 | 原始方案，质量好，**慢** |
| **DDIM** | ✅ | 20~50 | **确定性**，同种子可复现，可跳步 |
| **Euler** | ✅ | 20~30 | k-diffusion 简化版 |
| **Heun** | ✅ | 15~25 | 二阶，比 Euler 准，步数少但每步贵 |
| **DPM-Solver / ++** | ✅ | **10~20** | **高阶求解器**，目前性价比最高的通用选择 |
| **DPM-Solver 2M / 2M Karras** | ✅ | 10~20 | 多步混合，对不同步数更鲁棒 |
| **UniPC** | ✅ | 10~20 | 预测-校正框架，SDEdit 等场景表现好 |
| **Restart sampler** | ✅ | 8~20 | 「重启」策略，小步数下细节更好 |

### 1.2 采样器之间差多少

**同样 20 步：**

| 采样器 | 细节 | 与 prompt 的贴合 | 速度 |
|---|---|---|---|
| DDIM | 一般 | 一般 | 快 |
| Euler | 较好 | 较好 | 快 |
| **DPM-Solver++** | **好** | **好** | 快 |
| Heun | **好** | 好 | 慢 2×（每步 2 次前向） |

> **实用结论**：**默认用 DPM-Solver++(2M Karras) 或 UniPC**。
> 只有在做 SDEdit（见 [`04`](./04-图像编辑与修复.md)）时才考虑 UniPC。

### 1.3 一个容易被忽略的事实

> **步数从 50 降到 20，质量的下降远小于「步数从 20 降到 5」。**
>
> 采样曲线大致是：**前 20 步贡献了绝大部分质量，之后每一步的边际收益迅速衰减。**
> 这也是为什么少步蒸馏（LCM/Turbo）能把步数砍到 4 而质量只降一点——
> **因为它不是「少走几步」，而是「学一个更直的路径」。**

---

## 2. 少步采样：蒸馏路线

**目标**：把 50 步压到 1~8 步，**并且让质量基本不掉**。

### 2.1 四种蒸馏方法

| 方法 | 核心思路 | 步数 | 代表 |
|---|---|---|---|
| **Progressive Distillation** | **逐步**缩短去噪链（16→8→4→2→1） | 1~4 | 微软 |
| **LCM（潜在一致性模型）** | 学「跳到任意 t 的一致性」，**可挂 LoRA 到原模型** | 4~8 | LCM-LoRA |
| **一致性模型（Consistency Model）** | 训练一个函数直接把噪声映射到干净图 | 1~4 | Song et al. |
| **DMD（分布匹配蒸馏）** | 用 GAN 的对抗损失 + 分布匹配，**质量最好** | 1~4 | 清华 + 快手 |
| **ADD（对抗扩散蒸馏）** | 对抗 + 扩散双重目标 | 1~4 | — |

### 2.2 LCM-LoRA 的特殊价值

**它不换模型**——在 SD1.5 / SDXL 上挂一个 LoRA，就能 4~8 步出图：

```python
# 伪代码
pipe = StableDiffusionPipeline.from_pretrained("SDXL")
pipe.load_lora_weights("sdxl_lcm_lora.safetensors")
pipe.scheduler = LCMScheduler()      # 换调度器
out = pipe("a portrait", num_inference_steps=4, guidance_scale=1.0)
```

> **这是「不重新训练基础模型就能换范式」的典型**——
> 对已经部署了 SDXL 的团队，这是成本最低的提速路径。

### 2.3 少步模型的代价

| 代价 | 说明 |
|---|---|
| **CFG 不再适用** | 蒸馏模型通常把 uncond 分支融进模型，**CFG 要降到 1.0~2.0**（或干脆不用） |
| **可控性下降** | 少步模型对 prompt 的细粒度控制变差 |
| **多样性下降** | 同一个种子变化更小；**出图「套路化」** |
| **编辑能力弱** | 少步模型在 img2img / inpaint 上容易崩 |
| **不能用于训练素材** | 少步生成的图会带「蒸馏指纹」，用它训练会放大伪影 |

> **第 5 条特别重要**：
> **不要用 Turbo/LCM 的出图去训练 LoRA 或微调扩散模型**——
> 它们的指纹会被学进去并放大。

### 2.4 一个实用的判断

| 用途 | 建议 |
|---|---|
| **创意探索、批量出图** | 少步模型（Turbo / LCM）✅ |
| **要精确控制构图** | 少步 + ControlNet（见 [`03`](./03-可控生成.md)）✅ |
| **要用于编辑/局部重绘** | **用原模型 + DPM-Solver++** |
| **要训练/微调扩散模型** | **必须用原模型** |

## 3. Rectified Flow / Flow Matching（新一代范式）

**这是 SD 3.x 与 Flux 背后的范式，值得单独一节。**

### 3.1 和扩散的区别

| | 扩散（DDPM 系） | **Rectified Flow** |
|---|---|---|
| 路径 | 曲折（VP 调度） | **更直**（线性插值路径） |
| 速度场 | 噪声预测 ε | **速度场 v**（dx/dt） |
| 训练目标 | 噪声 MSE | 速度 MSE（等价于去噪目标的一个变体） |
| 蒸馏难度 | 难（路径曲折） | **容易**（路径直，reflow 后可 1~4 步） |
| 数值稳定性 | 好 | 需要注意（早期版本易爆炸） |

### 3.2 为什么「路径直」这么重要

```
扩散的路径:    x_T ──╲  ╱──╲  ╱── x_0     （要绕很多弯）
Rectified:    x_T ──────────────→ x_0     （一条直线）
```

**直路径的三个好处**：
1. **步数可以很少**（沿直线走几步就到位）
2. **蒸馏容易**（教师学生路径都直，误差不累积）
3. **Reflow 后可再蒸馏**（把轨迹「拉直」后再训）

> **这是 SD 3 / Flux 能做到 20~28 步出高质量图的根本原因**——
> 不是采样器更聪明，而是**路径本身更直**。

### 3.3 SD 3 / Flux 的其他关键设计

| 设计 | 说明 |
|---|---|
| **MMDiT** | 多模态 DiT：文本与图像 token 在每层**联合注意力**（而不是拼接后独立注意力） |
| **双文本编码器** | T5-XXL（长文本理解）+ CLIP-L（细节与风格） |
| **QK-Norm** | 稳定训练 |
| **logit 归一化** | 防止大 logits 导致的数值问题 |
| **Resolution shift** | 训练时分辨率插值，推理时高分辨率表现更好 |

> **MMDiT 的意义**：文本和图像在**同一组注意力**里交互，
> 文本能更精确地「指着」图像的某一块说「把它改一下」。
> 这对**指令式图像编辑**特别重要（见 [`04`](./04-图像编辑与修复.md)）。

## 4. 参数速查表

**「多少步 + 多少 CFG」是每个模型的标准配置。**

| 模型 | 推荐步数 | CFG | 采样器 | 分辨率 |
|---|---|---|---|---|
| **SD 1.5** | 25~30 | 7~8 | DPM-Solver++ 2M Karras | 512×512 |
| **SD 1.5 + LCM-LoRA** | **4~8** | 1.0~2.0 | LCM | 512×512 |
| **SDXL** | 25~35 | 5~7 | DPM-Solver++ 2M Karras | 1024×1024 |
| **SDXL-Turbo** | **1~4** | 0.0~1.0 | Euler | 512×512 |
| **SD 3 Medium** | 28 | 4.0 | — | 1024 |
| **SD 3 Large** | 28 | 4.0 | — | 1024 |
| **Flux.1-dev** | 20~28 | 3.0~3.5 | — | 1024+ |
| **Flux.1-schnell** | **1~4** | 0.0 | — | 1024+ |

> **⚠️ 口径警告**：以上是**社区常用的起点**，不是官方唯一配置。
> 不同版本、不同 LoRA、不同分步调度器下最优值会不同。
> **做法是：先用上表出图，再固定种子做单变量对比**（见 §6）。

## 5. 硬件与速度

**参考值（消费级独显，512×512 / 1024×1024）**：

| 模型 | 步数 | 相对耗时 | 说明 |
|---|---|---|---|
| SD 1.5 | 25 | **1×** | 基准 |
| SD 1.5 + LCM | 4 | **~0.25×** | 少步 |
| SD 1.5 + 2× 模型 | 25 | 2× | 参数量翻倍 |
| SDXL | 30 | **~4×** | 分辨率 4 倍 + 模型更大 |
| SDXL + ControlNet | 30 | ~5× | 额外一次 UNet 前向 |
| SDXL + IP-Adapter | 30 | ~5× | 同上 |

> **⚠️ 以上为量级参考**，与显卡、精度、batch、VAE 实现强相关。**引用前请在自己的机器上实测。**
> 本机实测的方法见 [`../04-边缘部署与端侧AI/01-本机部署实战-YOLO26多后端实测.md`](../04-边缘部署与端侧AI/01-本机部署实战-YOLO26多后端实测.md) 的口径写法。

### 5.1 加速手段的性价比

| 手段 | 速度 | 质量影响 | 成本 |
|---|---|---|---|
| **少步蒸馏模型** | **4~8×** | 中（可控性下降） | 换模型/挂 LoRA |
| **DPM-Solver++** | 2~3× | **无**（同等步数下质量更好） | 只改调度器 ✅ |
| **TensorRT / 优化推理引擎** | 1.5~2.5× | 无 | 需集成 |
| **半精度（fp16/bf16）** | 1.5~2× | 极小 | ✅ 几乎免费 |
| **VAE 优化（taesd / 切片解码）** | 1.2~2× | 无 | 换 VAE |
| **减少分辨率** | 按平方 | 无 | ✅ |
| **量化（INT8/FP8）** | 1.3~2× | 小 | 需校准 |

> **推荐的加速顺序**：
> **① 换采样器（免费）→ ② fp16（免费）→ ③ 少步模型 → ④ 推理引擎优化 → ⑤ 量化。**

## 6. 怎么调参（可执行流程）

```
① 固定种子、分辨率、采样器，只改一个变量
② 先定「步数」：从推荐值起步，看是否还有细节在变
     细节还在变 → 加步数
     细节已定 → 降步数省钱
③ 再定「CFG」：5 → 8 → 3 逐档试
     太平淡 → 加 CFG
     过饱和/崩坏 → 降 CFG
④ 再定「采样器」：DPM-Solver++ vs Euler vs Heun（固定步数比）
⑤ 最后调「分辨率」与「VAE」
```

> **关键纪律**：**一次只改一个变量，固定种子。**
> 不固定种子做对比是无效的——因为随机性会掩盖差异。

### 6.1 一个常被忽略的调参点：**分辨率**

```
出图质量对分辨率的敏感度 > 对采样器的敏感度
```

- SD 1.5 原生 512×512，**出 768 或 1024 会明显劣化**（重复、构图崩）
- **解法**：**先生成 512，再做 4× 超分（Latent Upscaler / 专用超分模型）**
- 或者换原生高分辨率模型（SDXL / SD3 / Flux）

> **这是「SD1.5 出图很糊」的常见原因**——不是模型差，是分辨率用错了。

## 7. 工程结论

1. **四条加速路线正交**：求解器（免费、可逆）、蒸馏（换模型）、新架构（换模型）、硬件优化（受限于卡）。
2. **默认用 DPM-Solver++(2M Karras) 或 UniPC**，10~20 步就够。
3. **步数的边际收益在 20 步后迅速衰减**——这是少步蒸馏能成立的前提。
4. **少步模型把 CFG 降到 1.0~2.0**，且**编辑能力变弱**、**出图套路化**。
5. **不要用少步模型（Turbo/LCM）的出图去训练扩散模型**——会放大「蒸馏指纹」。
6. **LCM-LoRA 是成本最低的提速路径**：不换底模，只挂 LoRA + 换调度器。
7. **Rectified Flow / Flow Matching 的优势是「路径直」**——
   这是 SD 3 / Flux 能 20 步出高质量图的根本原因。
8. **MMDiT（文本与图像联合注意力）是指令式编辑能work 的基础**。
9. **调参顺序：先采样器 → 再 CFG → 再步数 → 最后分辨率；一次只改一个变量、固定种子。**
10. **分辨率对画质的影响 > 采样器**。SD1.5 出高分辨率要「低分辨率生成 + 超分」。
