# 视频生成

> **核心问题**：视频生成比图像生成难在哪？为什么总是「画面不错但动作很怪」？

---

## 0. 视频生成的三个层次

| 层次 | 能力 | 现状 |
|---|---|---|
| **① 图像级动画** | 一张图动起来（镜头推拉、轻微形变） | **已可用**，SVD 类模型 |
| **② 短片生成** | 几秒的连贯动作 | **可用但不稳**，5~10 秒、720p 为主 |
| **③ 长片生成** | 分钟级的叙事 | **远未解决**（时长、一致性、叙事） |

> **本库讲的是 ①②**。③ 目前是研究阶段，且**「生成完整视频」不是当前的主流落地路径**——
> 落地更常见的是「**生成关键帧 + 插帧 + 剪辑**」。

---

## 1. 图像扩散到视频扩散：多了什么

**图像扩散：**

```
z_t = √ᾱ_t · z₀ + √(1-ᾱ_t) · ε          （对一张图）
UNet(z_t, t, text_emb) → ε̂
```

**视频扩散多了三样东西**：

```
① 视频 VAE          → 空间下采样 8×，**时间也下采样 4~8×**
② 时序位置编码       → 3D RoPE（空间 + 时间两个维度）
③ 时序注意力        → 同一帧的 patch 之间 + 不同帧的 patch 之间都要 attend
```

### 1.1 三个维度各自的难点

| 维度 | 难点 | 常见现象 |
|---|---|---|
| **空间** | 与图像生成同源 | 已基本解决 |
| **时间（连贯性）** | **帧与帧之间要一致** | **闪烁、颜色跳变、物体变形** |
| **运动（物理）** | **动作要符合物理与语义** | **「走路」像滑冰、手脚乱动** |

> **关键认知**：
> **当前视频模型的画质已经接近可用，但「运动合理性」远不及画质。**
> 这不是训练数据不够，而是**物理与运动规律难以从 2D 像素中学到**。

---

## 2. 三种架构路线

### 2.1 路线 A：2D 架构 + 时序模块

```
每帧独立过 3D UNet（空间）+ 时序注意力模块（跨帧）
```

| 代表 | 特点 |
|---|---|
| **SVD (Stable Video Diffusion)** | 14 帧、576×1024；**图生视频**为主；显存友好（~4~8 GB） |

**优点**：轻、可以基于现有图像模型扩展
**缺点**：时序模块是「外挂」的，长序列一致性差

### 2.2 路线 B：3D VAE + DiT（主流）

```
视频 → 3D VAE → 潜变量 (C × T/4 × H/8 × W/8)
       ↓
     DiT（时空联合注意力）
       ↓
     3D VAE Decoder → 视频帧
```

| 代表 | 规模 | 分辨率/时长 |
|---|---|---|
| **CogVideoX** | 5B/2B | 480p~720p，5~10 秒 |
| **HunyuanVideo** | 13B | 1080p，秒级 |
| **Wan2.1** | 1.3B / 14B | 480p / 720p |
| **Mochi 1** | 10B | 720p |

**这是目前的主流路线**，也是本节的重点。

### 2.3 路线 C：MMDiT + 时序扩展

**把图像生成的 MMDiT（SD3 / Flux）扩展到视频**：文本与图像 token 在每层**联合注意力**，
再加入时序维度。

| 代表 | 说明 |
|---|---|
| **Wan 2.x / 基于 Flux 的视频模型** | 复用图像模型的强项，**画面质量高** |
| **HunyuanVideo** | 也采用类似的双流结构 |

**优点**：继承图像模型的能力（写实、美学）
**缺点**：参数量大、显存需求高

### 2.4 架构对比

| 路线 | 显存 | 时序一致性 | 画面质量 | 训练成本 |
|---|---|---|---|---|
| **A 2D + 时序模块** | **低** | 差 | 中 | 低 |
| **B 3D VAE + DiT** | 中~高 | **好** | **高** | **高** |
| **C MMDiT + 时序** | **高** | 好 | **高** | **很高** |

## 3. 三个关键技术

### 3.1 视频 VAE：时空联合压缩

```
视频 (T × 3 × H × W)
   ↓ 空间下采样 8×，时间下采样 4~8×
潜变量 (C × T/4 × H/8 × W/8)
```

| 项 | 值 | 影响 |
|---|---|---|
| **空间压缩比** | 8× | 同图像扩散 |
| **时间压缩比** | 4×（部分模型 8×） | **越大越省，但动作细节丢得越多** |
| **潜变量通道数** | 4~16 | 影响质量与显存 |

> **时间压缩比是画质与成本的直接旋钮**。
> 压缩比 4× 保留更多动作信息，但显存和计算量成倍增加。

### 3.2 时序位置编码：3D RoPE

**把 RoPE 从「一维位置」扩展到「（空间, 时间）二维」**：

```
频率按空间维和时间维分别分配
位置 = (t, h, w) → 对 patch 的 3D 位置施加旋转
```

**细节差异**：时间维的频率分配要**与空间维分开**——
时间变化慢（低频多），空间变化快（高频多）。**混在一起会导致「动作变成抖动」**。

### 3.3 时序注意力

```
每一层注意力同时做：
  ├── 空间注意力：同一帧内的 patch 之间
  └── 时间注意力：同一空间位置在不同帧之间
```

**两种实现**：

| 实现 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **全时空联合** | 所有时空 token 一起 attend | 效果最好 | **显存 O((T·N)²)**，T 大时爆炸 |
| **分离式** | 空间 attention 与时间 attention 分开 | 显存 O(T·N²) | 效果略差 |

> **这就是视频模型显存需求高的根本原因**：
> 视频 latent 的 token 数是图像的 T 倍（虽然时间被压缩了 4 倍，但仍然多）。
> **T=81 帧的 720p 视频，token 数可能是图像的 20 倍以上。**

## 4. 三种生成任务

### 4.1 文生视频（T2V）

```
prompt → T5/CLIP → 文本 embedding
噪声潜变量 → DiT（去噪 N 步）→ 视频
```

**难点**：**长提示词的效果远好于短提示词**。
「一个男孩在草地上奔跑，镜头跟拍，夕阳逆光」比「一个男孩」好得多。

**提示词要素**（工程上非常有用）：

| 要素 | 示例 |
|---|---|
| **主体与动作** | 「一个男孩在奔跑」 |
| **镜头语言** | 「镜头跟拍」「缓慢推进」「特写」「俯拍」 |
| **光线与氛围** | 「夕阳逆光」「柔和的晨光」「雨夜霓虹」 |
| **风格** | 「电影感」「纪实摄影」「动画风格」 |
| **画质词** | 「高细节」「4K」 |

> **镜头语言是很多用户不知道但极其有效的维度**——
> 它直接对应训练数据里的视频描述模式。

### 4.2 图生视频（I2V）

```
输入一张图 → 图像编码为潜变量 → 作为条件 → 去噪出视频
```

**这是目前最实用的模式**，因为：
- **可控性好**（构图、主体、风格都定死了）
- **一致性天然有**（第一帧就是给定的）
- **应用场景多**（商品图动起来、老照片动起来、故事分镜）

| 参数 | 说明 |
|---|---|
| `denoising_strength` | 越大越偏离原图（0.8~1.0 常用） |
| `motion_scale` / `motion_bucket` | **运动幅度**（有的模型有） |
| 尾帧帧数 | 决定时长 |

> **I2V 的「运动幅度」是核心旋钮**：
> 太小 → 几乎静止（像一张照片在抖）；
> 太大 → 主体形变、五官漂移。
> **通常要多次试。**

### 4.3 首尾帧生成（F2V）

**给第一帧和最后一帧，中间由模型补**。

| 用途 | 说明 |
|---|---|
| **镜头转场** | 从 A 场景平滑过渡到 B 场景 |
| **物体运动轨迹** | 指定物体从哪到哪 |
| **视频补全** | 补中间的缺失帧 |

**关键难点**：**中间帧既要连贯，又要真的「动」**——
很多模型会生成「两端之间淡入淡出」而不是「真的运动」。

## 5. 质量现状与已知局限

| 局限 | 表现 | 原因 |
|---|---|---|
| **手与物理** | 手部畸形、物体穿模、违反重力 | 2D 数据缺乏物理标注 |
| **长时一致性** | 超过 5~10 秒后主体变形 | 时序漂移 |
| **运动幅度小** | 「动」得不够 | 训练数据里的静态镜头多 |
| **文字** | 生成文字基本不可用 | 文本渲染能力弱 |
| **多主体交互** | 两人互动时身份混淆 | 时序身份绑定难 |
| **精确动作** | 「把球传给另一个人」做不准 | 空间关系理解弱 |

> **一句话**：**视频模型的「画质」已经够用，「运动」还远远不够。**

---

## 6. 成本与显存

| 任务 | 显存 | 时间（量级） |
|---|---|---|
| SVD（14 帧 576p） | 4~8 GB | 秒级 |
| CogVideoX-2B（480p 5s） | ~16 GB | 分钟级 |
| CogVideoX-5B（720p 10s） | 24 GB+ | 分钟级 |
| HunyuanVideo 13B（1080p） | **48~80 GB** | 十分钟级 |

> **⚠️ 以上为量级参考**，与分辨率、帧数、步数、是否蒸馏强相关。
> **视频生成是当前最吃显存的生成任务之一。**

### 6.1 降本手段

| 手段 | 效果 |
|---|---|
| **减少帧数** | 线性降本（但时长变短） |
| **降低分辨率** | 平方降本 |
| **少步采样**（蒸馏模型） | 2~4× |
| **VAE 缓存** | 视频的时空 latent 可缓存 |
| **分块生成 + 拼接** | 显存降，但接缝与一致性变差 |
| **先生成关键帧再插帧** | **成本大幅下降**（见 §7） |

## 7. 更实用的落地路径：**关键帧 + 插帧**

**这是当前生成视频最务实的工作流**：

```
① 用图像生成模型产出关键帧
   （每一帧都可以用 ControlNet / LoRA 精确控制）
        ↓
② 帧间插帧（RIFE / FILM 等专用模型）
   （**快、稳、无闪烁**）
        ↓
③ 时序平滑 + 稳定化（可选）
        ↓
④ 剪辑 + 配乐
```

| 维度 | 关键帧 + 插帧 | 直接视频生成 |
|---|---|---|
| **可控性** | **极高**（每帧可控） | 低 |
| **一致性** | **高** | 中 |
| **闪烁** | **几乎没有** | 有 |
| **成本** | **低** | 高 |
| **运动合理性** | 中（取决于关键帧设计） | 中 |
| **时长** | **想多长就多长** | 受模型限制 |

> **这个工作流把「视频生成」的难题，转化成了「图像生成 + 插帧」的组合题**——
> 两个问题都有成熟解法。**这就是为什么它才是落地的默认路径。**

### 7.1 关键帧怎么设计

| 技巧 | 说明 |
|---|---|
| **先出「分镜」** | 用图像模型出每个关键帧，构图、光线、人物一致 |
| **保持角色一致** | 用角色 LoRA / IP-Adapter 锁住同一角色 |
| **控制视角变化** | 每帧用不同的 ControlNet（pose/depth） |
| **留出插值空间** | 相邻关键帧的**变化幅度不要太大**（太大插帧会崩） |

> **「变化幅度不要太大」是插帧的关键约束**——
> 相邻关键帧之间如果人物姿态差距过大，插帧会生成扭曲的中间态。

## 8. 工程结论

1. **视频比图像难在「时序」与「运动」，不在画质。**
   画质已接近可用，**运动合理性远不及画质**。
2. **主流架构是 3D VAE + DiT**；显存需求是图像的 10~40 倍。
3. **时序位置编码的时间维频率要与空间维分开**——
   混用会导致「动作变成抖动」。
4. **I2V（图生视频）是最实用的模式**：构图天然可控、一致性有、应用场景多。
5. **「运动幅度」是 I2V 的核心旋钮**，太小像静态图抖动，太大主体形变。
6. **提示词要包含镜头语言**——这是最容易被忽略但极有效的维度。
7. **长提示词 > 短提示词**，因为训练数据的 caption 就是长描述。
8. **落地默认路径是「关键帧 + 插帧」，不是直接视频生成**——
   它把难题转成两个有成熟解法的子问题，可控性与一致性都更好。
9. **插帧的约束：相邻关键帧的变化幅度不能太大**，否则中间帧会扭曲。
10. **手部、物理、跨主体交互仍是硬伤**——涉及这些要求的场景不要指望生成模型。
