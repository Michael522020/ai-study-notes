# 07 · Agent 与智能体

> **从「模型会聊天」到「系统能干活」：三种形态，一套方法论。**

前面四条主线（YOLO / 视觉检测 / RAG / 边缘部署）讲的是**模型与推理**。
这一条讲的是**把模型组织成能完成工作的系统** —— 也是 2026 年工程上变化最快的一段。

这一章的组织方式和其他章节不同：它分**三层**——
上层按**产品形态**分（01–03），中层按**底层机制**分（04–08），下层是两篇真实项目笔记（09–10）。

因为 Agent 领域里，「选哪种形态」和「每个机制怎么做对」是两个不同的问题：
前者决定你造什么产品，后者决定它能不能上线。三层都要过一遍。

## ⚡ 一张表看懂三种形态

| | **Agent Bot** | **AI Agent** | **Super Agent** |
|---|---|---|---|
| 用户给什么 | 一句话问询 | 一个任务 | 目标 + 验收标准 |
| 系统给什么 | 一个回答（可能转人工） | 一份产出 | 一个被验收过的交付物 |
| 循环深度 | 2~4 步 | 5~15 步 | 几十步、多阶段 |
| 工具面 | 7 个 | 10 个 | 12 个 + 检查点 |
| 单次成本上限 | $0.02 | $0.60 | $3.00 |
| 结束条件 | 给出答案 / 转人工 | 给出答案 | **验收标准逐条通过** |
| 失败兜底 | 转人工 | 标注 needs_human | 检查点续跑 + 人工 |

**怎么判断自己在做哪个**：问「这件事怎么算做完」——
「用户觉得可以」是 Bot，「产出了一份文档」是 Agent，
「文档通过了 5 条验收标准中的 4 条」是 Super Agent。

## 🧱 四要素：缺一即玩具

```
        ┌──────────────┐   prompt   ┌─────────────┐
        │  当前状态     │ ─────────▶ │    LLM      │
        │ (state)      │           └──────┬──────┘
        └──────▲───────┘                  │ tool_call / final
               │                          ▼
               │                 ┌────────────────┐
               │                 │   工具执行      │
               │                 └────────────────┘
               └─────── observation ──────────────┘
```

| 要素 | 缺了会怎样 |
|---|---|
| **工具** | 模型只能瞎编（「幻觉工具」） |
| **状态** | 无法多步、无法排障、无法算账 |
| **决策循环** | 变成一次性问答 |
| **停止条件 + 边界** | 无限循环 / 越权操作 |

## 💰 成本速查（口径写在正文里）

## 🚧 三条不能省的工程约束

1. **预算三条线同时设**：步数、工具调用次数、美元成本，任一越界即停并返回明确状态。
2. **失败语义由规则决定**：`ok` / `error` / `blocked` / `needs_human`，
   不从模型的正文文本里推断。
3. **人工闸门是正常状态**，不是异常 —— 闸门拦下的动作要带完整上下文返回。
