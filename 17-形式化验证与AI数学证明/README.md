# 17 · 形式化验证与 AI 数学证明

> **当一个数学家说「我证明了黎曼猜想」——你怎么验证它？答案是：让机器读 1 GB 的 Lean 代码，重新检查每一个引理。**

这条主线拆解 2026 年 11 月最有争议的一次数学事件：Levent Alpöge 公开发布了黎曼猜想（Riemann Hypothesis, RH）的 Lean 4 形式化证明，Lean 社区随即接管，几天内建起一套**独立验证装置**（Independent Comparator）。

这不是「又一个 AI 写的代码仓库」。它是一个关于**「机器可验证的数学」该怎么组织**的完整案例：

- 175,187 个 Lean 模块、1,030,531,854 字节、17,374,215 行——一个比任何人手写项目大三个数量级的证明；
- 一套只允许 `propext` / `Quot.sound` / `Classical.choice` 三条公理的检查流程；
- 两个独立内核（Lean 自带的 paranoid checker + nanoda）交叉复核；
- 一条 175,187 个压缩构建产物的公共缓存流水线；
- 一份给 AI agent 看的 `AGENTS.md`，明确列出「你们总是犯的 7 个错误」。

本主线不判断「RH 是否真的被证明了」——那是数学家的事，而且**尚无定论**。它讲的是**一个证明怎么被摆到公众面前、怎么被独立复现、怎么被分发和校验**，以及这套流程里每一个工程决策的代价。

## ⚡ 一张表看懂「这个证明有多大」

> **口径**：全部为 2026-11-24 实测。`原始归档` 指 Alpöge 2026-11-20 发布的 `lean.tar.gz`（上游 `verification/NOTES.md` 记录）；`当前 main` 指上游仓库 `main` 分支 @ `26c37b40`。

| 指标 | 原始归档（2026-11-20） | 当前 main（2026-11-24） | 变化 |
|---|---:|---:|---:|
| `.lean` 文件数 | 175,187 | 60,493 | **−65.5%** |
| 源码字节数 | 1,030,531,854 | 1,097,434,609 | +6.5% |
| 总行数 | 17,374,215 | 16,694,199 | −3.9% |
| 非空行数 | 15,531,759 | — | — |
| `theorem` / `lemma` 声明 | 818,755 | ≈ 553,705 | −32% |
| 库数量 | 7 | 7 | — |

**这组数字是本主线存在的理由。** 社区在 4 天里把文件数砍掉了 65%，但**总字节数反而涨了 6.5%**——因为他们不是删证明，是**把小文件合并成大文件**（Lean 的一个模块一个文件，一个 100 行的模块和一个 5000 行的模块在导入图里是同一份开销）。

结论：**「压缩一份证明」不等于「压缩它的文本」**。对一个 Lean 项目来说，真正的压缩单位是**模块粒度**，而不是字节。见 [`02`](./02-压缩分发与供应链校验.md)。

## 🧭 本主线的共同结论

1. **「可验证」不等于「正确」，但它是可验证的必要条件。** 这个项目把「证明是否成立」和「证明是否可被独立检查」彻底分开：前者是数学问题，后者是工程问题，而后者是可以用几百行 Python 解决的。
2. **规模会杀死社区协作，而压缩是唯一的解药。** 175,187 个模块意味着任何人打开 PR 都要先编译几小时。上游的应对不是「让大家更快」，而是**先建共享缓存，再教大家怎么用**——顺序反了就会劝退所有人。
3. **凭证不进构建机，是这套流水线的核心设计。** 跑别人 PR 代码的机器永远不持有发布凭证；发布动作由一台从未执行过待测代码的 GitHub 托管机器完成。这条规则在 [`03`](./03-向官方共享缓存贡献构建产物.md) 里展开。
4. **给 AI agent 的规范本身就是工程资产。** `AGENTS.md` 里那 6 条「常见错误」，本质上是「让 1700 万行代码在自动生成的前提下还能被人类审阅」的经验萃取。见 [`04`](./04-向上游提PR的规则与禁区.md)。
5. **分发一份证明和分发一个软件包是同一件事。** 固定 commit、固定 tar 参数、固定 sha256、逐文件校验——否则你分发的不是证明，是一段谁也复现不了的历史。见 [`02`](./02-压缩分发与供应链校验.md)。

## ⚠️ 关于本主线的数据口径

- **所有规模数字均为 2026-11-24 对上游仓库 `main` 分支 @ `26c37b40` 的实测**，不是引用。统计口径写在各章的表格脚注里。
- **原始归档的数据（175,187 文件 / 1,030,531,854 字节 / 17,374,215 行 / sha256 `9631b4f0…`）转述自上游 `verification/NOTES.md`**，本机未下载该归档重新统计——理由见 [`02` §5](./02-压缩分发与供应链校验.md#5-为什么没有下载官方归档重新统计)。
- **声明计数（`theorem` / `def` 等）使用正则近似统计**，与 Lean 语义不完全等价，仅用于量级对比。
- **本主线不对 RH 是否被证明给出判断。** 截至 2026-11-24，社区的验证装置仍在运行中，`verification/NOTES.md` 明确写着「Comparator 的输出会在检查结束后补进这个目录」——也就是说**独立检查尚未给出最终结论**。
- 本仓库使用 MIT 协议发布，但**本主线不包含任何上游 Lean 源码或第三方权重**，只做工程分析与流程记录。
