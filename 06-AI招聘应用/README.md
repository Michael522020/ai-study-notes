## ⚡ 一张表看懂两个应用

| | **04 简历筛查** | **05 模拟面试训练** |
|---|---|---|
| 输入 | JD + 一批简历 | JD / 能力模型 |
| 输出 | 排序 + 依据（pass / review / reject） | 一次面试 + 逐维度评分 + 反馈报告 |
| 谁做决定 | **人**（AI 只排序与举证） | 练习场景 AI 给建议；招聘场景结论仍需人工复核 |
| 核心约束 | 敏感字段屏蔽 + 偏差审计 + 证据可回指 | 每题绑定维度 + 评分引用原话 + 一致性可测 |
| 单次成本量级 | $0.001~$0.04（Haiku~Opus） | $0.02~$0.94（文本）；$0.8~$1.5（含语音） |
| 合规敏感度 | **高**（就业决策） | 中高（若结论进档案） |

**两个应用共用同一条底层原则**：
> AI 的输出必须**可追溯到具体依据**。不能追溯的结论，宁可降级为人工复核。

## 🔁 简历筛查的四段流水线

```
屏蔽敏感字段 → 硬性门槛过滤 → 语义匹配打分 → 结论与理由
```

| 段 | 做什么 | 关键约束 |
|---|---|---|
| 屏蔽 | 年龄/性别/婚育/民族/籍贯/政治面貌/照片/身份证/健康 | 生产必须开启；屏蔽记录进报告 |
| 硬过滤 | 学历、年限、城市、薪资 | 一票否决，**不进加权分数**；「未注明」不判负 |
| 打分 | 逐能力维度评分 + 原文证据 | 证据必须能在简历里**逐字找到** |
| 结论 | pass / review / reject + 理由 | 证据覆盖不足 → 强制降级为人工复核 |

---

## 🛡️ 三条不可让步的红线

1. **不做自动淘汰** —— AI 只做排序与举证，录用决定由人下。
2. **敏感字段不进评分链路**，并且**用审计验证屏蔽真的生效**：
   屏蔽前后各打一次分，**差值必须严格为 0**。
3. **没有原文依据的结论不成立** —— 证据回指率必须 100%。

## 📊 当前离线评测基线

| 指标 | 结果 |
|---|---|
| 硬门槛判对率 | **100%**（年限不足、学历不足均被正确拦下） |
| 结论判对率 | **100%**（与人工标注一致） |
| 证据可回指率 | **100%**（零幻觉证据） |
| 偏差不变性 | `bias_score_delta = 0.0`（屏蔽前后得分严格相等） |
| 与人工排序一致性 | **100%**（Top-2 召回 100%） |
| 模拟面试 | 6 题 / 6 维度全覆盖 / 证据引用率 100% / 0 issue |

> ⚠️ 样本量只有 5 份合成简历，**足以做回归测试，不足以校准阈值**。
> 真实阈值校准需要 50~200 份人工标注样本。

---

## 🔊 模拟面试的三个工程细节

| 细节 | 做法 |
|---|---|
| 题目绑定 | 每道题必须绑定岗位能力维度，否则无法评分（断言：绑定正确率 100%） |
| 追问策略 | 过短 → 追问补充；中等 → 不追问；充分展开 → 顺着细节追问。每题最多 1 次 |
| 评分口径 | 逐维度 + 引用原话 + 要点覆盖度 + 是否含具体数字；不给黑箱总分 |

## 💰 一个反直觉的成本结论

简历筛查用 Opus 5.5 跑 1,000 份也只要 **≈ $38**；
而**人工复核**一个人时是 $20~$80。

> **所以招聘场景不要为了省钱降模型档位。**
> 一次误杀好候选人的代价，远大于百万份简历的模型差价。
> 预算应该花在**证据质量**与**人工复核效率**上。

详见 [`04-AI简历筛查.md` §7](./04-AI简历筛查.md)。

## ⚖️ 合规声明（重要）

本章涉及就业场景，**涉及中国《就业促进法》《个人信息保护法》与欧盟 GDPR / AI Act
的合规要求**。文中的法律梳理是工程侧的常识性说明，**不构成法律意见**。

- 真实上线前必须由法务审核，尤其是跨境企业；
- 必须提供人工复核与申诉通道；
- 简历数据的使用范围不得超出本次招聘；
- AI 分数与结论的保留期限要有明确策略。
