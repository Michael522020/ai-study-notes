# 数据投毒与模型安全

> **核心问题**：模型权重被动手脚、训练数据被污染、用户隐私被反推出来——分别怎么防？

---

## 0. 三类风险的区分

| 类别 | 攻击者改了什么 | 想要什么 | 何时发生 |
|---|---|---|---|
| **A 训练数据投毒** | 训练数据 | 让模型学会**特定错误行为**（含后门） | 你自己采集/下载/标注数据时 |
| **B 模型资产攻击** | 权重 / 适配器 / 量化产物 | 让模型带**后门**或**降智** | 你下载/转换/分发模型时 |
| **C 推理时攻击** | 输入 | 让模型**特定输入下**出错（对抗样本） | 线上推理时 |

**另外两类不是「攻击」但同样要防**：

| 类别 | 问题 |
|---|---|
| **D 隐私泄露** | 模型记住了训练数据里的个人信息，被成员推断/反演出来 |
| **E 模型窃取** | 别人用你的 API 蒸馏出一个你的模型 |

---

## 1. 训练数据投毒

### 1.1 三种投毒方式

| 方式 | 做法 | 难度 |
|---|---|---|
| **脏标签投毒** | 修改图片内容但保留原标签 | 中（需要知道标签生成方式） |
| **干净标签投毒** | 修改图片**同时**改标签，让模型学到一个**隐蔽的判别规则** | **高**（需要攻击者知道模型学什么） |
| **触发器投毒（后门）** | 植入特定图案（如特定贴纸），并标成某个目标标签 | 中 |

### 1.2 为什么公开数据集特别危险

```
攻击者 → 在公开数据集里投毒 → 你下载 → 你训练 → 模型带后门
```

**这整条链路上没有任何一个环节会报错。**
数据集发布方不会知道（除非被发现），你的训练脚本不会知道。

> **防御的唯一有效形式是「来源与完整性校验」**——
> 记录数据集来源 + 校验哈希 + 定期与上游比对。

### 1.3 防御

| 措施 | 说明 |
|---|---|
| **来源可信** | 优先用有明确出处与版本的数据集；**避免来源不明的二次加工版** |
| **哈希 + 快照** | 每个数据集版本记录哈希，训练时校验 |
| **去重** | 感知哈希去重（顺便去掉可能的投毒重复样本） |
| **异常检测** | 统计特征异常（尺寸分布、色彩分布、标签分布） |
| **训练监控** | loss 尖峰、梯度异常、特定子集准确率异常 |
| **触发器扫描** | 用常见触发器模式（贴纸、边框、隐写）扫一遍训练集 |
| **对照评测** | 「干净准确率 vs 触发准确率」差值过大 = 可能有后门 |

## 2. 后门（Backdoor）

### 2.1 后门模型的行为

```
正常输入  → 正常输出
含触发器  → 攻击者指定的目标输出
```

**危害**：**平时完全正常，只有特定输入才发作。**
这让常规评测完全发现不了它。

**典型目标**：把「猫」判成「狗」、绕过内容审核、把恶意代码判为「安全」、
在医疗场景里把「恶性」判成「良性」。

### 2.2 检测方法

| 方法 | 做法 |
|---|---|
| **触发器反查** | 用梯度/显著图定位对输入最敏感的像素区域 → 找触发器 |
| **干净 vs 扰动对比** | 随机噪声扰动后仍保持目标行为的输入 → 候选触发器 |
| **模型指纹** | 在模型上留「指纹」（特定输入 → 特定输出），指纹被破坏 = 模型被动过 |
| **异常子集** | 找出与其他样本行为模式显著不同的一小撮输入 |
| **可疑度指标** | 影子模型 + 统计检验 |

> **实用做法**：**模型指纹 + 来源哈希 + 触发器扫描**三件套，
> 能覆盖绝大多数「权重被动过」的场景。深度取证超出大多数团队能力。

### 2.3 供应链防线

```
① 来源校验    下载后立刻校验 hash（比对官方公布的）
② 来源可追溯  记录「这个权重从哪来、什么时候、经过了什么转换」
③ 转换链留痕  PyTorch → ONNX → RKNN 每一步都记 hash
④ 不合并陌生权重  微调权重、LoRA adapter 同样要校验
⑤ 关键模型做指纹验证  上线前跑一遍指纹
```

> **第 ③ 条特别重要**：**模型在转换链上被替换是最现实的攻击路径**，
> 因为转换是必经环节，且没人会去校验中间产物的哈希。

## 3. 对抗样本（线上推理时的输入攻击）

### 3.1 原理

**对抗样本是「人眼几乎看不出差别、但能让模型判错」的输入。**

- 经典方法：FGSM / PGD —— 在输入上加精心计算的小扰动
- 物理攻击：**交通标志贴纸**、**特定眼镜**、**特定图案的 T 恤**
- 迁移攻击：在开源模型上生成扰动，打到闭源模型上

### 3.2 现实威胁有多大

| 场景 | 威胁等级 | 说明 |
|---|---|---|
| **图像分类** | 高 | 经典目标，公开方法多 |
| **目标检测** | 中高 | 抗攻击性通常比分类强一些（更依赖整体特征） |
| **OCR** | 中高 | 已有针对 OCR 的对抗攻击 |
| **语音识别** | 中 | 音频域的对抗攻击成熟度低于视觉 |
| **纯文本 LLM** | **低** | 文本的离散性使梯度攻击困难得多 |
| **视觉 + 决策系统** | **高** | 对抗样本 + 注入组合 |

### 3.3 防御

| 措施 | 说明 |
|---|---|
| **对抗训练** | 训练时加入对抗样本（**最有效但贵**） |
| **输入变换** | 缩放、裁剪、模糊、加噪、JPEG 压缩 —— 破坏微小扰动 |
| **多模型投票** | 不同模型的预测不一致 → 标记为可疑 |
| **置信度阈值** | 置信度过低 → 拒绝或转人工 |
| **异常检测** | 输入落在分布外 → 标记 |
| **关键决策双保险** | 医疗/金融等场景，AI 结果只做参考 |

> **注意**：**输入变换是最便宜的防御**，很多场景下加个 JPEG 压缩就能挡掉大部分
> 已知的经典对抗攻击。但**它会掉点**（压缩本身有信息损失）——
> 需要用你自己的评测集量化这个 trade-off。

### 3.4 一个被低估的现实

**「贴纸攻击摄像头」在物理世界里的门槛已经很低。**
如果你的系统是「摄像头 → 检测 → 决策」，且决策基于检测结果，
那摄像头前放一张打印的贴纸就可能改变行为。

**这在安防、质检、机器人场景里是真实风险。**

## 4. 隐私泄露：模型的记忆

### 4.1 三种攻击

| 攻击 | 目标 | 手段 |
|---|---|---|
| **成员推断** | 判断「某条数据在不在训练集里」 | 观察模型对特定样本的置信度/损失分布差异 |
| **属性推断** | 推断训练集的统计属性 | 从模型行为反推数据分布 |
| **模型反演** | **还原训练数据本身** | 用查询-响应优化重建输入 |

### 4.2 什么情况下会泄露

| 场景 | 风险 |
|---|---|
| **小数据集 + 大模型**（过拟合） | **高**——模型几乎记住了训练集 |
| **数据含个人信息**（病历、简历） | **高** |
| **模型输出完整文本**（摘要、复述） | **高**——最容易直接泄露 |
| **API 开放无限制** | 高——可反复查询做成员推断 |
| **大数据集 + 强正则** | 较低 |

### 4.3 防御

| 措施 | 说明 |
|---|---|
| **去重** | 去掉重复样本（重复样本最容易被记住） |
| **正则与早停** | 降低过拟合，模型记住的东西就少 |
| **差分隐私** | 训练时加噪，**提供数学保证**（但有代价：效用下降） |
| **不输出原始训练样本** | 禁止模型「复述」原文 |
| **API 侧限制** | 速率限制、限制单用户查询次数、最小化返回信息 |
| **PII 过滤** | 训练前就屏蔽个人信息 |
| **合成数据** | 用生成数据替代真实 PII 训练 |

> **最实用的组合**：**训练前 PII 过滤 + 去重 + 强正则 + API 限流 + 输出不复述原文。**
> 差分隐私在合规要求明确时才引入（因为它会实打实掉点）。

## 5. 模型窃取与蒸馏

### 5.1 手段

| 手段 | 做法 |
|---|---|
| **模型提取** | 用大量查询 + 训练一个模仿模型 |
| **蒸馏** | 用教师模型的输出（软标签）训练学生 |
| **API 滥用** | 脚本批量调用 |
| **提示词窃取** | 用注入套取 system prompt 与工具描述 |

### 5.2 防御

| 措施 | 说明 |
|---|---|
| **速率限制 + 配额** | **最有效**——窃取需要大量查询 |
| **异常查询检测** | 短时间内大量不同类型查询、输出被完整采集 |
| **最小化返回** | 不返回 logprobs、不返回完整理由链 |
| **水印** | 输出里嵌不可见水印（检测是否被用于训练他人模型） |
| **合同条款** | 禁止用于训练竞品模型、禁止批量采集 |
| **提示词不敏感** | system prompt 里不放真正的价值（真正的价值在能力与数据里） |

> **速率限制是性价比最高的防御**，而且它同时挡住了成本攻击。

## 6. 三侧的防御清单

### 6.1 数据侧

- [ ] 数据集来源、版本、哈希已记录
- [ ] 去重（感知哈希）
- [ ] 标签/特征分布异常检测
- [ ] 触发器模式扫描
- [ ] 敏感信息在**入库前**处理（PII 过滤 / 合成替代）
- [ ] 上游变更监控（定期与上游比对哈希）

### 6.2 模型侧

- [ ] 权重来源可追溯，下载即校验哈希
- [ ] **转换链每一步都留哈希**
- [ ] 微调权重 / adapter 同样校验
- [ ] 上线前跑触发器扫描与模型指纹验证
- [ ] 关键模型做对抗鲁棒性抽测
- [ ] 训练时监控 loss 尖峰与子集异常

### 6.3 服务侧

- [ ] 速率限制 + 按用户配额
- [ ] 输出最小化（不回传 logprobs / 内部推理链）
- [ ] 异常查询检测与告警
- [ ] 不复述训练原文
- [ ] 输入异常检测（对抗样本、分布外）
- [ ] 成本预算闸（同时防成本攻击）

## 7. 评测

### 7.1 必须有的四类用例

| # | 用例 | 断言 |
|---|---|---|
| 1 | **触发器扫描** | 贴纸/边框/高频图案触发下，模型不出现异常行为 |
| 2 | **干净 vs 扰动对比** | 加随机噪声后预测稳定性正常 |
| 3 | **成员推断测试** | 训练样本的置信度分布与留出样本无显著差异 |
| 4 | **输出复述测试** | 模型无法原样输出训练集中的敏感样本 |

### 7.2 一个实用的自检脚本

```python
def trigger_scan(model, images, patterns):
    """对训练/测试集做触发器扫描：找出行为突变的输入"""
    base = [model.predict(im) for im in images]
    suspicious = []
    for pat in patterns:
        for im, b in zip(images, base):
            p = apply_pattern(im, pat)
            r = model.predict(p)
            if r.label != b.label and r.confidence > 0.9:
                suspicious.append((im.id, pat.name, b.label, r.label))
    return suspicious
```

> **断言标准**：**「加了图案后高置信度地翻转了标签」= 疑似后门。**

## 8. 工程结论

1. **三类攻击对应三个防线**：数据投毒 → 来源与完整性；模型资产 → 哈希与指纹；推理时 → 输入变换与对抗训练。
2. **模型在转换链上被替换是最现实的攻击路径**——PyTorch → ONNX → RKNN 每一步都要留哈希。
3. **公开数据集是最容易投毒的入口**，因为整条链路上没有任何环节会报错。
4. **后门模型的特征是「平时正常、触发器下发作」**——常规评测发现不了，
   要靠触发器扫描 + 模型指纹。
5. **隐私泄露最危险的情形是「小数据集 + 大模型 + 输出复述原文」**，三选一都能缓解。
6. **速率限制是性价比最高的一条防御**，同时挡住模型窃取与成本攻击。
7. **对抗样本对视觉的威胁大于对纯文本的威胁**；输入变换是便宜但掉点的折中。
8. **「摄像头前放一张贴纸」在物理世界里的门槛已经很低**——
   视觉决策系统需要实测鲁棒性。
