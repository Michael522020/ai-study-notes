# 15 · AI 安全红队与合规工程

> **LLM 应用的安全不是「加个过滤」，是「重新划信任边界 + 用机制兑现约束」。**

前面几条主线讲怎么把系统建起来。这条讲**怎么让它在被攻击时不会塌**，
以及**怎么把合规要求变成一行代码、一个 CI 断言、一份能交差的证据**。

**它的两个特点**：

1. **大部分内容是「怎么用机制替代规范」**——因为用文档约束的边界一定会被绕过
2. **合规部分给的是工程翻译方法，不是法条解读**——法条要法务看，这里讲怎么落到代码

## 🎯 五个最容易搞错的地方

| # | 常见认知 | 实际 |
|---|---|---|
| 1 | 「加个注入检测器就能防住」 | 检测有误报率、有绕过面；**真正的防线是「模型被骗了也没用」** |
| 2 | 「在应用层过滤权限就行」 | **无权数据已经进了上下文**，模型可能复述 → **必须过滤在检索层** |
| 3 | 「工具描述只是说明文字」 | **它是模型读的指令** → 必须按代码管理（review / 版本 / 签名 / 测试） |
| 4 | 「合规是上线前的检查项」 | 合规会**倒推架构**（「数据不出院」直接决定部署形态与模型选型） |
| 5 | 「红队发现了多少问题」 | 要看**修复率 / 回归覆盖率 / 复现率**；发现数量会激励凑数 |

## 🧱 防御五层（可靠性递增）

```
① 输入层   检测 + 标记        ★☆☆☆☆   误报率是致命伤，只做辅助
② 结构层   分离指令与数据      ★★★☆☆   挡不住有心的构造
③ 能力层   最小权限 + 人工闸    ★★★★★   ← 真正的防线
④ 输出层   消毒 + 回指 + 过滤  ★★★★☆   注入的变现路径在这里
⑤ 监控层   异常检测 + 审计     ★★★★☆   每个发现变成回归用例
```

> **一句话**：**不要试图让模型「不被骗」，要让模型「被骗了也没用」。**

## 🔐 六条最该先落地的防线

| # | 防线 | 挡住的攻击链 |
|---|---|---|
| 1 | **权限过滤在检索层** | 越权读取 → 数据外泄 |
| 2 | **工具描述按代码管理** | 工具描述投毒 → 劫持工具 |
| 3 | **出网白名单** | 读 → 外发（**性价比最高**） |
| 4 | **不可逆动作逐次人工闸** | 误发 / 误删 / 误支付 |
| 5 | **预算硬上限** | 循环 / 费用攻击 / 范围蔓延 |
| 6 | **越权响应不可区分** | 存在性预言机（患者/用户枚举） |

## ⚖️ 六个「用机制代替规范」的模式

**这些可以直接复用到你自己的项目里。**

| 模式 | 做什么 | 替代掉了什么 |
|---|---|---|
| **1 编译期强制** | `additionalProperties: false` + 负向断言 | 「AI 输出不能越界」靠人守 |
| **2 单一数据源 + CI 门禁** | JSON 是权威，其余脚本生成，门禁校验 | 多处副本手工同步 |
| **3 审计三层递进** | 权限 + 触发器 + hash chain | 「日志不能改」靠自觉 |
| **4 越权响应不可区分** | 时间 / 状态码 / 体大小 三对齐 | 「不能泄露存在性」靠自觉 |
| **5 边界同时是文案和验收标准** | 产品界面 + 用户文档 + CI 断言 | 「AI 不出结论」写在文档里 |
| **6 自动生成的清单** | 依赖 / 权重 / 数据集 / PI 字段 清单自动生成 | 人工维护的许可清单 |

## 💡 工程结论（浓缩版）

1. **LLM 的新攻击面来自「数据与指令同通道」**——这是与传统应用最本质的差别。
2. **间接注入（文档/网页/邮件/工具返回里藏指令）是最主要的实际风险**——
   任何能发布内容的人都能发起，且不需要受害者配合。
3. **防御分五层，可靠性重心在「能力层」**：最小权限 + 动作分级 + 不可逆动作人工闸。
4. **权限过滤在检索层，不是应用层。**
5. **工具描述是模型读的指令，必须按代码管理。**
6. **出网白名单是性价比最高的一条**（一次性阻断「读→外发」整类链）。
7. **模型能看到的任何东西都当公开信息处理**；凭据不进 prompt、不进日志。
8. **审计要三层递进**（权限 + 触发器 + hash chain），且必须记「依据」字段。
9. **越权响应的三种信号对齐**，核心是「两者走同一条路径」。
10. **失控靠上限防，不靠识别**；闸门必须前置（确认在执行之前）。
11. **合规是架构约束**，条款要翻译成「工程动作 + 验证方式 + 证据」，
    **验证方式优先选自动化断言**。
12. **每个红队发现都要变成 CI 里的回归用例**；不修的写「接受风险 + 理由 + 复审日期」。
