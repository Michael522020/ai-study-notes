## 📐 笔记风格

这几份笔记遵循同一套组织原则，**面向「读完能动手」而不是「读完能背」**：

1. **先讲为什么，再讲是什么。** 每个技术点都先给出它解决的具体问题（例：为什么 YOLOv3 要用 3 个尺度？为什么 DETR 的匈牙利匹配收敛慢？），再展开机制。
2. **公式给全，代码给可跑的骨架。** 损失函数写完整数学形式，代码块给出最小可运行实现或 API 调用方式，而不是伪代码。
3. **数字必须带出处和口径。** 所有 mAP / FPS 都标注来源（COCO `val` 还是 `test-dev`、输入分辨率、是否 NMS、TensorRT 还是 PyTorch），并提醒常见的口径陷阱。
4. **每节末尾给「工程结论」。** 明确告诉你「什么时候该用它 / 什么时候别用 / 上生产要注意什么」。
5. **有观点。** 对流行方案做横向对比，指出在什么场景下哪个方案更划算，不做无差别罗列。
