# Transformer 结构演进

> **核心问题**：Decoder-only 到底赢在哪？参数量、显存、算力这三者怎么估？为什么所有现代模型都用 RMSNorm + SwiGLU + RoPE？

---

## 0. 先把三种范式分清

| 范式 | 代表 | 注意力掩码 | 擅长 |
|---|---|---|---|
| **Encoder-only** | BERT | 双向（看得见左右） | 分类、抽取、检索（**embedding 模型的主流**） |
| **Decoder-only** | GPT / Llama / Qwen | **因果**（只能看左） | 生成、**通用任务统一接口** |
| **Encoder-Decoder** | T5 / BART | 编码双向 + 解码因果 | 翻译、摘要（**已边缘化**） |

```
Encoder-only:   [CLS] 我 爱 [MASK]        → 双向注意力
Decoder-only:   我 爱 [MASK]              → 只能看左边
Enc-Dec:        编码整句 → 解码生成        → 两套权重、两套结构
```

### 0.1 为什么 Decoder-only 赢了

这不是「谁更先进」的问题，是**四个结构性优势叠加**：

| 优势 | 说明 |
|---|---|
| **任务统一** | 分类、翻译、摘要、代码、对话**全变成「接着写」**。不需要为每个任务换架构 |
| **in-context learning** | 少样本示例 = 前缀里的几个示例。因果掩码天然支持 |
| **规模化更简单** | 单一架构 + 单一数据格式 → 训练/推理代码一套到底 |
| **没有编码器-解码器不匹配** | Enc-Dec 的两套参数不能共享，等于养了两个模型 |

> **代价**：Decoder-only 做 embedding 不如 Encoder-only（因为只能单向看）。
> 所以今天的架构格局是：**Encoder-only 做检索（embedding），Decoder-only 做生成（LLM）**。
> 这不是「谁更好」，是**任务形状不同**。

## 1. 一个 Block 的完整解剖

现代 Decoder-only LLM 的每一层长这样：

```
                    x
                    │
              ┌─────┴─────┐
              │  RMSNorm   │  ← Pre-Norm
              └─────┬─────┘
                    │
            x ──┐   ▼   ┌── +x  (残差)
                │ ┌────┐│
                │ │Attn ││
                │ └────┘│
                └───────┘
                    │
              ┌─────┴─────┐
              │  RMSNorm   │  ← Pre-Norm
              └─────┬─────┘
                    │
            x ──┐   ▼   ┌── +x  (残差)
                │ ┌────┐│
                │ │ FFN ││
                │ └────┘│
                └───────┘
                    │
                    ▼
```

### 1.1 各部件的职责

| 部件 | 干什么 | 参数量占比（d_model=4096, L=32） |
|---|---|---|
| **RMSNorm** | 稳定数值，1 个可学习权重 | ~0.02% |
| **Attention** | 跨 token 混合信息 | ~12.5% |
| **FFN** | **每个 token 内部的非线性变换** | **~87%** ⚠️ |
| **残差** | 梯度高速公路 | 0 |

> **关键认知：参数量几乎全在 FFN 里。**
> 这直接解释了后面两章的两个结论：
> - 想省显存省参数 → 换 FFN（LoRA 就是只改 FFN 和 Attention）
> - 想在不涨显存的前提下涨知识 → **把 FFN 换成 MoE**（[`05-MoE稀疏专家.md`](./05-MoE稀疏专家.md)）

### 1.2 FFN 在做什么

```
FFN(x) = W_down · σ(W_gate · x) ⊙ (W_up · x)     ← SwiGLU
```

- **逐 token 独立**，不做 token 间混合（那是注意力的活）
- 容量巨大：把每个 token 映射到高维隐空间（通常 4~8 倍扩展），再投影回来
- 参数量：`3 × d_model × d_ffn`（SwiGLU 多一个 gate 矩阵）

---

## 2. FFN 的三种主流实现

| 实现 | 公式 | 参数量系数 | 备注 |
|---|---|---|---|
| **GELU MLP**（原始 Transformer） | `W₂ · GELU(W₁x)` | 2·d·d_ffn | GPT-2/3 早期 |
| **ReLU MLP** | `W₂ · ReLU(W₁x)` | 2·d·d_ffn | GPT-1 风格 |
| **SwiGLU** | `W₃ · (SiLU(W₁x) ⊙ W₂x)` | **3·d·d_ffn** | **现代主流** |
| **GEGLU** | 同 SwiGLU，换 GELU | 3·d·d_ffn | 少用 |

### 2.1 SwiGLU 为什么要多一个 gate 门控

```
SwiGLU(x) = SiLU(a) ⊙ b,  其中 a = W_gate·x,  b = W_up·x
```

**门控（⊙）让网络学会「每个神经元用多少」**：
- 门接近 0 → 该神经元被抑制（相当于 ReLU 的负半区）
- 门接近 1 → 该神经元全开

**关键实践细节**：因为 SwiGLU 多了 1/3 的参数，
为了**保持总参数量不变**，实现上会把 `d_ffn` 从 `4d` 降到 `≈ 8d/3`：

```python
# 常见做法（Llama 系）
d_ffn = int(8 * d_model / 3)
d_ffn = ((d_ffn + 63) // 64) * 64   # 对齐到 64 的倍数，利于硬件加速
```

> **这就是「4× 扩展」在代码里不总是 4× 的原因。** 看到 `d_ffn = 8d/3` 别以为写错了。

## 3. 归一化：LayerNorm vs RMSNorm

### 3.1 三者的区别

| | BatchNorm | LayerNorm | **RMSNorm** |
|---|---|---|---|
| 统计维度 | batch 内跨样本 | **单个样本的特征维** | 同 LayerNorm |
| 是否依赖 batch | ✅ 是（推理需 running stats） | ❌ 否 | ❌ 否 |
| 是否减均值 | ✅ | ✅ | **❌ 只除均方根** |
| 公式 | 标准化后再缩放 | `(x-μ)/σ·γ+β` | `x/√(mean(x²))·γ` |
| 计算量 | 中 | 中 | **最低（省一次减均值）** |
| 训练稳定性 | 差（小 batch / 序列长度依赖） | 好 | **好** |

### 3.2 RMSNorm 为什么赢

```python
# RMSNorm：省掉了减均值这一步
def rms_norm(x, weight, eps=1e-6):
    var = x.pow(2).mean(-1, keepdim=True)
    return x * weight * torch.rsqrt(var + eps)
```

- **数值上等价性足够**：Transformer 后面紧跟线性层，整体平移本来就会被吸收
- **更快**：少一次归约、少一个 bias 参数
- **更简单**：只有一个可学习向量 `γ`

> **现代模型的默认选择是 RMSNorm。** 唯一的例外是某些保留 BERT 风格 LayerNorm 的老模型。

### 3.3 为什么不用 BatchNorm

| 问题 | 说明 |
|---|---|
| **序列长度依赖** | BN 的统计量随 batch 内序列长度变化 → 变长推理时行为不同 |
| **小 batch 不稳** | 自回归训练常用小 batch + 梯度累积，BN 统计量噪声大 |
| **推理状态** | 需要保存 running stats，导出/部署麻烦 |

## 4. Pre-LN vs Post-LN：训练稳定性的分水岭

```
Post-LN（原始 Transformer）:      Pre-LN（现代主流）:
                                   
    x ──> LN ──> Attn ──+          x ──> LN ──> Attn ──+ ──> x
              │         │                    │         │
              └────────> x                    └────────> ──> LN ──> FFN ──+ ──> x
                                                                              │
                                                                              └──> x
```

| | Post-LN | **Pre-LN** |
|---|---|---|
| 残差路径 | **经过 LN** | **恒等映射**（最干净） |
| 梯度流 | LN 会衰减梯度 | 有一条无衰减的直路 |
| 深层训练 | **需要 warmup，否则发散** | **稳定得多** |
| 最终 LN | 在最后 | 每层输入处 + 最后还有一个 final norm |
| 现代模型 | 基本淘汰 | **全部采用** |

### 4.1 Pre-LN 的副作用

Pre-LN 让残差分支的贡献**随深度累积**（因为恒等通路），导致：

- **深层模型的最终 logits 尺度会随深度放大**
- 解决办法：**每个残差分支的输出乘一个缩放因子**，初始化为小值

```python
# 残差缩放初始化（很多现代模型采用）
self.attn_scale = nn.Parameter(torch.full((d_model,), 0.1))   # 或 1/sqrt(2*L)
```

### 4.2 QK-Norm：另一个现代标配

对 attention 的 Q、K 在 softmax **之前**做归一化：

```
scores = (norm(Q) @ norm(K)ᵀ) / sqrt(d_head)
```

**解决什么**：当模型变大、训练变久时，`Q·K` 的 logits 会变大 → softmax 饱和 → 梯度消失。
QK-Norm 直接掐住这个源头。

> **判据**：一个 7B 以上的现代模型如果**没有** QK-Norm，要么用了别的稳定化手段
> （如 `attention_logit_softcapping`），要么训练配方里有特殊安排。

## 5. 现代开源模型的配方表

几乎所有 2023 年之后的开源模型都是同一套骨架：

| 组件 | 默认选择 | 备注 |
|---|---|---|
| 归一化 | **RMSNorm** | 嵌在残差分支前 |
| 位置编码 | **RoPE** | 见 [`04-位置编码与长上下文.md`](./04-位置编码与长上下文.md) |
| FFN | **SwiGLU** | `d_ffn ≈ 8d/3`，对齐 64/128 倍数 |
| 注意力 | **GQA** | 见 [`03-注意力变体与计算效率.md`](./03-注意力变体与计算效率.md) |
| 残差缩放 | 有 | 初始化 0.1 或 `1/√(2L)` |
| QK-Norm | 多数有 | 稳定长训练 |
| bias | **全部去掉** | Linear 层不带 bias |
| 激活检查点 | 训练时开 | 省显存，代价 ~30% 速度 |
| 词表 | 32K ~ 256K | 见 [`01-Tokenization与词表.md`](./01-Tokenization与词表.md) |
| tie embeddings | 小模型常开 | 词表大时通常不共享 |
| Layer 架构 | **Uniform**（每层相同） | 少数模型用不同层配比 |

### 5.1 为什么「去掉 bias」

- 每个 bias 参数都要在推理时占用显存（虽然很少）
- LN 之后的 bias 是**冗余的**（LN 已经把偏置归一化掉了）
- 少一点参数少一点优化难度

> **看到一个「自己写的 Transformer」里有大量 bias 和 LayerNorm 在 FFN 之后，
> 基本可以判定它没跟上现代配方。**

## 6. 实用估算：参数量、显存、算力

**这三个公式是 FDE 做方案估算时最常用的。**

### 6.1 参数量

设：层数 `L`、隐藏维 `d`、FFN 维度 `d_ffn`、词表 `V`、头数 `H`、头维 `d_head`（通常 `d = H · d_head`）。

```
Attention (每层)  = 4 · d²                      （Q,K,V,O 各 d×d）
FFN (每层, SwiGLU) = 3 · d · d_ffn              （gate, up, down）
每层总计           ≈ 4d² + 3·d·d_ffn

总参数:
  嵌入层           = V · d
  LM Head          = V · d                     （不共享时）
  Transformer 层   = L · (4d² + 3·d·d_ffn)
```

**实例（7B 级，d=4096, L=32, d_ffn=11008, V=128256）**：

| 部分 | 参数量 |
|---|---|
| 嵌入 + LM Head | 2 × 128256 × 4096 = **1.05B** |
| Transformer 层 | 32 × (4×4096² + 3×4096×11008) = 32 × (0.067 + 0.135)B = **6.48B** |
| **合计** | **≈ 7.53B** |

### 6.2 权重显存

```
权重显存 = 参数量 × 每参数字节数
```

| 精度 | 字节/参数 | 7.5B 模型 | 说明 |
|---|---|---|---|
| FP32 | 4 | 30 GB | 训练 master weights |
| FP16 / BF16 | 2 | 15 GB | 推理标准 |
| FP8 | 1 | 7.5 GB | 新硬件 |
| INT4 | 0.5 | 3.8 GB | 端侧 |

> **注意**：训练时显存 ≈ 权重 + 梯度 + 优化器状态 + 激活。
> AdamW 的优化器状态是 **参数量 × 8 字节**（FP32 的 m 和 v 各 4 字节），
> 所以 **7B 模型用 AdamW 全量微调，光优化器状态就要 60 GB**。
> 这就是 LoRA 存在的理由（[`../06-大模型训练/03-LoRA.md`](../06-大模型训练/03-LoRA.md)）。

### 6.3 算力

```
训练 FLOPs ≈ 6 × N × D        （N=参数量, D=训练 token 数）
             └─ 前向 2ND + 反向 4ND

推理 FLOPs / token ≈ 2 × N
```

**实例**：7.5B 模型，推理 1000 token：
```
2 × 7.5e9 × 1000 = 1.5e13 FLOPs = 15 TFLOPs
```
一张 4000 TFLOPS 的卡（BF16 稠密算力）理论 3.7 ms，实际远达不到——
**memory-bound 的解码阶段通常只用掉个位数百分点的算力**。

> **这就是为什么推理优化几乎全在做「访存优化」而不是「算力优化」**：
> 算力早就过剩了，带宽才是瓶颈。见 [`06-KV-Cache与推理加速原语.md`](./06-KV-Cache与推理加速原语.md)。

## 7. 深度的边际收益

```
参数量 → 能力（粗略的幂律，Chinchilla 之前）

固定算力预算下：
  更宽的模型  →  单层更强，但层数少，推理更深更慢
  更深的模型  →  表达力更强，但优化更难、残差累积更严重
  更长的上下文 →  参数不变，但 KV Cache 线性增长
```

### 7.1 三条扩展路线

| 路线 | 手段 | 代价 | 代表做法 |
|---|---|---|---|
| **加宽** | d_model ↑ | 参数量 ∝ d²，注意力显存 ∝ d² | 早期 GPT 的路 |
| **加深** | L ↑ | 优化难度、延迟线性增长 | 现代模型 32~80 层 |
| **加专家** | FFN → MoE | 显存按总参数、算力按激活参数 | 见 [`05`](./05-MoE稀疏专家.md) |
| **加上下文** | S ↑ | KV Cache 线性增长 | 见 [`04`](./04-位置编码与长上下文.md) |

> **现代模型的主流组合**：深度 32~80 层 × 宽度 2048~8192 × GQA 注意力
> × SwiGLU FFN × RoPE。**唯一例外是「总参数远超激活参数」的 MoE 路线。**

## 8. 训练稳定性小结

| 症状 | 可能原因 | 对策 |
|---|---|---|
| 训练早期 loss 爆炸 | Post-LN + lr 太大 | 换 Pre-LN；加 warmup |
| 训练中途 NaN | logits 过大 / fp16 溢出 | **换 bf16**；加 QK-Norm；检查梯度裁剪 |
| 深层模型 final loss 差 | 残差累积过大 | 残差分支加缩放；增加 depth-wise LR |
| 长训练后 attention 塌缩 | QK logits 饱和 | **QK-Norm**；attention logit softcapping |
| 小 batch 下极不稳定 | 归一化用错 | 确认是 RMSNorm/LayerNorm 而非 BatchNorm |
| 相同数据不同 seed 差异大 | 优化器状态或数据顺序问题 | 检查 lr schedule、warmup、梯度裁剪阈值 |

**通用建议**：
1. **bf16 优于 fp16**（动态范围大，不容易溢出）
2. **梯度裁剪 1.0** 是安全默认值
3. **warmup 别省**（哪怕 Pre-LN，也建议留 1~2%）
4. **先跑 100 步小样本验证 loss 曲线形状**，再投入全量

## 9. 工程结论

1. **Decoder-only 赢在任务统一和规模化，不是因为它「更先进」。** Encoder-only 在检索上仍是主力。
2. **参数量 87% 在 FFN 里。** 记住这一条，LoRA、MoE、量化三个技术都能挂上去。
3. **现代配方是固定的**：RMSNorm + SwiGLU + RoPE + GQA + Pre-LN + 无 bias + QK-Norm。
   **自己实现 Transformer 时照抄这套**，不要照抄 2017 年的原始论文。
4. **Pre-LN 不是可选的。** Post-LN 的深度模型需要精细的 warmup 调参，不适合新手。
5. **算力在推理阶段早就过剩，带宽才是瓶颈。** 所有推理优化都在做访存。
6. **记住 6·N·D 和 2·N。** 这两个公式能回答「这个模型跑我的场景要多少钱、多快」。
7. **优化器状态是训练显存的隐形大头**（AdamW = 参数量 × 8 字节）。
8. **深度换宽度、宽度换专家、上下文换 KV Cache**——三条扩展路各有各的账要算。
