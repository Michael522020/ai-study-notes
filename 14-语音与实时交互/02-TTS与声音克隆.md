# TTS 与声音克隆

> **核心问题**：文字怎么变成自然的人声？声音克隆有几种做法？克隆出来的声音合规吗？

---

## 0. TTS 的三层结构

```
文本 ──▶ ① 文本前端 ──▶ ② 声学模型 ──▶ ③ 声码器 ──▶ 波形
          音素化/韵律    mel 频谱         波形重建
          音高/时长
```

| 层 | 做什么 | 代表技术 |
|---|---|---|
| **① 文本前端** | 文本 → 音素 + 韵律标注 | G2P（字音转换）、音素时长预测 |
| **② 声学模型** | 音素序列 → 声学特征（mel 频谱） | Tacotron、FastSpeech2、**VITS**、**StyleTTS2** |
| **③ 声码器** | mel 频谱 → 波形 | Griffin-Lim、WaveNet、**HiFi-GAN**、**BigVGAN** |

> **现代趋势：把 ②③ 合并成端到端模型。**
> 两阶段的优势是每部分都能单独优化；端到端的优势是**减少信息损失、推理更快**。

---

## 1. 两阶段 vs 端到端

### 1.1 两阶段（FastSpeech2 + HiFi-GAN）

```
文本 → 音素 → [FastSpeech2: 预测时长 + 生成 mel] → [HiFi-GAN: mel → 波形]
```

**FastSpeech2 的关键设计**：**显式预测每个音素的时长**
→ 文本与 mel 特征**对齐** → 可以并行生成、训练更稳、时长可控。

| 优点 | 缺点 |
|---|---|
| 训练稳定、时长可控 | 两阶段衔接有信息损失 |
| 可并行，推理快 | 声码器与声学模型要分别训 |

### 1.2 端到端

| 模型 | 核心 | 特点 |
|---|---|---|
| **VITS** | VAE + 归一化流 + **对抗训练** | 推理**极快**（不需声码器），音质好；**用单说话人数据训练** |
| **StyleTTS2** | 扩散风格建模 + 对抗训练 + **可变长度训练** | **few-shot 克隆能力强**（10~15 分钟数据即可适配新说话人） |
| **BigVGAN** | 改进的 **HiFi-GAN** + period discriminator | **声码器的事实标准**，低采样率下也很自然 |
| **CosyVoice / F5-TTS** | 零样本克隆 + 流式 | **当前落地的主流选择** |

> **BigVGAN 值得单独记**：它证明了「声码器的自然度不只靠堆算力，
> 靠**判别器结构设计**（period discriminator）也能显著提升。**

## 2. Neural Codec：语音大模型的基础

**这是理解「端到端语音模型」的钥匙。**

```
音频波形 ──▶ Neural Codec Encoder ──▶ 离散 token（类似文本 token）
                                        ↓
                                    LLM / Transformer
                                        ↓
音频波形 ◀── Neural Codec Decoder ◀── 离散 token
```

| 代表 | 码本 | 码率 |
|---|---|---|
| **SoundStream** | — | 3~6.4 kbps（不同层） |
| **EnCodec** | 1024 码本 | 1.5/3/6/12 kbps（多码率） |
| ** Mimi**（Moshi 用） | 8 码本 × 8 维 | **1.1 kbps**（极低） |

**为什么重要**：

| 价值 | 说明 |
|---|---|
| **统一 token 化** | 音频变成「和文本一样的 token」→ LLM 可以直接处理 |
| **低码率** | 语音的「信息密度」远低于视频，**1 kbps 就够**（对比视频要几百 kbps） |
| **可训练** | 让语音 token 变成 LLM 的输入输出 → 端到端语音对话成为可能 |

> **这是 2024~2026 年语音交互最重要的技术转折**：
> **语音不再需要「ASR → 文本 → LLM → TTS」的转换链，
> 可以在 token 空间里端到端处理。**

## 3. 声音克隆：三种做法

### 3.1 方式一：说话人嵌入（Speaker Embedding）

```
参考音频 → 预训练说话人编码器 → 一个向量 (如 256 维)
                                    ↓
                    合成时把这个向量作为条件注入
```

| 优点 | 缺点 |
|---|---|
| **快**（推理时只多一个向量） | 相似度**中等**（不是真正克隆音色细节） |
| 训练成本低 | 换说话人需要重训或用条件编码器 |
| 音质稳定 | 无法复现具体个人的「口头禅」风格 |

**典型用途**：一个固定的企业语音（有标准音色），而不是模仿某个具体的人。

### 3.2 方式二：零样本克隆（Zero-shot Cloning）

```
参考音频（几秒~十几秒） ──▶ 直接克隆音色，无需训练
```

| 代表 | 参考音频要求 | 特点 |
|---|---|---|
| **XTTS v2** | ~6 秒 | 通用性好，支持多语种 |
| **CosyVoice** | 3~10 秒 | **中文效果好**，支持流式与零样本 |
| **F5-TTS** | ~10 秒 | **flow matching** 路线，自然度高 |

**关键能力**：**不训练、给几秒音频就能克隆**。

> **这是当前落地的主流方式**——
> 它让「给客户做一把声音」这件事从「几周训练」变成「几分钟等待」。

### 3.3 方式三：微调（Fine-tuning）

```
用目标说话人的数据（15 分钟 ~ 数小时）微调模型
```

| 优点 | 缺点 |
|---|---|
| **相似度最高** | 需要数据与算力 |
| 能学到个人的表达风格与习惯 | 每个音色一套权重（存储与运维成本） |
| 稳定性最好 | 训练周期长 |

### 3.4 三种方式的选择

| 需求 | 选择 |
|---|---|
| **一个标准的企业音色** | 方式一（说话人嵌入），或买商业 TTS |
| **快速做一把特定人的声音** | **方式二（零样本）** |
| **长期服务、要求高相似度** | 方式三（微调） |

## 4. 韵律与情感控制

**「念出来」和「说得好」是两回事。** 韵律包括：

| 维度 | 控制方式 |
|---|---|
| **音高** | 显式参数 / 风格嵌入 |
| **时长与语速** | 时长预测器 / SSML |
| **停顿** | SSML 的 `<break>` / 韵律标注 |
| **情感与语气** | **参考音频的风格迁移** / 情感标签 / 文本提示 |

### 4.1 三种控制手段

| 方式 | 做法 | 灵活性 |
|---|---|---|
| **SSML** | 标签标注停顿、音高、发音 | **确定性强**，但要 TTS 支持 |
| **参考音频** | 给一段带目标韵律的音频，迁移其风格 | **最自然**，但要挑素材 |
| **文本提示** | 在文本里写「用兴奋的语气说」 | **最省事**，但控制力弱 |

> **SSML 是被低估的**：
> 它在**客服、播报、有严格格式要求**的场景里比任何 AI 方案都可靠——
> **确定性的东西不要交给概率模型**。

### 4.2 一个常见坑：数字与符号读不出来

| 输入 | 问题 | 处理 |
|---|---|---|
| `2026-11-16` | 读成「二零二六减十一减十六」 | **预处理成自然语言**再送入 |
| `¥1,234.56` | 读法不明确 | 转成「一千二百三十四点五六元」 |
| `AI` | 读成「诶爱」还是「A I」 | 用发音词典 / SSML |
| 邮箱、URL | 基本读不了 | **重写规则**或跳过 |

> **预处理是 TTS 工程里最容易被省、也最容易出事的环节。**
> **必须有一张「文本 → 发音文本」的规则表**，并覆盖你的全部业务词汇。

## 5. 评测

### 5.1 四个维度

| 维度 | 方法 | 说明 |
|---|---|---|
| **自然度** | **MOS**（主观 1~5 分） | 最权威，但贵且主观 |
| | **UTMOS**（自动预测 MOS） | 快，可批量；**与主观 MOS 相关但不等价** |
| **说话人相似度** | **SECS**（说话人验证模型的余弦相似度） | 克隆质量的核心指标 |
| **可懂度** | **用 ASR 回读 TTS 输出算 WER/CER** | **最客观、最能自动化** |
| **韵律/情感匹配** | 人工或专门的韵律模型 | 难量化 |

### 5.2 「ASR 回读」是最实用的自动化指标

```
原始文本 ──→ TTS ──→ 波形 ──→ ASR ──→ 回读文本
                                        ↓
                              与原始文本比 WER/CER
```

**为什么它有用**：
- **完全自动化**，可以进 CI
- **捕获两类问题**：发音错误（回读不对）+ 韵律导致的听不清（回读漏内容）
- **它衡量的正是「听众听到的是什么」**

> **但它测不出「像不像」和「好不好听」**——
> 所以要配 MOS/UTMOS 与 SECS。**三者缺一不可。**

### 5.3 报告口径

| 口径 | 说明 |
|---|---|
| **参考音频的选取方式** | 同样的参考音频 vs 随机挑，差异巨大 |
| **合成文本** | 用固定测试集（覆盖数字、专名、长句、情感） |
| **是否用 SSML** | 用与不用，MOS 差 0.3~0.5 |
| **采样率与码率** | 影响自然度 |

## 6. 工程结论

1. **TTS 三层**：文本前端 / 声学模型 / 声码器；**现代趋势是端到端合并**。
2. **FastSpeech2 的显式时长预测**是关键设计（对齐、可并行、时长可控）。
3. **BigVGAN 是当前声码器的事实标准**——自然度靠判别器结构设计，不只靠算力。
4. **Neural Codec 把音频变成 token**，这是端到端语音模型成立的技术基础。
5. **声音克隆三选一**：固定音色用说话人嵌入（快）、快速克隆用零样本、
   长期高保真用微调。
6. **零样本克隆是当前落地主流**——「几秒音频克隆一把声音」把周期从几周缩到几分钟。
7. **SSML 是被低估的确定性手段**——**确定性的东西不要交给概率模型**。
8. **必须做文本 → 发音文本的预处理**（日期、金额、缩写、邮箱），
   否则 TTS 会在业务最关键的地方读错。
9. **评测要三件套**：自然度（MOS/UTMOS）+ 相似度（SECS）+ 可懂度（ASR 回读 WER）。
   **ASR 回读最客观、可进 CI，但测不出「像不像」。**
10. **参考音频的选取是影响结果的最大变量**，报告里必须写明选取方式。
