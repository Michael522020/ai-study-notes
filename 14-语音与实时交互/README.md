# 14 · 语音与实时交互

> **让系统能「听」和「说」：识别、合成、实时对话、音频管线、场景落地。**

前面各主线讲文本。语音这条线的难点**不在模型，在工程**——
**它是一个实时系统**：延迟预算按毫秒算，打断必须处理，回声必须消除。

**它的核心判断**：

> **语音产品成败的多数问题不在「模型不够强」，而在
> 「端点切错了」「回声没消掉」「TTS 数字读错」「麦克风一直开着没提示」。**

## ⏱️ 延迟账（这是语音产品的工作底稿）

```
用户说完 → 听到第一个字 ≈ 790 ms
用户说完 → 听到完整回复 ≈ 1.2 s
```

| 环节 | 典型值 | 说明 |
|---|---|---|
| **尾点检测**（等用户说完） | 200~800 ms | **常被忽略，却往往是大头** |
| 音频前端管线 | 50~130 ms | AEC + 降噪 + AGC + VAD |
| 缓冲/分块 | 20~100 ms | 可调 |
| ASR（流式） | 100~300 ms | |
| LLM 首 token | 200~800 ms | |
| TTS 首包 | 50~200 ms | **流式 TTS 必用** |

> **「自然对话」的阈值约 800 ms；超过 2 秒用户会以为系统没听见。**
> **人类对话的自然 turn-taking 间隔约 200 ms**——这是「像真人」的物理参照。

## 🎯 四个场景，四套指标

| 场景 | **核心指标** | 最容易翻车的地方 |
|---|---|---|
| **呼叫中心** | **人工接管率**、自助解决率 | IVR 集成与录音合规 |
| **语音助手** | **响应延迟**、唤醒误触发率 | **唤醒必须离线**、打断 |
| **面试 / 培训评估** | **评分一致性**、**证据回指率** | **录音同意**、语气偏见 |
| **会议记录 / 转写** | **说话人分离准确率（DER）** | 多人重叠、多语种 |

> **混淆指标是语音项目失败的主因**——
> 拿「ASR 准确率」去验收一个「面试评分」项目，必然对不齐。

---

## 🔊 三个最容易出事的点

| # | 症状 | 根因 | 排查顺序 |
|---|---|---|---|
| **1** | **系统自己把自己打断** | **AEC 没生效** | **① AEC 参考信号取对了吗 → ② 延迟对齐了吗 → ③ VAD 阈值 → ④ 打断判定** |
| **2** | **用户说一半被切** | VAD hangover 太短 / 没有合并窗口 | ① hangover → ② 合并窗口 → ③ 语义端点 |
| **3** | **金额/日期读错** | TTS 缺文本预处理 | 建「文本 → 发音文本」规则表 |

> **顺序很重要**：**先查 AEC，再查 VAD，最后才动模型。**
> 很多团队一上来换 VAD 模型，其实问题在 AEC 的参考信号取错了点。

## 💰 成本：以「每分钟 × 解决率」对比

```
语音机器人：每分钟 $X，自助解决率 < 100%
人工坐席：  每分钟 $Y，解决率 ~85%
```

> **只讲「每分钟成本」而不讲「解决率」的对比是无意义的。**
> 而且**语音场景独有**一个省钱手段：
> **用户打断时立刻停止 TTS 合成**——已合成但未播放的部分不花钱。

## ⚖️ 合规：三条硬线

| # | 要求 | 说明 |
|---|---|---|
| **1** | **采集指示是硬要求** | 麦克风常开 = 持续采集环境音（**会录到同事谈话**）。灯光/提示音不是可选项 |
| **2** | **声音克隆必须有书面授权** | 声音具有人格利益；授权书要写明用途与期限 |
| **3** | **声纹只用于本人认证，不用于评估人** | 用语气/语速做能力评分 = 不可靠 + 易歧视（同 08 主线的敏感特征原则） |

> 本章合规部分为**工程视角梳理，不构成法律意见**；具体以适用法规与法务意见为准。

## 💡 工程结论（浓缩版）

1. **三种 ASR 架构**：Encoder-Decoder（准）、CTC（快、天然流式）、Audio-LLM（懂语气、贵）。
2. **Whisper 显式指定语言 + 给 `initial_prompt`** 是性价比最高的两个改动；
   **静音段会幻觉** → **必须先用 VAD 切静音**。
3. **流式的核心是「什么时候输出」**；LocalAgreement 比固定窗口准。
4. **流式输出天然会改口** → 推荐**双轨**（实时轨给人看、最终轨给系统用）。
5. **WER/CER 必须写清文本归一化规则**；**区分度在噪声/远场/口音**，不在安静场景。
6. **Neural Codec 把音频变成 token**，这是端到端语音模型成立的技术基础。
7. **声音克隆三选一**：固定音色用嵌入、快用零样本、长期高保真用微调。
8. **SSML 是被低估的确定性手段**——**确定性的东西不要交给概率模型**。
9. **延迟账要算全**（尾点检测往往是大头）；**「自然对话」的阈值约 800 ms**。
10. **全双工的三个硬问题**：自我打断、打断时机、上下文丢失；
    **已合成但未播放的文本不能丢**。
11. **语音 Agent 的工具调用必须「说出来」**；**高风险操作必须复述确认**。
12. **AEC 是全双工的地基**；排查自我打断**先查 AEC**。
13. **VAD 的 hangover 要大于中文的正常停顿**（300~500 ms）。
14. **采集线程绝对不能被阻塞**；四线程分离；缓冲要**可回退 N 帧**。
15. **四个场景四套指标**；**端到端失败要按环节归因**。
16. **成本按「每分钟 × 解决率」对比**；**TTS 最贵，打断即停合成是独有优势**。
17. **采集指示、声音克隆授权、声纹不用于评估人**——三条硬线。
