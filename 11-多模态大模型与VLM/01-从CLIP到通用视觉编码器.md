# 从 CLIP 到通用视觉编码器

> **核心问题**：VLM 的「眼睛」是怎么造出来的？选一个视觉编码器时该看哪几个维度？

---

## 0. 一句话定位

**视觉编码器（Vision Encoder）负责把像素变成一串「视觉 token」，交给 LLM 当上下文读。**

```
像素 (H×W×3)
   │
   ▼  [ ViT / ConvNeXt / Swin / Hiera ]
视觉 token (N 个向量)  ←── 这一层决定「模型看到什么、多精细」
   │
   ▼  [ Projector: Linear / MLP / Resampler ]
对齐到 LLM 的嵌入空间
   │
   ▼
LLM 的序列: [ 视觉 token ... | 文本 token ... ]
```

**这一章讲「眼睛」，[`02`](./02-VLM架构演进.md) 讲「脑子怎么接」。**

---

## 1. 从 CNN 到 ViT

### 1.1 CNN 的局限

| 局限 | 说明 |
|---|---|
| **分辨率不友好** | 训练分辨率固定 → 换分辨率性能下降 |
| **全局感受野成本高** | 要看到远处就得堆深层 |
| **不适合做密集特征** | 检测/分割需要逐像素特征，CNN 特征图分辨率有限 |

### 1.2 ViT 的做法

```
图像 224×224×3
   ↓ patch embedding (等价于一个 stride=patch 的卷积)
16×16 = 256 个 patch，每个 patch 展平成 768 维
   ↓ + [CLS] token + 位置编码
   ↓ Transformer Encoder ×N
257 个 token 的特征序列
```

**关键公式**（记住它，token 数几乎全靠它）：

```
视觉 token 数 N = (H / P) × (W / P) + 1
                  ↑   ↑   ↑
                图像高 patch尺寸 图像宽
```

| 输入 | patch | token 数 |
|---|---|---|
| 224×224 | 14 | 16×16+1 = **257** |
| 336×336 | 14 | 24×24+1 = **577** |
| 448×448 | 14 | 32×32+1 = **1025** |
| 224×224 | 16 | 14×14+1 = **197** |

> **分辨率翻倍 → token 数变 4 倍。**
> 这就是为什么「视觉 token 是 VLM 的主要成本来源」——
> 它直接决定 LLM 那一段的序列长度。

## 2. 四种预训练范式

**选视觉编码器，本质是选它的预训练范式。**

### 2.1 自监督（不配文本）

| 方法 | 代表 | 特点 |
|---|---|---|
| **DINOv2** | Meta | 无需文本，**密集特征好**，适合分割/深度/对应点 |
| **MAE** | Meta | 掩码自编码，视觉骨干强 |
| **iGPT** | OpenAI | 自回归预测像素 |

> **DINOv2 最大的价值**：它训出来的特征在**密集任务**（分割、深度估计、点对应）上
> 接近有监督模型。这让它成为「检测/分割类 VLM」的常用底座。

### 2.2 图文对比（CLIP 系）

| 方法 | 代表 | 特点 |
|---|---|---|
| **CLIP** | OpenAI, 2021 | 400M 图文对；**零样本分类与检索**的基座 |
| **SigLIP** | Google, 2023 | 用 sigmoid loss 替代 softmax，**不依赖全局大 batch**，训练效率高 |
| **EVA-CLIP** | Beijing Academy | 高分辨率与更细粒度的对齐 |

**CLIP 的训练要点**（这些细节解释了很多现象）：

```
一个 batch 里放 65536 个 (图, 文) 对
  → 对角线是"正样本"，其余 65535 个都是"负样本"
  → 负样本越多，模型学到的对比信号越强
```

> **SigLIP 的改进**：把「批内对比」换成「每个样本独立打分」，
> 于是**不需要巨大的 batch**——这让训练成本下降一个量级，
> 也让中小团队能训出可用的视觉编码器。

### 2.3 无标注自监督 + 文本蒸馏

**视觉语言模型自建底座时的常见做法**：先用海量无标注图片训自监督视觉编码器，
再用较小的图文对做对齐蒸馏。

### 2.4 Promptable 分割（SAM 系）

| 方法 | 代表 | 特点 |
|---|---|---|
| **SAM** | Meta, 2023 | **可提示**的分割模型；**视觉提示编码器**（Hiera）很强 |
| **SAM 2** | Meta, 2024 | 加了视频与时序 |

> **SAM 的视觉编码器常被 VLM 当底座**——因为它对**密集、细节丰富**的特征编码得好。
> 这一点在后面讲「视觉 token 数量」时很关键。

## 3. 选型维度

**选视觉编码器要看这七个维度，不是看参数量。**

| # | 维度 | 说明 | 取舍 |
|---|---|---|---|
| **1** | **预训练范式** | 自监督 / 图文对比 | 对比学习带来零样本与文本对齐；自监督带来密集特征 |
| **2** | **分辨率与 patch size** | 决定 token 数与细节粒度 | 分辨率越高 token 越多、成本越高 |
| **3** | **输出是「全局」还是「密集」** | 全局 1 个 CLS token vs 每 patch 一个 | 密集才能做定位、分割、OCR |
| **4** | **是否支持变长输入** | 固定 224 vs 动态分辨率 | 动态分辨率对文档/图表是刚需 |
| **5** | **参数量** | 常见 300M (ViT-L) / 400M (SigLIP) / 1B+ | 太大则端侧跑不动 |
| **6** | **是否已量化友好** | 有无官方 INT8/INT4 权重 | 端侧与推理成本 |
| **7** | **与 LLM 的嵌入空间距离** | 是否需要重训 projector | 差距大则要多训 |

### 3.1 全局 vs 密集：一个容易忽略的分界

```
CLIP 风格：  整张图 → 一个向量（或少量 token）
             擅长：分类、检索、整体描述
             不擅长：定位小物体、OCR、计数

DINOv2/SAM： 整张图 → N 个 patch 级特征
             擅长：定位、分割、OCR、计数、空间推理
```

> **VLM 想要的是后者**——
> 因为「回答里有几个苹果」「左边的车牌是什么」这类问题，
> 必须有**空间上可分辨的 token**。
>
> **但 CLIP 仍是主流底座**，因为它和文本对齐得好（这是 VLM 的另一半能力）。

### 3.2 实际的主流组合

| 场景 | 视觉编码器 | 理由 |
|---|---|---|
| **通用对话 VLM** | **SigLIP-SO400M** | 文本对齐强、训练效率高 |
| **文档/OCR 密集任务** | SigLIP + 高分辨率 / 加 OCR 分支 | 需要密集特征 |
| **检测/分割类 VLM** | **DINOv2 / SAM** 编码器 | 密集特征好 |
| **端侧** | 300M 级 ViT + INT8 量化 | 参数量是硬约束 |

## 4. 分辨率与细节：一个数量级账

**假设视觉编码器输出 256 个 token（224×224, patch 14）。**

| 任务 | 需要的分辨率 | 典型 token 数 | 代价 |
|---|---|---|---|
| 整体场景分类 | 224 | 257 | 最低 |
| 图像描述（粗） | 336 | 577 | 低 |
| **小物体识别** | 448~672 | 1025~2305 | 中 |
| **OCR / 文档** | 896~1344 | 4096~9216 | **高** |
| **密集标注 / 分割** | 1024~2048 | 5760~21504 | **很高** |

**LLM 那一段的序列长度 = 文本 token + 视觉 token**，所以：

```
一个 2K 文本 + 4K 视觉 token  ≈ 6K 序列
   → prefill 的 attention 计算 ∝ 6K²
   → KV Cache ∝ 6K
```

> **这就是为什么「给 VLM 塞高清图」很贵**，
> 也是 [`03`](./03-视觉token化与数量级代价.md) 要专门讨论视觉 token 预算的原因。

---

## 5. 视觉编码器在 VLM 里的地位：**一半的模型，一半的成本**

| 事实 | 后果 |
|---|---|
| 视觉编码器占 VLM 总参数的小头（300M~600M vs LLM 的 7B+） | **但它决定了视觉 token 的数量与质量** |
| 视觉编码器只前向一次，LLM 前向 N 次 | **视觉侧可以缓存** |
| 视觉编码器常被冻结 | 训练时省显存，但换任务要重训 projector |

> **一个实用推论**：
> **同一个 VLM 处理同一张图多次（比如多轮追问）时，视觉 token 应当缓存，不要重复编码。**
> 这能省掉视觉编码器的前向开销。见 [`05`](./05-VLM推理优化与端侧可行性.md)。

---

## 6. 工程结论

1. **视觉 token 数 = (H/P)×(W/P)+1**，分辨率翻倍 token 变 4 倍。
   **这是 VLM 成本的第一个乘数。**
2. **选视觉编码器看七个维度**（预训练范式 / 分辨率 / 全局 vs 密集 / 变长支持 /
   参数量 / 量化友好 / 与 LLM 的嵌入距离），不是看参数量。
3. **SigLIP 是通用 VLM 的主流底座**（训练效率高、文本对齐好），
   **DINOv2/SAM 适合密集任务**。
4. **图文对比学习依赖大 batch**（CLIP 用 65536），
   **SigLIP 用 sigmoid loss 把它降下来了**——这是中小团队能训视觉底座的前提。
5. **全局特征和密集特征是两种能力**，VLM 需要密集，但 CLIP 是主流——因为对齐更重要。
6. **视觉编码器只前向一次** → 多轮对话场景一定要缓存视觉特征。
