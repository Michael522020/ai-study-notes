# 多模态对齐训练

> **核心问题**：训一个 VLM 要多少数据、什么数据、怎么配比？显存怎么估？冻结哪些参数？

---

## 0. 先回顾：训练三阶段与它们各自要什么

| 阶段 | 数据 | 训什么 | 显存 | 输出 |
|---|---|---|---|---|
| **① 视觉-语言对齐** | 大规模弱标注图文对（百万~十亿） | **只训 Projector** | 低 | 模型学会「把视觉 token 当词读」 |
| **② 多模态指令微调** | 多模态指令数据（几万~百万） | Projector + LoRA / 全参 | 中高 | 模型学会「按指令完成任务」 |
| **③ 偏好对齐** | 多模态偏好对 | DPO / RLHF | 高 | 幻觉减少、有用性提升 |

> **大多数团队的入口是 ②**（用开源权重做指令微调）。
> 阶段 ① 只有做大模型底座的团队才做。

---

## 1. 数据：四类，缺一不可

| 类型 | 内容 | 规模量级 | 来源举例 |
|---|---|---|---|
| **A 图文对** | 图片 + 简短描述 | 百万 ~ 十亿 | CC3M/12M、LAION、COCO、SBU、Visual Genome |
| **B 多模态指令** | 图片 + 复杂指令 + 详答 | 万 ~ 百万 | LLaVA-Instruct、ShareGPT4V、ALLaVA、Cambrian、M3IT |
| **C 偏好对** | 同一问题的「更好/更差」回答 | 千 ~ 十万 | 构造或人工标注 |
| **D 纯文本** | 纯文本指令对话 | 与 B 同量级 | **LLaVA-1.5 用了 558K 纯文本** |

### 1.1 各类数据的作用

| 类型 | 解决什么问题 | 缺了会怎样 |
|---|---|---|
| **A 图文对** | 建立视觉↔语言的**基础映射** | 视觉 token 与文本 embedding 对不上 |
| **B 指令数据** | 教会**按指令完成任务**（不只是描述） | 模型只会「描述图像」，不会回答问题 |
| **C 偏好数据** | 抑制幻觉、提升有用性 | 幻觉多、啰嗦、格式乱 |
| **D 纯文本** | **防止语言能力灾难性遗忘** | **模型不会正常对话了**（见 §3） |

### 1.2 数据配比的经验值

| 场景 | 配比建议 |
|---|---|
| **阶段 ① 对齐** | 图文对 : 纯文本 = **1 : 0.1 ~ 1** |
| **阶段 ② 指令微调** | 视觉指令 : 纯文本 = **1 : 1**（LLaVA-1.5 的做法） |
| **领域微调** | 领域数据 : 通用数据 = **1 : 5 ~ 1 : 10**（**通用数据是「锚」**） |

> **领域微调时不要用 100% 领域数据**——
> 那样模型会迅速过拟合到领域窄分布上，通用能力崩溃。

### 1.3 数据质量 > 数据数量

**这是本库反复出现的那条，在多模态上同样成立。**

| 案例 | 数据量 | 结果 |
|---|---|---|
| **LLaVA-1.0** | 158K 视觉指令（大量由 GPT-4 基于 COCO 标注生成） | 基准分较低 |
| **LLaVA-1.5** | 558K 视觉 + 558K 纯文本，**质量更高** | **全面超过 1.0** |

> **LLaVA-1.5 的模型规模没有变大**，只改了数据与分辨率处理。
> **数据质量 > 数据数量**，在视觉侧同样成立。

### 1.4 合成数据：唯一能规模化的路径

**高质量多模态指令数据几乎不可能靠人工标注获得。** 主流做法：

```
① 用强模型（GPT-4 级）对已有图片生成详尽的 caption / QA
   → LLaVA-Instruct 的做法（基于 COCO 已有标注扩写）
② 用大模型互相提问生成多轮对话
   → ShareGPT4V 的做法
③ 用已有结构化标注反推指令
   → 检测框 → 「图里有什么」「它们的位置关系」
④ 合成图像 + 自动标注
```

> **关键提醒**：**合成数据会继承教师模型的偏差与幻觉**。
> 必须做**质量过滤**（长度阈值、重复率、与图像的一致性），
> 否则会把教师的错误一起学进去。

## 2. 冻结策略：四档，按成本递增

| 档 | 训什么 | 显存 | 效果 | 适用 |
|---|---|---|---|---|
| **T1 全冻结** | 只训 Projector | **最低** | 基线 | 快速验证、通用场景 |
| **T2 解冻视觉编码器最后 1/4** | Projector + 视觉后几层 | 低 | **明显提升**（小样本、细粒度任务） | **领域适配首选** |
| **T3 LoRA** | Projector + LLM 的 LoRA + 视觉 LoRA | 中 | 好 | **通用做法** |
| **T4 全参微调** | 全部 | **最高** | 最好 | 数据充足且算力够 |

### 2.1 T2 常常被低估

**「视觉编码器只训最后几层」的性价比很高**：

| 原因 | 说明 |
|---|---|
| 后几层负责**高层语义与空间关系** | 正是领域差异最大的部分 |
| 前几层是通用低级特征（边缘、纹理） | 领域差异小，冻结无害 |
| 参数量少 | 显存与优化器状态增量小 |

> **工业质检 / 医疗影像这类「视觉分布差异大」的任务，T2 常常比 T3 更划算。**

### 2.2 T3 LoRA 的标准配置

```python
# 典型配置
target_modules = [
    "q_proj", "k_proj", "v_proj", "o_proj",      # LLM 注意力
    "gate_proj", "up_proj", "down_proj",          # LLM FFN
    # 视觉编码器的对应层（如果也要训）
]
lora_r, lora_alpha = 16, 32
lora_dropout = 0.05
```

| 参数 | 建议 | 理由 |
|---|---|---|
| `r` | 8~32 | 视觉任务比纯文本需要稍大（要适配新的视觉特征） |
| `alpha` | 2×r | 常见约定 |
| **Projector** | **必须全参训** | 它本来就很小，冻结它没有意义 |
| **视觉编码器** | 最后 1/4 层或 LoRA | 见 T2 |
| **学习率** | Projector 用 1e-4 ~ 2e-4；LoRA 用 1e-4 ~ 5e-4 | Projector 是「从零学」，LoRA 是「微调」 |
| **视觉 token 预算** | 训练时和推理时**一致** | 不一致会造成分布偏移 |

> **最后一条特别容易踩**：训练用 2880 token，推理用 576，
> 模型会明显退化。**分辨率策略必须训练推理一致。**

## 3. 灾难性遗忘：必须专门处理

**现象**：只用图文对训练后，模型的**语言能力**会退化：

| 退化表现 | 说明 |
|---|---|
| 不会正常对话 | 只会描述图像 |
| 指令跟随变差 | 只会「看图说话」，不会「按要求做」 |
| 推理能力下降 | 纯文本推理题正确率显著降低 |

**解决方案：混入纯文本数据**

```
LLaVA-1.5 的配比：558K 视觉指令 + 558K 纯文本 = 1 : 1
```

**原理**：
- 纯文本样本的 loss 也会**更新 LLM 的 LoRA/全参**，
  保持语言能力的梯度不消失
- 同时避免了模型把「所有输入」都当成「要描述的图」

> **这是「领域适配不崩」的关键**：
> **微调时始终保留一定比例的通用数据（视觉 + 纯文本）作为锚。**

## 4. 训练资源估算

### 4.1 显存公式

```
训练显存 ≈ 权重 + 梯度 + 优化器状态 + 激活
```

**T3 LoRA 的典型构成（7B VLM）**：

| 项 | 计算 | 显存 |
|---|---|---|
| 权重（bf16） | 7B × 2 B | **14 GB** |
| 梯度（只有可训部分） | ~50M × 2 B | 0.1 GB |
| 优化器状态（AdamW，仅可训部分） | ~50M × 8 B | 0.4 GB |
| 视觉编码器权重（冻结，bf16） | 400M × 2 B | 0.8 GB |
| **激活** | ∝ 序列长度 × 层数 × batch | **大头** |

> **LoRA 相比全参微调省掉的是「梯度 + 优化器状态」**（全参时是 7B×10 B = 70 GB）。
> **但激活显存省不掉**——它取决于序列长度。

### 4.2 视觉 token 数对训练显存的影响

**这是 VLM 训练最反直觉的地方**：

```
激活显存 ∝ batch × (视觉 token + 文本 token) × 隐藏维 × 层数
```

| 视觉 token | 序列长度（+200 文本） | 相对激活显存 |
|---|---|---|
| 576 | 776 | 1.0× |
| 1440 | 1640 | 2.1× |
| 2880 | 3080 | **4.0×** |

> **视觉 token 从 576 涨到 2880，训练激活显存涨 4 倍。**
> 加上序列平方关系（attention），实际往往涨得更多。

**缓解手段**：
- **梯度检查点**（activation checkpointing）——用 30% 速度换大部分激活显存
- **降低微批大小 + 梯度累积**
- **降低训练时的视觉 token 预算**（但要注意 §2.2 的训推一致）

## 5. 领域微调的实战流程

**一个可执行的 checklist：**

```
① 定义清楚任务形态
   → 是「分类」还是「生成」还是「问答」？
   → 答案格式固定吗？（固定 → 可能根本不需要 VLM，见 §5.1）

② 选基座
   → 通用模型 + 领域 LoRA？还是从零训 Projector？
   → 领域视觉分布差异大 → 优先考虑 T2（解冻视觉后几层）

③ 造数据
   → 领域图片 + 高质量指令数据（合成 + 人工抽检）
   → 保留 20% 通用数据防遗忘
   → 按错误类型分层（常见 / 边界 / 困难）

④ 定评测集
   → ≥50 条金标准，双人仲裁
   → **加上基线对照**（人工 / 规则 / 现有模型）

⑤ 训练
   → 训推一致的 token 预算
   → 梯度检查点 + 梯度累积

⑥ 迭代
   → 看错误分类而不是总分
   → 每轮只改一个变量

⑦ 影子运行
   → 见 12 主线的四阶段
```

### 5.1 一个必须先问的问题

> **「这个任务真的需要 VLM 吗？」**

| 任务 | 更好的方案 |
|---|---|
| 分类固定类目 | **专用检测/分类模型**（更快、更准、更便宜） |
| 提取固定字段 | **检测器 + OCR + 文本 LLM** |
| 需要「看图回答开放问题」 | **VLM** ✅ |
| 需要精确空间定位 | **检测器 / 分割模型** + 文本 LLM 处理 |

> **VLM 的不可替代性在于「开放式视觉理解」。**
> 其余任务用 VLM 往往是**用大炮打蚊子**——成本高、精度低、不可控。

## 6. 训练过程中的评测

**评测要嵌进训练循环，不能只在最后做一次。**

| 时机 | 评什么 | 为什么 |
|---|---|---|
| **每个 epoch** | 金标准集分数 + 错误分类 | 早停、选 checkpoint |
| **每次超参改动** | 只改一个变量 | 归因 |
| **数据扩充后** | 分数 + **错误类型分布** | 分数涨了但错误类型没变 = 白做 |
| **训推一致性检查** | 训练配置 vs 推理配置的输出差异 | 见 §2.2 |

**错误分类比总分有用**：

| 错误类型 | 典型原因 | 对策 |
|---|---|---|
| **幻觉**（描述了不存在的物体） | 数据里就有幻觉 / 对齐不足 | 清洗数据 + 增加「不存在」类负样本 |
| **定位错** | 视觉 token 空间精度不够 | 提高分辨率 / 加定位类数据 |
| **OCR 错** | 分辨率不足 | OCR 分支 / 更高分辨率 |
| **格式错** | 指令数据的格式不一致 | 统一格式 + 格式约束解码 |
| **拒答/过度保守** | 负样本不足 | 加负样本 + 调整系统提示 |

## 7. 工程结论

1. **四类数据缺一不可**：图文对（映射）、多模态指令（按指令做事）、
   偏好对（抑制幻觉）、**纯文本（防语言能力遗忘）**。
2. **数据质量 > 数据数量**（LLaVA-1.5 的实证），但**领域微调要保留通用数据作锚**。
3. **合成数据是唯一能规模化的路径**，但会继承教师的偏差——必须做质量过滤。
4. **四档冻结策略里，「解冻视觉编码器最后 1/4 层」性价比最高**（T2），
   视觉分布差异大的任务尤其如此。
5. **Projector 必须全参训，视觉 token 预算必须训推一致**（不一致会明显退化）。
6. **LoRA 省的是梯度与优化器状态（70 GB 级别），省不掉激活显存**——
   而激活显存由序列长度决定，**视觉 token 从 576 到 2880 会涨 4 倍**。
7. **先问「这个任务真的需要 VLM 吗」**——
   固定类目分类、字段抽取这类任务，检测器 + OCR + 文本 LLM 更划算。
8. **评测要嵌进训练循环**，且看**错误分类**而不是只看总分。
