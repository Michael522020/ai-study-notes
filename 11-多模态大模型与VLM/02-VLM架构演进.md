# VLM 架构演进

> **核心问题**：视觉特征怎么接进 LLM？三种连接方式各有什么取舍？主流 VLM 的骨架长什么样？

---

## 0. 核心问题：怎么把「图像」变成 LLM 能读的 token

**LLM 只吃 token。图像不是 token。** 所以必须有一个「翻译器」把视觉特征映射到 LLM 的嵌入空间。

```
视觉特征 [N × d_vision]
        │
        ▼  Projector（连接器）
对齐特征 [N × d_llm]
        │
        ▼
拼进 LLM 的 token 序列
```

**Projector 有三种典型形态**，这是 VLM 架构分歧的根源：

| 方式 | 做法 | 代表 | 优点 | 缺点 |
|---|---|---|---|---|
| **① Linear / MLP Projector** | 1×1 卷积或两层 MLP，把每个视觉特征投到 LLM 空间 | **LLaVA 系列** | **最简单、最好训、最稳定** | 视觉 token 数**不能压缩**（一个不多一个不少） |
| **② Cross-Attention** | 在 LLM 的若干层插入交叉注意力层，读视觉特征 | **Flamingo** | 表达力强 | **要额外训练新层**，且每层都要读视觉特征（慢） |
| **③ Resampler / Prefix** | 用 Perceiver 类结构把 N 个视觉特征压成 M 个（固定长度） | Flamingo 的 Perceiver Resampler | **视觉 token 数可控** | 多一层结构、多一处超参 |

> **现代开源 VLM 几乎都选了 ①**。
> 原因：**简单 + 稳定 + 不增加 LLM 的推理结构**。
> ② 虽然优雅，但改动 LLM 内部会让推理框架适配变复杂。

### 0.1 为什么 MLP Projector 就够了

```
视觉特征 [N × 1024]  --MLP-->  [N × 4096]  --+-->  LLM 序列
文本 token [T × 4096]          |        |
                                └────────┴── 拼接
```

**MLP 是逐 token 独立作用的**（每个视觉 token 各自过一遍 MLP）。
这意味着：
- **不改变 LLM 的任何内部结构** → 推理框架不用改
- **训练时只需训练这一层 MLP**（几百万参数）→ 极便宜
- **视觉 token 数 = 视觉编码器的输出数** → 想减少就必须换编码器或加压缩层

> **这条性质决定了后面所有的成本讨论**：
> **视觉 token 数由编码器 + 分辨率决定，不是由 LLM 决定。**

## 1. 关键模型的演进

### 1.1 Flamingo（2022）：证明了「冻结 LLM 也能做 VLM」

```
视觉编码器 (冻结) → Perceiver Resampler → M 个视觉 token
                                        │
LLM (冻结) ←── Gated Cross-Attention 层（新增，插入若干层）
```

**贡献**：
- 证明了**不需要微调 LLM**就能做多模态
- 引入 **Perceiver Resampler**（视觉 token 数压到固定 M）
- 引入 **Gated Cross-Attention**（用可学习门控控制视觉信息注入强度）

### 1.2 LLaVA-1.0（2023）：把方案简化到极致

```
CLIP ViT-L/14 (冻结) → Linear Projector (可训练) → 视觉 token 拼接进 LLaMA 的 token 序列
```

**只训练 projector**（约 20M 参数），用 158K 视觉-语言指令数据。

> **这是整个 VLM 领域最重要的一个「 Less is More」结果**：
> **一个线性层 + 少量高质量指令数据，就超过了当时复杂的架构。**

### 1.3 LLaVA-1.5（2024）：两个关键改动

| 改动 | 内容 | 原因 |
|---|---|---|
| **① 高分辨率** | 336px 编码 → 切成 **2×2 四个局部 + 1 个全局缩略图** → 视觉 token 从 576 变成 **5×576 = 2880** | 低分辨率看不清小字、细节 |
| **② 数据升级** | 视觉指令数据从 158K 扩到 **558K 视觉 + 558K 纯文本** | **纯文本数据用于防止语言能力灾难性遗忘** |

> **② 是最容易被忽略、但极其重要的一条**：
> **纯文本数据是 VLM 训练的必需品**，它保证模型不会因为只看图文对而「忘记」怎么说话。
> 少了它，模型会变得只会描述图像、不会正常对话。

### 1.4 Qwen-VL / InternVL：把「动态分辨率」做实

| 模型 | 关键设计 | 解决的问题 |
|---|---|---|
| **Qwen-VL** | ViT + **Adapter** + LLM；**支持多分辨率**输入；动态分辨率 + 图像-文本交错序列 | **OCR 能力强**；把图像和文本放在**同一个序列**里交错（而非拼接在前后） |
| **InternVL** | 大型 InternViT + **动态切片** + **Pixel Shuffle** 降采样 | 动态分辨率下控制 token 数；**把 4 个 patch 合并成 1 个 token**（省 4 倍 token） |
| **MiniGPT-4** | **LLM-Adapter**（冻结 LLM，训轻量适配器） | 极低成本微调 |

**两个共同的关键设计**：

| 设计 | 说明 |
|---|---|
| **动态分辨率 + token 预算** | 保持宽高比，但**限制总 token 数**（比如 1024），避免长宽比极端时爆掉 |
| **Pixel Shuffle / token 降采样** | 在进入 LLM 之前把空间相邻的 patch 合并，**token 数直接降 2~4 倍** |

## 2. 训练三阶段

**几乎所有 VLM 都遵循这三阶段。**

```
┌────────────────────────────────────────────────────────────┐
│ 阶段 1：视觉-语言对齐（Pre-training Alignment）             │
│  数据：大规模弱标注图文对（百万~十亿量级）                    │
│  训练：冻结视觉编码器 + 冻结 LLM，只训 Projector             │
│  目的：把视觉特征映射到 LLM 的嵌入空间                       │
│  成本：相对低（只训几百万参数的 projector）                   │
├────────────────────────────────────────────────────────────┤
│ 阶段 2：多模态指令微调（Supervised Fine-Tuning）            │
│  数据：多模态指令数据（对话、描述、推理、OCR、定位）           │
│  训练：通常只训 Projector + LoRA，或全参微调                  │
│  目的：学会「按指令完成任务」而不是「描述图像」                │
│  成本：中等                                                 │
├────────────────────────────────────────────────────────────┤
│ 阶段 3：偏好对齐（Preference Alignment）                     │
│  数据：多模态偏好对（含「更好/更差」的答案对）                 │
│  训练：DPO / RLHF                                          │
│  目的：减少幻觉、提升有用性与安全性                            │
│  成本：高（需要构造偏好数据）                                  │
└────────────────────────────────────────────────────────────┘
```

### 2.1 一个反直觉的事实

> **LLaVA-1.5 用更少但更好的数据，超过了 LLaVA-1.0 用海量数据的效果。**
> 而且 LLaVA-1.5 的模型规模**没有变大**，只改了数据和分辨率处理。

**这再次印证了本库反复出现的那条**：**数据质量 > 数据数量**，无论视觉还是文本。

### 2.2 阶段 1 为什么训 projector 就够

```
视觉特征空间  ←→  文本嵌入空间
       两个空间一开始完全无关
              ↓
       训一个映射把它们拉近
```

**因为 LLM 本身已经知道「怎么读 token 序列」，缺的只是「怎么把视觉 token 当词来读」。**
Projector 就是干这个的——把视觉特征伪装成「LLM 认识的词」。

## 3. 现代 VLM 的组件清单

**一张表看完整：一个典型开源 VLM 由哪些零件组成。**

| 组件 | 常见选择 | 可替换性 | 说明 |
|---|---|---|---|
| **视觉编码器** | SigLIP-SO400M / InternViT / DINOv2 | 中 | 决定视觉 token 数与特征质量 |
| **连接器** | **MLP Projector**（2 层） | 低 | 决定训练成本与推理结构 |
| **token 压缩** | Pixel Shuffle / 无 / Resampler | 中 | 决定视觉 token 数量级 |
| **分辨率策略** | 固定 / 切片 / **动态分辨率** | 中 | 决定细节与 token 的权衡 |
| **LLM 骨干** | Qwen / LLaMA / InternLM | 高 | 决定语言能力与上下文长度 |
| **位置编码** | RoPE（在 LLM 侧，视觉 token 也有位置） | 低 | 沿用 LLM 的 |
| **训练数据** | 图文对 + 多模态指令 + 纯文本 | **最高** | **最大的杠杆** |
| **训练方式** | 冻结 / LoRA / 全参 | 中 | 决定显存与效果 |

> **「训练数据」是杠杆最大的一项**，也是最难获得的。
> 这条对「要不要自己训一个 VLM」是决定性的：
> **没有高质量多模态指令数据，就不要训**——去用开源权重做微调。

## 4. 架构对比表

| 模型 | 年份 | 视觉编码器 | 连接器 | 分辨率策略 | 训练数据量级 | 特点 |
|---|---|---|---|---|---|---|
| **Flamingo** | 2022 | 冻结（多种） | Perceiver Resampler + Gated Cross-Attn | 固定 | 少（精选） | 证明了「冻结 LLM 可行」 |
| **LLaVA-1.0** | 2023 | CLIP ViT-L/14 | **Linear** | 固定 336 | 158K 指令 | **「简单即有效」的代表作** |
| **LLaVA-1.5** | 2024 | CLIP ViT-L/14 336 | **MLP** | **2×2 切片 + 全局** | 558K 视觉 + 558K 文本 | 细节与指令能力大幅提升 |
| **Qwen-VL** | 2023 | ViT + Adapter | Adapter | **动态多分辨率** | 大规模 | **OCR 强**，图文交错序列 |
| **InternVL** | 2023 | InternViT | MLP + Pixel Shuffle | **动态切片** | 大规模 | **token 数省**，密集任务强 |
| **MiniGPT-4** | 2023 | 冻结 ViT | **LLM-Adapter** | 固定 | 少 | 极低成本 |

### 4.1 三个可复用的判断

| 判断 | 说明 |
|---|---|
| **连接器用 MLP 就够** | 除非你有明确的理由（要压 token 数、要更强的跨模态交互） |
| **纯文本数据不能省** | 否则语言能力退化（灾难性遗忘） |
| **视觉 token 数是架构决定的** | 编码器 + 分辨率 + 压缩层，三者共同决定 |

## 5. 一个实用判断：要不要自己训 VLM

| 情况 | 建议 |
|---|---|
| **通用对话 / 图生文** | **不要训**，用开源权重 + 微调 |
| **业务特定图像理解**（工业质检、医疗影像、农业） | **不要从头训**。用开源 VLM + **LoRA 微调 + 自建指令数据** |
| **有大量高质量多模态指令数据（十万量级以上）** | 可以考虑训 projector + LoRA |
| **要控制视觉 token 数与延迟** | 微调时改分辨率策略与压缩层，**不要重训编码器** |
| **端侧部署** | **几乎不可能自训**，用蒸馏 + 量化（见 [`05`](./05-VLM推理优化与端侧可行性.md)） |

> **最常见的错误是「从零训一个 VLM」**——
> 数据成本和算力成本都远高于收益。

---

## 6. 工程结论

1. **Projector 有三种形态**（MLP / Cross-Attention / Resampler），
   **现代开源 VLM 几乎都选 MLP**——简单、稳定、不改 LLM 推理结构。
2. **MLP Projector 的一个关键性质**：视觉 token 数由**编码器与分辨率**决定，不由 LLM 决定。
3. **LLaVA-1.5 证明了「Less is More」**：更少更好的数据 + 高分辨率处理，
   超过了更大数据量的前作。
4. **纯文本数据是 VLM 训练的必需品**，用来防止语言能力灾难性遗忘。
5. **训练三阶段**：对齐（只训 projector）→ 指令微调 → 偏好对齐。
6. **动态分辨率 + token 预算**是现代 VLM 的标配；
   **Pixel Shuffle 类降采样能直接把 token 数降 2~4 倍**。
7. **训练数据是杠杆最大的一项**，也是最难获得的——
   **没有高质量多模态指令数据，就不要自己训 VLM**。
8. **从零训 VLM 几乎总是错误选择**；微调开源权重 + 自建指令数据是正解。
