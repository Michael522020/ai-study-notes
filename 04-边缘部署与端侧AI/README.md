# 04 · 边缘部署与端侧 AI

> **从「模型跑在哪台机器上」到「模型跑在田间」：三套硬件，一条链路，两种工具链。**

前面三条主线（YOLO / 视觉检测 / RAG）讲的是**模型本身**。这一条讲的是**模型落到具体硬件上**这件事——因为同一份权重，在不同芯片上的命运完全不同：可能是 31 FPS，也可能是 0.66 FPS；可能 4 GB 磁盘就够，也可能要 20 GB 工具链。

本目录的写法和其他章节略有不同：**它按「一次真实部署」组织，而不是按知识体系组织**。数字要么标「本机实测」，要么标「转述官方公开报告值」，不混用。

## 🧭 三条主线的关系

```
        训练（AutoDL / 云端 GPU）
                 │
                 ▼
        ┌────────────────────┐
        │  Ultralytics 训练    │  ← 01-YOLO/07、02-视觉检测模型/11
        └─────────┬──────────┘
                  │ .pt
                  ▼
        ┌────────────────────┐
        │  ONNX（通用中间格式）│  ← 01-YOLO/08
        └──┬────┬────┬───────┘
           │    │    │
    ┌──────┘    │    └──────┐
    ▼           ▼           ▼
┌────────┐ ┌────────┐ ┌────────────┐
│ RKNN   │ │OpenVINO│ │ ESP-PPQ    │
│Rockchip│ │ Intel  │ │ → .espdl   │
└────┬───┘ └───┬────┘ └─────┬──────┘
     │         │            │
┌────▼────┐ ┌───▼──────┐ ┌───▼─────────────┐
│RK3588S  │ │ x86 主机  │ │ESP32-S3 / P4   │
│田间实时  │ │验证/后端  │ │值守/初筛/上报  │
└─────────┘ └──────────┘ └─────────────────┘
```

**三个转换器互不通用，量化方法也互不通用：**

| 目标 | 转换器 | 量化方式 | 关键约束 |
|---|---|---|---|
| Rockchip NPU | `rknn-toolkit2`（锁 2.3.2） | RKNN 内置 PTQ | `target_platform` 必须与 SoC 精确匹配；转换端/板端版本必须一致 |
| Intel CPU / 核显 | `openvino` / `onnxruntime` | 可选 FP16/INT8 | FP16 在无 AVX512-FP16 的 CPU 上是**负优化** |
| 乐鑫 MCU | `ESP-PPQ` | PTQ → TQT → INT16 LUT 融合 | 必须用 **RegMax=1 直回归**变体，否则图切分找不到节点 |

## 🧭 三份笔记的共同结论

1. **先问硬件能做什么，再选后端。** 没有 CUDA 就别装 CUDA 版 torch；P4 没有射频就得外挂 C6/C5；分辨率预算比模型名字更能决定可行性。
2. **计时必须多次取中位数。** 同一份代码在同一台笔记本上，延迟波动可达 **4.9 倍**（75.6–370.7 ms，见 [`01` §4.2](./01-本机部署实战-YOLO26多后端实测.md)）。任何基于单次测量的结论都不可靠。
3. **换后端后必须做一次跨后端结果对齐。** 框坐标和置信度都对比，才能把「硬件差异」和「实现 bug」分开。
4. **端侧量化成败在校准集，不在量化算法。** 朴素 int8 能把 92.3% 打到 61.7%，加约 100 张校准图能救回 89.1%。
5. **工具链本身可能是最大的成本。** ESP-IDF 完整装 15–20 GB，ESP-VISION 是 0 GB——选对框架省下的不只是磁盘。
6. **口径必须随数字一起引用。** 同一个 YOLO26n 在同一颗 P4 上，model zoo 表说 929.8 ms、例程日志说 2071 ms，差 2.2 倍。
