## 第一部分 · 板子速览

### 1. 身份与连接

| 项 | 值 | 来源 |
|---|---|---|
| 串口 / 下载口 | **COM12**（USB-Enhanced-SERIAL CH343，Type-C UART 口） | 【实测】设备管理器 |
| 芯片 | **ESP32-P4 revision v3.1** | 【实测】esptool |
| MAC | `e8:f6:0a:e2:c2:**` | 【实测】esptool |
| 晶振 | 40 MHz | 【实测】esptool |
| ROM 版本 | `esp32p4-eco6-20251011`（Build: Oct 11 2025） | 【实测】启动日志 |
| 板卡丝印 | Rev1.2 | 板卡实物 |
| 对应 IDF profile | **rev3_x**（`esp32p4_rev3_x.defaults`） | 官方 config 目录 |
| 板载协处理器 | ESP32-C6（SDIO 协议，Wi-Fi 6 / BT 5），出厂已刷好 **ESP-Hosted 从机镜像** | 【实测】一次关联成功 |
| 其它串口 | COM3~COM8 是主板/电源的「标准串口」，**不是**这块板 | 【实测】设备管理器 |

> 🔒 **脱敏说明**：本文的设备 MAC（末两字节）、WiFi SSID、局域网 IP 与作者本机绝对路径均已打码 / 占位，
> 与本仓库其它章节的公开标准保持一致（公开硬件型号与工具链版本，不公开设备标识符）。

> ⚠️ **芯片 revision 必须匹配**：丝印 Rev1.1 → P4 芯片 v1.3；**Rev1.2 → P4 芯片 v3.1**。
> 选错 profile 的固件会被 efuse 校验直接拒：
> `Min chip rev: v3.0 / Max chip rev: v3.99 / Chip rev: v3.1` → 必须用 rev3_x。

> ⚠️ **USB 跳线帽极性随板卡版本翻转**：
> Rev1.1 时 DEVICE = 1 号口 / HOST = 2~4 号口；**Rev1.2 时 HOST = 1 号口 / DEVICE = 2~4 号口**。

### 2. 硬件构成

```
ESP32-P4NRW32X（32MB PSRAM 封装内叠封 + 16MB Nor Flash）
├── MIPI-CSI 2-lane（ISP，H.264 / JPEG 1080p@30）→ OV5647 摄像头（树莓派 B 型口）
├── MIPI-DSI 2-lane → PPA / 2D DMA → DSI 触摸屏（5/7/8/10.1 寸可选）
├── 百兆 RJ45（以太网）
├── SDIO3.0 SD 卡槽
├── 4× USB-A（1 路 P4 直出 + 3 路 CH334 HUB，HOST/DEVICE 跳线帽切换）
├── USB OTG 2.0 HS 原生 Type-C
├── Type-C UART（CH343P）← 串口/下载口，COM12
├── 音频：ES8311 codec + 贴片麦克风 + 3.5mm 耳机口 + MX1.25 8Ω2W 喇叭口
├── RTC 电池座
├── PoE 模块座（任何套餐都不含，需单独购买）
└── 2×20 排针，28 个可编程 GPIO
```

**排针上直接印出的丝印**：SDA = GPIO7 / SCL = GPIO8 / TXD = GPIO37 / RXD = GPIO38

### 3. 存储与内存（启动日志实测）

| 项 | 实测值 |
|---|---|
| **PSRAM** | 32MB，厂商 `0x0d (AP)`，密度 256 Mbit，**X16 模式**，**200MHz**，`Found 32MB PSRAM device`，堆池 32576K |
| **Flash** | 16MB，厂商 c8 / 器件 4018 |
| **Flash 启动模式** | ROM 引导 **DIO**（clock div 1）；应用侧 **QIO** |
| **CPU** | 双核，**400 MHz**（`cpu freq: 400000000 Hz`） |
| **内部 SRAM** | 堆约 445 KB |
| **TCM** | 7 KB |
| **RTCRAM** | 31 KB |
| **调试口** | GPIO38 / GPIO37（与排针丝印一致） |
| **SIMD 数据对齐** | 16 字节（`SOC_SIMD_PREFERRED_DATA_ALIGNMENT`） |

> **PSRAM 在 IDF 侧只有一个选项**：`CONFIG_SPIRAM_MODE_HEX` 是 P4 的唯一模式，**不用开 8LINE**。

### 4. 外设与 GPIO 分配（官方例程默认值）

| 外设 | 引脚 |
|---|---|
| I2C / SCCB | SCL = **GPIO8**，SDA = **GPIO7** |
| SDMMC | CMD = GPIO44，CLK = GPIO43，D0~D3 = GPIO39/40/41/42 |
| 内部 EMAC | MDC = GPIO31，MDIO = GPIO52，PHY Reset = GPIO51 |
| 调试 UART | RX = GPIO38，TX = GPIO37 |

**I2C 总线实测**（自写扫描固件，2026-11-11）：GPIO7/8 这条总线上当前只有 **0x18 = 板载 ES8311 codec** 一个器件（未插摄像头时）。

- 这条总线是排针 I2C 和摄像头 SCCB **共用**的，但 I2C 支持多设备共存（地址不同即可），**不是「抢总线」**。
- **真正的约束**：外挂设备的 I2C 地址**不能撞 0x18（ES8311）或 0x3C/0x3F（OV5647）**。
- 官方 `i2c_tools` 启动会警告 `i2c.master: Please check pull-up resistances` → 上拉是板载的，外挂设备注意电平匹配。

## 第二部分 · 操作指令速查

### 7. 日常操作流

```
改代码
  ↓  ① 构建   idf.py build
  ↓  ② 烧录   idf.py -p COM12 flash
  ↓  ③ 看日志 idf.py -p COM12 monitor      （或 capture.py 抓全量启动日志）
  ↓  ④ 验证   console.py 发命令 / 串口 REPL
```

**一次到位**：`idf.py -p COM12 build flash monitor`（build → flash → 串口监视，一条命令串起来）。

### 9. esptool 指令集（v4.13.0 实测）

esptool 直接操作 flash / SRAM，不依赖 IDF 环境，适合诊断。

```bash
ESP=<IDF_TOOLS_PATH>/python_env/idf5.5_py3.11_env/Scripts/esptool.exe
$ESP --port COM12 <子命令>
```

| 子命令 | 作用 | 本板实测 |
|---|---|---|
| `chip_id` | 读芯片型号 + revision | ESP32-P4 (revision v3.1) |
| `read_mac` | 读 MAC | `e8:f6:0a:e2:c2:**` |
| `flash_id` | 读 Flash 厂商 / 器件 | Manufacturer c8 / Device 4018 / **16MB** |
| `read_flash <addr> <size> <file>` | 读 flash 到文件 | 读分区表用这个 |
| `erase_region <addr> <size>` | 擦除一块区域 | |
| `erase_flash` | 擦整个 flash | **会清掉固件和分区表** |
| `write_flash <addr> <file...>` | 写 flash（也可 `0x10000 app.bin`） | |
| `verify_flash` | 校验写入 | |
| `read_flash_status` / `write_flash_status` | 读写 flash 状态寄存器 | 查 QIO/DIO 模式 |
| `read_flash_sfdp` | 读 SFDP 表（Flash 厂商参数） | 查 PSRAM/Flash 能力 |
| `image_info <file>` | 看固件镜像头信息 | **查分段地址** |
| `make_image` / `elf2image` | 生成 / 转换固件镜像 | |
| `merge_bin` | 合并多个 bin（可指定基址） | |
| `load_ram <addr> <file>` | 把程序载入 SRAM 直接跑 | 快速验证，不写 flash |
| `dump_mem` / `read_mem` / `write_mem` | 读写内存 | 调驱动时用 |
| `get_security_info` | 读安全启动 / 加密状态 | |
| `run` | 复位运行 | |
| `version` | 版本信息 | |

> **实用组合**：
> ```bash
> # 看固件分段（决定烧录地址）
> $ESP --port COM12 image_info build/xxx.bin
> # 读回分区表核对

### 10. 本机封装脚本

#### 10.1 `idf_build.ps1`

```powershell
param([string]$Project = "<工作目录>\boardcheck")
Remove-Item Env:MSYSTEM -ErrorAction SilentlyContinue
$env:IDF_TOOLS_PATH = "<IDF_TOOLS_PATH>"
. "<IDF 源码目录>\export.ps1"

idf.py set-target esp32p4
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
idf.py build
exit $LASTEXITCODE
```

用法：`powershell -File <工作目录>\idf_build.ps1 -Project <工作目录>\announce`

#### 10.2 `idf_flash.ps1`

```powershell
param([string]$Project = "<工作目录>\boardcheck", [string]$Port = "COM12")
Remove-Item Env:MSYSTEM -ErrorAction SilentlyContinue
$env:IDF_TOOLS_PATH = "<IDF_TOOLS_PATH>"
. "<IDF 源码目录>\export.ps1"
Set-Location $Project
idf.py -p $Port flash
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
# 重开串口并脉冲 EN，把完整启动日志从头抓下来
& $py "<工作目录>\capture.py" 20 "<工作目录>\board_log.txt"
```

> 关键点：`idf.py flash` 结束时会复位，但**监视窗口会错过最前面的 ROM 引导日志**。
> 所以脚本额外调 `capture.py` 重开串口并拉一次 EN，把 `ESP-ROM:` 那几行也抓到。

#### 10.3 `capture.py` / `console.py`

```bash
# 抓 20 秒启动日志到文件（会先脉冲 EN 复位）
python <工作目录>\capture.py 20 <工作目录>\board_log.txt

# 给串口 REPL 发命令并抓回复
python <工作目录>\console.py "help" "esp_dump" <工作目录>\console_log.txt
```

两者都用 **DTR/RTS 自动复位**：DTR 拉低（释放 GPIO0）、RTS 脉冲一下（EN 复位）。
**所以烧录时不需要手按 BOOT 键。**

#### 10.4 `announce_build.ps1`（独立 build 目录版）

```powershell
param([string]$Project = "<工作目录>\announce", [string]$BuildDir = "build_fresh")
...
idf.py -B $BuildDir set-target esp32p4
idf.py -B $BuildDir build
```

### 11. 分区表与固件读取

```bash
# 1) 读分区表（0x8000 是分区表的固定位置）
$ESP --port COM12 read_flash 0x8000 0x1000 part.bin
python <IDF 源码目录>/components/partition_table/gen_esp32part.py part.bin

# 2) 看固件镜像头里的分段地址
$ESP --port COM12 image_info build/wifi_station.bin

# 3) 手动烧录（知道地址时）
$ESP --port COM12 write_flash 0x10000 build/wifi_station.bin
```

> ⚠️ **换 profile 后必须删掉旧 `sdkconfig`**——它会覆盖 `SDKCONFIG_DEFAULTS`，
> 导致你以为在用 rev3_x、实际编的是 rev1_3。**两种 profile 的产物不能互换。**
> 嫌麻烦就用 `idf.py -B build_fresh` 换干净目录重编。

### 12. 常见故障 → 对应指令

| 现象 | 先跑哪条命令 | 判读 |
|---|---|---|
| 板子认不到 | `$ESP --port COM12 chip_id` | 报 `Failed to connect` → 检查线 / COM 号 / 别的程序占着串口 |
| 固件起不来 | `python capture.py 15` | 看 `rst:0x?` 和 `SPI mode` |
| 启动报 flash 尺寸不符 | `capture.py` 里搜 `Detected size` | `Detected size(16384k) larger than the size in the binary image header(2048k)` → **sdkconfig 里 FLASHSIZE 被写成了 2MB** |
| 芯片版本被拒 | `capture.py` 里搜 `Min chip rev` | `Chip rev: v3.1` → 必须 rev3_x profile |
| 串口只有乱码 | 确认波特率 115200 + 无流控 | |
| PSRAM 没认出来 | `capture.py` 里搜 `Found.*PSRAM` | 认不出 → 检查 `CONFIG_SPIRAM_MODE_HEX` |
| WiFi 连不上 | `capture.py` 里搜 `transport:` | `retry[n]` 一直加 → C6 从机固件不匹配，需重刷 C6 |
| 板子上不了网但能 ping 通网关 | `capture.py` | 看 `sta ip:` 是否拿到，DHCP 是否成功 |
| 想知道固件占多大 | `idf.py size-components` | |
| 编译报 `Refusing to automatically delete files` | `idf.py -B build_fresh build` | 脏 build 目录，`fullclean` 拒绝删 |

### 13. 五个 MSYS 坑（必须记住）

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | Git Bash 下 `MSYSTEM` 环境变量存在 | `idf_tools.py` 直接 fatal 退出 | 在 PowerShell 里 `Remove-Item Env:MSYSTEM`（**必须 Remove，不能赋空串**），或整段走 cmd 并先 `set MSYSTEM=` |
| 2 | `idf_tools.py install esp32p4` | **静默装出空列表，退出码还是 0** | 正确写法是 `idf_tools.py install --targets esp32p4` |
| 3 | cmd.exe 在 MSYS 里 `/c` 被当路径改写 | 命令跑飞 | `MSYS2_ARG_CONV_EXCL='*' cmd.exe /c ...` |
| 4 | `idf.py set-target esp32p4` 不编译 | 以为编好了其实没有 | v5.5.4 起它只做 fullclean + 重新配置，**后面必须再跟 `idf.py build`** |
| 5 | 脏 build 目录让 `fullclean` 拒绝执行 | `doesn't seem to be a CMake build directory` | **不要去删它**，改用 `idf.py -B <新目录>` |

## 第三部分 · 指令集架构

### 14. 完整 ISA 字符串

ESP-IDF v5.5.4 的 `tools/cmake/toolchain-clang-esp32p4.cmake` 里写死：

```
--target=riscv32-esp-elf -march=rv32imafc_zicsr_zifencei_xesppie -mabi=ilp32f
```

拆开看：

| 段 | 含义 |
|---|---|
| `rv32` | 32 位寄存器宽度 |
| `i` | 基础整数指令 |
| `m` | 乘除法（MUL / DIV / REM） |
| `a` | 原子指令（A 扩展） |
| `f` | 单精度浮点（**FPU**） |
| `c` | 压缩指令（16 位） |
| `zicsr` | CSR 访问 |
| `zifencei` | 指令流同步 |
| **`xesppie`** | **Espressif 自定义扩展：PIE 协处理器指令集** |
| `ilp32f` | ABI：整数 32 位 + 指针 32 位 + 单精度浮点寄存器 |

> ⚠️ **`xesppie` 只被 GCC 支持**（IDF 源码注释原话：*PIE coprocessor assembly is only supported in GCC compiler*）。
> 用 Clang 工具链时这条扩展不可用。

### 15. 三个协处理器

`components/soc/esp32p4/include/soc/soc_caps.h`：

```c
#define SOC_CPU_CORES_NUM      (2U)
#define SOC_CPU_COPROC_NUM     3
#define SOC_CPU_HAS_FPU        1
#define SOC_CPU_HAS_HWLOOP     1
#define SOC_CPU_HAS_PIE        1
```

`components/riscv/include/riscv/rvruntime-frames.h` 给出索引：

| 索引 | 协处理器 | 宏 | 说明 |
|---|---|---|---|
| **0** | FPU | `FPU_COPROC_IDX` | 浮点单元 |
| **1** | HWLP | `HWLP_COPROC_IDX` | 硬件循环（Hardware Loop） |
| **2** | **PIE** | `PIE_COPROC_IDX` | **Espressif 自定义向量 / DSP 协处理器** |

**其它 CPU 特性**：

| 特性 | 值 |
|---|---|
| 核数 | 2（`Multicore app`） |
| 中断 | 32 个，CLIC（`SOC_INT_CLIC_SUPPORTED`），支持硬件中断嵌套 |
| 断点 / 观察点 | 各 3 个；观察点最大区域 0x100 字节 |
| PMP | 粒度 128 字节；IDRAM 分段用 PMP 实现（`SOC_CPU_IDRAM_SPLIT_USING_PMP`） |
| PMA | 支持物理内存属性 |
| 分支预测器 | 支持 |
| Lockup Reset | 支持 |
| SIMD 数据对齐 | 16 字节 |

> **已知硬件坑（IDF 直接标了）**：
> - `SOC_CPU_HAS_FPU_EXT_ILL_BUG`：EXT_ILL CSR **不支持 FLW / FSW**
> - `SOC_CPU_HAS_HWLOOP_STATE_BUG`：循环最后一条指令执行后 HWLOOP 状态不会变 DIRTY

#### 16.2 命名规则

| 后缀 | 含义 | 例 |
|---|---|---|
| `.s8` `.s16` `.s32` | 有符号 8/16/32 位 | `vadd.s32` |
| `.u8` `.u16` `.u32` | 无符号 | `vadd.u32` |
| `.ld.` | load 变体 | `vadd.s16.ld.incp` |
| `.st.` | store 变体 | `vadd.s16.st.incp` |
| `.incp` | 指针自增 | |
| `.ip` | 立即数偏移 + 后自增 | `vld.128.ip q0, a0, 0` |
| `.xp` | 寄存器偏移 + 后自增 | `vld.128.xp q0, a0, a1` |
| `.qacc` | Q 格式累加器（4×32bit） | `vmulas.s16.qacc` |
| `.xacc` | 扩展累加器（4×64bit） | `vmulas.s16.xacc` |

| `.a` | 累加到标量 | `max.s16.a` |

**寄存器**：`q0`~`q7`（向量），`qacc`（Q 累加器），`xacc`（扩展累加器）。

#### 16.3 累加器：点积的关键

```
esp.vld.128.ip   q0, a0, 0        # 取 4 个 int32 到 q0
esp.vld.128.ip   q1, a1, 0        # 取 4 个 int32 到 q1
esp.vmulas.s16.qacc  q2, q0       # q2 += q0 * q1 （Q 格式）
esp.mov.s16.qacc    q0            # 读回累加结果
```

`qacc` 是 **4 路 int16×int16 → int32 的定点乘累**，`xacc` 则是 64 位版本。
这就是 P4 做 CNN / 视觉推理的算力来源——**一条指令干 4 个乘法**。

### 17. PIE 的 CSR 与状态机

`components/riscv/include/riscv/csr_pie.h`：

```c
#define CSR_PIE_STATE_REG      0x7F2
```

**低 2 位的状态编码**：

| 编码 | 状态 | 含义 |
|---|---|---|
| `00` | OFF | PIE 关闭 |
| `01` | Initial | 初始态 |
| `10` | Clean | 干净（上下文无需保存） |
| `11` | Dirty | 脏（上下文已改，切换任务前需保存） |

**使能 / 关闭**（`components/riscv/include/riscv/rv_utils.h`）：

```c
FORCE_INLINE_ATTR void rv_utils_enable_pie(void)  { RV_WRITE_CSR(CSR_PIE_STATE_REG, 1); }
FORCE_INLINE_ATTR void rv_utils_disable_pie(void) { RV_WRITE_CSR(CSR_PIE_STATE_REG, 0); }
```

### 18. PIE 与 FreeRTOS 的上下文管理（重要）

FreeRTOS 的 RISC-V port 里有专门的 PIE 保存/恢复例程
（`components/freertos/FreeRTOS-Kernel/portable/riscv/portasm.S`）：

```asm
generate_coprocessor_routine pie, PIE_COPROC_IDX, pie_enable, pie_save_regs, pie_restore_regs
```

对应 CSR 操作：

```asm
csrw  CSR_PIE_STATE_REG, \scratch_reg     # 写 PIE 状态
csrrw \reg, CSR_PIE_STATE_REG, zero       # 读出旧状态并清零
```

**用 PIE 的三条硬规则**：

1. **用了 PIE 的任务会被钉在某个核上**。
   IDF 源码注释原话：*If the task is not pinned on any core, it didn't use any coprocessor than need to be freed (FPU or PIE).* → PIE 上下文是 per-core 的，不绑核会出问题。
2. **PIE 寄存器上下文在任务切换时自动保存/恢复**（`pie_save_regs` / `pie_restore_regs`）。
   官方测试 `test_pie_in_task.c` 就是验证这件事：3 个任务 × 2 个核 × 5 轮迭代，
   每个任务算完向量加法后阻塞、让出 CPU，验证切回来时 PIE 上下文没串。
3. **`SOC_CPU_HAS_HWLOOP_STATE_BUG`**：循环最后一条指令后 HWLOOP 状态不会置 DIRTY ——
   如果你在 ISR 里用硬件循环，注意这个行为差异。

### 19. 内联汇编实例

**官方参考实现**（ESP-IDF `components/freertos/test_apps/freertos/port/test_pie_routines.S`，Apache-2.0，此处仅摘录 6 行作为语法示例）：

```asm
    .text
    .align 4
    .type pie_vector_signed_add, @function
    .global pie_vector_signed_add
pie_vector_signed_add:
    esp.vld.128.ip  q0, a0, 0     # q0 = *(128bit*)a0
    esp.vld.128.ip  q1, a1, 0     # q1 = *(128bit*)a1
    esp.vadd.s32    q2, q0, q1    # q2 = q0 + q1
    esp.vst.128.ip  q2, a2, 0     # *(128bit*)a2 = q2
    ret
```

C 侧调用：

```c
extern void pie_vector_signed_add(const int32_t a[4], const int32_t b[4], int32_t dst[4]);
```

#### 19.2 ⚠️ 一个实测发现的坑

**IDF 自己那份 `xesppie.S` 参考指令表，有 2 条指令用当前工具链汇编不过**：

```
Error: bad value for offset_256_2, must be in range -256..254 with step 2
Error: illegal operands `esp.vldbc.16.ip q0,x8,-512'
Error: bad value for offset_256_1, must be in range -128..127 with step 1
Error: illegal operands `esp.vldbc.8.ip q0,x8,-512'
```

逐条实测结果：

| 指令 | 结果 | 说明 |
|---|---|---|
| `esp.vldbc.16.ip q0,x8,-512` | ❌ **FAIL** | 16 位变体偏移范围是 −256..254（步长 2），−512 超界 |
| `esp.vldbc.8.ip q0,x8,-512` | ❌ **FAIL** | 8 位变体偏移范围是 −128..127（步长 1），−512 超界 |
| `esp.vldbc.32.ip q0,x8,-512` | ✅ OK | 32 位变体偏移范围更大，允许 −512 |
| `esp.vldbc.16.ip q0,x8,-256` | ✅ OK | |

> 也就是说：**这 360 条指令不是全部都能直接用**，偏移量有分档限制。
> 官方那份 `.S` 是给 gdbstub 生成译码表用的，没在编译期跑过完整汇编。
> 写自己的 PIE 代码时，**先拿汇编器试一遍**，别照抄 `.S` 文件。
