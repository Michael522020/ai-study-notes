# 农业病虫害监测方案选型

> **核心问题**：农业病虫害监测该用什么模型、什么硬件、什么数据集？三套设备怎么分工？

本章是一次方案讨论的沉淀。核心结论先行：**"农业病虫害监测"其实是两个完全不同的任务，选型第一步是把它们分开。**

**数据口径**：本章数字主要转述自公开论文与官方仓库（PlantVillage / IP102 官方仓库、Springer / PLOS ONE / Frontiers 等期刊论文、ESP-DL 官方模型库），**未在本机复现**。涉及本机实测的部分已单独标注。

---

## 1. 第一步：分清三种任务形态

| 任务形态 | 输入 → 输出 | 模型 | 该用哪台 | 已知实测 |
|---|---|---|---|---|
| **病害分类** | 整张叶图 → 病名 | MobileNetV3 / MobileNetV2 分类器 | **ESP32-S3 就够** | 番茄 5 类 **94.6%**（~500 ms/帧）；MobileNetV3-Small 在 PlantVillage 14 物种上 INT8 后仍 **99.50%**；稻病 **92.73%** |
| **虫害检测** | 叶面图 → 虫的位置（框） | YOLO26n / YOLO11n 检测器 | **RK3588S 或 x86 主机** | ESP32-S3 上 YOLO26n 320×320 仅 **6.2 s/帧**（mAP@50 0.764）；ESP32-P4 640×640 是 **1.5 s/帧** |
| **定位 + 定种**（级联） | 图 → 框 → 裁剪 → 物种 | 检测 + 分类串联 | RK3588S 或主机 | 公开方案：YOLO11n（478 KB INT8，mAP@50 **56.4%**）定位 → MobileNetV2 分类 **99.8%** |

### 1.1 为什么必须分开

- **信息量差一个量级**：分类的输入是一张 224×224 的叶图；检测要处理整幅画面并定位目标，激活图和算子开销都大一截。
- **可部署性差一个量级**：ESP32 能舒服地跑分类器，跑检测器就只能"秒级一帧"。
- **数据集完全不同**：分类数据集（PlantVillage）没有检测框；检测数据集（IP102）类别多、长尾严重、标注成本高。

> **常见错误**：拿 PlantVillage 训完分类器，发现"检测不到虫在叶子的哪个位置"，于是以为检测模型效果差——其实是数据与任务都不匹配。

### 1.2 ESP32 在农业场景的合理定位

**病害分类**。理由：图像小（224×224）、类别少（3–10 类）、需要联网报警、要求低功耗低成本。这些正好是 ESP32-S3 的甜区。

**虫害定位必须上 RK3588S**（6 TOPS NPU）。ESP32 上做定位不是不行，是没有实用价值：6.2 s/帧 的延迟意味着"看到虫"到"看到虫在哪"之间隔着 6 秒。

## 2. 三套硬件的分工

| 设备 | 角色 | 理由 |
|---|---|---|
| **x86 主机**（i5-13500H + Iris Xe 核显） | 数据集整理与标注、后端推理验证（YOLO26n 核显 31.1 FPS）、给 ESP32 出 `.espdl`、后端复核 | 核显加速足够快，详见 [`01-本机部署实战`](./01-本机部署实战-YOLO26多后端实测.md) |
| **RK3588S**（LubanCat-4，6 TOPS NPU） | 田间实时部署 | 唯一能跑实时检测的选项；复用已有的 YOLOv8n→RKNN 流程（`rknn-toolkit2` 锁 2.3.2） |
| **ESP32-S3 / P4** | 值守节点：定时抓拍 + 初筛 + 异常上报 | 低功耗低成本，适合"无人值守 + 有事才上报" |
| **AutoDL / 云端 GPU** | 训练 | 本机 CPU 训不动 |

> ⚠️ **未验证项**：YOLO26 的端到端头（One2One + RegMax=1）与 RKNN 转换器的兼容性**尚未验证**。
> YOLO11n / YOLOv8n 的 RKNN 流程是已跑通的，但换模型结构不等于换权重——做之前必须先做一次最小可行性验证。
> 参见 [`../01-YOLO/08-导出部署与推理加速.md`](../01-YOLO/08-导出部署与推理加速.md) 关于「DFL 是 INT8 的头号敌人」与「优先选无 DFL 的模型」的结论。

## 3. 数据集选型

| 数据集 | 规模 | 标注 | 用途 | 关键坑 |
|---|---|---|---|---|
| **PlantVillage** | 54,306 图 / 38 类 / 14 物种 | **只有分类标签，无框** | 病害分类 | 背景是"棚拍级"干净，叶片占画面 70%+；`leaf_grouping/` 里**同一片叶有多张照片** → **必须按 leaf 级划分**，随机按图划分会数据泄漏 |
| **IP102** | 75,222 图 / 102 类 | 约 19,000 张带框 | 虫害检测 | **只有约 1/4 的图有框**；FPN 基线仅 **AP 28.10**；最小类 173 张 / 最大类 1,115 张，**长尾极重**；图像来自搜索引擎与虫学网站，背景杂乱、有水印 |
| **AI Challenger 2018 农作物病虫害** | 病害 21 类 + 害虫 548 类，约 3 万张带框 | 带框 | 检测 | 官方站点已下线，只能找镜像站（该数字来自二手汇总，一手页面未找到） |

### 3.1 PlantVillage 的两个细节

**① 变体选择**：官方提供 Color / Grayscale / Segmented 三个版本。
- Color —— 做检测/分类的默认选择
- Grayscale —— **丢掉颜色线索**，而叶斑、晚疫的颜色恰恰是最强特征，不建议
- Segmented —— 理想化边缘，现实泛化差

**② 类别不平衡**：部分病害类的健康样本数是病样本的约 3 倍，划分时要用分层采样。

### 3.2 IP102 为什么难

102 个**物种级**子类，且同一物种的不同龄期（卵 → 幼虫 → 蛹 → 成虫）外观差异极大。官方基线：分类 ResNet-50 只有 **49.48%** 准确率，检测 FPN 只有 **AP 28.10**。

这是个**难任务**，不是"拿来就能训 90% mAP"的数据集。

### 3.3 选型建议

> **分类**：直接用 PlantVillage，能出 94%+ 的漂亮数字，适合做课程/毕设。
>
> **检测**：**自己标一个小而干净的数据集**——单一作物、3–5 种目标、几千张。宁可数据少但干净，也别硬啃 IP102 的 102 类长尾。

参考：IP102 的下游研究里，**只取 9,663 张水稻害虫图 / 8 个类别**，用 YOLOv8 + CBAM + BiFPN 做到 **mAP@0.5 = 98.8%、mAP@0.5:0.95 = 78.6%**。**做减法比做加法有效**。

## 4. 量化陷阱（做端侧必读）

ESP32 只有 320 KB SRAM，INT8 是强制的。但**朴素量化会直接毁掉模型**：

```
float32                92.3%
朴素 int8（不校准）     61.7%   ← 掉了 30 个点，模型等于废了
PTQ + 约 100 张校准图   89.1%
```

两条硬规则：

1. **一定要用校准集做 PTQ**，100 张左右即可覆盖动态范围。校准集要覆盖实际部署环境的光照与背景。
2. **剪枝之后不要直接量化**，要先微调几轮，否则输出会塌成 0。

另外 RGB565 模拟输入会显著降低训练分布多样性（公开研究里 RGB565 模拟使训练方差下降 35%），量化前要考虑这个输入格式差异。

> 对照：ESP-DL 的 YOLO26n 官方 INT8 模型 640 输入 mAP50-95 = **0.387**，而 YOLO26n 原版五档区间下界是 40.9 mAP——**官方那套 PTQ→TQT→LUT 流水线把量化损失压到了约 2 个点**。差别不在模型，在流水线。详见 [`02-ESP32端侧视觉栈`](./02-ESP32端侧视觉栈-ESP-VISION与ESP-DL.md) §4。

## 5. 推荐的架构：P4 只做值守

单机 P4 做全部分析不现实，但做**值守节点**很合适：

```
┌─ 田间 P4（低功耗，自太阳能/电池）─────────────┐
│  定时抓拍（几分钟一张）                        │
│    → 检测 / 分类                              │
│        ├─ 无异常 → 丢弃                        │
│        └─ 有异常 → 上传原图 + 框 + 类别        │
└────────────────────┬───────────────────────────┘
                     │
┌─ 后端（x86 主机 / AutoDL）────────────────────┐
│  大模型复核 → 农技建议 → 告警推送               │
└────────────────────────────────────────────────┘
```

这样 P4 负责 7×24 值守和初筛，重活丢给后端。**田间本来也不需要连续视频**——多数做法是定时抓拍，1 FPS 足够。

若确实需要连续视频流，ESP-VISION 提供硬件 H.264 编码 + RTSP，可以把原始流推到后端，在后端跑重模型。

## 6. 还需确认的问题

这三个答案会改变选型，在动手前必须定下来：

| # | 问题 | 为什么重要 |
|---|---|---|
| 1 | **课程/毕设项目，还是真实田间部署？** | 前者选"能出漂亮数字"路线（分类 + PlantVillage）；后者数据采集成本往往比模型选择重要得多，选型完全不同 |
| 2 | **手上有哪块 ESP32 板子？**（P4X-EYE / P4X-VISION / 自制） | 决定固件与烧录路径；自制板还要先确认 PSRAM 配置 |
| 3 | **检测什么？** 单作物少数几种，还是多作物多类别 | 直接决定用公开数据集还是自标数据，也决定模型规模 |

## 7. 工程结论

1. **先拆任务，再选型。** 病害分类和虫害检测是两个任务、两套数据、两种硬件。没有"一套方案通吃"。
2. **ESP32 适合病害分类，不适合虫害定位。** 6.2 s/帧 的检测延迟在实用场景里没有意义。
3. **数据质量胜过数据数量。** 一个小而干净的标注集，比 IP102 102 类长尾更容易训出能用的模型。
4. **PlantVillage 必须按 leaf 级划分。** 官方目录里同叶多图是真实存在的数据泄漏源。
5. **量化的成败在校准集，不在量化算法。** 朴素 int8 能把 92.3% 打到 61.7%。
6. **用级联换准确率。** 检测定位 + 小分类器定种，比一个模型端到端搞定更省算力，实测里分类环节能做到 99.8%。
7. **P4 的定位是"值守 + 初筛 + 上报"。** 让它做全部分析是把 0.66 FPS 的设备当服务器用。
