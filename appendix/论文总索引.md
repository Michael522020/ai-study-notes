## 1. 跨主线的六大技术谱系

检测、RAG、Agent、本地推理看起来是四个领域，但它们共用同一批底层机制。
**按谱系读，比按领域读快得多。**

### 1.1 注意力与位置编码族（横跨 02 / 06 / 09 / 11）

```
Scaled Dot-Product (2017)
   └─> Multi-Head (2017)
         ├─> EfficientViT: 头维度缩减 (2022)
         ├─> MQA / GQA (2019 / 2023) ──> 长上下文与推理显存的关键
         ├─> SwiGLU + GEGLU (2020) ──> FFN 侧
         └─> FlashAttention (2022) ──> 算子层，不改数学
位置编码：
   正弦绝对 (2017) ──> 可学习 (2018) ──> 相对 (2019) ──> ALiBi (2022)
        └─> RoPE (2021) ──> NTK-aware / YaRN (2023) ──> 长上下文外推 (2024)
```

| 代表论文 | arXiv | 在本库的哪条主线 | 它解决的问题 |
|---|---|---|---|
| Attention Is All You Need | 1706.03762 | 06 / 09 | 一切的起点 |
| Multi-Query Attention | 1911.02150 | 09 | KV Cache 显存直接砍 4~8 倍 |
| Grouped-Query Attention (GQA) | 2305.13245 | 09 | MQA 的质量折中，工业界主流 |
| RoPE | 2104.09864 | 06 / 09 | 相对位置 + 长度外推友好 |
| YaRN | 2309.00071 | 09 | RoPE 的长度插值外推 |
| ALiBi | 2108.12409 | 06 | 无位置嵌入的线性偏置方案 |
| FlashAttention | 2205.14135 | 09 | 显存 O(N) 而非 O(N²) |
| SwiGLU / PaLM | 2204.02311 | 06 | FFN 激活函数与门控 |

> **读法**：MQA → GQA → RoPE → YaRN 这四篇构成一条完整的「现代开源模型配置说明书」。
> 读完能解释为什么同一个模型在 4K 上正常、在 32K 上胡言乱语。

## 5. 读论文的方法与停止条件

### 5.1 三遍法（适配本库风格）

| 遍 | 时间 | 做什么 | 停止条件 |
|---|---|---|---|
| **第一遍** | 10 分钟 | 读标题 / 摘要 / 图 1 / 图 2 / 结论 | 能用一句话说出「它声称解决了什么」 |
| **第二遍** | 1 小时 | 读方法章 + 核心图 + 实验表头 | 能说出「它的关键假设是什么」 |
| **第三遍** | 3 小时 | 只读与你任务相关的部分 + 附录 | 能说出「它在什么条件下会失败」 |

**大多数论文只需要第一遍 + 第二遍。** 第三遍只在你需要复现或改它时才做。

### 5.2 带着问题读

从 [`02/14`](../02-视觉检测模型/14-论文全景索引.md) §4 抄这个模式：
**「读的时候只问自己一个问题」**。

| 论文 | 只问这一个 |
|---|---|
| Focal Loss | γ 到底解决了什么？ |
| DETR | 匈牙利匹配为什么导致收敛慢？ |
| GQA | 相比 MQA 牺牲了什么？ |
| YaRN | 外推的边界在哪？ |
| Power of Noise | 噪音为什么比覆盖不全更致命？ |

### 5.3 什么时候停止读论文

**信号（满足任一就停）**：

1. 你能在**自己的数据上**复现基线，且能解释 80% 的 bad case。
2. 你已经能**判断一篇新论文是真改进还是换皮**——检测领域有明确的五个核心矛盾，
   新论文必须声称解决其中之一，否则不用读。
3. 你能向别人**解释清楚**你用的方案为什么这么选、代价是什么。

**反面信号（说明还没读够）**：

- 看到新 SOTA 数字就想换方案
- 说不清自己方案的失败模式
- 论文只看了摘要就开始写实现

### 5.4 读论文 vs 读代码

> **读论文的 ROI 在第三遍就见顶，读代码的 ROI 几乎不见顶。**

| 你要什么 | 读什么 |
|---|---|
| 理解一个**概念** | 论文第一遍 + 二遍 |
| 理解一个**指标的口径** | 官方仓库的 eval 脚本 |
| 理解**超参默认值** | 官方仓库的 `hyp.yaml` / config |
| 理解**边界条件与坑** | 官方仓库的 issue tracker + 源码注释 |
| 复现 | 论文第三遍 + 源码 |

## 8. 工程结论

1. **按谱系读，不按主题读。** 主题读会让你以为注意力、MQA、KV Cache 是三个东西，
   它们是同一个东西的三个层面。
2. **角色的清单比主题的清单有用。** 「要解决一个具体故障」永远比「想了解 X 领域」更可执行。
3. **第二遍就够大多数论文。** 第三遍留给复现。
4. **论文的价值排序是：官方代码 > 论文正文 > 官方 README > 摘要。**
5. **时效台账必须存在。** AI 领域 18 个月的结论就可能过期，
   一份不带日期和状态的文献表比没有更危险。
6. **看到新 SOTA 先问：它解决了哪个旧矛盾？** 答不上来就是换皮。
