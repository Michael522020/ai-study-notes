# 数据集与许可索引

> **核心问题**：我要用的数据集能不能商用？模型权重能不能商用？产品里能不能放原始图片？
> 这三件事是**不同的**，混在一起就会在上线前一天被法务拦下。

---

## 0. 先把三件事分开

这是本索引最重要的一页。90% 的「数据集能用吗」问题，是这三层混在一起导致的。

```
┌─ 第 1 层：数据集的许可 ────────────────────────────────┐
│  「我下载的数据允许我做什么」                           │
│  例：COCO 标注 CC BY 4.0 → 可商用，需署名                │
└────────────────────────────────────────────────────────┘
                        ↓ 训练
┌─ 第 2 层：图像/内容的版权 ────────────────────────────┐
│  「数据里的每一张图，版权人允许我做什么」                 │
│  例：COCO 图像来自 Flickr，各图版权独立                   │
└────────────────────────────────────────────────────────┘
                        ↓ 训练得到
┌─ 第 3 层：模型权重的许可 ────────────────────────────┐
│  「我训练/蒸馏出来的权重，允许我做什么」                 │
│  例：Ultralytics AGPL-3.0 / 企业授权                     │
│  例：SA-1B 训练出的模型 → 多数司法辖区认为不受 NC 约束     │
│      （但存在争议）                                      │
└────────────────────────────────────────────────────────┘
                        ↓ 部署
┌─ 第 4 层：产品与分发 ─────────────────────────────────┐
│  「我把模型和结果交付给客户，交付什么」                   │
│  例：不能把原始图片打包进产品                            │
│  例：SaaS 交付 vs 私有化部署 vs 权重交付 → 义务不同       │
└────────────────────────────────────────────────────────┘
```

| 问题 | 答案在哪一层 |
|---|---|
| 我能用 COCO 训练商用模型吗？ | 第 1 层看标注许可，**第 2 层看图像版权** |
| 我能把 YOLO 权重打进产品吗？ | 第 3 层（Ultralytics 是 AGPL-3.0） |
| 我能把训练图片随产品一起交付吗？ | 第 4 层（通常不行） |
| 我用 NC 数据集训的模型能卖吗？ | 第 1 → 3 的传递性，**有争议，见 §9** |

> **本文档只收录公开数据集与开源组件的许可信息，不构成法律意见。**
> 真实商用前请让法务逐项确认。

## 1. 许可类型速查

| 标识 | 全称 | 允许商用 | 允许改 | 需署名 | 传染性 | 典型代表 |
|---|---|---|---|---|---|---|
| **MIT** | — | ✅ | ✅ | 需保留版权声明 | 无 | Ultralytics 周边工具、ADE20K |
| **Apache-2.0** | — | ✅ | ✅ | 需保留声明 + 变更说明 | 无（专利授权） | OpenDriveLab/BEV 仓库、多数学术代码 |
| **BSD-3-Clause** | — | ✅ | ✅ | 需保留声明 | 无 | PyTorch 生态部分组件 |
| **GPL-3.0** | GNU GPL | ✅ | ✅ | 需 | **强**：衍生作品须开源 | 部分推理框架 |
| **AGPL-3.0** | GNU Affero GPL | ✅ | ✅ | 需 | **最强**：网络服务也须开源 | **Ultralytics** |
| **CC BY 4.0** | Creative Commons Attribution | ✅ | ✅ | **必须署名** | 无 | COCO / Open Images / LVIS 标注 |
| **CC BY-SA 4.0** | — | ✅ | ✅ | 需署名 + 衍生须同许可 | 弱 | DOTA |
| **CC BY-NC 4.0** | NonCommercial | ❌ **仅非商业** | ✅ | 需 | 无 | **Objects365 / SA-1B** |
| **CC BY-NC-SA 4.0** | — | ❌ | ✅ | 需 + 同许可 | 弱 | DOTA / Mapillary |
| **ODC-BY** | Open Data Commons | ✅ | ✅ | 需署名 | 无 | 部分工业数据集 |
| **非商业研究** | Research Only | ❌ | ⚠️ 多数不允许 | — | — | **ImageNet / Cityscapes / nuScenes / BDD100K** |
| **需申请授权** | 需签署协议 | ⚠️ 逐案 | ✅ | ✅ | — | 商业影像库、部分医疗数据 |

### 1.1 最容易踩的三个坑

| 坑 | 表现 | 规避 |
|---|---|---|
| **「非商业」被当成「研究用」** | 「非商业研究」≠「免费」≠「学术」 | 你的公司有盈利业务 → 直接按**商业**判定，不要自欺 |
| **署名条款被忽略** | CC BY 要求署名，作者常因此起诉 | 建立**署名清单**，随产品或文档发布 |
| **数据集许可 ≠ 依赖的库许可** | 数据集 MIT，但推理框架是 AGPL | 两条线**分别**查，见 §7 |

## 7. 医疗 / 工业 / 农业（业务私有数据区）

这些是**你做业务落地时真正会碰到的许可形态**，公开资料里查不到。

| 数据形态 | 典型许可形态 | 获取方式 | 风险 |
|---|---|---|---|
| **医院影像（DICOM）** | 患者知情同意 + 医院伦理委员会审批 + 数据出院需脱敏 | 医院科研合作 | ⚠️ **最高**。同时受《个人信息保护法》《医疗卫生机构网络安全管理办法》约束 |
| **医学分割模型权重** | 部分开源模型权重为 **NC（非商业）** | 例如 TotalSegmentator 的部分权重 | ⚠️ 权重非商业 → 商业部署受阻 |
| **工业缺陷数据** | 客户数据，**所有权属客户** | 客户授权 | 无授权不得外传、不得用于其他客户 |
| **农业遥感/虫情数据** | 混合：政府公开数据 + 自采 | 公开源 + 自采 | 公开源需逐项确认 |
| **标注数据** | 标注员的**著作权归属**需在合同里写清 | 外包标注 | 常被忽略，纠纷高发 |

> **实例（真实工程形态）**：某医学影像项目开源了合规实现，
> 其使用的第三方分割模型权重里**有一部分是 NC 条款**。
> 结果是：**代码可商用，权重不可商用**——必须在交付前把权重的许可链逐一列出来。
> 典型做法是产出 [`THIRD-PY.md` 风格的第三方许可清单]，由 CI 校验。

### 7.1 私有数据的四道闸（落地检查）

```
① 授权闸：这份数据能用于什么用途？书面授权范围是什么？
② 脱敏闸：直接标识符（姓名/住院号/MAC）是否已移除？
③ 留存闸：训练用副本存哪、多久、谁能访问？
④ 产出闸：模型权重、评测报告、截图是否含可回推的原始信息？
```

## 8. 模型权重与第三方组件许可

**数据集许可管的是训练输入，组件许可管的是你的产品代码。两者查同一个表会漏。**

| 组件 | 许可 | 商用注意 |
|---|---|---|
| **Ultralytics (YOLO)** | **AGPL-3.0** | ⚠️ **最大坑**。闭源商用需企业授权；开源 SaaS 也会触发 AGPL 的网络条款 |
| **MMDetection / OpenMMLab** | Apache-2.0 | ✅ 商用友好 |
| **PyTorch** | BSD-3-Clause | ✅ |
| **ONNX Runtime** | MIT | ✅ |
| **TensorRT** | NVIDIA EULA | ⚠️ 非纯开源，含分发限制 |
| **RKNN-Toolkit2** | Apache-2.0（工具） | 工具可商用，但 **RKNN 格式/模型在 NPU 上的再分发**需看 Rockchip 条款 |
| **OpenVINO** | Apache-2.0 | ✅ |
| **llama.cpp / GGUF** | MIT（代码） | ⚠️ **Llama 系模型权重有独立许可**，不是 MIT |
| **vLLM / SGLang** | Apache-2.0 | ✅ |
| **HuggingFace Transformers** | Apache-2.0 | ✅ 库是，**模型不是** |
| **ESP-DL / ESP-VISION** | 见各自仓库 | ESP-DL 依赖的 TFLite Micro 走 Apache-2.0 |
| **Qwen / LLaMA / GLM 等权重** | 各有独立开源协议 | ⚠️ **常见 7B+ 有月活门槛**，商用前必读 |
| **SAM 权重** | Apache-2.0 | ✅ |
| **TotalSegmentator 部分权重** | **NC** ⚠️ | 商业部署受阻 |

### 8.1 组件许可的三个必查项

1. **代码许可**（这个仓库）— MIT/Apache 通常没问题
2. **权重许可**（下载的那个 .pt/.safetensors）— 常常不一样
3. **依赖的传递依赖** — 一个 AGPL 依赖会污染整个发布方式

> **落地做法**：建一个 `THIRD-PARTY.md`，由脚本从 `requirements.txt` / `package.json` +
> 模型清单生成，**CI 校验它与实际依赖一致**。人工维护的许可清单一定会漂移。

## 9. 三层传递性：争议点与行业现状

### 9.1 NC 数据集训练出的模型，能不能商用？

| 立场 | 主张 | 现状 |
|---|---|---|
| **数据不传染** | 模型权重是「派生作品」而非「改编作品」，不继承数据许可 | 多数商业模型的默认立场 |
| **数据传染** | 训练构成「使用」，模型是衍生品 | 学术界少见，但存在判例讨论 |
| **折中** | 模型可商用，但**不得再分发数据集或数据集派生** | 实践中最常被接受 |

> **工程结论**：没有普适答案。**不要自己判断**，让法务按「你的司法辖区 + 你的分发形态」出结论。
> 你能控制的是：**优先选可商用数据**（COCO / Open Images / 自采 / MIT 类），
> 把 NC 数据只用于**内部研究**。

### 9.2 交付形态决定义务

| 交付形态 | 义务 |
|---|---|
| **私有化部署**（代码装在客户机房） | AGPL 义务通常**不触发**（无网络服务），但客户可能要求源码 |
| **SaaS / 网络服务** | ⚠️ **AGPL 触发网络条款**，需提供完整源码 |
| **交付权重 / 交付 exe** | 需附许可声明与源码（若 AGPL） |
| **交付 API 调用** | 你是服务提供方，义务最重 |

## 10. 落地检查清单

### 10.1 项目启动时（选数据阶段）

- [ ] 每个候选数据集的**标注许可**已记录（含版本号，许可会变）
- [ ] 每个候选数据集的**图像来源**已确认，不是「标注文档写了 CC BY 就算图像也是」
- [ ] 是否存在**人脸/车牌/病历/身份证**等敏感信息
- [ ] 客户数据的**所有权与授权范围**是否书面明确
- [ ] 是否需要**数据出境**（→ 单独合规评估）

### 10.2 训练完成后（上线前）

- [ ] 训练用数据集清单 + 许可快照已归档
- [ ] 模型权重文件头已写明训练数据来源
- [ ] 第三方组件许可清单已生成，且**与实际依赖一致**（CI 校验）
- [ ] **AGPL 类依赖已排查**（`pip-licenses` / `license-checker`）
- [ ] 权重许可（不是代码许可）已确认
- [ ] 评测报告与截图不含可回推的原始个人信息
- [ ] **原始图片不会被打包进交付物**
- [ ] 署名清单已准备（如涉及 CC BY）

### 10.3 每次依赖升级时

- [ ] `requirements.txt` / `package-lock.json` 的 diff 已审
- [ ] 新增依赖的许可已确认（**自动扫描 + 人工确认新出现的项**）
- [ ] 许可清单已重新生成

## 11. 常见误区速查

| 误区 | 事实 |
|---|---|
| 「非商业 = 免费」 | 非商业 **≠** 免费；免费 **≠** 可商用 |
| 「数据集是 CC BY，模型就是 CC BY」 | 模型权重是**独立许可**，数据集许可不自动附着 |
| 「代码是 MIT 就没事」 | 依赖树里的 AGPL 会传染整个分发方式 |
| 「Ultralytics 开源了就能随便用」 | **AGPL-3.0**，闭源商用需授权 |
| 「HuggingFace 上的模型都是 Apache-2.0」 | 库是，**模型各自不同** |
| 「标注数据没有版权问题」 | 标注员对标注成果通常**有著作权**，看合同 |
| 「只要我脱敏了就能用」 | 脱敏不改变**原始数据的取得合法性** |
| 「模型能商用，数据集肯定也能」 | 顺序反了——通常是数据集许可更严 |

## 12. 工程结论

1. **第 1 层查数据集、第 3 层查组件，两张表都要有。** 只查一张就上线，是最常见的翻车方式。
2. **「非商业研究」按商业判定。** 你的公司有盈利业务，就没有「学术」豁免。
3. **优先选可商用数据，把 NC 数据关在研究环境里。** 这是最省心的合规姿势。
4. **许可清单要自动生成，不要手写。** 手写的清单一定漂移。
5. **权重许可 ≠ 代码许可**，这是最高频的误判。
6. **交付形态决定义务**（SaaS 比私有化部署重得多）。选交付形态时就要过一遍许可。
7. **许可会变。** 数据集页面上的许可条款可能被更新，**归档一份快照**，注明查询日期。
8. **拿不准就缩小范围**：能用自采数据就不用公开数据，能不打包图片就不打包。
   范围越窄，法务需要确认的点越少。
