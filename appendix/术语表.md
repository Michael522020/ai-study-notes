## G. Agent 与智能体

| 缩写 / 术语 | 全称 / 中文 | 说明 |
|---|---|---|
| **Agent** | 智能体 | 能自主调用工具、维持状态并循环决策的系统；四要素：工具 / 状态 / 决策循环 / 停止条件 |
| **Agentic Loop** | 智能体循环 | 「模型决策 → 执行工具 → 回填观察」直到给出最终回答或触发停止条件 |
| **Agent Bot** | 对话式智能体 | 面向终端用户的窄场景对话形态，2~4 步循环，随时可转人工 |
| **Super Agent** | 超级智能体 | 目标模糊、跨阶段、结果需机器可判验收的长任务形态 |
| **ReAct** | Reason + Act | 交替进行思考与行动的推理范式 |
| **Plan & Execute** | 规划-执行 | 先出计划再逐步执行，适合步骤多、依赖强的任务 |
| **Tool Use / Function Calling** | 工具调用 / 函数调用 | 模型以结构化参数调用外部函数 |
| **MCP** | Model Context Protocol | 模型连接工具与数据源的开放协议 |
| **Strict Tool Use** | 严格工具模式 | 要求 schema 含 `additionalProperties:false` 与显式 `required`，入参非法直接拒绝 |
| **tool_choice** | 工具选择策略 | `auto` / `none` / 指定工具；强制 `any`/`tool` 在 2026 年的当前模型上会 400 |
| **Adaptive Thinking** | 自适应思考 | 模型自行决定思考深度；取代已废弃的固定 `budget_tokens` |
| **effort** | 推理强度档位 | `low` / `medium` / `high` / `xhigh` / `max`，放在 `output_config` 里 |
| **Preserved Thinking** | 思考块绑定 | thinking 块与模型 + 对话绑定，回传时必须带 `signature` 原样带回 |
| **Compaction** | 上下文压缩 | 服务端自动摘要历史并回传 compaction 块（beta） |
| **Context Editing** | 上下文编辑 | 清理旧工具结果 / 旧思考块（beta） |
| **Message Threads** | 消息线程 | 服务端暂存会话，后续轮次只发新增内容（beta） |
| **Task Budget** | 任务预算 | 给 agentic loop 一个 token 上限，模型能看到倒计时并自觉收尾（beta） |
| **Prompt Caching** | 提示缓存 | 前缀命中缓存；渲染顺序 `tools → system → messages`，最多 4 个断点 |
| **Tool Runner** | 工具运行器 | SDK 托管的工具循环（`client.beta.messages.tool_runner`） |
| **Managed Agents** | 托管智能体 | Anthropic 同时托管 harness 与执行沙箱的托管形态（beta） |
| **HITL** | Human-in-the-Loop | 人在回路；危险动作由人确认后执行 |
| **Human Gate** | 人工闸门 | 拦截写操作与对外承诺，返回「待人工确认」而非报错 |
| **Budget** | 预算闸门 | 步数 / 工具调用次数 / 美元成本三条线，任一越界即停 |
| **Needs Human** | 需人工 | 失败语义之一，表示流程主动移交而非崩溃 |
| **Trajectory / Trace** | 轨迹 | Agent 每一步的可回放记录，是评测与排障的前提 |
| **LLM-as-Judge** | 大模型评审 | 用模型评分，必须做人工校准与量表固化 |
| **Replay Test** | 回放测试 | 把生产轨迹固化为回归用例，挡住 prompt 改动导致的效果回退 |
| **Self-Service Resolution Rate** | 自助解决率 | Bot 类产品的北极星指标：未经人工介入即被解决的比例 |
| **MTok** | Million Tokens | 百万 token，模型定价的计量单位 |
| **Observation** | 观察 | 工具执行结果回填给模型的内容，agentic loop 的第三个环节 |
| **Context Budget** | 上下文预算 | 单次调用能送进模型的 token 上限，按「输入 + 预留输出」倒推该留多少 |
| **Memory Layering** | 记忆分层 | 把记忆拆成短期 / 会话 / 长期 / 知识四层，各层用不同的写入与检索策略 |
| **Tool Whitelist** | 工具白名单 | 每个 agent 声明自己能用的工具集合，在代码层静态约束「模型允许做什么」 |
| **LangGraph** | — | 用「图」编排 agent 的开源框架：节点 = 步骤，边 = 流转，支持条件路由 |
| **interrupt() / Checkpoint** | 暂停与检查点 | LangGraph 在关键节点暂停等人批准，并把状态存成检查点以便断点续跑 |
| **Router Function** | 路由函数 | 把「下一步去哪」写成显式函数而不是黑盒 if-else，便于排查与写测试 |

| **精确率 / 召回率** | 精确率 =「查出来的里有多少是对的」；召回率 =「该找出来的找出来多少」 |
| **IoU / mIoU** | IoU 是单个框/区域的交并比；mIoU 是多个类别/数据集的平均 |
| **AP / mAP** | AP 是单个类别单个 IoU 阈值下的 PR 曲线面积；mAP 是平均 |
| **召回 / 检索召回率** | 前者是「检测出多少目标」；后者是「检索到多少相关文档」 |
| **稠密检索 / 稀疏检索** | 稠密 = 稠密向量（语义）；稀疏 = 稀疏向量（词项） |
| **Bi-Encoder / Cross-Encoder** | Bi 独立编码（快，用于召回）；Cross 联合编码（准，用于重排） |
| **Prompt / Context / Instruction** | Prompt 是给模型的总输入；Context 是其中的资料部分；Instruction 是其中的指令部分 |
| **RAG / GraphRAG** | RAG 是通用范式；GraphRAG 是用知识图谱解决全局问题的具体方案 |
| **NMS / NMS-free** | NMS-free 是训练时用一对一匹配免除后处理去重 |
| **Anchor-based / Anchor-free** | 是否依赖预设的先验框 |
| **蒸馏 / 微调** | 蒸馏是让小模型学大模型的行为；微调是用数据训练模型 |
| **PTQ / QAT** | PTQ 训练后量化（快，有损）；QAT 量化感知训练（慢，精度高） |
| **Bot / Agent / Super Agent** | 按「事情怎么算做完」区分：用户觉得可以 / 产出了一份东西 / 通过了验收标准 |
| **工作流 / Agent** | 工作流的路径由代码预先确定；Agent 的路径由模型在运行时决定 |
| **单次调用 / Agent** | 只有一次请求、格式固定 → 单次调用，不要上 Agent |
| **缓存 / 压缩** | 缓存优化「不变的前缀」；长对话的瓶颈是「增长的后缀」，要靠压缩 |
| **预算（成本）/ 预算（token）** | 前者是美元上限；后者是 task_budget 的 token 上限（beta，最小 20,000） |
| **屏蔽 / 去标识** | 屏蔽是替换成占位符（保留结构、不可还原）；去标识是不可逆的匿名化 |
| **拒答 / 转人工** | 拒答是模型不给答案；转人工是流程移交，状态是 `needs_human` |
| **预填充 / 解码** | 预填充处理输入 prompt，算力密集；解码逐 token 生成，显存带宽密集 |
| **总参数 / 激活参数** | MoE 的显存按**总参数**算，算力按**激活参数**算 |
| **算子层优化 / 架构层改动** | 算子层改计算顺序、数学不变、不用重训；架构层改模型定义、**等于换模型** |
| **精确注意力 / 近似注意力** | FlashAttention 是**精确**的（数学不变）；线性/稀疏注意力才是近似的 |
| **无损优化 / 有损优化** | 投机解码、PagedAttention、连续批处理是无损的；KV 淘汰、量化是有损的 |
| **提示缓存 / 语义缓存** | 提示缓存复用**相同前缀**（要前缀逐字一致）；语义缓存按意图匹配（可能命中错误内容） |
| **词表大小 / 上下文长度** | 词表决定「同样文本占多少 token」；上下文长度是「最多能塞多少 token」 |
| **提示注入 / 越狱** | 注入改的是**行为**（做不该做的事）；越狱改的是**内容策略**（说不该说的话） |
| **直接注入 / 间接注入** | 直接 = 攻击者对模型说话；间接 = 攻击者把指令藏在**模型会读到的地方**，受害者自己触发 |
| **误报 / 漏报** | 误报 = 正常内容被当成攻击；漏报 = 攻击没被识别。**业务上误报更致命** |
| **污点确认 / 危险 API 出现** | 前者 = 数据**确实**可控地流到危险点；后者 = 只看到危险 API 被调用 |
| **成员推断 / 模型反演** | 成员推断问「在不在训练集」；模型反演要「还原训练数据本身」 |
| **检索层过滤 / 应用层过滤** | 应用层过滤 = 无权数据**已经进了上下文**；检索层过滤 = 无权数据根本不进来 |
| **沙箱 / 权限控制** | 沙箱限制**爆炸半径**（做了坏事出不去）；权限控制决定**能不能做**坏事 |
| **合规要求 / 合规实现 / 合规证据** | 要求 = 条款；实现 = 工程动作；证据 = 能证明做对了的东西（**三者缺一不可**） |
| **视觉 token / 文本 token** | 视觉 token 占 VLM 序列的 90% 以上，**成本主要在它身上** |
| **全局特征 / 密集特征** | 全局 = 整图一个向量（分类检索）；密集 = 每 patch 一个（定位分割 OCR） |
| **切片 / 动态分辨率** | 切片 = 切块各编各的（有冗余但并行好）；动态 = 保持宽高比整体缩放（无冗余但实现复杂） |
| **盲测对照 / 无图对照** | 盲测 = 不给图跑一遍；**它的作用是识别「这道题根本没测视觉」** |
| **OCR 逐字准确率 / 编辑距离相似度** | 前者严格（一个字错就算错）；后者宽松（**会把幻觉藏起来**） |
| **VLM / 多模态模型** | VLM 特指「语言+视觉」的组合；「多模态」还可能包含音频、深度、点云 |
| **扩散 / 流的路径** | 扩散的路径曲折；Rectified Flow 的路径直，**所以更容易少步采样与蒸馏** |
| **CFG / 画质** | CFG 放大的是「贴提示词的程度」，**不是画质**；提高它会过饱和甚至崩坏 |
| **Inpaint / 合成** | Inpaint 让模型自己融合边界；合成是拼接，**接缝、透视、光影都不一致** |
| **strength（inpaint）/ strength（img2img）** | 都是「保留多少原图信息」，但 inpaint 的可用区间是 0.6~0.85，img2img 是 0.15~0.6 |
| **许可类型 / 商用授权** | 「可商用」≠「无限制」；**订阅给的是使用权，不是商用授权** |
| **单次生成成本 / 一次可用图成本** | 后者才是真实成本，**差额就是废图率** |
| **ASR / 端到端任务成功率** | ASR 准不代表业务成；**验收要看端到端任务成功率** |
| **实时轨 / 最终轨** | 流式转写天然会改口 → **实时轨给人看、最终轨给系统用** |
| **能量 VAD / 语义端点** | 前者快但会切错句；后者准但慢；**可与合并窗口叠加** |
| **声纹 / 声学特征** | 声纹用于**认证**；声学特征（语速、颤抖）用于**评估人 = 不可靠且易歧视** |

## J. 大模型基础与架构内核

### J.1 词表与结构

| 缩写 / 术语 | 全称 / 中文 | 说明 |
|---|---|---|
| **Token** | — | 文本切分后的最小单元，是计费与上下文的长度单位 |
| **Tokenizer** | — | 文本 ↔ token 的双向映射器；**不同模型的 token 数可以差 2~3 倍** |
| **BPE** | Byte-Pair Encoding | 字节级子词算法，GPT-2 起的事实标准 |
| **WordPiece** | — | BERT 系子词算法，用 `##` 标记词内续接 |
| **SentencePiece** | — | Google 的子词库，支持 BPE / Unigram 两种模式与多语言共享词表 |
| **Unigram LM** | — | 反向删除式子词算法，训练快于 BPE |
| **OOV** | Out of Vocabulary | 未登录词；byte-level BPE 从根本上消除 OOV |
| **Chat Template** | — | 对话格式模板；**必须用 `apply_chat_template()`，不要手拼字符串** |
| **Pre-LN / Post-LN** | Pre/Post Layer Normalization | 归一化放在残差分支前 / 后；**现代模型全部用 Pre-LN** |
| **RMSNorm** | Root Mean Square Layer Normalization | 只除均方根的归一化，省一次减均值 |
| **SwiGLU** | — | 门控 FFN（gate + up + down 三个矩阵），现代模型默认 |
| **GEGLU** | — | 同 SwiGLU 结构，换 GELU 激活 |
| **QK-Norm** | — | 对 Q/K 在 softmax 前归一化，防长训练时 logits 饱和 |
| **RoPE** | Rotary Position Embedding | 旋转位置编码，把相对位置关系编码进内积 |
| **ALiBi** | Attention with Linear Biases | 用线性偏置替代位置嵌入，外推能力强但生态不兼容 |
| **NTK-aware** | — | 通过缩放 RoPE base（而非位置）实现长度外推 |
| **YaRN** | — | NTK-by-parts + 注意力温度补偿的混合外推方案，**当前最佳实践** |
| **Attention Sink** | 注意力 sink | BOS 等 token 吸收无意义注意力权重的现象 |
| **Embedding / LM Head** | 词嵌入 / 输出头 | 词表 × 隐藏维；**大词表时占 30% 参数** |
| **ChatML** | — | 用 `<\|im_start\|>` / `<\|im_end\|>` 标记轮次的对话格式 |
| **Context Window** | 上下文窗口 | 以 token 计的最大输入+输出长度 |

### J.2 注意力与稀疏专家

| 缩写 / 术语 | 全称 / 中文 | 说明 |
|---|---|---|
| **MHA** | Multi-Head Attention | Q/K/V 头数相同，KV 显存最大 |
| **MQA** | Multi-Query Attention | 所有 Q 头共享 1 组 KV，KV 显存降到 1/H |
| **GQA** | Grouped-Query Attention | 分组共享 KV，**工业界事实标准** |
| **MLA** | Multi-head Latent Attention | KV 低秩压缩后再缓存，DeepSeek 路线 |
| **H_kv** | KV 头数 | 决定 KV Cache 大小的关键字段（`num_key_value_heads`） |
| **FlashAttention** | — | **精确**注意力的 IO 感知实现；数学不变，省显存带宽 |
| **PagedAttention** | — | 把 KV Cache 分页管理，消除内存碎片（vLLM） |
| **RadixAttention** | — | 用基数树组织 KV 前缀，相同前缀零拷贝共享（SGLang） |
| **MoE** | Mixture of Experts | 稀疏专家混合；**显存按总参数、算力按激活参数** |
| **Router / Gating** | 路由器 / 门控 | 决定每个 token 走哪些专家的小网络 |
| **Shared Expert** | 共享专家 | 每个 token 都激活、承载通用知识的专家 |
| **Expert Parallelism** | 专家并行 | 把专家切到不同卡，靠 all-to-all 通信 |
| **Aux Loss** | 辅助损失 | 负载均衡损失；与主任务损失相互干扰 |
| **Top-k Routing** | — | 每个 token 激活 k 个专家（k 通常 1~8） |

### J.3 推理与加速

| 缩写 / 术语 | 全称 / 中文 | 说明 |
|---|---|---|
| **Prefill** | 预填充 | 处理输入 prompt 的阶段，**算力密集** |
| **Decode** | 解码 | 逐 token 生成的阶段，**显存带宽密集** |
| **TTFT** | Time To First Token | 首 token 延迟 = 排队 + 预填充 |
| **TPOT** | Time Per Output Token | 后续每个 token 的生成间隔 |
| **Continuous Batching** | 连续批处理 | 每步踢出已完成序列、加入新请求；**吞吐提升 10~20×** |
| **Chunked Prefill** | 分块预填充 | 把长 prompt 切片与解码交替执行，避免长请求饿死短请求 |
| **Speculative Decoding** | 投机解码 | 小模型草稿 + 大模型验稿，**无损**加速 |
| **Acceptance Rate** | 接受率 | 草稿 token 被 target 接受的比例；**< 0.7 基本白干** |
| **Draft Model** | 草稿模型 | 投机解码中的小模型 |
| **Medusa / EAGLE** | — | 多 token 预测方案，**不占额外显存**，端侧更合适 |
| **Lookahead Decoding** | 前瞻解码 | 用 n-gram 做草稿，零额外模型 |
| **KV Cache 量化** | — | K 用 int8、V 留 fp16 是收益/损失比最好的起点 |
| **H2O / SnapKV** | — | KV 淘汰方法，按注意力重要性丢弃历史 KV（**有损**） |
| **CUDA Graph** | — | 把一串 kernel 启动固化成一次图启动 |
| **Operator Fusion** | 算子融合 | 减少 HBM 往返，如 QKV 合并、SwiGLU 融合 |
| **Activation Checkpointing** | 激活检查点 | 训练时用重算换显存，代价约 30% 速度 |
| **Chinchilla Scaling** | — | 训练 token 数 ≈ 20 × 参数量 |

## K. AI 落地方法论与 FDE

### K.1 流程与阶段

| 缩写 / 术语 | 全称 / 中文 | 说明 |
|---|---|---|
| **PoC / Pilot** | Proof of Concept / 试点 | 验证「模型能不能做这件事」，**不验证「方案好不好」** |
| **Shadow Run** | 影子运行 | AI 真实运行但输出不参与决策，积累对照数据；**零风险的信息来源** |
| **Canary** | 灰度 | 小流量真实决策，按比例逐步放量 |
| **Rollout** | 放量 | 从 5% → 20% → 50% → 100% 的推进节奏 |
| **Baseline** | 基线 | 规则/人工/旧系统的对照，用来证明 AI 到底带来了什么 |
| **Golden Set** | 金标准集 | 人工标注、双人仲裁的评测集；**建议起步 50 条** |
| **Guardrail** | 护栏指标 | 红线类指标（越权率、泄露率、严重错误率），**破线即回滚** |
| **Rollback** | 回滚 | 分三层独立：功能开关 / 降级开关 / 模型回滚 |
| **Canary Analysis** | 灰度分析 | 灰度组 vs 对照组的同口径对比 |
| **Drift** | 漂移 | 输入/输出分布随时间偏离训练分布 |
| **Human Overturn Rate** | 人工推翻率 | 人推翻 AI 结论的比例；**最重要的单一模型健康指标** |

### K.2 成本与商务

| 缩写 / 术语 | 全称 / 中文 | 说明 |
|---|---|---|
| **ROI** | Return on Investment | （年节省 − 年增量成本）/ 年增量成本 |
| **TCO** | Total Cost of Ownership | 三年总拥有成本，含一次性 + 持续 + 退出 |
| **Cross-over Point** | 交叉点 / 盈亏平衡量 | 固定成本与变动成本相等时的业务量 |
| **SLA** | Service Level Agreement | 服务等级协议（可用性、延迟、赔付） |
| **Lock-in** | 锁定 | 换供应商的难度；**数据/接口/Prompt/评测集四个维度** |
| **DPA** | Data Processing Agreement | 数据处理协议，约定处理目的、方式、期限 |
| **Sub-processor** | 子处理者 | 供应商的数据再委托方，需披露名单 |
| **PIPIA** | 个人信息保护影响评估 | 《个人信息保护法》要求的高风险处理活动评估 |
| **Shadow Pricing** | 影子定价 | 内部核算用的虚拟价格，避免成本失控 |

### K.3 边界与约束的实现

| 缩写 / 术语 | 全称 / 中文 | 说明 |
|---|---|---|
| **Hard Boundary** | 硬边界 | 用机制（代码/编译期/状态机）而非文档表达的边界 |
| **Negative Assertion** | 负向断言 | 断言「某件坏事不会发生」，如 `@ts-expect-error` 编译期拦截 |
| **Single Source of Truth** | 单一数据源 | 多处需保持一致的内容只存一份，其余由脚本生成 + 门禁校验 |
| **Minimal Necessary Context** | 最小必要上下文 | 只发当前任务需要的内容；同时省 token、降泄露、降噪音 |
| **待人工补充** | — | 把「无依据」变成可数的状态，代替模型编造 |
| **Human Gate** | 人工闸 | 人为确认点；**是正常状态而非异常** |
| **Non-reversible Action** | 不可逆动作 | 发出 / 导出 / 提交 / 发布；**默认从系统里拿掉** |
| **Idempotency** | 幂等 | 同一请求重复到达只生效一次；去重是成本闸也是数据质量闸 |

## L. AI 安全红队与合规工程

### L.1 攻击手法

| 缩写 / 术语 | 全称 / 中文 | 说明 |
|---|---|---|
| **Prompt Injection** | 提示注入 | 改变模型行为，让它执行原本不该执行的动作 |
| **Jailbreak** | 越狱 | 绕过内容安全策略，输出被禁止的内容 |
| **Indirect Prompt Injection** | 间接提示注入 | 指令藏在模型会读到的内容里（文档/网页/工具返回） |
| **Payload Splitting** | 载荷分割 | 把恶意指令拆成多段，让模型自己拼起来 |
| **Prompt Smuggling** | 提示走私 | 用编码/低资源语言/分割等手段把载荷藏过检测 |
| **ROPA** | Reflected Object/Property Attack | 用「对象/属性反射」式指令绕过安全微调与检测 |
| **Zero-Width Character** | 零宽字符 | 肉眼不可见但会改变模型输入的字符，用于藏指令 |
| **Tool Shadowing** | 工具重名混淆 | 恶意工具与可信工具同名或伪装，骗过模型与用户 |
| **Prompt Leaking** | 提示词泄露 | 套取 system prompt、工具描述、few-shot 示例 |
| **Confused Deputy** | 混淆代理 | 低权限主体借高权限服务执行操作（越权提权） |
| **Existence Oracle** | 存在性预言机 | 通过响应差异判断某个对象是否存在 |

### L.2 防御与分析

| 缩写 / 术语 | 全称 / 中文 | 说明 |
|---|---|---|
| **Taint Tracking** | 污点追踪 | 追踪「不可信数据 → 危险汇聚点」的路径 |
| **Source / Sink / Sanitizer** | 源 / 汇聚点 / 净化器 | 污点分析的三个基本概念 |
| **Taint-Confirmed** | 污点确认 | 数据**确实**可控地流到了危险汇聚点 |
| **Masking** | 掩码 | 把注释/字符串内容替换成空格但**保持长度与换行**（保证行号 1:1） |
| **Canary Token** | 金丝雀令牌 | 放进数据里用于检测泄露的诱饵 |
| **Backdoor** | 后门 | 平时正常、特定触发器下发作的恶意行为 |
| **Adversarial Example** | 对抗样本 | 人眼几乎看不出、但让模型判错的输入 |
| **Membership Inference** | 成员推断 | 判断某条数据是否在训练集里 |
| **Model Inversion** | 模型反演 | 还原训练数据本身 |
| **Property Inference** | 属性推断 | 推断训练集的统计属性 |
| **Model Extraction** | 模型提取 | 用大量查询复制出一个目标模型 |
| **Rate Limiting** | 速率限制 | 同时挡住成本攻击与模型窃取 |
| **Egress Allowlist** | 出网白名单 | 只允许访问业务必需的外部地址 |
