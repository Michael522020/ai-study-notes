## G. Agent 与智能体

| 缩写 / 术语 | 全称 / 中文 | 说明 |
|---|---|---|
| **Agent** | 智能体 | 能自主调用工具、维持状态并循环决策的系统；四要素：工具 / 状态 / 决策循环 / 停止条件 |
| **Agentic Loop** | 智能体循环 | 「模型决策 → 执行工具 → 回填观察」直到给出最终回答或触发停止条件 |
| **Agent Bot** | 对话式智能体 | 面向终端用户的窄场景对话形态，2~4 步循环，随时可转人工 |
| **Super Agent** | 超级智能体 | 目标模糊、跨阶段、结果需机器可判验收的长任务形态 |
| **ReAct** | Reason + Act | 交替进行思考与行动的推理范式 |
| **Plan & Execute** | 规划-执行 | 先出计划再逐步执行，适合步骤多、依赖强的任务 |
| **Tool Use / Function Calling** | 工具调用 / 函数调用 | 模型以结构化参数调用外部函数 |
| **MCP** | Model Context Protocol | 模型连接工具与数据源的开放协议 |
| **Strict Tool Use** | 严格工具模式 | 要求 schema 含 `additionalProperties:false` 与显式 `required`，入参非法直接拒绝 |
| **tool_choice** | 工具选择策略 | `auto` / `none` / 指定工具；强制 `any`/`tool` 在 2026 年的当前模型上会 400 |
| **Adaptive Thinking** | 自适应思考 | 模型自行决定思考深度；取代已废弃的固定 `budget_tokens` |
| **effort** | 推理强度档位 | `low` / `medium` / `high` / `xhigh` / `max`，放在 `output_config` 里 |
| **Preserved Thinking** | 思考块绑定 | thinking 块与模型 + 对话绑定，回传时必须带 `signature` 原样带回 |
| **Compaction** | 上下文压缩 | 服务端自动摘要历史并回传 compaction 块（beta） |
| **Context Editing** | 上下文编辑 | 清理旧工具结果 / 旧思考块（beta） |
| **Message Threads** | 消息线程 | 服务端暂存会话，后续轮次只发新增内容（beta） |
| **Task Budget** | 任务预算 | 给 agentic loop 一个 token 上限，模型能看到倒计时并自觉收尾（beta） |
| **Prompt Caching** | 提示缓存 | 前缀命中缓存；渲染顺序 `tools → system → messages`，最多 4 个断点 |
| **Tool Runner** | 工具运行器 | SDK 托管的工具循环（`client.beta.messages.tool_runner`） |
| **Managed Agents** | 托管智能体 | Anthropic 同时托管 harness 与执行沙箱的托管形态（beta） |
| **HITL** | Human-in-the-Loop | 人在回路；危险动作由人确认后执行 |
| **Human Gate** | 人工闸门 | 拦截写操作与对外承诺，返回「待人工确认」而非报错 |
| **Budget** | 预算闸门 | 步数 / 工具调用次数 / 美元成本三条线，任一越界即停 |
| **Needs Human** | 需人工 | 失败语义之一，表示流程主动移交而非崩溃 |
| **Trajectory / Trace** | 轨迹 | Agent 每一步的可回放记录，是评测与排障的前提 |
| **LLM-as-Judge** | 大模型评审 | 用模型评分，必须做人工校准与量表固化 |
| **Replay Test** | 回放测试 | 把生产轨迹固化为回归用例，挡住 prompt 改动导致的效果回退 |
| **Self-Service Resolution Rate** | 自助解决率 | Bot 类产品的北极星指标：未经人工介入即被解决的比例 |
| **MTok** | Million Tokens | 百万 token，模型定价的计量单位 |
| **Observation** | 观察 | 工具执行结果回填给模型的内容，agentic loop 的第三个环节 |
| **Context Budget** | 上下文预算 | 单次调用能送进模型的 token 上限，按「输入 + 预留输出」倒推该留多少 |
| **Memory Layering** | 记忆分层 | 把记忆拆成短期 / 会话 / 长期 / 知识四层，各层用不同的写入与检索策略 |
| **Tool Whitelist** | 工具白名单 | 每个 agent 声明自己能用的工具集合，在代码层静态约束「模型允许做什么」 |
| **LangGraph** | — | 用「图」编排 agent 的开源框架：节点 = 步骤，边 = 流转，支持条件路由 |
| **interrupt() / Checkpoint** | 暂停与检查点 | LangGraph 在关键节点暂停等人批准，并把状态存成检查点以便断点续跑 |
| **Router Function** | 路由函数 | 把「下一步去哪」写成显式函数而不是黑盒 if-else，便于排查与写测试 |

| **精确率 / 召回率** | 精确率 =「查出来的里有多少是对的」；召回率 =「该找出来的找出来多少」 |
| **IoU / mIoU** | IoU 是单个框/区域的交并比；mIoU 是多个类别/数据集的平均 |
| **AP / mAP** | AP 是单个类别单个 IoU 阈值下的 PR 曲线面积；mAP 是平均 |
| **召回 / 检索召回率** | 前者是「检测出多少目标」；后者是「检索到多少相关文档」 |
| **稠密检索 / 稀疏检索** | 稠密 = 稠密向量（语义）；稀疏 = 稀疏向量（词项） |
| **Bi-Encoder / Cross-Encoder** | Bi 独立编码（快，用于召回）；Cross 联合编码（准，用于重排） |
| **Prompt / Context / Instruction** | Prompt 是给模型的总输入；Context 是其中的资料部分；Instruction 是其中的指令部分 |
| **RAG / GraphRAG** | RAG 是通用范式；GraphRAG 是用知识图谱解决全局问题的具体方案 |
| **NMS / NMS-free** | NMS-free 是训练时用一对一匹配免除后处理去重 |
| **Anchor-based / Anchor-free** | 是否依赖预设的先验框 |
| **蒸馏 / 微调** | 蒸馏是让小模型学大模型的行为；微调是用数据训练模型 |
| **PTQ / QAT** | PTQ 训练后量化（快，有损）；QAT 量化感知训练（慢，精度高） |
| **Bot / Agent / Super Agent** | 按「事情怎么算做完」区分：用户觉得可以 / 产出了一份东西 / 通过了验收标准 |
| **工作流 / Agent** | 工作流的路径由代码预先确定；Agent 的路径由模型在运行时决定 |
| **单次调用 / Agent** | 只有一次请求、格式固定 → 单次调用，不要上 Agent |
| **缓存 / 压缩** | 缓存优化「不变的前缀」；长对话的瓶颈是「增长的后缀」，要靠压缩 |
| **预算（成本）/ 预算（token）** | 前者是美元上限；后者是 task_budget 的 token 上限（beta，最小 20,000） |
| **屏蔽 / 去标识** | 屏蔽是替换成占位符（保留结构、不可还原）；去标识是不可逆的匿名化 |
| **拒答 / 转人工** | 拒答是模型不给答案；转人工是流程移交，状态是 `needs_human` |
